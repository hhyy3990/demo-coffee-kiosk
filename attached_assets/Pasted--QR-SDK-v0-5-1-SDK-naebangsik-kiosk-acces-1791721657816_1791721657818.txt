# 내 방식 QR — 공통 SDK v0.5.1 안정화 릴리스 제작 및 독립 소비자 검증

현재 데모커피 프로젝트에서 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.0`을 개발·관리하고 있습니다.

최근 첫 화면의 QR 하단 도크를 적용한 뒤 이중 세로 스크롤이 발생하는 문제를 수정했습니다.

수정 전에는 문서 전체 스크롤과 내부 콘텐츠 스크롤이 동시에 발생했으며, 안쪽 스크롤을 끝까지 내려도 마지막 '직원 도움' 카드에 접근하기 어려웠습니다.

원인 분석 결과 다음 문제가 확인됐습니다.

- QR 도크 추가 후 문서 높이가 약 72px 증가
- 호스트 `.shell`의 `min-height: 100dvh`가 SDK의 콘텐츠 높이 제한과 충돌
- 문서와 내부 콘텐츠에 별도 스크롤 범위가 발생
- QR 도크가 마지막 콘텐츠를 가리는 현상

현재 공통 SDK 소스에는 해당 수정이 반영되어 있고, 데모커피 실제 화면에서도 정상 작동하는 것을 사용자가 확인했습니다.

**그러나 기존 v0.5.0 tarball에는 수정사항이 포함되지 않았습니다.**

이번 작업은 수정된 소스를 정식 SDK v0.5.1로 패키징하고, 실제 배포 파일을 기준으로 독립 소비자 검증을 수행하는 것입니다.

## 1. SDK 소스 상태 확인

먼저 다음 내용을 확인해 주세요.

- 현재 SDK package.json 버전
- QR 하단 도크 공개 API
- 수정된 스크롤 관련 SDK 스타일
- QR 도크가 콘텐츠 표시 높이를 계산하는 구조
- 문서 스크롤과 내부 스크롤을 구분하는 처리
- 기존 fixed / sticky 조작부 회피 방식
- 변경된 SDK 소스와 빌드 결과의 일치 여부
- 기존 v0.5.0 tarball에 포함되지 않은 수정사항

현재 정상 작동하는 코드를 기준으로 작업합니다.

기존 기능을 새롭게 설계하거나 불필요하게 변경하지 마세요.

## 2. SDK v0.5.1 버전 업데이트

SDK 패키지 버전을 npm SemVer 규칙에 맞는 `0.5.1`로 변경해 주세요.

다음 사항을 확인합니다.

- SDK package.json의 version = 0.5.1
- 패키지 빌드 결과에 최신 스타일 반영
- QR 하단 도크 공개 API 유지
- 방법 B 하단 조작 API 유지
- 기존 QR v1/v2 호환성 유지
- README와 관련 메타데이터에서 필요한 버전 정보만 갱신

기존 v0.1.0부터 v0.5.0까지의 tarball은 삭제하거나 덮어쓰지 마세요.

## 3. 첫 화면 단일 스크롤 구조 검증

이번 릴리스의 가장 중요한 검증 항목입니다.

QR 도크를 활성화한 첫 화면에서 다음을 만족해야 합니다.

- 문서와 내부 콘텐츠가 동시에 세로 스크롤되지 않음
- 실제 사용자에게 필요한 주 스크롤 영역이 하나만 존재
- 해당 스크롤만으로 마지막 콘텐츠까지 접근 가능
- QR 도크는 화면 하단에 고정
- QR 도크가 콘텐츠를 가리지 않음
- QR 도크가 문서 높이를 불필요하게 증가시키지 않음
- 스크롤바만 숨기는 임시 처리 금지
- 스크롤 위치를 반복해서 강제로 조정하지 않음

데모커피에서는 특히 마지막 '직원 도움' 카드가 온전히 나타나고 클릭되는지 확인해 주세요.

### 실제 측정

다음 요소의 scrollHeight, clientHeight, 최대 스크롤 거리, overflow-y를 확인해 주세요.

- html
- body
- #root
- 키오스크 루트
- SDK가 관리하는 콘텐츠 스크롤 영역
- QR 하단 도크

검증 결과에는 실제 스크롤 소유 요소를 명시해 주세요.

## 4. 기존 QR 하단 도크 기능 회귀

다음 기능을 유지합니다.

- 첫 화면에서만 QR 도크 표시
- QR 적용 전에도 표시
- QR 적용 후에도 첫 화면에서 유지
- 버튼 문구 '내 QR로 화면 설정'
- 버튼 클릭 시 기존 QR 모달 바로 열림
- 카메라·주소·토큰 직접 입력 유지
- 주문 단계 진입 시 QR 도크 제거
- 주문 중 별도의 QR 진입 버튼 없음
- 주문 완료 후 첫 화면 복귀 시 QR 도크 재표시
- SDK 세션 종료 후 이전 사용자 접근성 설정 초기화

QR 도크 버튼의 실제 터치 높이와 클릭 가능 여부를 확인해 주세요.

## 5. 방법 B 하단 조작 모드 결합 검증

현재 SDK는 화면을 축소하지 않고, 아래쪽 60%·70%·80% 영역에서 조작하는 방법 B를 지원합니다.

QR 도크가 있는 첫 화면에서는 **QR 도크 및 등록된 기존 고정 조작부를 제외한 나머지 높이**를 기준으로 비율을 적용합니다.

다음 조합을 확인합니다.

- QR 도크만 표시
- QR 도크 + 하단 60%
- QR 도크 + 하단 70%
- QR 도크 + 하단 80%
- QR 도크 + 아주 큰 글씨 + 큰 버튼 + 고대비
- 주문 화면 + 하단 60%·70%·80%
- SDK 세션 종료 후 일반 화면 복원

각 조합에서 다음을 검증합니다.

- 글씨·버튼 크기 유지
- 실제 하단 표시 영역 높이
- QR 도크와 콘텐츠 겹침 없음
- 스크롤 최하단 접근 가능
- 화면 가로 넘침 없음
- 고정 조작부와 QR 도크 충돌 없음
- 화면 전환 및 복귀 후 스크롤 상태 정상

기존 QR의 bottomControls 값만으로 방법 B가 자동 활성화되지 않는 정책도 유지합니다.

## 6. 스크롤 안내 및 스마트 길잡이 회귀

다음 공통 안내 문구를 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

확인 사항:

- 스크롤할 내용이 있으면 시작 위치부터 안내 표시
- 중간에서도 정상 표시
- 최하단에 도달하면 숨김
- 다시 위로 이동하면 재표시
- 일반 메뉴와 제한적인 중첩 허용
- QR 버튼과 고정 필수 조작부는 가리지 않음
- 스마트 길잡이 표시 중 스크롤 안내 숨김
- 스마트 길잡이 종료 후 필요한 경우 안내 재표시
- QR 모달이 열리면 기존 업무 스크롤 상태 유지

안내 요소의 변화가 스크롤 튐이나 반복적인 레이아웃 보정을 일으키지 않아야 합니다.

## 7. 독립 소비자 tarball 설치 검증

이번에는 데모커피 프로젝트에서 SDK 소스를 직접 참조하는 검사만으로 성공 처리하지 마세요.

**반드시 새 v0.5.1 tarball을 별도의 소비자 프로젝트에 설치해 검증해야 합니다.**

독립 소비자에서 다음 구조를 확인합니다.

A. 원래 document가 스크롤을 소유하는 키오스크

B. 내부 콘텐츠 영역이 스크롤을 소유하는 키오스크

C. 기존 하단 고정 버튼이 있는 키오스크

각 구조에 공개 SDK API로 QR 도크를 연결합니다.

확인 사항:

- 기존 문서·내부 이중 스크롤 발생 여부
- QR 도크 활성화·비활성화
- QR 도크의 고정 위치
- 마지막 메뉴 접근 및 실제 클릭
- 고정 하단 버튼과 충돌 없음
- 60%·70%·80% 하단 표시 영역
- SDK 적용·해제 후 원상 복구
- 동일 SDK 인스턴스 반복 사용
- 가로 넘침 없음

특정 데모커피 CSS를 복사해야만 정상 동작한다면 범용 적용에 한계가 있는 것으로 보고해 주세요.

- 0.1초·0.5초·1초·3초 후 스크롤 위치

## 10. 기존 진단 결과와 별도 개선 과제 구분

이전 보고에서 360×667 화면의 일부 메뉴 버튼에 약 43.5px 터치 영역 경고가 있었습니다.

이번 v0.5.1의 직접적인 수정 대상은 아닙니다.

해당 문제를 이번 패키징 작업에 섞어 수정하지 말고, 재현 여부와 향후 수정 필요성만 보고해 주세요.

또한 동적 모달 삽입 시 SDK의 createLayoutEnhancer가 스크롤 위치를 변경할 가능성이 확인된 적이 있으므로, 해당 문제도 후속 범용성 개선 과제로 보존합니다.

## 11. 패키징

다음 명령에 해당하는 검증을 수행합니다.

- npm run sdk:build
- npm run typecheck
- npm test
- npm run build
- SDK npm pack
- 독립 소비자 tarball 설치
- 소비자 타입 검사
- 소비자 테스트
- 소비자 프로덕션 빌드

새 tarball 경로:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.1.tgz`

tarball 내부 package.json에서 다음을 직접 확인해 주세요.

- name: `@naebangsik/kiosk-accessibility-sdk`
- version: `0.5.1`

**특히 수정된 CSS가 실제 tarball 안에 들어 있는지 압축 파일 내용까지 검증해 주세요.**

또한 독립 소비자 프로젝트에서 설치된 패키지의 CSS를 실제로 불러와 브라우저 테스트해야 합니다.

SDK 소스에만 수정이 있고 tarball에는 빠지는 문제가 없어야 합니다.
