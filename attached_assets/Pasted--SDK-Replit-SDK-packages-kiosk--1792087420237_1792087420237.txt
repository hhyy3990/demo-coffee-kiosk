# 공통 SDK 긴급 점검 — 스마트 길잡이 조기 종료 및 스크롤 안내 불안정

현재 프로젝트는 **데모커피 Replit**이며, 공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`에 있습니다.

현재 SDK 버전은 v0.5.19입니다.

사용자가 무인민원발급기를 실제 테스트하면서 다음 오류를 발견했습니다.

이번 작업에서는 **무인민원발급기 전용 코드를 수정하지 말고**, 먼저 공통 SDK에서 해당 증상을 재현하고 원인을 분석한 뒤 범용 SDK 결함만 수정해 주세요.

## 1. 스마트 길잡이가 15초 전에 사라지는 오류

실제 발생 화면:
- 주민등록번호 숫자 키패드
- 증명서에 표시할 항목 선택
- 발급 부수 선택

현상:
스마트 길잡이가 나타난 상태에서 숫자나 선택지를 누르면 15초가 끝나기 전에 안내가 사라집니다.

다음을 조사하세요.

- 클릭·입력 이벤트가 Smart Guide를 종료하는지
- `notifyScreenChange()`가 불필요하게 호출되는지
- `setGuideState()` 반복 호출로 타이머가 초기화되는지
- 동일 stepId에서 입력값 변경을 새로운 업무 단계로 처리하는지
- SDK가 강조 대상 클릭 시 길잡이를 의도적으로 종료하는지
- 패널이 사라진 것인지 실제 안내 상태가 끝난 것인지
- 배치 억제(`guide-suppressed`)가 발생한 것인지

### 원하는 정책

같은 업무 단계에서 숫자 입력, 선택지 변경, 부수 증감 등이 발생하더라도 **그 자체만으로 스마트 길잡이의 15초 표시 타이머가 중단되면 안 됩니다.**

단, 사용자가 실제로 다음 업무 화면으로 이동하거나 세션을 종료하면 이전 스마트 길잡이를 정리해야 합니다.

또한 스마트 길잡이가 사라지지 않게 하려고 입력·선택 기능을 방해해서는 안 됩니다.

실제 단계 전환과 동일 단계 안의 값 변경을 구분하세요.

## 2. 스마트 길잡이 실제 시간 검증

v4 체험 프로필:

- smartGuide: true
- guideDelaySeconds: 10
- slowGuidance: true

브라우저에서 스마트 길잡이가 표시된 상태로:

1. 숫자 키패드 반복 입력
2. 표시 항목 여러 개 선택
3. 부수 증가·감소
4. 화면 스크롤
5. 이전·다음 업무 단계 이동

을 각각 수행하세요.

동일 단계에서 조작하는 동안에는 안내 표시가 시작된 시점부터 약 15초간 유지되어야 합니다.

실제 단계 이동 시에는 이전 안내가 종료되고 새로운 단계의 안내 일정이 시작돼야 합니다.

각 경우 실제 표시 시간과 종료 원인을 기록하세요.

## 3. 하단 스크롤 안내 문제

사용자 증상:
- 스크롤 가능한 화면인데도 하단 스크롤 안내가 표시되지 않음
- 일부 마지막 화면에서만 등장
- 등장한 뒤 스크롤하면 위쪽·중간·아래쪽으로 계속 이동

다음을 조사하세요.

- SDK의 스크롤 가능 영역 판정
- 실제 scrollHeight와 clientHeight
- 스크롤 안내 표시 조건
- 호스트가 등록한 스크롤 컨테이너
- 하단 조작 60/70/80% 적용 시 좌표계
- 일반 화면에서의 위치
- 스크롤할 때 위치 재계산
- 쉬운 말·스마트 길잡이와의 충돌
- 스크롤 안내가 SDK의 재배치 대상에 잘못 포함되는지

### 목표

스크롤이 필요한 화면에서 아직 아래쪽에 내용이 남아 있다면 사용자가 쉽게 알아볼 수 있는 스크롤 안내를 제공합니다.

스크롤 안내는 화면 안에서 **예측 가능한 안정적인 위치**를 유지해야 합니다.

스크롤 중 상단·중앙·하단으로 갑자기 뛰어다니면 안 됩니다.

주요 버튼이나 키패드를 가리지 않아야 합니다.

실제로 더 내려갈 내용이 없을 때는 안내가 사라질 수 있습니다.

**모든 화면에 무조건 안내를 표시하는 방식으로 해결하지 마세요.**

## 4. 쉬운 말과 스마트 길잡이의 역할 분리

현재 일부 호스트 안내문에서 쉬운 말과 스마트 길잡이가 모두 행동 지시처럼 작성되어 사용자가 차이를 느끼기 어렵습니다.

공통 SDK의 역할과 호스트의 안내 데이터 계약을 다음처럼 명확히 구분해 문서화하세요.

### 쉬운 말 안내

어려운 용어·개념·선택지의 의미를 일상적인 말로 설명합니다.

예:
- 발급 부수: 서류를 몇 장 받을지 뜻해요.
- 수수료 면제: 정해진 조건에 해당하면 돈을 내지 않아도 된다는 뜻이에요.
- 표시 항목: 서류에 어떤 내용을 넣을지 고르는 거예요.

### 스마트 길잡이

현재 화면에서 사용자가 다음에 해야 할 행동을 안내합니다.

예:
- 서류를 몇 장 받을지 고른 뒤 다음 버튼을 눌러주세요.
- 서류에 표시할 내용을 고르고 확인해 주세요.

두 기능 모두 SDK가 공통 패널에서 표시하지만, 안내 문구의 실제 내용은 호스트가 제공합니다.

이번 단계에서 OpenAI API를 추가하거나 SDK가 임의로 설명을 생성하지 마세요.

대신 호스트가 두 종류의 안내를 구분해서 제공할 수 있도록 기존 공개 API의 사용법을 점검하고 문서화하세요.

## 5. 독립 소비자 재현 테스트

데모커피와 무인민원발급기에 종속되지 않는 fixture에서 다음 화면을 구성해 테스트하세요.

- 숫자 키패드
- 여러 선택지가 있는 화면
- 부수 증감 버튼
- 스크롤이 긴 화면
- 고정 하단 버튼이 있는 화면
- 일반 화면
- 하단 조작 60/70/80%

스마트 길잡이 표시 중 동일 단계 조작을 반복하는 상황과 실제 단계 전환을 분리해서 검증하세요.

스크롤 안내는 표시 여부뿐 아니라 위치 변화와 버튼 충돌도 측정하세요.

## 6. 기존 기능 회귀

반드시 유지할 기능:

- QR v1~v4 호환
- 쉬운 말 즉시 표시
- 스마트 길잡이 10/15/20초 표시 전 대기
- 스마트 길잡이 10/15초 표시 후 유지
- 접기·펼치기
- 이전·다음
- 스마트 길잡이의 단일 안내
- 스크롤 중 안내 상태 유지
- 주요 업무 버튼 보호
- 15초 완료 후 자동 복귀
- 세션 종료 시 초기화
- 브라우저 무응답 방지

## 7. 수정 범위 및 릴리스

- 공통 SDK 결함이면 데모커피 프로젝트의 SDK 원본에서 수정
- SDK 소스가 변경되면 v0.5.20으로 버전 업데이트
- 기존 v0.5.19 tarball 보존
- 독립 소비자에 새 tarball 설치 후 테스트
- 데모커피 주문 흐름 회귀 검증
- 무인민원발급기 프로젝트는 수정 금지
- 중앙 내 방식 QR 프로젝트 수정 금지
- 호스트별 CSS 예외 금지
- Publish 금지

SDK 문제가 아니라 호스트의 화면 단계 정보 전달 문제라면 SDK를 억지로 바꾸지 말고, 무인민원발급기에서 수정해야 할 정확한 연결 사항을 별도로 보고하세요.

7. SDK에서 수정한 내용

14. 미검증 사항
15. Publish 미실행 확인

**성공 기준은 동일 업무 화면에서 조작하더라도 스마트 길잡이 표시 시간이 조기에 종료되지 않고, 스크롤이 필요한 화면에서는 스크롤 안내가 안정적으로 표시되며, 기존 쉬운 말·스마트 길잡이·키오스크 조작 기능을 유지하는 것입니다.**

문제가 재현되지 않으면 완료라고 단정하지 말고, 어떤 부분을 검증하지 못했는지 정확히 보고하세요.
