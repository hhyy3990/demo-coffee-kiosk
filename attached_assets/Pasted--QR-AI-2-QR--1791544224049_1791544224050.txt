프로젝트: 내 방식 QR 연동 카페 키오스크 데모
목표
AI 라이프 솔루션 챌린지 시제품의 2단계로,
기존에 만든 “내 방식 QR” 중앙 프로필 서비스와 연동되는 카페 키오스크 데모 웹앱을 별도의 Replit 프로젝트로 구현한다.
이 키오스크는 사용자가 자신의 QR을 불러오면, 저장된 접근성 설정에 따라 화면이 자동으로 바뀌는 모습을 보여줘야 한다.
핵심 컨셉
- 실제 상용 키오스크와 100% 호환되는 것이 아니라,
- 하나의 공통 접근성 프로필이 서로 다른 연동 가능 기기에 재사용될 수 있음을 보여주는 데모다.
- 이번 단계에서는 카페 키오스크를 먼저 구현한다.
- 디자인은 사용자가 첨부한 카페 키오스크 사진을 참고하되,
  투썸플레이스 계열처럼 비교적 깔끔하고 보기 쉬운 구조를 참고한다.
- 하지만 실제 브랜드 로고, 상호명, 고유 디자인 요소는 그대로 복제하지 말고
  브랜드 비의존적인 데모 키오스크로 구현한다.
기술 목표
- React + TypeScript
- Vite
- 모바일/태블릿/세로형 키오스크 비율 대응
- 상태 관리가 단순하면 React state로 구현, 필요 시 작은 유틸 훅 사용
- 접근성 스타일은 CSS 변수 또는 토큰 기반으로 관리
- 배포 가능한 구조
- 중앙 QR 서비스는 별도 프로젝트이며, 여기서는 연동 클라이언트만 구현
중앙 서비스 연동
기존 공개 중앙 서비스 URL:
[https://naebangsikqr.replit.app](https://naebangsikqr.replit.app/?utm_source=chatgpt.com)
이 키오스크는 QR에 포함된 token을 이용해 중앙 서비스의 프로필 조회 API를 호출해야 한다.
가능하면 다음 흐름으로 구현:
1. QR 전체 URL 입력 또는 붙여넣기
2. URL에서 token 파라미터 추출
3. 중앙 서비스의 프로필 조회 API로 접근성 설정 조회
4. 반환된 설정을 현재 키오스크 화면에 즉시 적용
가능하면 다음 2가지 방식을 모두 지원:
- 데모용 간편 불러오기: QR URL 붙여넣기
- 확장용 UI: “QR 불러오기” 버튼 및 스캔 UI 자리(실제 스캔은 후순위라도 좋음)
주의:
- 중앙 서비스 코드는 수정하지 않는다.
- CORS 또는 환경 문제로 직접 연동이 막히면 오류 메시지를 명확히 보여주고,
  개발용 데모 프로필(JSON 샘플)을 선택해 적용하는 fallback도 함께 제공한다.
- 하지만 최우선은 실제 공개 중앙 서비스와 연결되는 구조다.
구현할 화면 흐름
1. 시작 화면
- 상단: 데모 카페 키오스크 제목
- 메인 선택:
  - 매장 이용
  - 포장
- 보조 버튼:
  - QR 불러오기
  - 직원 도움 요청
- 하단 또는 상단 작게:
  - 현재 접근성 프로필 상태(기본 모드 / 프로필 적용됨)
2. 메뉴 선택 화면
참고 구조:
- 상단 카테고리 탭
  - 커피/음료
  - 케이크
  - 디저트
  - 푸드
- 본문:
  - 메뉴 카드 그리드
  - 각 카드에 이름, 가격, 간단한 이미지 자리
- 오른쪽 또는 하단:
  - 장바구니 요약
  - 선택 수량
  - 총 금액
  - 다음 버튼
- 직원 도움 요청 버튼 유지
3. 옵션 선택 화면
예:
- 온도: 아이스 / 핫
- 사이즈: 레귤러 / 라지
- 컵 선택: 매장컵 / 개인 텀블러
- 수량 증감
- 버튼:
  - 이전
  - 담기
4. 장바구니 / 주문 확인 화면
- 담은 메뉴 목록
- 수량 / 금액
- 총 금액
- 버튼:
  - 이전
  - 결제하기
5. 결제 방법 선택 화면
- 결제 방법 예시:
  - 일반 카드
  - 간편결제
  - 모바일쿠폰
  - 기프트카드
- 너무 복잡한 실결제 로직은 필요 없음
- 클릭 후 다음 화면으로 진행
6. 결제 안내 화면
- 카드 꽂기 또는 태그 안내
- “결제 중입니다” 표시
- 이후 완료 화면으로 자동 전환
7. 주문 완료 화면
- “주문이 완료되었습니다”
- 대기 안내
- 영수증 출력 여부 버튼(예 / 아니오)
- 처음으로 돌아가기 버튼
데모용 메뉴 데이터
하드코딩된 데모 데이터로 충분하다.
예:
- 아메리카노
- 카페라떼
- 바닐라라떼
- 콜드브루
- 레몬티
- 치즈케이크
- 마카롱
- 크루아상
각 메뉴는
- id
- name
- price
- category
- option 지원 여부
  를 가진다.
접근성 프로필 적용 기능
중앙 서비스에서 받아올 수 있는 프로필 항목 예시:
- 글씨 크기: 기본 / 크게 / 아주 크게
- 버튼 크기: 기본 / 크게
- 화면 대비: 기본 / 고대비
- 쉬운 말: 사용 / 미사용
- 화면 구성 단순화: 사용 / 미사용
- 하단 조작 모드: 사용 / 미사용
- 스마트 길잡이: 사용 / 미사용
- 스마트 길잡이 시작 시간: 10초 / 15초 / 20초
- 음성 안내: 사용 / 미사용
적용 방식
1) 글씨 크기
- 기본 / 크게 / 아주 크게에 따라 CSS 변수로 전체 텍스트 스케일 조정
- 아주 크게일 때 제목/버튼/핵심 안내는 더 굵게 표시
- 가로 스크롤 금지
2) 버튼 크기
- 클릭 버튼 높이와 패딩 증가
- 카드 내부 버튼도 커지도록
3) 고대비
- 배경/텍스트 대비 강화
- 선택 상태/비선택 상태 구분 선명하게
- 버튼 테두리와 포커스도 더 명확히
4) 쉬운 말
일반 문구 예:
- “옵션을 선택해 주세요”
  쉬운 말 버전 예:
- “원하는 항목을 하나씩 골라 주세요”
일반 문구 예:
- “결제하기”
  쉬운 말 버전 예:
- “돈 내기”
단, 너무 어색하지 않게 자연스럽고 이해 쉬운 수준으로 조정
5) 화면 구성 단순화
- 한 화면의 정보량 축소
- 부가 문구 줄이기
- 중요 버튼만 강조
- 불필요한 배너/장식 제거
- 메뉴 카드 수도 한 번에 적게 보여주기
6) 하단 조작 모드
- 이전 / 다음 / 담기 / 결제하기 같은 주요 버튼을 화면 하단 고정 영역으로 이동
- 휠체어 사용자나 손이 아래쪽에 더 닿기 쉬운 상황 고려
7) 음성 안내
- 브라우저 speechSynthesis 사용 가능 시 사용
- 버튼 클릭 또는 길잡이 발동 시 짧게 읽어주기
- 음성 안내 켜짐 상태를 표시
스마트 길잡이 구현
이 기능은 꼭 구현해 주세요.
목적
사용자가 조작을 멈췄을 때, 다음 단계로 어떻게 가는지 안내한다.
동작 원리
- 마지막 사용자 조작 시각을 기록
- 설정된 시간(10/15/20초) 동안 아무 조작이 없으면
  현재 단계에 맞는 안내를 표시
- 안내는 다음 버튼 또는 핵심 버튼 근처에 말풍선/안내 상자로 띄운다
- 필요하면 해당 버튼을 강조한다
화면별 예시
시작 화면
- “주문을 시작하려면 ‘매장 이용’이나 ‘포장’을 눌러 주세요.”
메뉴 선택 화면
- 메뉴를 하나 선택하지 않은 경우:
  - “원하는 메뉴를 한 번 눌러 주세요.”
- 메뉴는 선택했지만 다음으로 안 가는 경우:
  - “선택한 메뉴를 담거나 다음으로 가려면 아래 버튼을 눌러 주세요.”
옵션 선택 화면
- “온도와 크기를 고른 뒤 아래 ‘담기’ 버튼을 눌러 주세요.”
장바구니 화면
- “주문을 끝내려면 ‘결제하기’를 눌러 주세요.”
결제 방법 화면
- “원하는 결제 방법을 하나 눌러 주세요.”
길잡이 UI
- 노란색/연한 크림색 안내 박스
- 쉬운 문장
- 필요 시 화살표나 강조 테두리
- 음성 안내가 켜져 있으면 함께 읽어주기
중요한 UX 요구사항
- 사용자가 QR을 적용하기 전에는 기본 키오스크 UI
- QR 적용 후에는 접근성 반영 UI
- 현재 어떤 설정이 적용되었는지 간단히 보여주는 영역 필요
- “프로필 해제” 또는 “기본 화면으로 돌아가기” 버튼 필요
- 데모 종료 후 다음 사용자를 위해 초기화 가능해야 함
디자인 방향
- 첨부된 사진들 중 투썸플레이스 계열처럼
  정돈된 상단 카테고리 + 카드형 메뉴 + 명확한 하단 결제 영역을 참고
- 하지만 실제 로고/브랜드명/고유 상표 요소는 사용하지 말 것
- 따뜻한 오프화이트 배경
- 진한 네이비/차콜 텍스트
- 포인트 컬러는 너무 튀지 않게
- 키오스크처럼 세로형 화면 비율에서 자연스럽게 보이도록
필수 검증
다음 상황을 실제 Preview에서 확인해 주세요.
1. 기본 주문 흐름이 끝까지 동작하는지
2. QR URL 붙여넣기로 프로필을 불러올 수 있는지
3. 불러온 프로필에 따라 UI가 즉시 바뀌는지
4. 큰 글씨 / 고대비 / 하단 조작 / 쉬운 말 조합에서 레이아웃이 깨지지 않는지
5. 스마트 길잡이가 실제로 무조작 시간 후 발동하는지
6. 음성 안내가 켜졌을 때 브라우저에서 동작하는지
7. 모바일 폭과 키오스크 세로형 폭에서 가로 스크롤이 생기지 않는지

- 병원 키오스크 구현
- 중앙 QR 서비스 자체 수정
