# 내 방식 QR — 공통 SDK v0.5.4 개발: 화면 전환 시 스크롤 초기화 및 스크롤 소유자 관리

현재 데모커피 프로젝트에서 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.3`의 소스를 개발·관리하고 있습니다.

SDK v0.5.3은 QR 프로필 v3를 지원하며, 하단 조작 60·70·80% 자동 적용, QR 도크, 스크롤 안내, 스마트 길잡이, 세션 초기화 등을 제공합니다.

이번에는 무인민원발급기에서 발견된 **업무 화면 전환 시 스크롤 위치가 이전 화면에서 그대로 유지되는 문제**를 공통 SDK 차원에서 해결하고 싶습니다.

## 1. 무인민원발급기에서 확인된 실제 문제

무인민원발급기 Replit Agent의 진단 결과입니다.

### A. QR 적용 후 업무 화면 전환

390×844 화면에서 큰 글씨·큰 버튼·고대비·하단 80%의 v3 QR 프로필을 적용했습니다.

- 기존 `.stage` 위치: y=136~677
- 기존 `.stage` 높이: 541px
- 기존 스크롤 범위: 658px
- 실제 휠로 80px 스크롤
- 증명서 메뉴 선택 후 다음 업무 화면으로 이동
- 화면 ID는 변경됐지만 `.stage.scrollTop`은 80px 그대로 유지
- 다음 화면 `.stage` 위치: y=150.6~751.6
- 다음 화면 높이: 601px

즉, 새로운 화면이 시작됐는데 스크롤은 맨 위로 돌아가지 않았습니다.

### B. 업무 도중 처음화면 복귀

QR 미적용 390×844 화면에서도 문제가 있었습니다.

- 발급 중 문서가 최대 26px 스크롤 가능
- 처음화면 버튼으로 복귀
- SDK QR 도크가 다시 활성화
- `.stage.scrollTop`이 108px가 됨
- 첫 화면 제목이 원래 y=116에서 y=8로 밀림
- 상단 헤더가 잘려 보임

반면 새로운 탭에서 최초 진입하는 첫 화면은 정상입니다.

### C. 스크롤 소유자 차이

무인민원발급기에서 화면에 따라 스크롤 소유자가 다르게 나타났습니다.

- 첫 화면: 주로 `.stage` 내부 스크롤
- 일부 긴 입력 화면: document 스크롤
- 하단 조작 모드: SDK가 지정한 `.stage` 스크롤
- QR 도크 활성화·비활성화 시 overflow와 높이 변화

현재 SDK에는 업무 화면이 변경됐다는 사실을 전달하고, 새로운 화면의 스크롤 상태를 초기화하는 공개 API가 없습니다.

이번 작업에서는 이를 **공통 SDK의 기능으로 구현**해 주세요.

무인민원발급기 프로젝트는 이번에 수정하지 않습니다.

## 2. 최우선 설계 원칙

**공통 SDK의 범용성을 가장 우선합니다.**

목표는 데모커피·무인민원발급기·향후 병원 키오스크에서 동일한 SDK 공개 API를 사용할 수 있도록 하는 것입니다.

다음 원칙을 지켜 주세요.

- SDK에 무인민원발급기의 `.stage` 선택자 하드코딩 금지
- SDK에 카페 전용 화면 이름 하드코딩 금지
- SDK가 업무 단계 이름을 추측하지 않기
- 호스트는 화면 변경 사실만 SDK에 알리기
- SDK가 실제 스크롤 소유자를 파악하고 초기화
- 일반 스크롤·모달·안내·리사이즈에서는 초기화하지 않기
- 기존 접근성 프로필 및 QR 도크 기능 유지
- SDK 외부에서 반복적인 `scrollTo(0,0)` 호출로 우회하지 않기

기존 SDK 기능만으로 해결할 수 있다면 공개 API를 불필요하게 늘리지 않아도 됩니다.

다만 별도 API가 필요하다면 최소한의 범용 인터페이스로 설계해 주세요.

## 3. 기존 SDK 구조 분석

코드 수정 전에 다음 구조를 확인해 주세요.

- `createAccessibilitySdk()`
- `applyProfile()`
- `setViewportMode()`
- `endSession()`
- `createQrEntryDock()`
- `bottom-viewport.configureTarget()`
- QR 도크 활성화·비활성화
- `getLayoutRegions()` 및 scrollArea 등록
- 실제 document 스크롤 처리
- MutationObserver / ResizeObserver 기반 레이아웃 갱신
- 기존 레이아웃 복원 및 안전한 초기화 로직

특히 기존 화면 전환 중 scrollTop이 유지되는 이유를 분석하고, **스크롤 위치를 초기화해야 하는 시점과 레이아웃이 안정되는 시점**을 구분해 주세요.

가능하면 독립 fixture에서 무인민원발급기와 동일한 문제를 먼저 재현해 주세요.

## 4. 범용 화면 전환 API

SDK에서 호스트가 업무 화면 변경 사실을 명시적으로 알릴 수 있는 기능을 설계해 주세요.

예시:

` sdk.notifyScreenChange(screenId) `

API 이름과 정확한 형태는 기존 SDK 아키텍처에 맞게 결정해도 됩니다.

필수 동작:

1. 호스트에서 화면 식별자를 전달
2. 이전 화면 식별자와 비교
3. 실제로 화면이 달라진 경우에만 스크롤 초기화
4. 새 화면 DOM과 레이아웃이 준비된 뒤 실행
5. 현재 실제 스크롤 소유자를 찾아 초기화
6. QR 도크 및 방법 B에 따른 높이 계산이 끝난 뒤에도 최상단 유지
7. 같은 화면을 반복해서 알리면 불필요한 초기화 없음

### 화면 식별자 조건

- 문자열 또는 SDK에서 명확히 정의한 안정적인 식별자 사용
- 카페·민원·병원 화면 이름을 SDK가 알 필요 없음
- 실제 업무 화면 변경에만 반응
- 동일한 screenId를 반복 전달해도 멱등적으로 동작

호스트가 화면의 현재 상태를 매 렌더링마다 반복 전달하더라도 스크롤이 계속 맨 위로 돌아가지 않아야 합니다.

## 5. 스크롤 초기화 범위

업무 화면이 바뀌면 다음 스크롤 위치를 확인합니다.

- document.scrollingElement
- SDK가 관리하는 스크롤 영역
- 호스트 어댑터에 등록된 scrollArea
- 이전 화면에서 스크롤을 소유했던 영역
- 현재 화면에서 실제 스크롤을 소유하는 영역

실제 활성 스크롤 소유자를 기준으로 필요한 영역만 초기화해 주세요.

스크롤 가능한 모든 DOM 요소를 무차별적으로 검색해서 초기화하는 방식은 피합니다.

필요한 경우 이전 소유자와 새로운 소유자의 스크롤 위치를 함께 정리할 수 있지만, 그 범위는 SDK 계약에 등록된 요소와 문서 스크롤 영역으로 제한해 주세요.

스크롤 초기화는 즉시 이동하도록 하며, 사용자가 화면 전환 후 직접 스크롤하기 시작했다면 늦은 비동기 초기화가 사용자 조작을 다시 맨 위로 되돌려서는 안 됩니다.

## 6. 화면 전환·레이아웃 갱신 순서

다음 상황을 각각 검토해 주세요.

### A. 일반 화면 → 일반 화면

- 업무 단계 변경
- 동일한 내부 스크롤 컨테이너 재사용
- 새 화면의 첫 번째 제목 표시

### B. 일반 화면 → QR 도크가 있는 첫 화면

- QR 도크 활성화
- 콘텐츠 영역 높이 재계산
- 기존 문서 스크롤이 내부 스크롤로 변경될 수 있음
- 첫 화면 제목부터 표시

### C. QR 도크 첫 화면 → 일반 업무 화면

- QR 도크 비활성화
- 콘텐츠 높이 재계산
- 필요하면 내부 스크롤에서 문서 스크롤로 전환
- 다음 화면 상단 표시

### D. 방법 B 60·70·80% 활성 상태

- SDK가 하단 viewport를 고정
- 새 화면에서 scrollArea가 변경될 가능성
- 새 화면의 첫 콘텐츠가 하단 영역 안에서 정상 표시
- 글씨·버튼 확대 비율 유지

### E. QR 적용 후 화면 전환

- QR 적용으로 DOM 크기 변경
- QR 도크 높이 변화
- 프로필 유지
- 새로운 업무 화면 상단부터 표시

다음과 같은 처리 순서가 필요한지 검토해 주세요.

화면 ID 변경 감지 → 호스트 렌더 반영 → QR 도크 및 viewport 레이아웃 갱신 → 실제 스크롤 소유자 확인 → 위치 초기화

단, 구체적인 실행 순서는 프레임워크 독립적이어야 합니다.

React 전용 hook만 제공하는 방식은 피하고, 일반 HTML·JavaScript 프로젝트에서도 사용할 수 있게 해 주세요.

## 7. 첫 화면 최초 진입과 세션 초기화

다음 상황도 명확히 처리합니다.

- 새 탭에서 첫 화면 최초 진입
- 새로고침
- 발급 완료 후 첫 화면 복귀
- 발급 도중 처음화면 복귀
- 주문 완료 후 첫 화면 복귀
- 새 사용자 세션 시작

화면 전환 통지 API가 호출되면 현재 화면 식별자를 기준으로 초기화해야 합니다.

`endSession()`은 기존 접근성 설정과 타이머를 해제하는 동작을 유지합니다.

화면 전환 API와 세션 종료 API의 역할은 구분하되, 함께 사용할 때 스크롤 위치가 다시 이전 값으로 돌아오지 않아야 합니다.

새 이용자의 첫 화면은 맨 위부터 표시되어야 합니다.

## 8. 스크롤 위치를 보존해야 하는 상황

다음 상황에서는 기존 스크롤 위치를 유지해야 합니다.

- 같은 업무 화면에서 입력값 변경
- React 재렌더링
- 상품 옵션 변경
- 메뉴 선택 상태 변경
- QR 모달 열기·닫기
- 발급 불가 안내 모달 열기·닫기
- 스마트 길잡이 표시·닫기
- 스크롤 안내 표시·숨김
- 화면 크기 변경
- QR 프로필 적용 중 단순 레이아웃 변경

모달을 열었다 닫는 행위를 업무 화면 변경으로 오인하면 안 됩니다.

스크롤 초기화 로직이 기존 스마트 길잡이·스크롤 안내의 위치나 표시 상태를 망가뜨려서도 안 됩니다.

## 9. 독립 fixture 구성

SDK 개발 프로젝트에 다음 구조를 가진 독립 fixture를 만들어 주세요.

### Fixture A — 문서 스크롤형

- 실제 document가 스크롤 소유
- 두 개 이상의 업무 화면
- 화면 전환 전 document를 아래로 스크롤
- 전환 후 상단 복원 확인

### Fixture B — 내부 스크롤형

- 재사용되는 내부 콘텐츠 컨테이너
- 화면 전환 전 scrollTop 설정
- 화면 전환 후 0으로 초기화
- 같은 화면 재렌더링에서는 유지

### Fixture C — QR 도크 포함

- 첫 화면에서 QR 도크 활성화
- 다음 화면에서 QR 도크 제거
- 이전 화면으로 돌아오면 다시 활성화
- 도크 추가·제거 후에도 스크롤 초기화 유지

### Fixture D — 방법 B 포함

- 하단 60·70·80%
- 화면 전환 전후 높이 재계산
- 새 화면 첫 제목 표시
- 마지막 콘텐츠도 스크롤로 접근 가능

### Fixture E — 기존 고정 하단 조작부

- QR 도크와 기존 고정 버튼 동시 존재
- 화면 전환 시 레이아웃 재계산
- 버튼 겹침 없음
- 스크롤 소유자 전환 시 상단 초기화

### Fixture F — 모달과 동일 화면 갱신

- 스크롤을 중간으로 이동
- 모달 열기·닫기
- 동일한 화면 ID 재통지
- 스크롤 위치 변화 없음

호스트 전용 CSS나 실제 카페·무인발급기 소스를 복사하지 않고 구현해 주세요.

## 10. 브라우저 검증

다음 뷰포트에서 검사합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920

각 화면에서 일반 모드, QR 도크, 하단 60·70·80%를 검증합니다.

측정 항목:

- 화면 변경 전 screenId
- 화면 변경 후 screenId
- document.scrollTop
- SDK 등록 scrollArea.scrollTop
- 실제 활성 스크롤 소유자
- 화면 첫 제목의 boundingClientRect
- 새 화면 시작 위치
- QR 도크 top / height
- 하단 viewport top / height
- 화면 전환 직후와 안정화 후 위치
- 늦은 MutationObserver / ResizeObserver 처리 후 위치
- 사용자 수동 스크롤 후 위치 유지
- 모달 전후 scrollTop 변화
- 이중 스크롤 여부
- 가로 넘침 여부

특히 스크롤 값이 0이어도 첫 제목이 화면 밖에 있다면 성공 처리하지 마세요.

**첫 콘텐츠가 실제 표시 영역 안에서 보이는지 반드시 검증해야 합니다.**

## 11. 데모커피에 공통 API 연결

SDK 공개 API를 만든 뒤 데모커피에도 동일한 방식으로 연결해 주세요.

- 첫 화면
- 매장·포장 선택
- 메뉴 목록
- 상품 옵션
- 장바구니
- 결제
- 주문 완료
- 처음화면 복귀

업무 화면이 실제로 바뀌는 시점에만 SDK로 화면 식별자를 전달합니다.

데모커피의 기존 주문 상태 변경과 같은 화면 안의 렌더링은 별개로 처리합니다.

QR 도크의 `setActive()`와 화면 전환 API가 서로 충돌하지 않도록 연결해 주세요.

향후 무인민원발급기에서도 같은 공개 API를 사용할 수 있도록 README에 프레임워크 독립적인 예시를 작성해 주세요.

## 12. 기존 기능 회귀

다음 기능을 유지합니다.

- QR 프로필 v1/v2/v3
- 하단 60·70·80% 자동 적용
- QR 프로필 교체·반복 적용
- QR 도크 첫 화면 전용 표시
- 스크롤 안내 no-safe-space 수정

### 최종 합격 기준

**1. 키오스크 업무 화면이 실제로 변경되면 새로운 화면의 스크롤이 맨 위에서 시작합니다.**

**2. QR 도크·방법 B 등으로 스크롤 소유자가 바뀌어도 올바르게 초기화됩니다.**

**3. 새 화면의 첫 제목이 실제 표시 영역 안에 나타납니다.**

**4. 같은 화면에서 스크롤하거나 모달을 열고 닫을 때에는 기존 위치가 유지됩니다.**

**5. 데모커피·무인민원발급기·미래 병원 키오스크에서 사용할 수 있는 공통 공개 API로 구현됩니다.**

**6. 기존 SDK v0.5.3 기능이 유지되고, 새 v0.5.4 tarball을 설치한 독립 소비자에서도 검증됩니다.**

검증되지 않은 항목은 성공으로 보고하지 말고 제한사항을 명확하게 기록해 주세요.
