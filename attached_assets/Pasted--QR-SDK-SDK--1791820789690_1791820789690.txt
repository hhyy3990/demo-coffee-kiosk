# 내 방식 QR 공통 SDK — 최소 글씨 크기 제한 제거 및 자동 보정 개선

현재 프로젝트는 데모커피 키오스크이자 공통 접근성 SDK 개발 프로젝트입니다.

현재 릴리스는 `@naebangsik/kiosk-accessibility-sdk@0.5.6`입니다.

이번 작업은 SDK의 자동 글씨 크기 보정이 실제 키오스크에서 작동하지 않았던 원인을 해결하는 것입니다.

## 1. 핵심 변경: 절대 최소 글씨 크기 제한 제거

기존 SDK는 큰 글씨에서 최소 14px, 매우 큰 글씨에서 최소 16px 등의 글씨 크기 하한을 사용하고 있습니다.

이 제한 때문에 자동 보정 대상으로 등록된 문구도 다음 축소가 차단됐습니다.

- 14px → 13.3px 또는 12.6px
- 16px → 15.2px 또는 14.4px

**이번에는 SDK가 강제하는 절대 최소 글씨 크기 제한을 완전히 제거해 주세요.**

구체적으로 다음을 확인합니다.

- 일반 큰 글씨 적용 경로의 최소 font-size 제한
- 매우 큰 글씨 적용 경로의 최소 font-size 제한
- 선택적 자동 글씨 보정 경로의 최소 font-size 제한
- 다른 내부 함수에서 14px·16px 등으로 강제하는 로직
- CSS와 JavaScript 양쪽의 중복 제한

단, **큰 글씨 확대 비율 자체는 유지합니다.** 절대 최소 크기 제한만 제거하는 것이며, 기본 글씨를 작게 만들거나 모든 문구를 일괄 축소하는 작업이 아닙니다.

기존 5%·10% 보정은 보정 전 크기를 기준으로 적용하며, 자동 보정의 최대 축소율 10%는 변경하지 않습니다.

## 2. 개인정보 안내 문구도 자동 축소 가능하도록 정책 변경

현재 무인민원발급기에서 다음 두 문구가 있습니다.

- 민원 발급 시뮬레이션
- 실제 신청 정보는 저장되지 않습니다

기존 통합에서는 두 번째 문구를 개인정보 관련 안내라는 이유로 자동 보정 대상에서 제외했습니다.

이번에는 **개인정보 관련 안내라는 이유만으로 SDK가 글씨 보정을 금지하지 않도록** 해 주세요.

단, 모든 개인정보 문구를 자동으로 축소하라는 뜻은 아닙니다.

- 호스트가 `getFontCorrectionTargets()`에 명시적으로 등록한 문구만 보정
- 민감한 입력값이나 개인정보 내용은 진단 로그에 수집하지 않음
- 호스트가 등록하지 않은 문구는 보정하지 않음
- 최대 10% 축소 제한 유지
- 문구 자체를 숨기거나 삭제하지 않음

SDK에 개인정보 관련 문구를 차단하는 별도 조건이 있다면 제거하되, 실제로 그런 조건이 있는지 먼저 확인하세요.

무인민원발급기의 특정 안내 문구를 SDK에 하드코딩하지 마세요.

## 3. 보정 실패 판정 개선

이전 무인민원발급기 진단에서 다음 문제도 확인됐습니다.

- 실제 글씨 축소 후보가 최소 크기 제한 때문에 시험되지 않았음
- 안내문과 그 부모인 고정 푸터가 겹친다는 이유로 실패 판정이 발생할 수 있음
- 실제 홈·전화면 버튼과의 겹침을 진단에서 놓침

따라서 다음을 개선합니다.

1. 정상적인 부모·자식 요소의 교차를 겹침 오류로 판정하지 않기
2. 실제 차폐 요소와 고정 조작 버튼을 기준으로 겹침 검사
3. 등록된 안내문이 고정 조작부의 버튼과 겹치는지 검사
4. 5% 보정 후 실제 DOM 좌표 재측정
5. 해결되지 않으면 10% 보정 후 다시 측정
6. 해결되면 최소한의 보정을 유지
7. 해결되지 않으면 원래 글씨 크기와 줄 높이 복원
8. 문제 원인과 시도한 보정값을 진단 결과에 기록

일부 문제가 해결됐다는 이유만으로 완전 해결로 판정하지 마세요.

실제 사용자가 누르는 버튼에 겹침이 남아 있다면 미해결로 표시해야 합니다.

## 4. 개발자용 레이아웃 진단 개선

`inspectLayout()`에 다음 검사 기능을 보완합니다.

- 텍스트와 고정 조작 버튼의 실제 교차
- 고정 높이 컨테이너에서 텍스트가 넘치는 상태
- 실제 가려진 텍스트와 단순히 부모 높이를 넘은 텍스트의 구분
- QR 도크 바깥 영역과 실제 QR 버튼 영역의 구분
- 정상적인 부모·자식 겹침 제외
- 실제 문제가 없는 요소의 오탐 최소화

진단 결과에는 가능하면 다음을 포함합니다.

- 보정 전후 font-size
- 5% 또는 10% 시도 여부
- 보정 후 실제 겹침 px
- 최종 성공·실패 여부
- 남은 문제 유형

민감한 사용자 입력값이나 안내문 본문은 진단 로그에 포함하지 않습니다.

## 5. 독립 fixture 테스트

React에 의존하지 않는 일반 HTML·CSS·JavaScript fixture에서 검사합니다.

반드시 다음 사례를 포함하세요.

- 원래 글씨가 작은 키오스크
- 큰 글씨 14px에서 12.6px까지 보정
- 매우 큰 글씨 16px에서 14.4px까지 보정
- 두 개의 보조 안내가 같은 고정 영역에 있는 경우
- 두 안내 모두 등록되어 보정되는 경우
- 하나만 등록되어 보정되는 경우
- 고정 하단 버튼과 실제 겹치는 경우
- 부모 푸터와 정상적으로 겹치는 경우
- QR 도크 외곽과는 겹치지만 QR 버튼과는 겹치지 않는 경우
- 5% 보정만으로 해결
- 10% 보정으로 해결
- 10% 보정 후에도 실패
- 보정 실패 후 완전한 스타일 복원
- 프로필 변경 및 세션 종료 후 스타일 복원

**최소 글씨 크기 제한 때문에 5%·10% 후보가 건너뛰어지는 일이 없어야 합니다.**

- QR v1/v2/v3
- 큰 글씨·매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말
- 스마트 길잡이
- 음성 안내
- QR 도크 하단 60/70/80% 자동 동기화
- 스크롤 안내
- notifyScreenChange()
- endSession()
- 데모커피 주문·결제 전체 흐름

특히 원래 크기가 작은 호스트 문구에 적용되는 확대 비율이 변경되지 않았는지 검사합니다.
