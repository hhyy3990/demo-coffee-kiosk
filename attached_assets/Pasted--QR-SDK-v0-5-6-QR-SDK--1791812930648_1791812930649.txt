# 내 방식 QR — 공통 SDK v0.5.6 개발: 선택적 글씨 크기 보정, 레이아웃 진단, QR 도크 자동 동기화

현재 프로젝트는 데모커피 키오스크와 공통 접근성 SDK의 개발 프로젝트입니다.

현재 SDK 릴리스 버전은 `@naebangsik/kiosk-accessibility-sdk@0.5.5`입니다.

이번 작업의 목적은 **서로 다른 키오스크에서 접근성 설정을 적용할 때 발생하는 레이아웃 문제를 보다 범용적으로 발견하고, 안전한 범위에서만 자동 보정하는 기능**을 개발하는 것입니다.

무인민원발급기의 특정 CSS를 수정하는 것이 아니라, 카페·민원발급기·향후 병원 키오스크에서 공통으로 사용할 수 있는 SDK 기능이어야 합니다.

이번에 개발할 후보 기능은 다음 세 가지입니다.

- 선택적 보조 문구 글씨 크기 자동 보정
- 개발자용 레이아웃 진단 기능
- QR 프로필 viewportMode와 QR 도크 하단 모드 자동 동기화

**세 기능 모두 독립 fixture에서 검증한 뒤, 전체 회귀와 독립 소비자 설치까지 통과했을 때만 SDK v0.5.6을 제작합니다.**

---

## 1. 현재 SDK 기능 보존

다음 기능은 반드시 유지합니다.

- QR v1/v2/v3 프로필 지원
- 큰 글씨·매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말
- 스마트 길잡이
- 단계별 음성 안내
- 스마트 길잡이 지연 시간 10·15·20초
- 하단 viewport 60·70·80%
- 방법 B: 콘텐츠 축소 없이 하단 작업 영역 적용
- QR 도크 첫 화면 전용 표시
- notifyScreenChange() 화면 전환 API
- scroll guidance 및 최하단 숨김
- 안전 중앙 정렬
- endSession() 세션 초기화

기존 호스트 API를 불필요하게 변경하지 않습니다.

## 2. 선택적 글씨 크기 자동 보정

이번 기능은 **큰 글씨 모드를 해제하지 않고, 실제로 잘리거나 겹치는 일부 보조 안내 문구에 한해서만 소폭 크기를 줄이는 기능**입니다.

기본 원칙:

1. 큰 글씨·매우 큰 글씨 프로필 자체는 유지합니다.
2. 모든 글씨에 자동 축소를 적용하지 않습니다.
3. 호스트 개발자가 축소를 허용한 보조 문구만 대상으로 합니다.
4. 문제가 없는 문구는 절대 축소하지 않습니다.
5. 문제가 생겼더라도 축소가 해결책이 아니면 축소하지 않습니다.
6. 원래 크기 대비 최대 10%까지만 줄입니다.
7. 먼저 5% 축소를 시도하고, 해결되지 않으면 10% 이내에서 최소한으로 조정합니다.
8. 10% 축소로도 해결되지 않으면 원래 접근성 확대 상태를 유지하고 진단 오류로 보고합니다.
9. 축소로 실제 겹침이나 잘림이 완전히 사라졌는지 다시 측정해야 합니다.

예시:

- 큰 글씨 적용 후 24px
- 5% 보정 → 22.8px
- 최대 10% 보정 → 21.6px

이는 접근성 설정 전체를 약화시키는 기능이 아니라 **일부 보조 문구에 한해 허용되는 제한적 보정**입니다.

### 적용 금지 대상

다음 요소에는 자동 축소를 적용하지 않습니다.

- 주요 업무 버튼의 텍스트
- 메뉴 이름
- 증명서 종류
- 결제 금액 및 수수료
- 개인정보 관련 필수 안내
- 오류·경고 문구
- 사용자 입력값
- 법적 고지 등 반드시 충분히 읽을 수 있어야 하는 내용

애매한 대상은 자동 축소하지 않는 것을 기본값으로 합니다.

## 3. 자동 보정 대상 등록 방식

SDK가 모든 DOM 텍스트를 임의로 조정하면 안 됩니다.

호스트가 공개 API나 명시적인 요소 등록 방식으로 **크기 보정을 허용한 보조 문구**를 지정할 수 있도록 설계해 주세요.

요구사항:

- React에 의존하지 않는 일반적인 API
- 기존 SDK 어댑터 구조와 호환
- 특정 키오스크 클래스 이름 하드코딩 금지
- DOM 요소 또는 선언적 속성 방식 중 간결하고 안정적인 설계 선택
- 동적으로 생성·제거되는 요소 지원
- 이전 화면 요소의 참조 정리
- 같은 요소에 보정이 중첩 적용되지 않음
- 원래 SDK 확대 크기를 기준으로 보정
- 프로필 변경·화면 전환·세션 종료 시 원상복구

반드시 호스트가 명시적으로 허용한 텍스트만 수정합니다.

## 4. 줄바꿈 처리 원칙

자동 줄바꿈을 모든 상황에서 우선 적용하지 않습니다.

**줄바꿈으로 요소의 높이가 증가하면 오히려 아래쪽 고정 버튼과 겹칠 수 있기 때문입니다.**

다음 사항을 측정합니다.

- 사용 가능한 너비
- 사용 가능한 높이
- 현재 텍스트 높이
- 줄바꿈 후 예상 높이
- 주변 고정 요소의 위치
- 실제 겹침 여부

높이를 확장할 충분한 공간이 확인된 경우에만 기존 글씨 크기를 유지하는 줄바꿈을 허용할 수 있습니다.

공간이 부족한데 줄바꿈으로 해결된 것처럼 처리하지 마세요.

기존 호스트의 줄바꿈·표시 규칙을 SDK가 무단으로 변경하지 않습니다.

## 5. 자동 보정 원인 판정

실제 레이아웃 문제를 다음 유형으로 구분합니다.

A. 텍스트 자체가 고정 높이 컨테이너에서 잘림

B. 텍스트 영역과 하단 고정 조작부가 겹침

C. 긴 글씨가 가로로 넘침

D. QR 도크와 보조 안내가 충돌

E. 스크롤할 수 없는 영역 밖에 텍스트 배치

F. 정상적인 의도된 요소 겹침

**5~10% 축소가 실제 문제를 해결할 수 있는 경우에만 자동 보정을 적용합니다.**

예를 들어 텍스트가 QR 도크 아래에 완전히 가려졌다면 10% 축소를 시도하기보다 레이아웃 문제로 보고해야 합니다.

## 6. 보정 알고리즘 안전성

다음 조건을 지켜 주세요.

- 과도한 DOM 전체 탐색 금지
- 모든 애니메이션 프레임마다 검사하지 않음
- SDK 프로필 적용 후 적절한 시점에 측정
- ResizeObserver 등으로 레이아웃 변화 감지
- 불필요한 반복 재계산 방지
- 보정으로 다시 레이아웃이 바뀌는 무한 루프 방지
- 기존 텍스트 확대와 CSS specificity 충돌 방지
- 폰트가 늦게 로드되는 경우 재측정
- 원래 font-size와 inline style 복원
- style의 !important 우선순위 훼손 방지
- 반올림으로 10% 제한을 초과하지 않도록 검증

보정으로 발생하는 새로운 겹침이나 잘림도 검사해야 합니다.

## 7. 개발자용 레이아웃 진단 기능

이 기능은 키오스크를 사용하는 일반 사용자에게 표시하지 않는 **개발자 전용 진단 도구**입니다.

다음 문제를 검사하도록 설계합니다.

- 텍스트 잘림
- 텍스트 가로 넘침
- 요소 간 의도치 않은 겹침
- QR 도크와 콘텐츠 충돌
- 고정 하단 조작부와 콘텐츠 충돌
- 첫 제목의 상단 잘림
- 마지막 필수 버튼의 접근 가능 여부
- 실제 스크롤 소유자
- 이중 스크롤 의심
- 접근성 확대 후 최소 터치 영역 미달
- SDK 보정 성공 또는 실패

각 결과에는 다음 정보가 포함되어야 합니다.

- 문제 유형
- 해당 DOM 요소
- 실제 측정 좌표
- 현재 접근성 설정
- 화면 크기
- 심각도
- 원인 후보
- 수정 권장 사항
- 자동 보정 적용 여부

진단 결과를 개발자가 JSON 또는 콘솔 출력 등으로 확인할 수 있게 해 주세요.

단, 모든 겹침을 오류로 판정해서는 안 됩니다. 의도적인 모달·배지·아이콘 겹침은 구분해야 합니다.

검출할 수 없는 경우에는 오류가 없다고 단정하지 말고 미검증 상태로 남깁니다.

## 8. 개발자 진단 기능 실행 정책

진단 기능은 다음을 만족해야 합니다.

- 기본적으로 비활성화
- 개발자가 명시적으로 활성화
- Production 사용자 화면에는 진단 UI 표시 금지
- 일반 사용자 조작과 분리
- 화면 레이아웃을 수정하지 않는 읽기 전용 검사
- 자동 보정 기능과 진단 기능은 서로 독립적으로 사용 가능
- 브라우저 성능 저하 최소화
- 민감한 입력값이나 주민등록번호, 결제정보 수집 금지
- 진단 로그에 사용자 입력값 포함 금지

가능하면 별도의 개발용 API를 제공해 현재 화면의 진단 결과를 요청할 수 있게 합니다.

SDK의 공개 API가 과도하게 복잡해지지 않도록 설계 이유를 설명해 주세요.

## 9. QR 도크 하단 모드 자동 동기화

기존 v0.5.5에서는 QR 프로필의 viewportMode를 적용하더라도 QR 도크의 bottomViewportPercent를 호스트가 별도로 전달해야 하는 경우가 있었습니다.

무인민원발급기에서는 이 연결 누락으로 165px의 불필요한 예약 공간이 발생했습니다.

이번에는 SDK 내부에서 다음을 자동 처리하도록 개선합니다.

- applyProfile()에서 v3 viewportMode 확인
- 하단 60·70·80% 설정 자동 동기화
- QR 도크의 하단 모드 업데이트
- viewportMode:null일 때 일반 모드 복귀
- v1/v2에서는 기존처럼 하단 모드 비활성
- 모드 변경 시 불필요한 예약 공간 제거
- QR 도크 중복 생성 방지
- QR 모달 및 카메라 세션 보존
- 호스트가 도크를 직접 재생성할 필요 없도록 개선
- endSession() 후 기본 도크 상태 복원

기존 createQrEntryDock() 공개 계약의 호환성을 유지합니다.

호스트에서 명시적으로 설정한 개발용 모드와 프로필 기반 모드가 충돌할 때의 우선순위를 명확히 정의해 주세요.

SDK 내부에서 실제 도크를 관리할 수 있는 범위와 호스트가 직접 소유하는 요소의 범위를 구분해 주세요.

## 10. 독립 fixture 테스트

카페·무인민원발급기 코드를 복사하지 않은 일반 HTML·CSS·JavaScript fixture를 사용합니다.

필수 사례:

- 짧은 보조 문구
- 긴 보조 문구
- 고정 높이 텍스트 컨테이너
- 자동 줄바꿈 발생
- 하단 고정 버튼
- QR 도크
- 모달
- 큰 글씨·매우 큰 글씨
- 하단 60·70·80%
- React 없이 동작하는 일반 DOM
- 중첩 flex/grid 레이아웃
- 고정 폭 및 반응형 레이아웃

검증 조건:

- 문제가 없으면 축소 없음
- 필요한 경우에만 5~10% 이내 축소
- 10% 축소로 해결되지 않으면 무리한 추가 축소 없음
- 축소한 뒤 실제 잘림·겹침 해결
- 중요한 텍스트 축소 없음
- 프로필 해제 시 스타일 복원
- 화면 변경 후 오래된 요소 참조 없음
- QR 도크 하단 모드 자동 동기화
- 중복 도크 없음
- 진단 기능이 실제 문제를 보고
- 의도된 겹침은 오탐 최소화

### 최종 성공 기준

**1. 큰 글씨 모드는 유지하면서 등록된 보조 문구만 필요한 경우 최대 5~10% 보정합니다.**

**2. 자동 보정으로 해결되지 않는 겹침은 개발자 진단 결과로 보고합니다.**

**3. SDK가 중요한 업무 문구나 버튼을 임의로 축소하지 않습니다.**

**4. QR 프로필의 하단 모드와 QR 도크가 자동으로 동기화됩니다.**

**5. React와 특정 키오스크에 종속되지 않는 공통 SDK 구조를 유지합니다.**

**6. 전체 검증에 성공한 경우에만 v0.5.6을 릴리스합니다.**
