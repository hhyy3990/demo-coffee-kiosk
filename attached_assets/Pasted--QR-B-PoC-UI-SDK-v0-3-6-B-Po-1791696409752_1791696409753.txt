# 내 방식 QR — 방법 B 하단 조작 모드 PoC: 안내 UI 개선 및 스마트 길잡이 연동

현재 데모커피 프로젝트에는 공통 SDK v0.3.6과 방법 B 하단 조작 모드 PoC가 구현되어 있습니다.

방법 B는 키오스크 화면을 축소하지 않고, 기존 글씨·버튼 크기를 유지하면서 화면의 아래쪽 60%·70%·80% 영역에 주요 UI를 배치하는 방식입니다.

기존 PoC에서는 70% 영역의 주문 흐름, 스크롤 안정성, 클릭 좌표, 큰 글씨·큰 버튼 동시 적용을 확인했습니다.

하지만 390×844 시작 화면에서 SDK의 세로 스크롤 안내가 제목 일부를 가리는 문제가 발견됐습니다.

이번에는 **스크롤 안내 문구를 간결하게 만들고, 안내 전용 공간을 확보하며, 스마트 길잡이와 표시 우선순위를 조정**해 주세요.

방법 B의 기본 구조를 다시 만들거나 방법 A로 변경하지 마세요.

## 1. 스크롤 안내 문구 간결화

현재 공통 안내 문구는 다음 두 가지입니다.

- 아래에도 내용이 있습니다. 화면을 위로 밀어보세요.
- 아래에도 버튼이 있습니다. 화면을 위로 밀어보세요.

하단 표시 영역이 줄어든 상황에서는 문구가 길고 두 줄 이상을 차지해 콘텐츠를 가릴 수 있습니다.

이번 PoC에서는 다음과 같이 간결하게 변경해 주세요.

**기본 안내:** `↓ 아래에도 내용이 있어요`

**버튼 안내:** `↓ 아래에도 버튼이 있어요`

카페·병원·은행·무인민원발급기에서 공통으로 사용할 수 있는 표현입니다.

아래쪽에 주요 조작 버튼이 있다는 사실을 안전하게 확인할 수 있으면 버튼 안내를 사용하고, 그렇지 않으면 기본 안내를 사용합니다.

안내에 사용한 아래쪽 화살표는 장식적 표시이며, 사용자가 화면을 아래로 내려야 한다는 의미입니다. 실제 조작은 손가락을 위로 밀어 스크롤하는 방식으로 유지합니다.

### 글씨 크기 원칙

- 기존 본문 글씨보다 약간 작게 표시할 수 있음
- 다만 큰 글씨·아주 큰 글씨 모드에서도 실제 읽기 어려울 정도로 축소하지 않기
- 안내 글씨의 실제 렌더링 크기를 px 단위로 측정
- 한 줄 표시를 우선하되 좁은 화면에서는 자연스러운 두 줄 허용
- 한 줄을 강제하기 위해 텍스트를 잘라내거나 가로 스크롤을 만들지 않기
- 높이 고정으로 안내 글씨가 잘리거나 버튼 영역으로 넘치지 않도록 하기
- 고대비 모드에서도 충분히 구분 가능해야 함

이 문구는 우선 PoC에만 적용하고 정식 SDK 버전 업데이트는 하지 않습니다.

## 2. 안내 전용 공간 확보

현재 스크롤 안내가 콘텐츠 위에 오버레이되어 제목과 겹치는 문제가 있습니다.

이를 해결하기 위해 방법 B의 하단 표시 영역 안에서 **스크롤 안내를 위한 독립적인 공간**을 확보해 주세요.

### 설계 원칙

- 하단 60%·70%·80% 표시 영역 자체는 유지
- 안내 영역과 일반 콘텐츠 영역을 시각적으로 분리
- 안내 때문에 제목·메뉴·상품·필수 버튼을 가리지 않음
- 하단 고정 조작 버튼이 있다면 그 위에 안내 영역 배치
- 안내가 나타나거나 사라져도 스크롤 컨테이너의 크기와 위치가 변하지 않음
- 안내 공간은 화면 단계 진입 시 미리 확보하고 해당 단계가 유지되는 동안 크기를 유지
- 안내가 사라질 때에는 기존 공간을 제거하지 말고 내용만 숨기기
- 스크롤 위치에 따라 안내가 계속 켜지고 꺼져도 레이아웃 재계산을 유발하지 않기

안내 공간이 필요 이상으로 커지지 않도록 실제 글씨 높이·패딩을 기준으로 계산해 주세요.

방법 B에서 화면 아래쪽을 사용할 수 있다는 장점을 지나치게 희생하지 않도록, 작은 안내 영역을 우선 실험해 주세요.

**주의:** 기존 SDK v0.3.5에서 발생했던 스크롤 튐 문제를 되살려서는 안 됩니다.

안내 전용 공간 구현이 스크롤 위치에 영향을 주는 경우에는 무리하게 적용하지 말고, 안내 영역을 안정적으로 고정할 수 있는 대안을 검토해 주세요.

## 3. 스마트 길잡이 우선 표시

스마트 길잡이와 스크롤 안내는 동시에 표시하지 않습니다.

다음 우선순위를 적용해 주세요.

1. 스마트 길잡이가 표시 중이면 스크롤 안내를 일시적으로 숨김
2. 스마트 길잡이가 사라지면 스크롤 위치를 다시 확인
3. 아래로 더 스크롤할 수 있다면 스크롤 안내를 다시 표시
4. 이미 스크롤 끝에 도달했다면 안내를 표시하지 않음

### 구체적인 시나리오

- QR 프로필에서 스마트 길잡이 지연이 10초로 설정돼 있음
- 사용자가 조작하지 않아 10초 후 스마트 길잡이 표시
- 기존 스크롤 안내는 즉시 숨김
- 스마트 길잡이가 사라지면 스크롤 안내 재표시 여부 판정
- 스마트 길잡이 표시 중 사용자가 스크롤 끝으로 이동한 경우, 길잡이가 사라져도 스크롤 안내는 다시 표시하지 않음
- 사용자가 처음화면으로 돌아가 세션이 종료되면 두 안내의 상태와 타이머 모두 정리

스마트 길잡이의 기존 10·15·20초 지연 설정은 변경하지 마세요.

스마트 길잡이와 스크롤 안내의 표시 우선순위는 데모커피만의 임시 로직이 아니라, 향후 공통 SDK에서 재사용할 수 있는 방식으로 설계해 주세요.

## 4. 안내 공간과 스마트 길잡이의 관계

가능하면 두 안내가 **동일한 안내 표시 공간을 번갈아 사용하는 구조**를 우선 검토해 주세요.

다만 스마트 길잡이의 실제 높이가 더 크거나 버튼을 포함한다면, 무조건 같은 높이로 강제하지 마세요.

다음 조건을 만족하는 안전한 구조를 선택해 주세요.

- 안내 전환 시 기존 콘텐츠의 위치 변화 없음
- 안내 표시 때문에 필수 버튼이 밀려나지 않음
- 스마트 길잡이가 기존 메뉴를 가리지 않음
- 스마트 길잡이에 실제 조작 요소가 있다면 해당 조작이 가능해야 함
- 스크롤 안내는 클릭을 가로채지 않음
- 두 안내가 동시에 표시되거나 서로 겹치지 않음

같은 공간을 사용하는 것이 안전하지 않으면 별도 공간과 우선순위 제어를 선택하고, 그 이유를 보고해 주세요.

## 5. 60%·70%·80% 검증

기존 개발 전용 PoC 경로를 그대로 사용합니다.

예시:

`/?bottom-poc=70&poc-profile=extra-buttons-contrast-bottom-guide`

다음 조합을 시험해 주세요.

- 60% 기본 글씨
- 70% 기본 글씨
- 80% 기본 글씨
- 60% 아주 큰 글씨 + 큰 버튼 + 고대비
- 70% 아주 큰 글씨 + 큰 버튼 + 고대비
- 80% 아주 큰 글씨 + 큰 버튼 + 고대비

320×844, 390×844, 1080×1920에서 확인합니다.

특히 390×844 시작 화면의 제목과 안내가 겹치던 문제를 다시 재현하고, 수정 후 실제 요소 좌표로 겹침이 사라졌는지 확인해 주세요.

## 6. 스크롤 안정성 검사

각 화면에서 다음을 검증합니다.

- 스크롤 시작 위치
- 최하단 scrollTop
- 0.1초·0.5초·1초·3초 뒤 위치
- 안내 표시 상태
- 최하단에서 안내 숨김
- 다시 위로 이동했을 때 안내 재표시
- 스마트 길잡이 출현·종료 시 스크롤 위치
- 화면 단계 변경 후 스크롤 초기화
- 기존 버튼 클릭 가능 여부

스크롤을 반복해서 강제로 제어하는 방식은 사용하지 마세요.

## 7. 데모커피 업무 흐름 회귀

다음 전체 흐름을 확인해 주세요.

- QR 설정 또는 개발용 프로필 적용
- 주문 방식 선택
- 메뉴 선택
- 상품 옵션 변경
- 장바구니
- 주문 확인
- 결제 방법 선택
- 가상 결제
- 주문 완료
- 처음화면 복귀 및 세션 초기화

방법 B 하단 70%에서 전체 주문 흐름을 반드시 확인하고, 가능하면 60%·80%에서도 핵심 동작을 점검해 주세요.

스마트 길잡이가 실제로 표시되는 시점까지 기다려 검증해야 합니다. 단순히 타이머를 모의 처리한 것만으로 화면 충돌이 없다고 보고하지 마세요.

## 8. 독립 구조 검증

데모커피 외에 기존 두 가지 독립 fixture에서도 확인합니다.

- 문서 전체 스크롤 구조
- 내부 스크롤 + 고정 하단 버튼 구조

독립 구조에서 안내 표시 영역을 공통 원리로 확보할 수 있는지 확인해 주세요.

특정 카페의 CSS 클래스나 화면 이름에만 맞춘 구현이라면 성공으로 처리하지 마세요.

### 성공 기준

1. 안내 문구가 짧아지고, 큰 글씨 모드에서도 읽을 수 있습니다.
2. 스크롤 안내가 제목·메뉴·필수 버튼을 가리지 않습니다.
3. 스마트 길잡이가 나타나면 스크롤 안내가 숨겨집니다.
4. 스마트 길잡이가 사라진 뒤 필요한 경우에만 스크롤 안내가 돌아옵니다.
5. 안내 전환 때문에 스크롤이 튀거나 화면 레이아웃이 흔들리지 않습니다.
6. 하단 60%·70%·80%에서 글씨·버튼 크기와 업무 기능이 유지됩니다.

실패한 항목은 성공으로 보고하지 말고 재현 조건과 원인을 기록해 주세요.
