# 내 방식 QR — 공통 SDK v0.5.13 안내창 통합 및 개선

## 0. 작업 대상 및 목적

현재 작업 대상은 **데모커피 Replit 프로젝트**입니다.

이 프로젝트는 공통 접근성 SDK의 원본을 관리합니다.

- SDK 패키지: `@naebangsik/kiosk-accessibility-sdk`
- 현재 안정 버전: `v0.5.12`
- 이번 목표 버전: `v0.5.13`
- SDK 원본: `packages/kiosk-accessibility-sdk/`

현재 SDK는 QR 프로필 v1~v4 읽기, 큰 글씨, 큰 버튼, 고대비, 하단 조작, 쉬운 말, 스마트 길잡이, 음성 안내, 완료 후 자동 복귀 등을 지원합니다.

이번 작업에서는 **쉬운 말 안내와 스마트 길잡이가 하나의 안내 공간을 공유하도록 개선**합니다.

추가할 기능은 다음과 같습니다.

1. 쉬운 말과 스마트 길잡이의 공통 안내창
2. 안내창 접기·펼치기
3. 여러 쉬운 말 설명의 이전·다음 이동
4. 스마트 길잡이 숫자 카운트다운
5. 천천히 안내받기 설정에 따른 15초 표시
6. 기존 안내 상태 보존·복원
7. 작은 화면과 하단 조작에서 업무 버튼을 가리지 않는 안전한 배치

**가장 중요한 원칙은 카페뿐 아니라 무인민원발급기·병원 등 서로 다른 키오스크에 같은 SDK를 적용할 수 있어야 한다는 것입니다.**

---

## 1. 기존 SDK 구조 먼저 조사

코드 변경 전 다음을 확인하세요.

- 쉬운 말 안내 UI의 현재 생성·표시 방식
- 스마트 길잡이 UI의 현재 생성·표시 방식
- `setGuideState()` 및 `notifyScreenChange()`의 공개 API
- `stepId`를 이용한 단계 변경 처리
- 스마트 길잡이 표시 전 대기 타이머
- 표시 후 10초 자동 닫힘
- 화면 전환 시 타이머 정리
- QR 프로필 v4의 `slowGuidance`
- 하단 조작 60/70/80% 적용 방식
- SDK의 DOM 격리 및 스타일 적용 방식
- 스크롤 안내
- QR 도크
- 완료 후 15초 자동 복귀
- 기존 테스트 및 독립 소비자 fixture

현재 호스트가 제공하는 업무 단계 ID와 안내 문구를 가능한 한 그대로 활용하세요.

**호스트별로 CSS를 수정해서 안내창 문제를 해결하지 마세요.**

공통 SDK 차원에서 해결해야 합니다.

## 2. 쉬운 말과 스마트 길잡이가 하나의 안내창 사용

현재 별도의 안내창이 존재하거나 두 기능이 같은 화면에서 충돌할 수 있다면, 이를 공통 안내창으로 통합하세요.

안내창의 표시 우선순위는 다음과 같습니다.

**스마트 길잡이 표시 중 > 쉬운 말 안내 > 안내 없음**

### 쉬운 말만 활성화된 경우

- 쉬운 말 설명 표시
- 사용자가 접기 전까지 안내 유지
- 자동으로 사라지지 않음
- 사용자가 필요할 때 접기·펼치기 가능

### 스마트 길잡이만 활성화된 경우

- 기존 표시 전 대기시간 10/15/20초 유지
- 대기시간이 지나면 스마트 길잡이 표시
- 표시 후 10초 유지
- `slowGuidance: true`면 15초 유지
- 시간이 지나면 자동으로 안내 닫힘
- 사용자가 수동으로 접은 경우 접힌 상태를 존중

### 두 기능이 모두 활성화된 경우

1. 처음에는 쉬운 말 안내 표시
2. 스마트 길잡이 표시 전 대기
3. 스마트 길잡이 시작 시 같은 안내창의 내용만 전환
4. 스마트 길잡이 표시 종료
5. 이전 쉬운 말 설명으로 복귀

이때 **별도의 안내창을 하나 더 띄우지 마세요.**

안내창의 위치와 크기가 갑자기 크게 변하면서 업무 화면을 가리는 현상도 최소화하세요.

## 3. 안내창 접기·펼치기

안내창에 다음 조작을 제공합니다.

- 펼쳐진 상태: **∨ 접기**
- 접힌 상태: **∧ 펼치기**

실제 아이콘 방향은 접히고 펼쳐질 동작을 직관적으로 나타내도록 적용하세요.

아이콘만 단독으로 사용하지 말고 반드시 텍스트를 함께 표시합니다.

### 접힘 상태 정책

- 사용자가 직접 접으면 그 상태를 유지
- 사용자가 다시 펼치면 설명을 계속 볼 수 있음
- 스마트 길잡이가 도착해도 접힌 안내창을 강제로 펼치지 않음
- 스마트 길잡이가 끝나도 기존 접힘 상태 유지
- 쉬운 말 설명을 보던 위치도 유지
- 화면 단계가 변경되면 현재 안내 문구는 새 단계에 맞게 갱신
- 새 단계에서 사용자가 직접 선택한 접힘 상태는 가능하면 유지
- QR 세션이 종료되면 접힘 상태를 기본값으로 초기화

중요한 예외:

**업무 입력이나 키패드가 가려지는 상황에서는 SDK가 안전하게 안내창을 축소하거나 자동으로 접을 수 있어야 합니다.**

이 경우 사용자가 수동으로 다시 펼칠 수 있는 경로를 유지하고, 안전상의 자동 접힘과 사용자의 직접 접힘을 구분해 관리하세요.

## 4. 여러 쉬운 말 설명의 이전·다음

하나의 업무 화면에 어려운 용어나 설명할 대상이 여러 개 있을 수 있습니다.

쉬운 말 설명을 모두 길게 나열하지 말고, **한 번에 하나씩** 표시하도록 개선하세요.

예시:

설명 1/3

**발급 부수**

서류를 몇 장 받을지 고르는 것입니다.

[이전] [다음]

### 동작 조건

- 설명이 1개면 이전·다음 버튼을 표시하지 않음
- 설명이 2개 이상이면 이전·다음 버튼 표시
- 현재 설명 위치를 1/3 같은 형태로 표시
- 첫 항목에서는 이전 버튼 비활성화
- 마지막 항목에서는 다음 버튼 비활성화
- 버튼은 큰 글씨·큰 버튼 설정에서도 누를 수 있어야 함
- 스마트 길잡이가 나타나면 현재 설명 위치를 보존
- 스마트 길잡이가 종료되면 이전 설명 위치로 복원
- 화면 단계가 바뀌면 해당 단계의 첫 번째 설명부터 표시
- 이전 단계의 설명이 새 단계에 남아 있으면 안 됨

### API 설계

현재 SDK 공개 API와 호환되는 방식으로 여러 쉬운 말 설명을 전달할 수 있게 해 주세요.

기존 단일 설명을 사용하는 호스트 코드는 그대로 동작해야 합니다.

필요하다면 복수 설명 배열을 받는 선택적 필드나 메서드를 추가하되, 기존 API를 깨지 마세요.

문구 자체는 호스트가 제공할 수 있지만, **표시 방식과 페이지 이동은 SDK가 전담**해야 합니다.

## 5. 스마트 길잡이 숫자 카운트다운

스마트 길잡이가 표시되는 동안 안내창의 **왼쪽 위**에 남은 시간을 숫자로 표시하세요.

예시:

**10초 → 9초 → 8초 …**

천천히 안내받기가 켜졌다면:

**15초 → 14초 → 13초 …**

### 요구사항

- 현재 표시 후 유지 시간 기준으로 계산
- 초 단위 숫자가 감소
- 스마트 길잡이 종료 시 카운트다운 제거
- 쉬운 말로 복귀할 때 이전 카운트다운이 남지 않음
- 새로운 스마트 길잡이가 시작되면 새 카운트다운 시작
- 이전 타이머가 새로운 안내를 종료시키지 않도록 방지
- 단계 변경 시 이전 타이머 완전 정리
- 세션 종료 시 타이머 완전 정리
- 여러 번 빠르게 화면 전환해도 중복 타이머 없음
- 남은 시간이 음수로 표시되지 않음
- 안내문과 카운트다운이 겹치지 않음

카운트다운은 작지만 읽기 쉬운 크기로 표시하고, 안내 내용보다 과하게 강조하지 마세요.

시간 감소마다 전체 안내창을 불필요하게 다시 생성해서 포커스나 접힘 상태가 초기화되는 일은 피하세요.

## 6. 천천히 안내받기 15초 적용

QR v4에는 다음 필드가 있습니다.

`slowGuidance: boolean`

이를 실제 SDK 안내창에 연결하세요.

- `false`: 스마트 길잡이 표시 후 10초 유지
- `true`: 스마트 길잡이 표시 후 15초 유지

### 매우 중요한 구분

`guideDelaySeconds`는 **스마트 길잡이가 나타나기 전 대기시간**입니다.

허용값:

- 10초
- 15초
- 20초

`slowGuidance`는 **스마트 길잡이가 나타난 뒤 유지시간**입니다.

두 기능은 서로 독립적이어야 합니다.

예시:

`guideDelaySeconds: 20`
`slowGuidance: true`

→ 업무 화면 진입 후 20초 기다림
→ 스마트 길잡이 표시
→ 15초 동안 유지
→ 쉬운 말 안내가 켜져 있으면 기존 설명으로 복귀

기존 QR v1~v3에는 slowGuidance가 없으므로 기본값 false, 즉 기존 10초 동작을 유지합니다.

## 7. 접혀 있는 상태에서 스마트 길잡이가 도착하는 경우

특히 중요하므로 별도로 검증하세요.

### 상황

1. 쉬운 말 안내가 표시됨
2. 사용자가 '접기'를 누름
3. 안내창이 접힘
4. 스마트 길잡이의 표시 전 타이머가 끝남
5. 스마트 길잡이가 시작됨

### 원하는 동작

- 접힌 안내창을 강제로 펼치지 않음
- 스마트 길잡이의 타이머는 정상적으로 진행
- 접힌 헤더 등에 현재 스마트 길잡이가 진행 중임을 표시할 수 있음
- 숫자 카운트다운도 헤더 영역에 안전하게 표시 가능
- 사용자가 원하면 펼쳐서 읽을 수 있음
- 스마트 길잡이 시간이 끝나면 기존 쉬운 말 안내로 복귀
- 안내창은 여전히 접힌 상태 유지

현재 사용자가 직접 접어둔 상태를 존중해야 합니다.

## 8. 좁은 화면과 하단 조작에서 안전한 배치

다음 조건에서 검증하세요.

- 일반 화면
- QR v3/v4 하단 조작 60%
- 하단 조작 70%
- 하단 조작 80%
- 글씨 매우 크게
- 버튼 크게
- 고대비
- 쉬운 말 + 스마트 길잡이 동시 사용

### 안전 요구사항

공통 안내창 때문에 아래 요소들이 사용 불가능해지면 안 됩니다.

- 숫자 키패드
- 금액·수량 등 입력 결과
- 확인·다음·결제 버튼
- 뒤로 가기
- 화면 스크롤
- QR 도크

특히 **무인민원발급기 키패드처럼 좁은 화면에 입력 기능이 집중된 경우**도 고려하세요.

안내창이 중요한 조작 영역과 겹치면 SDK에서 안전한 위치를 찾거나 크기를 축소하고, 필요할 경우 접힌 상태로 표시하는 범용 대체 동작을 구현하세요.

호스트별 선택자나 특정 사이트 전용 CSS를 하드코딩하지 마세요.

새 안내창이 화면을 가리는 문제를 해결하려고 기존 글씨 크기·버튼 크기 접근성을 무조건 낮추면 안 됩니다.

기존 스크롤 안내 및 하단 뷰포트 처리와 연동하세요.

## 9. SDK 공개 API 호환성

기존 호스트가 사용하는 다음 API를 유지하세요.

- `notifyScreenChange()`
- `setGuideState()`
- `endSession()`
- `beginCompletion()`
- `subscribeCompletion()`
- `extendCompletion()`
- `cancelCompletion()`
- `finishCompletion()`

기존 단일 안내 문구를 받는 방식도 유지합니다.

여러 쉬운 말 설명을 위한 공개 API는 필요하다면 추가할 수 있으나, 기존 호출자의 코드 변경을 필수로 만들면 안 됩니다.

공통 안내창의 현재 모드, 펼침 상태, 쉬운 말 설명 인덱스, 스마트 길잡이 표시 타이머는 SDK 내부에서 일관되게 관리하세요.

여러 호스트에서 동일하게 동작하도록 SDK 외부에 흩어진 상태 관리 코드를 만들지 마세요.

## 10. 사용자 접근성

다음을 지켜 주세요.

- 접기·펼치기 버튼에 명확한 텍스트 제공
- 키보드 조작 지원
- 적절한 ARIA 레이블
- 버튼 크기 설정 적용
- 큰 글씨에서 줄바꿈 가능
- 스크린리더에서 카운트다운을 매초 과도하게 읽지 않도록 처리
- 고대비 모드 지원
- 애니메이션 줄이기 설정 고려
- 버튼 클릭 시 불필요한 포커스 손실 방지

고령층 사용자가 안내창을 쉽게 이해할 수 있는 표현을 사용하세요.

## 11. 독립 소비자 검증

데모커피 외에도 SDK만 설치한 **독립 HTML/JavaScript 소비자 fixture**에서 검증하세요.

최소 다음 시나리오를 포함합니다.

1. 쉬운 말만 활성화
2. 스마트 길잡이만 활성화
3. 둘 다 활성화
4. 둘 다 비활성화
5. 설명 1개
6. 설명 3개 및 이전·다음 이동
7. 설명 2/3을 보다가 스마트 길잡이 시작
8. 종료 후 설명 2/3 복원
9. 안내창 접기
10. 접힌 상태에서 스마트 길잡이 시작
11. 스마트 길잡이 종료 후 접힌 상태 복원
12. slowGuidance false → 10초
13. slowGuidance true → 15초
14. guideDelaySeconds 10/15/20초 각각의 표시 전 대기 유지
15. 빠른 단계 전환
16. 단계별 stepId 변경
17. endSession() 시 타이머·상태 초기화
18. QR v1~v4 호환
19. 잘못된 QR v4 응답 거부
20. 좁은 화면에서 키패드 및 입력값 조작 가능

가상 타이머 단위 테스트뿐 아니라 실제 Chromium 브라우저 상호작용도 확인하세요.

실시간 10초·15초 자동 닫힘도 가능하면 최소 한 번씩 검증하세요.

검증하지 못한 항목은 별도로 보고하세요.

## 12. 데모커피 회귀 검증

기존 데모커피 흐름을 유지합니다.

- 첫 화면 진입
- 메뉴 선택
- 옵션 선택
- 장바구니
- 결제
- 영수증 선택
- 완료 화면 15초 복귀
- 시간 연장
- 수동 처음으로
- QR 적용·세션 초기화

쉬운 말·스마트 길잡이를 함께 켜도 주문 진행을 방해하면 안 됩니다.

특히 작은 모바일 화면에서 장바구니·결제 버튼이 가려지지 않는지 확인하세요.
