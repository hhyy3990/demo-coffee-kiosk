# 내 방식 QR — 방법 B 하단 조작 모드 PoC: 작은 오버레이 안내 방식 실험

현재 데모커피 프로젝트에는 공통 접근성 SDK v0.3.6과 방법 B 하단 조작 모드 PoC가 구현되어 있습니다.

방법 B는 키오스크 화면 전체를 축소하지 않고, 글씨와 버튼 크기를 유지하면서 화면의 아래쪽 60%·70%·80% 영역에서 조작하도록 만드는 기능입니다.

현재 PoC는 스크롤 안내와 스마트 길잡이를 위해 120px 높이의 별도 안내 슬롯과 약 88px의 하단 여백을 예약하고 있습니다.

이 구조는 안내와 콘텐츠가 겹치지 않는 장점이 있지만, 이미 하단 고정 버튼 영역이 있는 다른 키오스크에서는 사용 가능한 콘텐츠 공간이 지나치게 줄어들 수 있습니다.

이번에는 **별도 안내 공간 대신 작은 오버레이 방식으로 변경해 사용 가능한 콘텐츠 영역을 최대한 확보하는 실험**을 진행합니다.

중앙 QR 서버와 무인민원발급기는 수정하지 않습니다.

## 1. 실험 목표

다음 다섯 가지를 확인합니다.

1. 120px 안내 슬롯과 불필요한 여백을 제거해 콘텐츠 영역을 늘릴 수 있는가?
2. 안내를 작은 오버레이로 표시하면서 중요한 버튼을 가리지 않을 수 있는가?
3. 스마트 길잡이와 세로 안내의 우선순위를 유지할 수 있는가?
4. 안내가 나타나거나 사라져도 스크롤 위치가 변하지 않는가?
5. 카페 외에 기존 하단 고정 버튼이 있는 키오스크에도 적용 가능한가?

이번에는 정식 SDK 기능을 출시하지 않고 기존 PoC만 개선합니다.

## 2. 기존 안내 슬롯 구조 분석 및 제거

먼저 다음을 확인해 주세요.

- 현재 120px 안내 슬롯을 만드는 SDK 함수
- 스마트 길잡이와 스크롤 안내가 슬롯을 공유하는 방식
- 88px 하단 여백의 실제 용도
- 슬롯이 스크롤 영역 높이에 영향을 주는 방식
- 하단 버튼과 안내의 위치 계산

기존 기능을 확인한 뒤 **하단 조작 PoC에서 항상 120px을 예약하는 안내 슬롯을 제거**해 주세요.

88px 여백도 실제 필수 조작부 보호에 필요한 부분과 단순 안내 공간 확보를 위한 부분을 구분하고, 불필요한 부분만 제거합니다.

기존 주문·결제 버튼 자체를 위한 공간은 유지해야 합니다.

안내가 표시되거나 숨겨진다는 이유로 콘텐츠 영역 높이가 달라져서는 안 됩니다.

## 3. 작은 오버레이형 스크롤 안내

기존 스크롤 안내 문구는 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

다음 방식으로 표현해 주세요.

- 큰 안내 카드 대신 작고 간결한 알약형(pill) UI
- 배경과 텍스트는 충분한 대비 유지
- 과도한 그림자·테두리·애니메이션 사용하지 않기
- 기존 콘텐츠 위에 오버레이로 표시
- pointer-events: none 적용
- 사용자가 스크롤할 필요가 없는 경우 미표시
- 끝까지 스크롤하면 즉시 숨김
- 다시 위로 스크롤하면 재표시
- 스마트 길잡이가 표시될 때는 숨김

### 글씨 크기

- 기본 모드에서는 읽기 쉬운 크기 유지
- 큰 글씨·아주 큰 글씨 모드에서는 안내도 적절하게 확대
- 한 줄 표시를 우선하지만, 좁은 화면에서는 자연스러운 두 줄 허용
- 줄 수에 따라 pill 높이가 안전하게 늘어나야 함
- 글씨 잘림·영역 밖 침범·가로 넘침 금지
- 한 줄을 만들기 위해 글씨를 지나치게 줄이지 않기

실제 computed font-size와 렌더링 높이를 측정해 주세요.

## 4. 오버레이 위치와 필수 버튼 보호

안내 위치는 키오스크 구조에 따라 자동으로 결정하도록 설계해 주세요.

### A. 하단 고정 버튼이 없는 경우

- 하단 조작 영역 안쪽의 하단에 작은 안내 표시
- 일반 콘텐츠 일부와 제한적으로 겹치는 것은 허용
- 버튼과 메뉴의 실제 클릭은 방해하지 않음

### B. 하단 고정 버튼이 있는 경우

- 하단 고정 조작부 바로 위에 안내 표시
- 처음화면·전화면·확인·결제 버튼은 가리지 않음
- 고정 조작부 높이를 실제 DOM 좌표 기준으로 판단
- SDK가 안전하게 판단할 수 없다면 호스트 어댑터에서 해당 조작부를 선택적으로 등록할 수 있도록 검토

### 공통 조건

- 기존 필수 버튼이 안내 때문에 보이지 않거나 찾기 어려워지면 안 됨
- 일반 콘텐츠와 시각적으로 겹치더라도 끝까지 스크롤하면 모든 내용을 읽고 조작할 수 있어야 함
- 중요한 버튼 위에 안내를 띄우는 것보다 안내를 일시적으로 숨기는 것이 우선
- 모달·QR 카메라·키패드가 열리면 위치를 다시 판단하거나 필요 시 안내 숨김
- 안내가 상단 비조작 영역 밖으로 넘어가지 않음
- 안내 UI가 실제 스크롤 소유 요소의 높이를 변경하지 않음

pointer-events: none만으로 접근성 검증을 통과했다고 판단하지 말고 실제 화면 표시와 클릭 가능성을 확인해 주세요.

## 5. 스마트 길잡이 표시 정책

기존 스마트 길잡이 기능은 유지하되, 스크롤 안내와 항상 동시에 표시되지 않도록 합니다.

### 우선순위

1. 스마트 길잡이가 표시되면 스크롤 안내 숨김
2. 스마트 길잡이가 사라지면 현재 스크롤 위치 확인
3. 아래쪽에 내용이 남았다면 스크롤 안내 재표시
4. 이미 마지막 위치라면 미표시

스마트 길잡이는 짧은 스크롤 안내와 달리 설명이 길어질 수 있으므로 동일한 크기의 pill로 강제하지 않습니다.

스마트 길잡이의 기존 카드 크기와 가독성은 유지하되, 새로운 하단 표시 영역 안에서 필수 버튼을 가리지 않도록 위치를 조정해 주세요.

안전한 위치가 없다면 스마트 길잡이 카드의 내용을 잘라내거나 필수 조작부 위에 강제로 올리지 말고, 안전한 대체 배치 또는 표시 보류를 검토하고 그 한계를 보고해 주세요.

기존 10·15·20초 지연 설정 및 음성 안내 동작은 유지합니다.

## 6. 스크롤 튐 오류 재발 방지

SDK v0.3.5에서 발생했던 스크롤 자동 복귀 오류는 v0.3.6에서 해결됐습니다.

이번 실험에서 다시 발생해서는 안 됩니다.

다음 사항을 준수해 주세요.

- 안내 표시·숨김 시 콘텐츠 높이 변경 금지
- 안내 표시·숨김 시 글씨 확대 재계산 불필요하게 실행하지 않기
- SDK가 생성한 오버레이 변경을 호스트 콘텐츠 변경으로 오인하지 않기
- MutationObserver·ResizeObserver 재실행 루프 방지
- 사용자 스크롤 좌표를 반복적으로 강제 변경하지 않기
- 브라우저 scroll anchoring과 충돌하지 않기
- 비율 변경 이외의 일반 스크롤에서 viewport shell 높이를 다시 설정하지 않기

스크롤 위치를 끝까지 이동한 뒤 0.1초·0.5초·1초·3초 동안 동일한 위치가 유지되는지 확인해 주세요.

## 7. 방법 B 비율 및 큰 글씨 조합 검증

다음 비율을 모두 검사합니다.

- 60%
- 70%
- 80%

각각 다음 설정에서 확인합니다.

- 기본 글씨
- 큰 글씨
- 아주 큰 글씨
- 큰 버튼
- 아주 큰 글씨 + 큰 버튼 + 고대비

320×844, 390×844, 1080×1920에서 확인해 주세요.

### 측정 항목

- 실제 표시 영역 높이
- 기존 슬롯 방식과 비교한 가용 콘텐츠 높이
- 안내 pill 실제 크기
- 안내 위치
- 글씨·버튼 픽셀 크기
- 스크롤 최대 거리
- 마지막 메뉴·버튼의 실제 클릭 가능 여부
- 겹침 발생 위치
- 가로 넘침 여부

특히 기존 120px 슬롯과 88px 여백을 제거하거나 줄였을 때, 실제로 얼마나 콘텐츠 영역을 확보했는지 수치로 보고해 주세요.

## 8. 독립 fixture 검증

데모커피 외에 다음 두 가지 구조에서 검증합니다.

A. 문서 전체 또는 최상위 영역이 스크롤하는 키오스크

B. 내부 스크롤 + 하단 고정 버튼이 있는 키오스크

B에서는 하단 고정 버튼의 위쪽에 안내가 안전하게 표시되는지 집중적으로 확인해 주세요.

스마트 길잡이가 표시돼도 하단 고정 버튼이 가려지면 안 됩니다.

카페 전용 클래스나 화면 이름에 의존한 위치 계산은 피하고, 공통 SDK에서 재사용 가능한 방식으로 구현해 주세요.

## 9. 카페 주문 전체 회귀 테스트

70% 기본 모드와 70% 아주 큰 글씨·큰 버튼·고대비 조합에서 다음을 확인해 주세요.

- 첫 화면
- 주문 방식 선택
- 상품 카테고리 이동
- 메뉴 선택
- 옵션 선택
- 장바구니
- 주문 확인
- 결제 방식 선택
- 가상 결제
- 주문 완료
- 처음화면 복귀

60%와 80%에서도 핵심 주문 흐름을 확인해 주세요.

특히 하단의 주문·결제 버튼과 안내 pill이 겹치지 않고, 스크롤로 마지막 버튼까지 접근 가능한지 확인해야 합니다.

## 10. 개발 범위 및 제한

기존 방법 B의 구조는 유지합니다.

- 화면 전체 transform: scale() 금지
- 기존 글씨·버튼 크기 유지
- 개발용 `?bottom-poc=60|70|80` 경로 유지
- 중앙 QR 서버·DB 수정 금지
- QR 프로필 스키마 수정 금지
- 무인민원발급기 실제 프로젝트 수정 금지
- QR 설정 진입 버튼 위치 변경 금지
- 주문·가격·결제 로직 변경 금지
- SDK 버전 변경·tarball 생성 금지
- AI 연결 금지
- Publish 금지

기존 안정적인 일반 데모커피 화면은 영향을 받지 않아야 합니다.

### 이번 실험의 최종 성공 기준

1. 별도 안내 슬롯을 없애거나 최소화해 실제 콘텐츠 공간을 더 확보합니다.
2. 스크롤 안내는 작고 읽기 쉬운 pill 형태로 표시합니다.
3. 하단 고정 버튼은 안내에 가려지지 않습니다.
4. 스마트 길잡이가 나타나면 스크롤 안내가 숨겨집니다.
5. 안내 표시·숨김과 스크롤이 서로 충돌하지 않습니다.
6. 60%·70%·80%에서도 기존 글씨·버튼 크기와 주문 기능을 유지합니다.

결과가 좋지 않으면 기존 슬롯 방식과 비교하여 어떤 구조가 더 안전한지 판단할 수 있도록 문제를 정확하게 기록해 주세요.
