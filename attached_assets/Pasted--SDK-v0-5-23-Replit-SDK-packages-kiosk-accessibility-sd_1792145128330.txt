# 데모커피 SDK v0.5.23 미해결 오류 재수정

현재 프로젝트는 데모커피 Replit입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`이며 현재 버전은 v0.5.23입니다.

사용자가 실제 Development Preview에서 다시 확인한 결과, 이전 작업에서 해결됐다고 보고한 두 문제가 여전히 남아 있습니다.

이번에는 다른 기능을 추가하거나 이미 해결한 메뉴 분류 탭을 다시 수정하지 마세요.

**작업 대상은 정확히 두 가지입니다.**

1. 데모커피 첫 화면의 스크롤 안내가 나타나지 않는 문제
2. 쉬운 말·스마트 길잡이 패널의 이전·다음·접기·펼치기 버튼이 세로로 지나치게 큰 문제

SDK-first 원칙을 유지합니다.

## 1. 첫 화면 스크롤 안내 실제 미표시 오류

이전 작업에서 확인한 수치:

- 첫 화면의 실제 스크롤 소유자: `.shell`
- 일반 상태 scrollHeight/clientHeight: 845/595px
- 접근성 체험 상태 scrollHeight/clientHeight: 1101/357px

즉 아래에 스크롤할 내용이 있습니다.

그러나 사용자의 실제 Development Preview에서는 **첫 화면에 스크롤 안내가 보이지 않습니다.**

이전 Agent는 Smart Guide에 의한 숨김 조건을 제거했다고 보고했으나 사용자 테스트에서 문제가 해결되지 않았습니다.

### 이번에 반드시 조사할 내용

실제 데모커피 첫 화면을 열고 다음을 구분하세요.

- SDK가 스크롤 안내 DOM을 생성하는지
- DOM이 실제 화면에 렌더링되는지
- CSS visibility, opacity, display, z-index 상태
- 안내가 화면 밖에 배치됐는지
- 다른 요소 뒤에 가려졌는지
- 스크롤 소유자가 정확히 등록되는지
- 등록 시점에 scrollHeight/clientHeight를 잘못 측정하는지
- 접근성 체험 시작 직후 스크롤 컨테이너 변경을 놓치는지
- 첫 화면의 실제 viewport 계산이 정상인지
- 스크롤 안내가 생성됐다가 즉시 제거되는지
- 안내가 화면 아래에 있지만 다른 요소와 겹쳐 보이지 않는지

### 반드시 재현할 상황

1. 데모커피 Development Preview 첫 화면 진입
2. '접근성 체험하기' 실행
3. 메뉴를 선택하지 않은 첫 화면에서 대기
4. 실제 `.shell`의 scrollHeight/clientHeight 측정
5. 아직 아래에 내용이 있을 때 스크롤 안내 DOM 및 화면 표시 확인
6. 실제 모바일 크기에서 눈으로 볼 수 있는지 스크린샷과 boundingRect로 확인
7. 스크롤했을 때 안내가 유지되는지 확인
8. 스크롤 끝에 도달했을 때만 사라지는지 확인
9. 다시 위로 이동하면 안내가 복귀하는지 확인

**첫 화면에서 쉬운 말이 없는 것은 정상입니다. 쉬운 말이 없더라도 스크롤 안내는 독립적으로 표시돼야 합니다.**

### 필수 정책

- 실제 아래에 스크롤할 내용이 있다면 힌트는 반드시 표시
- 스마트 길잡이·쉬운 말 유무와 무관하게 표시
- 다른 버튼과 겹친다는 이유로 숨기지 않음
- 버튼과 겹치더라도 클릭은 통과
- 스크롤 중 위치 점프 없음
- 끝까지 내려갔을 때만 숨김
- 위치를 억지로 변경하는 호스트 CSS 우회 금지

사용자는 스크롤 안내가 주문 확인 버튼 등과 시각적으로 겹치는 것은 허용한다고 명확히 밝혔습니다. 겹침 방지를 이유로 힌트를 숨기지 마세요.

## 2. 안내창 버튼 실제 세로 높이 축소

이전 v0.5.23 보고:

- 접기 버튼: 44×50.6px
- 이전·다음 버튼: 44×50.6px
- 패널 높이: 192.6px → 184.6px

하지만 사용자가 직접 보기에 버튼은 여전히 세로로 큽니다.

이번에는 패널 바깥 여백만 줄여서 완료 처리하지 마세요.

**버튼의 실제 렌더링된 세로 높이를 줄이세요.**

### 목표

- 접기·펼치기: 실제 높이 44px
- 이전·다음: 실제 높이 44px
- 폭은 내용과 터치 접근성에 맞게 조정
- 모든 버튼의 실제 터치 영역은 최소 44×44 CSS px
- 매우 큰 글씨 모드에서도 불필요하게 50px 이상 높아지지 않도록 수정
- 본문 설명 글씨 크기와 줄 간격은 유지
- 버튼의 세로 패딩, line-height, min-height, box-sizing, 상속된 폰트 크기 확인
- 높이 축소 과정에서 텍스트 잘림·겹침이 발생하면 해당 원인을 해결
- 이전·다음 버튼의 글자가 읽기 어려워지지 않도록 유지

44px보다 작게 만드는 것은 이번 작업 목표가 아닙니다.

정확히 44px의 높이 안에서 글씨와 아이콘이 보기 좋게 가운데 정렬되도록 구성하세요.

접기·펼치기 버튼의 접근성 이름도 유지합니다.

### 확인할 내용

특히 공통 SDK의 큰 버튼 설정이 안내창 내부 버튼에도 적용돼 50.6px 이상이 되는 구조인지 조사하세요.

일반 키오스크 업무 버튼 크기는 바꾸지 마세요.

SDK 안내 패널 내부 조작 요소만 조정합니다.

## 3. 수정 전후 실측

다음 크기에서 측정합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920

모드:

- 일반 화면
- 하단 60%
- 하단 70%
- 하단 80%

특히 `textSize: extraLarge`, `buttonSize: large`, `contrast: high`를 동시에 적용하세요.

측정 항목:

- 접기·펼치기 버튼의 실제 width/height
- 이전·다음 버튼의 실제 width/height
- 버튼 텍스트 실제 가시성
- 안내창 전체 높이
- 본문 폰트 크기
- 주요 버튼 클릭 가능 여부
- 첫 화면 스크롤 안내 표시 여부

스크린샷만 찍지 말고 DOM boundingRect도 수집하세요.

## 4. 기존 정상 기능 보존

다음을 절대 회귀시키지 마세요.

- 쉬운 말 즉시 표시
- 스마트 길잡이 10/15/20초 대기
- 스마트 길잡이 10/15초 표시
- 동일 단계 조작 중 길잡이 유지
- 쉬운 말 페이지 및 접힘 상태 복원
- 스마트 길잡이 단일 안내
- 스크롤 힌트 항상 표시 정책
- 스크롤 중 안내 패널 위치 안정성
- 메뉴 분류 탭의 정상 스크롤
- 가로 카테고리 탐색
- 전체 주문·결제 시뮬레이션
- QR v1~v4 호환
- 하단 60/70/80% 지원
- Observer 무한 반복 방지
- 완료 후 초기화·자동 복귀

## 5. 수정 범위

SDK 공통 오류는 SDK 원본에서 수정합니다.

첫 화면의 스크롤 영역 등록이 호스트에서 실제로 누락된 경우에 한해 SDK 공개 API 연결을 수정할 수 있습니다.

메뉴 분류 탭 관련 CSS는 다시 변경하지 마세요.

이번에는 쉬운 말 문구도 다시 수정하지 않습니다.

무인민원발급기·중앙 QR 프로젝트 수정 금지.

Production DB 변경 및 Publish 금지.
