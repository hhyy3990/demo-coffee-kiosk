# 데모커피 — AI 메뉴 화면 변환 A 방식 확장 및 안전 계약 정합성 수정

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 최신 안정 버전은 `@naebangsik/kiosk-accessibility-sdk@0.5.31`입니다.

중앙 ‘내 방식 QR’에는 AI 화면 구성 API `POST /api/ai-layout/plan`이 구현됐지만, 아직 데모커피 화면 정책 등록 및 실제 서버 연결은 진행하지 않았습니다.

이번 작업은 **데모커피의 기존 Mock AI 화면 변환을 정식 화면 계약과 일치시키고, AI가 메뉴 목록 열 개수와 카드 내부 배치를 모두 선택할 수 있도록 확장하는 것**입니다.

**중앙 서버 연결, 실제 OpenAI API 호출, SDK 수정, Publish는 이번 범위가 아닙니다.**

실제 현재 소스를 확인하고 작업하세요.

- 390×844: 기존 2열에서 1열 가로형 카드로 변경
- 메뉴 5개, 상품 순서·이름·가격 유지
- 옵션·장바구니·가상 결제·주문 완료 정상
- 기존 접근성 기능 정상

## 2. 현재 계약 불일치 수정

현재 화면 모델은 다음 영역을 보호 대상으로 선언합니다.

`menu.product-list`

그런데 Mock AI 계획을 적용하는 CSS는 390×844 화면에서 메뉴 목록을 2열에서 1열로 변경합니다.

현재 계획에 등록된 연산은 다음 두 가지뿐입니다.

- `setGroupFlow`
- `setChildBasis`

즉, **AI 계획에서 메뉴 열 개수 변경을 명시적으로 승인하지 않았는데 실제 CSS가 열 개수를 변경하는 불일치**가 있습니다.

이번에는 이 동작을 제거하는 B 방식이 아니라, **메뉴 열 개수 변경을 명시적으로 허용하는 A 방식**으로 수정하세요.

단, 메뉴 목록을 보호한다는 기존 취지 중 다음은 반드시 유지해야 합니다.

- 메뉴 항목 삭제 금지
- 메뉴 항목 순서 변경 금지
- 카테고리 삭제·변경 금지
- 상품 가격 변경 금지
- 기존 상품 선택 이벤트 변경 금지
- 주문·결제 기능 변경 금지

**메뉴 목록의 '열 개수'만 별도로 허용된 AI 변경 대상으로 추가하는 것입니다.**

## 3. 새 공통 배치 연산 추가

현재 두 연산은 그대로 유지하세요.

### 기존 연산

`setGroupFlow`

- 대상: `menu.product-card`
- 방향: `row`
- `gapPx`: 8~20px

`setChildBasis`

- 대상: `menu.product-image`
- `basisPercent`: 20~30
- `minPx`: 72~96px

### 신규 연산

메뉴 목록의 열 개수를 선택하는 제한된 공통 연산을 추가하세요.

권장 이름:

`setGroupColumns`

대상:

`menu.product-list`

허용값:

- 1열
- 2열

이 연산은 다른 키오스크에서도 재사용할 수 있는 의미를 가져야 합니다.

다만 **실제 UI에서는 화면 크기와 QR 접근성 설정에 따라 안전하게 구현 가능한 열 개수만 허용**하세요.

예를 들어 360px 화면에서 2열이 기존 큰 글씨·큰 버튼 정책과 충돌하거나 콘텐츠가 잘린다면, 해당 조합은 허용하지 않거나 계획 적용을 거부해야 합니다.

현재 화면의 기본 반응형 배치는 변경하지 마세요.

AI 계획이 없으면:

- 360×667은 기존처럼 1열
- 390×844는 기존처럼 2열

AI 계획이 유효하게 적용된 경우에만 허용된 열 개수로 변경하세요.

## 4. 화면 모델과 검증 계약 갱신

현재 계약:

- `hostId`: `democoffee`
- `screenId`: `cafe.menu`
- `schemaVersion`: 1
- `structureVersion`: `menu.v1`
- `structureHash`: 기존 계약에 따라 계산
- `viewportClass`: `compact` / `regular`

새 연산을 추가하면서 화면 구조 계약이 변경되므로 **버전과 구조 해시 갱신 필요성을 확인**하세요.

기존 버전·해시를 무조건 유지하지 말고, 실제 모델의 의미 변경을 반영하여 일관되게 갱신하세요.

다음 사항을 검증하세요.

- 새로운 허용 연산이 모델에 명시됨
- 메뉴 목록 열 개수 변경이 보호 규칙의 예외로 정확히 표현됨
- 메뉴 목록의 항목·순서·내용은 계속 보호됨
- 기존 두 연산도 계속 유효함
- AI 계획에 없는 CSS 변경이 발생하지 않음
- 실제 적용되는 모든 레이아웃 변경이 계획의 연산으로 설명됨
- 대상 그룹 ID가 실제 React·CSS 적용 영역과 명확하게 연결됨
- 필수 메뉴 선택 버튼이 유지됨
- 알 수 없는 연산·요소·파라미터는 거부됨

특히 추상 모델 ID와 실제 DOM·React 요소의 대응 관계를 명시적으로 정리하세요.

## 5. AI가 열 개수를 결정할 수 있는 방식

이번 단계에서는 실제 OpenAI 호출 없이 Mock 계획으로 검증합니다.

다음 두 가지 변환을 확인하세요.

### 변환 A-1: 메뉴 목록 열 개수

390×844에서:

- 기본 화면: 기존 2열
- Mock AI 계획: 1열
- 상품 5개 모두 유지
- 기존 상품 순서 유지
- 메뉴 선택 정상

### 변환 A-2: 카드 내부 배치

유효한 Mock AI 계획에 따라:

- 카드 이미지와 상품 정보의 배치
- 이미지 너비 비율
- 이미지 최소 너비
- 카드 내부 간격

이 실제로 변경되어야 합니다.

**메뉴 목록 열 개수와 카드 내부 배치는 서로 독립적으로 검증 가능한 연산이어야 합니다.**

예를 들어 AI가 열 개수만 1열로 변경했는데 카드 내부 배치까지 자동으로 변경되는 경우, 그 변화가 기존 반응형 CSS에서 비롯된 것인지 계획에 포함된 것인지 구분해 보고하세요.

단, 기존 UI에 영향을 주지 않는 일반적인 반응형 동작까지 AI 연산으로 중복 구현할 필요는 없습니다.

## 6. 기존 접근성 기능 보호

이번 작업에서 다음 기능을 절대 변경하지 마세요.

- 큰 글씨
- 큰 버튼
- 고대비

기존 SDK가 관리하는 화면 영역을 이동하거나 크기를 강제로 덮어쓰지 마세요.

## 7. 계획 적용 전후 안전 검사

유효한 계획이라도 실제 화면에서 접근성 문제가 발생하면 적용해서는 안 됩니다.

다음 사항을 확인하세요.

- 상품 카드·버튼이 화면 밖으로 나가지 않음
- 가로 넘침 없음
- 상품명·가격·설명이 잘리지 않음
- 최소 터치 영역 유지
- QR 도크·footer와 겹침 없음
- 하단 조작 영역 설정 유지
- 스크롤 가능한 콘텐츠에 정상 접근 가능
- 쉬운 말·스마트 길잡이 영역을 침범하지 않음

기존 SDK의 레이아웃 진단 기능을 활용할 수 있는지 확인하세요.

현재 구조에서 즉시 자동 원복이 안전하게 구현 가능한 경우에만 적용하고, 구현 범위를 벗어난 대규모 진단 엔진 변경이 필요하면 임의로 확장하지 말고 보고하세요.

잘못된 계획은 기본 레이아웃을 유지해야 합니다.

## 8. React 적용 및 초기화

현재 React 기반 적용 구조를 유지하세요.

- DOM 직접 재배치 금지
- 기존 상품 클릭 핸들러 유지
- 기본 레이아웃 즉시 표시
- 유효한 Mock 계획만 적용
- 화면 이탈 시 계획 제거
- 프로필 변경 시 계획 제거
- 뷰포트 조건 변경 시 오래된 계획 제거
- 세션 초기화 시 계획 제거

AI 계획 적용을 이유로 QR 설정을 다시 적용하거나, 스마트 길잡이를 재시작해서는 안 됩니다.

개발용 `?mockAiLayout=menu-row` 기능은 유지하되, 일반 사용자에게 새로운 테스트 버튼은 추가하지 마세요.
