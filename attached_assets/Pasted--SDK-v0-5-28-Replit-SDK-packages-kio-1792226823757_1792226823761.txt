# 공통 SDK v0.5.28 — 실제 무인민원발급기 문구로 오류 재현 및 미완료 검증

현재 프로젝트는 데모커피 Replit입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`입니다.

기존 v0.5.28 후보를 그대로 이어서 작업합니다. 새로운 SDK 버전은 만들지 마세요.

이번에는 무인민원발급기에서 실제 사용한 쉬운 말 안내 문구를 확보했으므로, 이를 SDK 소비자 테스트 fixture에 사용해 66페이지·137페이지 오류를 재현하고 해결합니다.

사용자가 승인한 오류 수정 외의 새로운 기능, 디자인, AI, 안내 문구 변경은 금지합니다.

## 1. 정확한 오류 재현 데이터

### 화면 A: 주민등록표 등본 선택

stepId: `certificate.type-selection`

설명 1

제목: 주민등록표 등본

본문:
주민등록표 등본은 한 세대의 구성과 주소 정보를 확인하는 주민등록 서류입니다.

설명 2

제목: 주민등록표 초본

본문:
초본 발급은 아직 준비 중입니다. 이 데모에서는 등본만 진행할 수 있습니다.

이 화면에서 실제 사용자는 쉬운 말 안내가 66페이지로 나뉘는 오류를 관찰했습니다.

### 화면 B: 주민등록번호 입력

stepId: `certificate.id-input`

설명 1

제목: 주민등록번호

본문:
주민등록번호는 주민을 구분하는 데 쓰는 13자리 번호입니다. 실제 번호는 입력하지 마세요.

설명 2

제목: 입력한 숫자 보호

본문:
입력한 숫자는 화면에서 점으로 표시됩니다. 데모에는 임의 숫자만 사용하며, 화면을 나가거나 처음 화면으로 돌아가면 입력값이 지워집니다.

설명 3

제목: 입력 수정

본문:
‘정정’은 마지막 숫자 하나를 지우고, ‘전체 삭제’는 입력한 숫자를 모두 지웁니다.

이 화면에서는 137페이지로 나뉘는 오류가 발생했습니다.

위 문구는 실제 무인민원발급기 호스트에서 `setEasyLanguageState()`에 전달하는 내용입니다.

공백과 문장부호를 포함한 정확한 원문을 유지하세요.

## 2. 실제 재현 조건

- 화면: 320×844, 360×667, 390×844
- textSize: extraLarge
- buttonSize: large
- contrast: high
- easyLanguage: true
- smartGuide: true
- viewportMode: bottom 80%

두 화면의 설명을 실제 SDK API로 전달해 테스트합니다.

브라우저에서 다음을 측정하세요.

- 패널 실제 높이
- 헤더·버튼·패딩 높이
- 본문 사용 가능 높이
- 실제 텍스트 줄 높이
- 분할 페이지 수
- 각 페이지에 표시되는 글자 수
- 본문·버튼의 실제 경계 좌표
- 원문 누락·중복 여부

단순히 페이지 수만 줄어든 것을 성공으로 처리하지 마세요.

**모든 문구를 잘림 없이 실제로 읽을 수 있어야 합니다.**

## 3. 오류 수정 원칙

- 하단 80% 유지
- 자동 80% 적용 규칙 유지
- 명시적 60·70·80% 설정 유지
- 큰 글씨·큰 버튼 설정 유지
- 내부 스크롤 없음
- 기존 이전·다음 페이지 방식 유지
- 원문 누락·중복 없음
- 읽던 문장 위치 보존
- 패널 상단 위치 고정

본문에 들어갈 공간이 부족한 경우, 한 글자씩 수십 페이지를 만드는 방식이나 텍스트를 잘라 숨기는 방식으로 해결하지 마세요.

현재 레이아웃으로 해결할 수 없다면 원인을 실측해 보고하고, 새로운 표시 정책이 필요한 경우 사용자 승인을 기다리세요.

## 4. 긴 스마트 길잡이 검증

같은 화면 조건에서 실제로 긴 스마트 길잡이 문구가 잘리는지도 확인합니다.

기존 스마트 길잡이는 단일 페이지이며, 내부 스크롤이나 페이지 전환을 추가하지 않습니다.

현재 표시 영역에서 문구 전체를 보여줄 수 없다면, 가능한 수정 범위와 물리적 제약을 보고하세요.

쉬운 말 접힘 → 스마트 길잡이 자동 펼침 → 기존 접힘 상태 복원도 실제 브라우저에서 확인하세요.

## 5. 데모커피 미완료 검증

이미 통과한 전체 주문 E2E와 기존 하단 스크롤 안정성 결과는 유지합니다.

이번에는 다음 미완료 항목에 집중하세요.

1. 장바구니 비어 있음 → 하단 스크롤 안내 기본 위치
2. 메뉴 담기 → 주문 확인 바 바로 위로 안내 이동
3. 장바구니 비우기 → 기존 위치 복귀
4. 각 상태에서 스크롤 중 위치 점프 없음
5. 자동 하단 80%와 명시적 60·70·80% 브라우저 검증
6. QR 도크가 현재 레이아웃에서 정상 표시
7. 스마트 길잡이 접힘 상태 자동 복원

실제 스크롤 소유자가 `.shell`이라는 점을 반영해 검사하세요.

과거 `window.scrollY`를 기준으로 한 테스트가 현재 구조와 맞지 않는다면 테스트만 수정합니다.

## 6. 시간 제한 대응

전체 소비자 브라우저 행렬이 5분 제한에 걸려 중단된 문제가 반복됐습니다.

이번에는 검증을 작은 단위로 나눠 실행하세요.

1. 실제 안내문 2개로 320×844 오류 재현
2. 수정 후 동일 조건 재검증
3. 360×667과 390×844 검증
4. 스마트 길잡이 긴 문구 검증
5. 주문 바와 스크롤 안내 전환 검증
6. 자동 80%·명시적 모드 검증
7. 마지막으로 나머지 회귀 테스트

각 결과를 기록하고 실패를 숨기지 마세요.

전체 행렬을 한 명령으로 실행해 제한 시간에 걸리지 않도록 하세요.

- 주문 확인 바와 스크롤 안내 위치 정상
