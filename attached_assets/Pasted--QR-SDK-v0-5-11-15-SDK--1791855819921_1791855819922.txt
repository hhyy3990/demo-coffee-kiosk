# 내 방식 QR — 공통 SDK v0.5.11 개발: 업무 완료 후 15초 자동 처음화면 복귀

현재 프로젝트는 데모커피 키오스크이며, 공통 접근성 SDK의 원본 소스를 관리합니다.

현재 SDK 릴리스 버전은 `@naebangsik/kiosk-accessibility-sdk@0.5.10`입니다.

이번 작업에서는 **최종 업무 완료 후 15초가 지나면 자동으로 키오스크 첫 화면으로 복귀하는 범용 기능**을 개발합니다.

앞으로 데모커피, 무인민원발급기, 병원 키오스크에서 동일한 SDK API로 사용할 수 있어야 합니다.

가장 중요한 원칙은 **SDK 우선**입니다. 각 키오스크에 별도 자동 복귀 타이머를 만드는 방식은 사용하지 마세요.

---

## 1. 최종 목표

사용자가 업무를 완전히 마친 뒤 최종 완료 화면에 들어가면:

1. SDK가 15초 자동 복귀 타이머를 시작합니다.
2. 남은 시간이 사용자에게 표시됩니다.
3. 15초가 지나면 첫 화면으로 자동 복귀합니다.
4. 사용자가 '시간 연장'을 누르면 다시 15초를 제공합니다.
5. 사용자가 '처음 화면으로'를 누르면 즉시 복귀합니다.
6. 복귀할 때 접근성 프로필과 이전 사용자의 업무 데이터가 초기화됩니다.
7. 이후 새로운 사용자가 이전 사용자 정보 없이 처음부터 시작할 수 있습니다.

**결제 도중, 출력 도중, 영수증 처리 도중에는 절대 자동 복귀하지 않습니다.**

호스트가 실제로 완료됐다고 알려준 이후에만 SDK가 타이머를 시작해야 합니다.

## 2. SDK와 호스트의 역할 구분

### 공통 SDK 담당

- 자동 복귀 타이머 시작
- 15초 카운트다운
- 시간 연장
- 타이머 취소
- 타이머 중복 방지
- 남은 시간 변경 알림
- 완료 후 복귀 콜백 실행
- 스마트 길잡이 타이머와 충돌 방지
- 화면 전환·세션 종료 시 안전한 타이머 정리
- SDK 접근성 상태 초기화

### 각 키오스크 호스트 담당

- 실제 업무가 완료됐는지 판단
- 자동 복귀 기능에 완료 사실 전달
- 첫 화면으로 이동
- 장바구니·선택 옵션·가상 결제 정보·발급 입력값 등 업무 데이터 초기화
- 완료 화면 UI에 SDK가 제공한 남은 시간과 시간 연장 동작 연결

카페 주문 상태나 민원발급 업무 이름을 SDK 내부에 하드코딩하지 마세요.

## 3. 범용 SDK API 설계

현재 SDK의 공개 API와 세션 구조를 먼저 분석하세요.

기존 API를 불필요하게 바꾸지 말고, 다음 기능을 제공하는 간단한 범용 API를 설계합니다.

- 완료 상태 진입 알림
- 남은 시간 구독
- 시간 연장
- 자동 복귀 취소
- 즉시 처음 화면 복귀
- 완료 화면 이탈 시 타이머 정리

가령 다음 동작을 지원하는 형태입니다. 정확한 API 이름과 타입은 기존 SDK 구조에 맞게 설계하세요.

- `beginCompletion(...)`
- `extendCompletion(...)`
- `cancelCompletion(...)`
- `finishCompletion(...)`

이는 개념적 예시이며, 위 함수 이름을 반드시 그대로 구현하라는 뜻은 아닙니다.

기존 SDK의 endSession(), notifyScreenChange(), 스마트 길잡이 상태 관리와 안전하게 통합해야 합니다.

SDK는 카페나 무인민원발급기의 React 상태에 직접 의존하면 안 됩니다.

## 4. 15초 카운트다운 정책

기본 자동 복귀 시간은 **15초 고정**으로 구현합니다.

- 완료 화면이 실제로 표시되고, 호스트가 완료 상태를 확정한 뒤 타이머 시작
- 표시되는 남은 시간은 실제 타이머와 일치
- 15초 → 14초 → ... → 1초 → 자동 복귀
- 화면 렌더링 지연이나 백그라운드 탭에서도 타이머 중복 없음
- 사용자가 시간 연장을 누르면 다시 15초부터 시작
- 시간 연장을 여러 번 눌러도 정상 동작
- 복귀 동작은 단 한 번만 실행
- 완료 화면에서 다른 화면으로 이탈하면 기존 카운트다운 취소
- 새로운 완료 세션이 시작되면 이전 세션 타이머는 영향을 주지 않음

화면에 표시된 카운트다운이 실제 시간보다 크게 어긋나지 않도록 구현하세요.

## 5. 완료 화면 UI

**카운트다운 및 시간 연장 기능은 SDK가 제공하고, 실제 완료 화면은 각 키오스크의 디자인을 유지합니다.**

데모커피의 기존 주문 완료 화면에 다음 안내를 연결해 주세요.

'15초 후 처음 화면으로 돌아갑니다.'

남은 시간은 초 단위로 표시합니다.

사용자가 누를 수 있는 버튼:

- 시간 연장
- 처음 화면으로

버튼의 실제 디자인은 기존 데모커피 스타일을 따르되, 충분히 크고 명확하게 표시합니다.

큰 글씨·큰 버튼·고대비·하단 60·70·80% 설정에서도 카운트다운과 두 버튼을 읽고 누를 수 있어야 합니다.

시간 연장 버튼이 접근성 화면에서 가려지거나 스크롤로도 도달할 수 없다면 실패입니다.

SDK는 공통 UI를 강제로 덮어씌우기보다, 호스트가 자신의 디자인에 맞춰 표시할 수 있도록 상태와 액션을 제공하는 구조를 우선합니다.

## 6. 개인정보 및 세션 초기화

자동 복귀할 때 이전 사용자의 정보가 남아서는 안 됩니다.

데모커피에서는 다음을 확인합니다.

- 장바구니 비우기
- 주문 옵션 초기화
- 선택된 결제 수단 초기화
- 이전 영수증·주문 결과 상태 제거
- 접근성 프로필 초기화
- 스마트 길잡이 팝업과 강조 제거
- 음성 안내 종료
- 스크롤 위치 초기화
- QR 프로필 토큰 등 세션성 정보 정리

SDK의 endSession()과 호스트 상태 초기화 콜백의 실행 순서를 안전하게 설계하세요.

호스트 초기화 콜백에 실패한 경우, 새 사용자의 시작 화면에 이전 사용자 데이터가 남은 채 표시되지 않도록 처리해야 합니다.

완료 화면의 카운트다운이 세션을 다시 시작시키는 루프가 발생하지 않게 해 주세요.

## 7. 스마트 길잡이와의 충돌 방지

현재 SDK v0.5.10에는 다음 타이머가 있습니다.

- 스마트 길잡이 표시 전 대기 10·15·20초
- 스마트 길잡이 표시 후 자동 닫힘 10초

이번에 추가할 완료 후 자동 복귀 15초와 서로 간섭하면 안 됩니다.

특히 완료 상태 진입 시:

1. 이전 업무 단계의 스마트 길잡이 예약을 정리합니다.
2. 기존 안내창과 버튼 강조를 제거합니다.
3. 완료 화면 카운트다운을 시작합니다.
4. 완료 타이머 도중 스마트 길잡이가 다시 나타나지 않게 합니다.
5. 처음 화면 복귀 시 SDK 세션을 정상 종료합니다.

이전 스마트 길잡이 타이머가 완료 화면의 카운트다운을 취소하거나 반대로 완료 타이머가 새 세션의 안내를 닫지 않게 해 주세요.

## 8. 독립 SDK fixture 검증

데모커피 코드나 React 없이 일반 HTML·CSS·JavaScript 소비자 fixture에서 다음 상황을 검증합니다.

- 최종 완료 상태 진입
- 15초 후 자동 복귀 콜백 1회 실행
- 카운트다운 정확도
- 5초 남았을 때 시간 연장
- 1초 남았을 때 시간 연장
- 시간 연장 여러 번
- 수동 처음화면 복귀
- 타이머 진행 중 다른 화면 이동
- 빠른 완료 화면 진입·이탈
- 새로운 완료 세션 진입
- 자동 복귀와 수동 복귀 동시 발생
- 자동 복귀 콜백이 느리거나 실패하는 경우
- endSession() 중복 호출
- 스마트 길잡이 예약 상태에서 완료 진입
- 완료 중 브라우저 창 크기 변경
- 하단 60·70·80% 설정
- 큰 글씨·큰 버튼·고대비

특히 자동 복귀 콜백이 두 번 이상 실행되지 않는지 검증하세요.

## 9. 데모커피 통합

기존 데모커피 전체 주문 흐름을 유지합니다.

매장/포장 선택 → 메뉴 선택 → 온도·크기·컵 옵션 → 장바구니 → 주문 확인 → 결제 방법 → 가상 결제 → 주문 완료

최종 주문 완료 화면에 들어온 뒤부터 SDK의 15초 타이머를 시작합니다.

단, 실제 앱에 결제 처리·영수증 확인 등의 별도 단계가 있다면 해당 처리가 완료된 이후 시작해야 합니다.

호스트에 별도 setInterval이나 setTimeout으로 자동 복귀를 구현하지 마세요.

SDK의 공통 타이머 API만 사용합니다.

**카운트다운이 실행되는 동안 기존 주문 완료 내역은 사용자가 확인할 수 있어야 합니다.**

시간 연장을 누르면 완료 화면에 머문 상태에서 다시 15초가 주어져야 합니다.

## 10. 브라우저 및 반응형 검증

다음 크기에서 확인합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920
- 1440×900
- 1920×1080

프로필:

- 기본
- 큰 글씨
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 하단 60%
- 하단 70%
- 하단 80%

모든 조합을 실제로 검증하기 어렵다면 우선 주요 조합부터 확인하고, 나머지 미검증 항목을 명확히 보고하세요.

검증 항목:

- 남은 시간 표시
- 시간 연장 버튼 접근 및 클릭
- 처음 화면 버튼 접근 및 클릭
- 완료 화면 내용 가림 없음
- 다른 업무 단계에서 자동 복귀 발생하지 않음
- 초기화 후 새 사용자 정상 시작
- 스크롤 안내·스마트 길잡이 기존 기능 유지

## 11. 기존 SDK 회귀

다음 기능을 유지합니다.

- QR v1/v2/v3
- viewportMode null/60/70/80%
- QR 도크 동기화
- 큰 글씨·큰 버튼·고대비
- 선택적 최대 10% 글씨 보정
- 개발자용 레이아웃 진단
- 쉬운 말
- 스마트 길잡이 stepId
- 안내 표시 전 10·15·20초
- 안내 표시 후 10초 자동 닫힘
- 음성 안내
- 스크롤 안내
- notifyScreenChange()
- endSession()

새 API가 기존 호스트에 불필요한 변경을 요구해서는 안 됩니다.
