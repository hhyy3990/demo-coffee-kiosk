# 내 방식 QR — 범용 접근성 SDK 독립 패키징

현재 데모커피 프로젝트의 `packages/kiosk-accessibility-sdk`에 공통 접근성 SDK v0.1.0이 구현되어 있습니다.

이번 작업의 목표는 이 SDK를 데모커피 프로젝트 밖의 다른 Replit 프로젝트에서도 재사용할 수 있도록 독립적인 설치형 패키지로 만드는 것입니다.

향후 동일한 SDK를 카페, 병원, 은행 키오스크에 적용해 범용성을 검증할 예정입니다.

## 1. SDK 독립 패키지 만들기

현재 SDK의 기능과 공개 API를 유지하면서 독립적으로 빌드 가능한 패키지로 구성해 주세요.

- TypeScript 소스를 JavaScript로 빌드
- 타입 선언 파일(.d.ts) 생성
- 패키지 전용 package.json 구성
- CSS 파일을 패키지에서 사용할 수 있도록 포함
- 외부 키오스크가 import할 수 있는 진입점 설정
- SDK 버전 및 프로필 스키마 버전 명시
- 데모커피 내부 파일을 직접 import하지 않도록 의존성 분리
- React에 종속되지 않는 핵심 API 유지

npm에 공개 배포할 필요는 없습니다. 우선 로컬 설치나 패키지 파일을 통한 재사용이 가능하도록 만들어 주세요.

## 2. 기존 접근성 기능 유지

다음 기능이 동일하게 작동해야 합니다.

- QR 프로필 설정 검증 및 적용
- 큰 글씨
- 큰 버튼
- 고대비
- 하단 조작을 위한 공통 배치 규칙
- 화면 단순화 관련 공통 스타일
- 스마트 길잡이 무조작 타이머
- 안내 문구 표시 및 버튼 강조
- 음성 안내
- 레이아웃 잘림·넘침 진단
- SDK 해제 및 기본 화면 복원

키오스크마다 다른 업무 상태와 버튼 의미는 각 키오스크 어댑터가 담당하도록 유지합니다.

현재 구현되어 있지 않은 자동 레이아웃 보정이나 AI 기능을 이번 작업에서 새로 추가하지 마세요.

## 3. 다른 프로젝트에서 설치할 수 있는지 검증

가장 중요한 요구사항입니다.

데모커피 앱의 기존 import가 작동하는 것만 확인하지 말고, 실제로 SDK가 독립적으로 동작하는지 테스트해 주세요.

가능하다면 다음 과정을 자동화해 주세요.

1. SDK 독립 빌드
2. `npm pack`으로 설치 가능한 .tgz 파일 생성
3. 데모커피 코드에 의존하지 않는 별도 최소 테스트 프로젝트 생성
4. 해당 테스트 프로젝트에 .tgz 패키지 설치
5. 외부 프로젝트에서 SDK import
6. 테스트용 QR 프로필 설정을 적용해 큰 글씨·큰 버튼·고대비 확인
7. 별도 키오스크 어댑터를 연결해 스마트 길잡이 확인
8. 레이아웃 진단 API 실행 확인
9. SDK 해제 후 원래 화면 복원 확인

테스트 프로젝트에 데모커피 전용 코드나 접근성 CSS를 복사하지 마세요.

기존 중앙 QR 서버의 실제 사용자 토큰은 테스트에 사용하지 마세요.

## 5. 배포 및 버전 관리

현재 SDK 버전은 v0.1.0입니다.

공개 API를 불필요하게 변경하지 말고, 변경이 필요한 경우 변경 내용과 호환성 영향을 정리해 주세요.

패키지 파일을 재생성할 수 있는 빌드 명령을 제공하고, package.json의 exports, types, files 등을 정확하게 설정해 주세요.

다른 프로젝트에 옮길 수 있는 실제 .tgz 파일을 생성해 주세요.

Replit에서 파일을 다운로드할 수 있는 위치와 파일명을 알려주세요.

## 6. 기존 데모커피 회귀 테스트

SDK 패키징으로 기존 기능이 망가지면 안 됩니다.

다음 항목을 검증해 주세요.

- QR 설정 불러오기
- 카메라 QR 스캔
- 접근성 프로필 적용
- 스마트 길잡이와 음성 안내
- 기본 주문 → 메뉴 선택 → 옵션 → 장바구니 → 결제 → 완료
- 주문 종료 후 프로필 초기화
- 320px, 390px, 세로형 키오스크 해상도

타입 검사, 자동 테스트, 빌드도 수행해 주세요.
