# 내 방식 QR — 공통 SDK 하단 여백 중복 문제 분석 및 조건부 v0.5.6 개발

현재 이 프로젝트는 데모커피 키오스크와 공통 접근성 SDK의 개발 프로젝트입니다.

현재 SDK 릴리스 버전은 다음과 같습니다.

`@naebangsik/kiosk-accessibility-sdk@0.5.5`

SDK 릴리스 파일:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.5.tgz`

이번 작업의 목적은 무인민원발급기에서 발견된 **호스트 콘텐츠의 하단 여백과 SDK의 고정 조작부 예약 공간이 중복되는 문제**를 독립적으로 분석하고, 다른 종류의 키오스크에도 적용할 수 있는 범용 해결책을 마련하는 것입니다.

SDK 공통 결함이나 공개 계약의 부족이 확인된 경우에만 v0.5.6을 제작합니다.

무인민원발급기 프로젝트 자체는 수정하지 않습니다.

---

## 1. 문제 배경 및 실제 측정값

무인민원발급기의 360×667 화면에서 큰 글씨·큰 버튼·고대비와 하단 조작 60·70·80%를 적용했을 때, 마지막 증명서 메뉴 뒤에 지나치게 많은 스크롤 여백이 남았습니다.

실제 스크롤 소유자는 `<main class="stage">`이며, 호스트 어댑터에도 올바르게 등록돼 있습니다.

| 모드 | stage 표시 높이 | 최대 scrollTop | 최하단에서 마지막 메뉴 |
|---|---:|---:|---|
| 60% | 301px | 944px | 화면 위로 37.8px 벗어남 |
| 70% | 351px | 894px | 일부만 표시 |
| 80% | 401px | 844px | 위쪽 약 1px 잘림 |

마지막 메뉴 이후의 전체 스크롤 콘텐츠 공간은 약 **338.75px**입니다.

구성 요소는 다음과 같습니다.

- 호스트 안내문 위 여백 12px
- 안내문 높이 52.5px
- `.screen-view` 하단 padding 16px
- `.screen-content` 하단 padding 90px
- 호스트 하단 경계 약 3px
- SDK의 `.stage::after` 예약 공간 165px

SDK 예약 공간 165px은 진단상 QR 도크 높이 72px과 고정 하단 조작부 inset 93px의 합입니다.

문제는 실제 콘텐츠 표시 영역이 301px까지 작아지는데, 마지막 메뉴 이후의 여백이 약 339px에 달한다는 것입니다.

그 결과 최하단으로 스크롤하면 마지막 메뉴가 표시 영역 위로 지나가 버립니다.

호스트의 `padding-bottom:90px`만 제거하는 임시 실험으로도 하단 60%에서 잘림이 남았습니다.

따라서 호스트의 단일 CSS 속성만 제거하는 방식으로는 충분하지 않을 수 있습니다.

## 2. 작업 원칙

다음 원칙을 반드시 지켜 주세요.

1. 공통 SDK 범용성을 최우선으로 합니다.
2. 무인민원발급기 전용 CSS 선택자나 업무 이름을 SDK에 넣지 않습니다.
3. 기존 SDK v0.5.5 기능은 보존합니다.
4. 실제 콘텐츠의 정상적인 여백을 무조건 제거하지 않습니다.
5. QR 도크 및 고정 하단 조작부의 안전 공간을 임의로 없애지 않습니다.
6. 글씨·버튼 크기를 줄이지 않습니다.
7. 화면 전체를 축소하는 방법 A를 도입하지 않습니다.
8. 원인 확인 전 SDK 공개 API를 불필요하게 늘리지 않습니다.
9. 원인이 검증되지 않은 상태에서는 v0.5.6을 만들지 않습니다.

특히 SDK가 호스트의 모든 padding을 강제로 0으로 만드는 식의 해결은 금지합니다.

## 3. 기존 SDK 고정 영역 예약 구조 분석

먼저 SDK 소스를 조사합니다.

다음 항목을 확인해 주세요.

- `bottom-viewport.ts`
- `.stage::after` 또는 SDK가 생성하는 예약 공간
- `createQrEntryDock()`
- 고정 하단 조작부 영역 등록
- `getLayoutRegions()`
- 실제 QR 도크 높이 측정
- fixed bottom controls inset 계산
- 하단 60·70·80% viewport 높이 계산
- 화면별 QR 도크 활성화 여부
- scrollArea와 contentRoot의 역할
- scrollHeight 변화
- SDK 스타일 복원
- `endSession()`

특히 다음 질문에 답해 주세요.

**SDK가 QR 도크와 고정 하단 조작부의 예약 공간을 중복해서 계산하고 있는가?**

QR 도크와 고정 조작부가 실제로 서로 다른 영역을 차지하는 경우에도, 두 높이를 단순 합산해야 하는지 검토합니다.

스크롤 영역 자체가 이미 고정 조작부 위에서 끝난다면, 스크롤 콘텐츠 뒤에 동일한 높이를 또 추가할 필요가 있는지도 확인해야 합니다.

이때 QR 도크와 footer가 겹치는지, 수직으로 쌓이는지, 실제 viewport에 이미 반영돼 있는지를 구분해 주세요.

## 4. 독립 fixture 구성

무인민원발급기나 데모커피의 화면 코드를 복사하지 말고 일반 HTML·CSS로 독립 fixture를 만듭니다.

다음 레이아웃을 각각 준비합니다.

### Fixture A — 호스트 자체 하단 여백

- 스크롤 가능한 콘텐츠
- 안내문
- 호스트 padding-bottom
- SDK 하단 viewport
- 별도의 고정 조작부 없음

### Fixture B — 고정 하단 조작부

- 스크롤 가능한 콘텐츠
- 고정된 홈·이전 버튼
- 호스트의 기존 안전 여백
- SDK의 고정 조작부 등록
- 하단 60·70·80%

### Fixture C — QR 도크와 고정 조작부

- 첫 화면의 QR 도크
- 하단 고정 조작부
- 기존 호스트 하단 여백
- 큰 글씨·큰 버튼
- 하단 60·70·80%

### Fixture D — 이미 안전 영역이 확보된 스크롤 컨테이너

- 스크롤 영역 자체가 고정 조작부 위에서 종료
- 호스트가 이미 필요한 하단 안전 공간을 확보
- SDK에 같은 고정 조작부 등록
- 중복 예약 여부 확인

### Fixture E — 360×667 핵심 재현

- 콘텐츠 표시 영역 약 301px
- 마지막 메뉴 이후 실제 안내문
- 호스트 하단 여백
- SDK 예약 공간
- 마지막 메뉴가 최하단에서 위로 사라지는 구조

### Fixture F — 최소 여백 콘텐츠

- 호스트 하단 padding이 거의 없음
- QR 도크와 고정 조작부는 실제로 존재
- SDK 예약 공간을 줄였을 때 필수 버튼이 가려지지 않는지 확인

모든 fixture에서 실제 SDK 공개 API와 정상적인 레이아웃 어댑터를 사용합니다.

## 5. 중복 예약과 필요한 안전 공간 구분

각 fixture에서 다음 항목을 측정합니다.

- viewport top / bottom / height
- scrollArea top / bottom / height
- 실제 QR 도크 boundingClientRect
- 고정 조작부 boundingClientRect
- 고정 요소와 scrollArea의 실제 겹침
- SDK가 추가한 예약 공간
- 호스트 padding / margin
- 마지막 콘텐츠의 bottom
- 마지막 콘텐츠 이후의 스크롤 공간
- scrollHeight / clientHeight / 최대 scrollTop
- 현재 QR 도크 활성 여부
- 스크롤 최하단의 실제 가시 콘텐츠

이때 다음을 구별해 주세요.

**A. 이미 viewport 계산에 반영된 공간**

고정 조작부 때문에 scrollArea 자체가 짧아져 콘텐츠와 겹치지 않는 경우입니다.

**B. 스크롤 콘텐츠에 추가해야 하는 공간**

고정 요소가 실제로 scrollArea를 덮고 있어, 마지막 콘텐츠를 위로 올려 보이게 하기 위한 여백이 필요한 경우입니다.

**C. 호스트가 의도적으로 둔 여백**

안내문이나 디자인상 padding 등 SDK가 임의로 제거해서는 안 되는 공간입니다.

세 공간을 단순 합산하는 것이 항상 올바른지 확인해 주세요.

## 6. 목표 동작 정의

핵심 목표는 단순히 padding 수치를 줄이는 것이 아닙니다.

하단 60·70·80%에서 다음 조건을 만족해야 합니다.

- 첫 콘텐츠가 표시 영역 상단에서 잘리지 않음
- 마지막 업무 버튼까지 스크롤 가능
- 최하단에서도 마지막 주요 업무 버튼이 표시 영역 안에 남음
- 마지막 버튼이 QR 도크 또는 고정 조작부 아래에 가려지지 않음
- 실제 안내문은 유지
- 필요한 호스트 여백은 유지
- 스크롤이 불필요한 빈 공간에서 끝나지 않음
- 글씨·버튼 크기 유지
- 전체 화면 축소 없음
- 하나의 명확한 스크롤 소유자
- 스크롤 위치가 갑자기 되돌아가지 않음

마지막 버튼 뒤에 실제로 읽어야 하는 안내문이 존재하는 경우, 해당 안내문도 접근 가능해야 합니다.

**실제 필수 콘텐츠를 가리거나 자르면서 마지막 버튼만 보이게 만드는 해결은 허용하지 않습니다.**

## 7. 해결 방식 검토

다음 순서로 검토해 주세요.

### 1순위 — 기존 SDK 계약으로 해결 가능한지

현재 어댑터가 제공하는 scrollArea·고정 조작부 정보만으로 중복 예약을 판단할 수 있는지 확인합니다.

기존 기능을 정상 연결하는 것으로 충분하다면 새 API나 SDK 버전을 추가하지 않습니다.

### 2순위 — SDK 내부의 범용 예약 계산 개선

SDK가 실제 고정 요소와 viewport 사이의 겹침을 계산해 불필요한 예약 공간을 줄일 수 있는지 검토합니다.

이때 다음 조건을 지킵니다.

- 고정 요소가 여러 개일 때 중복 계산하지 않음
- 실제로 겹치는 영역만 반영
- DOM 크기 변경 시 다시 측정
- QR 도크 활성화·비활성화 반영
- 기존 예약 공간과 호스트 여백 중복 최소화
- 다양한 키오스크 DOM 구조에서 동작

### 3순위 — 공개 어댑터 계약 확장

호스트가 이미 고정 조작부용 여백을 확보했는지 SDK가 안전하게 판단할 수 없는 경우에만, 일반적인 선택적 어댑터 정보 추가를 검토합니다.

예를 들어 호스트가 관리하는 스크롤 영역의 안전 공간 정보를 명시하는 방식입니다.

단, 실제 구현 전 기존 공개 API와의 호환성, 필수 정보의 의미, 기본값, 오래된 소비자에 미치는 영향을 검토해야 합니다.

**특정 `.screen-content` padding을 SDK에서 직접 찾아 수정하는 방법은 사용하지 마세요.**

## 8. 안전성 검증

수정이 필요하다면 다음을 반드시 확인합니다.

### 첫 화면

- QR 도크 표시
- QR 도크와 고정 버튼 겹침 없음
- 필요한 스크롤 안전 공간 유지
- 하단 viewport 계산 정상

### 업무 화면

- QR 도크 숨김
- 고정 조작부 유지
- QR 도크 공간이 실제로 필요 없는 경우 불필요하게 예약되지 않음
- 마지막 업무 버튼 전체 표시
- 실제 안내문 접근 가능

### 화면 전환

- `notifyScreenChange()` 정상
- 새 화면 첫 제목 표시
- QR 도크 제거·재표시
- 스크롤 소유자 변경
- 사용자 스크롤 보존

### 세션 종료

- `endSession()` 초기화
- SDK가 수정한 스타일 복원
- 중복 예약 공간 제거
- QR 도크 재표시

## 9. 화면 크기 및 프로필 테스트

다음 화면 크기를 검증합니다.

- 320×844
- 360×667
- 390×844
- 1080×1920
- 1440×900
- 1920×1080

프로필:

- 기본
- 큰 글씨·큰 버튼·고대비
- 하단 60%
- 하단 70%
- 하단 80%
- 큰 글씨·큰 버튼·고대비 + 각 하단 모드

스크롤 최상단과 최하단 모두 검사합니다.

## 10. 실제 스크롤·클릭 검증

각 필수 조합에서 다음을 확인합니다.

1. 실제 휠 또는 Chromium 터치 시뮬레이션 입력
2. 마지막 업무 버튼까지 스크롤
3. 마지막 버튼 전체 표시
4. hit-test 성공
5. 실제 클릭 이벤트 성공
6. 실제 안내문 표시 및 접근 가능
7. 최하단에서 과도한 빈 공간 없음
8. 100ms·500ms·1초·3초 후 위치 안정
9. 다시 위로 스크롤 시 첫 제목 표시

강제 scrollTop 설정만으로 사용자 입력 테스트를 대신하지 마세요.

기존 v0.5.5 테스트에서 통과한 항목이 이번 수정으로 다시 실패하면 안 됩니다.

## 12. 조건부 SDK v0.5.6 제작

독립 fixture에서 SDK의 공통 예약 공간 계산 또는 공개 계약 문제가 확인되고, 범용 수정과 회귀 테스트가 모두 통과한 경우에만 v0.5.6을 제작합니다.

예상 패키지 경로:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.6.tgz`

조건:

- 핵심 여백 중복 재현
- 정확한 원인 확인
- 범용 수정 완료
- 실제 안내문 및 안전 영역 보존
- 최하단에서 마지막 버튼 접근 성공
- 화면 크기별 검증 통과
- 기존 SDK 회귀 통과
- 데모커피 주문 E2E 통과
- 타입 검사·테스트·빌드 통과
