# 공통 SDK v0.5.17 — 안내창 상태·스크롤·페이지 전환 안정화

현재 작업 대상은 **데모커피 Replit**입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`에 있으며 현재 SDK 버전은 v0.5.16입니다.

실제 사용자 모바일 테스트에서 여러 안내창 오류가 확인됐습니다.

이번에는 단순히 화면 위치를 수정하는 것이 아니라 **공통 SDK의 안내 표시 상태, 페이지 관리, 스크롤 시 배치, 단계별 안내 누락 처리 전반을 점검하고 수정**해 주세요.

이 SDK는 데모커피뿐 아니라 무인민원발급기와 향후 병원 키오스크에서도 재사용해야 합니다.

## 1. 확인된 사용자 오류

### A. 스크롤하면 쉬운 말 안내와 스마트 길잡이가 사라짐

사용자가 화면을 스크롤하면 안내창이 갑자기 사라집니다.

사용자는 접기 또는 닫기를 누르지 않았고 업무 단계도 바뀌지 않았습니다.

이것이 SDK의 안전 배치에 의한 일시적인 숨김인지, 상태가 실제로 삭제되는 것인지 구분하세요.

확인할 내용:

- scroll 이벤트 후 패널 상태 변경
- guide-suppressed 발생 여부
- 안전 영역 계산
- 스크롤 위치와 고정 요소의 좌표 계산
- 안내창이 화면 밖으로 이동하는지
- SDK의 레이아웃 재측정
- 기존 쉬운 말·스마트 길잡이 타이머 유지 여부

**스크롤만으로 쉬운 말의 내용과 페이지 위치가 사라지면 안 됩니다.**

업무 버튼을 가리지 않는 범위에서 안내창을 안정적으로 유지하세요.

안전한 펼친 위치가 없다면 접힌 안내 헤더를 유지하는 방법을 우선 검토하세요.

단, 버튼을 가리는 위치에 무조건 표시해서는 안 됩니다.

### B. 스마트 길잡이에 쉬운 말의 페이지 정보가 남음

현재 쉬운 말 안내가 2페이지일 때 스마트 길잡이로 전환하면, 길잡이에도 1/2, 2/2가 나타납니다.

다음 페이지를 눌러도 같은 스마트 길잡이 문장이 반복됩니다.

원인 후보:

- 쉬운 말 explanations 배열의 페이지 수가 스마트 길잡이 모드에도 사용됨
- 쉬운 말 페이지 인덱스가 길잡이 모드로 전달됨
- 공통 패널 렌더링에서 모드별 데이터 분리가 누락됨

수정 요구:

- 스마트 길잡이는 현재 단계의 안내 문구 하나를 표시
- 스마트 길잡이 중에는 쉬운 말의 이전·다음 버튼 숨김
- 스마트 길잡이 중에는 쉬운 말의 1/2, 2/2 페이지 표시 숨김
- 길잡이의 10초 또는 15초 숫자 카운트다운은 유지
- 길잡이 종료 후 원래 쉬운 말 페이지 번호 복원
- 원래 접힘 상태도 복원

예시:

쉬운 말 2/3 → 스마트 길잡이 단일 안내 → 쉬운 말 2/3 복귀

문구가 같은 페이지를 중복해서 출력하면 안 됩니다.

### C. 안내창 위치가 계속 달라지고 콘텐츠를 가림

사용자는 쉬운 말·스마트 길잡이·스크롤 안내가 위, 중간, 아래에 계속 나타나며 화면을 가리는 문제를 발견했습니다.

특정 화면의 위치를 하드코딩하지 말고 SDK 공통 배치 정책을 개선하세요.

요구사항:

- 같은 업무 단계에서 불필요한 위치 점프 최소화
- 스크롤할 때 패널이 콘텐츠를 따라 불규칙하게 이동하지 않음
- 키패드·입력값·선택지·주요 버튼과 충돌하지 않음
- 안내창과 스크롤 안내가 서로 겹치지 않음
- 가능한 한 일관된 위치 유지
- 위치 변경이 불가피하다면 화면이 급격하게 흔들리지 않도록 처리
- 좁은 화면에서는 접힌 안내 헤더 등의 안전한 대체 표시 우선

배치 상태 변경으로 새로운 재측정 무한 루프가 발생하지 않도록 v0.5.16의 성능 개선은 반드시 유지하세요.

### D. 빈 내용인데 펼치기 버튼 표시

표시할 쉬운 말 설명이 없는 단계에서 접힌 패널이나 '펼치기' 버튼이 나타나는 문제가 있습니다.

수정 요구:

- 설명 배열이 비어 있으면 쉬운 말 패널 없음
- 공백 문자열만 있는 경우도 빈 설명으로 처리
- 설명이 없는 상태에서 펼치기 버튼 표시 금지
- 이전 업무 단계의 설명 재사용 금지
- 스마트 길잡이가 있다면 해당 기능은 독립적으로 정상 작동
- 안내 모드가 바뀔 때 오래된 내용이나 버튼 상태가 남지 않도록 처리

### E. 일부 화면에서 안내 자체가 누락됨

무인민원발급기 사용자 테스트에서 다음 화면에 쉬운 말 안내가 나타나지 않았습니다.

- 오른손 엄지손가락 지문 확인
- 증명서에 표시할 항목 선택
- 수수료 면제 대상 선택
- 발급 부수 입력

또한 '신청 내용 확인' 화면에서는 스마트 길잡이가 나타나지 않았습니다.

이번 작업에서 무인민원발급기 프로젝트를 수정하지는 마세요.

대신 공통 SDK 관점에서 다음을 확인하세요.

- 새로운 stepId 등록 시 안내를 받을 수 있는지
- 스마트 길잡이 타이머가 단계 변경에 따라 정상 시작되는지
- 빠른 화면 전환 후 안내가 누락되는지
- 스크롤 상태에서 안내 데이터가 적용되는지
- 설명이 빈 단계 다음의 정상 단계에서 안내가 다시 나타나는지
- setEasyLanguageState 호출과 setGuideState 호출 순서에 따른 차이
- 동일 stepId로 반복 호출해도 안내가 정상 갱신되는지
- 화면이 바뀌었는데 stepId가 갱신되지 않는 경우를 안전하게 처리할 수 있는지

독립 소비자 fixture에서 여러 단계의 안내를 전달하고 누락 없이 표시되는지 검증하세요.

호스트가 실제 안내 데이터를 제공하지 않는 경우까지 SDK가 임의로 내용을 생성할 필요는 없습니다.

이 경우 호스트 데이터 누락과 SDK 표시 오류를 명확히 구분해 보고하세요.

## 2. 데모커피 첫 화면의 쉬운 말 제거

데모커피 첫 화면에는 현재 '매장 이용' 등의 쉬운 말 안내가 표시됩니다.

사용자는 첫 화면에서는 굳이 쉬운 말 안내가 필요하지 않다고 판단했습니다.

데모커피 첫 화면에서는 쉬운 말 안내 데이터를 제공하지 않도록 조정하세요.

단, 다음은 유지합니다.

- 메뉴·옵션·장바구니·결제 단계의 쉬운 말 안내
- 기존 스마트 길잡이의 업무 단계별 동작
- 접근성 체험하기 버튼
- QR 스캔·프로필 적용
- 기존 주문 흐름

첫 화면 정책 변경을 위해 공통 SDK에 카페 전용 조건을 추가하지 마세요.

호스트가 빈 설명을 제공했을 때 SDK가 정상적으로 빈 상태를 처리해야 합니다.

## 3. 검증할 안내 상태 전환

실제 브라우저에서 다음을 검증하세요.

1. 쉬운 말 설명 3개 표시
2. 2/3 페이지로 이동
3. 안내창 접기
4. 스마트 길잡이 시작
5. 접힌 상태 유지
6. 펼쳤을 때 스마트 길잡이 문구 하나만 표시
7. 이전·다음 버튼 및 1/3 페이지 표시 없음
8. 카운트다운 종료
9. 쉬운 말 2/3 복원
10. 접힌 상태 복원
11. 다시 펼쳤을 때 원래 설명 표시
12. 스크롤 후에도 쉬운 말 상태 보존
13. 단계 변경 후 새 안내 표시
14. 빈 설명 단계에서는 펼치기 버튼 없음
15. 다음 단계에서 정상 설명 다시 표시

## 4. 화면 크기별 검증

- 320×844
- 360×667
- 390×844
- 1080×1920

하단 조작 60/70/80%를 포함해 실제 스크롤·클릭으로 확인하세요.

안내창이 주요 버튼을 가리지 않는지 hit-test로 확인하세요.

안전한 위치가 없어 패널이 숨겨지는 경우, 위치·단계·이유를 기록하세요.

## 5. 성능 및 업무 회귀

v0.5.16에서 수정한 무응답 방지 기능을 유지하세요.

- MutationObserver / ResizeObserver 반복 호출 방지
- 프레임 단위 레이아웃 측정
- SDK 자신의 강조 효과로 인한 재측정 루프 방지
- 장시간 스크롤 후 화면 응답 유지
- 주문·옵션·장바구니·결제·완료 흐름 유지
- 완료 후 15초 자동 복귀
- 세션 종료 시 전체 안내 상태 초기화

## 6. SDK 릴리스

공통 SDK 소스 변경이 확인되면 v0.5.17로 올리고 새 tarball을 생성하세요.

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.17.tgz`

기존 v0.5.16 및 이전 tarball은 보존합니다.

독립 소비자 프로젝트에 새 tarball을 설치하여 타입·빌드·실제 브라우저 검증을 진행하세요.

- 데모커피 첫 화면 설명 데이터 제거는 호스트에서 처리
- 무인민원발급기 프로젝트 수정 금지
- 중앙 QR 프로젝트 수정 금지
- Production DB 변경 금지
- Publish 금지
- 카페 전용 SDK CSS 추가 금지
- 새로운 AI API 개발 금지
- QR 스키마 변경 금지

기존 기능을 삭제하거나 안내창을 무조건 숨기는 방식으로 테스트를 통과시키지 마세요.
