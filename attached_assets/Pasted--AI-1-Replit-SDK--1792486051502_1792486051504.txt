# 데모커피 — AI 화면 변환 1차 호스트 연동 및 공통 레이아웃 계약 구현

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본은 다음 경로에 있습니다.

`packages/kiosk-accessibility-sdk/`

현재 안정화된 SDK 버전은 `@naebangsik/kiosk-accessibility-sdk@0.5.31`입니다.

중앙 ‘내 방식 QR’ 서버에는 `POST /api/ai-layout/plan`의 1차 구현이 완료되어 있습니다.

다만 중앙 서버의 `server/layout-policies.ts`에는 실제 데모커피 화면 정책이 아직 등록되지 않아 API가 기본적으로 비활성화되어 있습니다.

이번 작업은 **데모커피의 실제 메뉴 목록 화면을 기준으로, AI가 적용할 수 있는 안전한 레이아웃 변환 기능과 공통 화면 계약을 구현하는 것**입니다.

**이번에는 Mock AI 계획만 사용합니다. 중앙 AI 서버 연결, 실제 OpenAI 호출, Production 배포는 진행하지 마세요.**

## 1. 작업 시작 전 실제 화면 확인

먼저 데모커피의 현재 메뉴 화면을 확인하세요.

이전 조사에서 확인된 주요 파일은 다음과 같습니다.

- `src/App.tsx`
- `src/accessibility/cafeAdapter.ts`
- 메뉴 컴포넌트 및 관련 CSS
- 메뉴·옵션·주문 흐름 관련 테스트

실제 파일 구조가 다르면 현재 소스를 기준으로 확인하세요.

**중요: 현재 데모커피 메뉴 화면은 이미 1열 구조입니다.**

따라서 존재하지 않는 2열 메뉴를 전제로 레이아웃을 설계하거나, 기존 화면을 2열로 변경해서 시연하지 마세요.

현재 화면에서 실제로 표시되는 메뉴 이미지, 상품명, 가격, 설명, 선택 영역, 카테고리 및 고정 버튼을 확인하세요.

그 결과를 바탕으로 **기존 화면과 명확하게 구분되면서 접근성에 실질적인 도움이 되는 레이아웃 변환**을 선정하세요.

예를 들어 실제 구조가 허용한다면 다음을 검토할 수 있습니다.

- 이미지와 상품명·가격의 상대적 배치
- 상품 카드 내부 요소의 세로·가로 구성
- 상품명과 가격을 읽기 쉬운 별도 행으로 구성
- 큰 글씨·큰 버튼 설정에서 카드 내부 간격 조정
- 작은 조작 영역에서 카드 내용을 세로로 재배치

예시는 확정된 요구사항이 아닙니다. 실제 화면 구조에 맞춰 판단하세요.

**실제 확인 결과 의미 있는 변환이 불가능하다면 임의로 기존 UI를 변경하지 말고 이유와 대안을 보고하세요.**

## 2. AI가 변경할 수 있는 영역 구분

데모커피 화면에서 다음을 명확하게 구분하세요.

### 변경 가능한 영역

- 메뉴 카드의 내부 정보 배치
- 메뉴 이미지와 텍스트의 상대적 위치
- 안전한 범위의 요소 정렬
- 허용된 간격 및 콘텐츠 그룹 배치
- 필요 시 메뉴 콘텐츠 영역 내부의 열 구성

### 변경하면 안 되는 영역

- QR 프로필 원본 값
- 글씨·버튼 크기 설정 정책
- 고대비 설정
- 하단 60·70·80% 조작 영역
- 자동 하단 80% 정책
- 상단 쉬운 말 안내의 위치와 페이지 이동
- 스마트 길잡이 표시·종료·복귀 동작
- 아래쪽 내용 안내 ON/OFF 및 위치 계산
- 고정 QR 도크
- footer와 고정 업무 버튼
- 메뉴 항목의 존재와 순서
- 상품 가격·옵션·수량·결제 정보
- 원래 버튼의 클릭 이벤트

특히 AI 변환이 스크롤 안내 위치나 스마트 길잡이 렌더링을 다시 건드리는 일이 없도록 하세요.

**AI는 업무 콘텐츠 내부 배치만 변경합니다. 기존 SDK의 접근성 시스템은 그대로 유지합니다.**

## 3. 재사용 가능한 화면 모델 작성

향후 중앙 AI 서버에 전달할 수 있는 안전한 화면 모델을 구성하세요.

모델에는 다음을 포함할 수 있습니다.

- 화면 모델 버전
- 호스트 식별자
- 업무 화면 ID
- 구조 버전 및 안정적인 구조 해시
- 정적인 요소·그룹 ID
- 요소 역할
- 그룹 관계
- 원래 표시 순서
- 변경 불가능한 필수 요소 ID
- 화면 크기 구간
- 허용된 공통 배치 연산
- 각 연산의 허용 파라미터
- QR 접근성 설정 중 배치에 필요한 제약

다음은 절대로 포함하지 마세요.

- QR 토큰
- 사용자 개인정보
- input·textarea·select의 현재 값
- 사용자별 주문 상태
- 선택한 상품·옵션·수량
- 결제 정보
- 호스트 React 상태 객체 전체
- DOM 전체 HTML
- 무차별적으로 추출한 textContent
- 사용자 자유 입력 문구

메뉴의 정적인 텍스트도 필요하지 않다면 외부 전송 모델에 포함하지 마세요.

**현재 화면을 이해하기 위해 DOM을 읽을 수는 있지만, 안전한 화면 모델은 호스트가 명시적으로 정의한 정보만 사용하세요.**

## 4. 공통 레이아웃 연산 설계

단순히 데모커피만 사용할 수 있는 완성형 템플릿을 여러 개 만드는 방식보다는, 다른 키오스크에서도 사용할 수 있는 제한된 배치 연산을 우선 검토하세요.

예시:

- 그룹 내부 세로·가로 배치
- 이미지와 텍스트의 상대적 위치
- 허용된 정렬 방식
- 안전한 간격 범위
- 카드 내부 정보 영역의 공간 배분

단, 실제로 사용할 연산은 **현재 데모커피 메뉴 화면에서 정상 적용할 수 있는 것만** 구현하세요.

처음부터 불필요하게 많은 연산을 추가하지 마세요.

각 연산은 다음 조건을 만족해야 합니다.

- 대상 요소 ID가 고정되고 명확함
- 원래 상품·버튼 기능이 유지됨
- 원래 항목 순서가 유지됨
- 사용자의 QR 설정을 변경하지 않음
- 값의 허용 범위를 검증할 수 있음
- 기존 화면으로 완전히 복귀할 수 있음

AI가 임의 CSS 문자열·HTML·JavaScript를 반환해 실행하는 구조는 만들지 마세요.

## 5. React 기반 화면 적용

AI 계획의 적용은 데모커피의 기존 React 렌더링 흐름을 활용하세요.

**DOM 요소를 강제로 옮기거나 기존 이벤트 핸들러를 제거·재생성하지 마세요.**

권장 방식:

1. 기본 레이아웃을 기존 React 화면으로 표시
2. 검증된 Mock AI 계획 수신
3. 허용된 레이아웃 속성만 React 상태로 반영
4. 기존 메뉴 데이터와 클릭 핸들러는 그대로 사용
5. 화면 이동·프로필 해제·세션 종료 시 기본 배치로 복귀

기존 SDK의 DOM 관찰·레이아웃 보정과 충돌하지 않는 구조로 구현하세요.

AI 계획 적용 때문에 불필요한 화면 전환, QR 재적용, Smart Guide 재등장, 안내 페이지 초기화가 발생해서는 안 됩니다.

## 6. 안전한 계획 검증

Mock 계획이더라도 실제 AI 응답과 동일한 안전 검증 경로를 거치게 하세요.

다음 항목을 확인하세요.

- 계획 스키마 버전
- 화면 ID
- 구조 해시
- 허용된 요소·그룹 ID
- 허용된 연산
- 파라미터 범위
- 화면 크기 구간
- 적용 가능한 QR 제약

다음 계획은 거부해야 합니다.

- 존재하지 않는 요소 ID
- 허용하지 않은 연산
- 범위를 벗어난 간격·정렬 값
- 다른 화면의 구조 해시
- 필수 요소를 없애는 요청
- 상품 순서를 변경하는 요청
- 가격·수량·결제 정보를 수정하는 요청
- 쉬운 말·스마트 길잡이·스크롤 안내·QR 도크·footer를 대상으로 하는 요청
- 알 수 없는 추가 필드

잘못된 계획은 적용하지 않고 기존 화면을 유지하세요.

중앙 서버의 검증만 믿지 말고 데모커피에서도 최종 검증을 수행할 수 있어야 합니다.

## 7. Mock AI 계획으로 실제 화면 변환 확인

이번 작업에서는 실제 서버를 호출하지 말고, 테스트에서 주입하는 Mock AI 계획을 사용하세요.

최소한 다음 두 가지 상태를 비교하세요.

**기본 상태**

- 기존 데모커피 메뉴 화면과 동일한 배치
- 기존 메뉴 조작 및 주문 흐름 유지

**Mock AI 계획 적용 상태**

- 선택한 콘텐츠 영역의 배치가 실제로 변경됨
- 변경 전과 후의 차이를 DOM·스크린샷으로 확인 가능
- 메뉴 항목·상품명·가격·순서가 유지됨
- 버튼 클릭·옵션 선택·장바구니 기능 유지
- 접근성 설정과 충돌하지 않음

Mock 계획은 테스트 코드 또는 개발 전용 검증 경로에서만 주입하세요.

**일반 사용자용 설정 버튼이나 새로운 테스트 버튼을 키오스크 화면에 추가하지 마세요.**

이번 Mock 변환을 실제 OpenAI의 판단 결과인 것처럼 표시하지 마세요.

## 8. AI 응답 지연 및 취소 대비

후속 단계에서 실제 AI 서버와 연결할 때 다음 조건을 지원할 수 있도록 설계하세요.

- AI 결과를 기다리지 않아도 기존 키오스크를 이용할 수 있음
- 같은 화면 구조·설정에 중복 요청이 발생하지 않도록 관리 가능
- 화면 이동 후 도착한 이전 계획은 무시
- QR 프로필 변경 후 이전 계획 무시
- 세션 초기화 후 이전 계획 무시
- 화면 구조 해시가 다르면 적용하지 않음
- 오류 시 기본 레이아웃 유지

이번 단계에서 서버 호출 코드를 억지로 만들 필요는 없습니다.

다만 적용·해제 로직은 추후 비동기 응답을 안전하게 연결할 수 있는 구조로 구현하세요.

## 9. SDK 변경 제한

현재 안정화된 SDK v0.5.31에는 이미 많은 접근성 기능과 회귀 테스트가 있습니다.

**가능하면 이번에는 SDK 원본을 변경하지 말고, 데모커피 호스트 코드에서 구현하세요.**

SDK 공통 타입이나 검증기 추가가 꼭 필요하다면 즉시 구현하지 말고 다음을 보고하세요.

- 호스트 내부 구현만으로 불가능한 이유
- 어떤 SDK 파일을 수정해야 하는지
- 다른 키오스크에 미치는 영향
- 기존 SDK 안정성과 회귀 위험

SDK를 수정해야 하는 것으로 판단되면 사용자 승인을 기다리세요.

SDK 버전을 올리거나 새 tarball을 만들지 마세요.

- 원래 메뉴와 상품 순서 유지

- 다른 화면 이동 시 기존 계획 제거
- QR 프로필 해제·세션 초기화 시 복귀

### 기존 접근성 기능

- 큰 글씨·큰 버튼·고대비

- 360×667

AI 배치 변경 전·후의 겹침·잘림·가로 넘침도 측정하세요.

특히 기존에 해결한 문제가 재발하지 않는지 확인해야 합니다.
