# 데모커피 공통 SDK v0.5.28 — 수정본의 남은 검증 완료 및 tarball 생성

현재 프로젝트는 데모커피 Replit입니다.

직전 작업에서 공통 SDK의 쉬운 말 안내 공간 최적화와 하단 스크롤 안내 위치 계산을 수정했지만, 검증이 완료되지 않아 tarball을 갱신하지 않았습니다.

**이번 작업에서는 새로운 기능이나 레이아웃 수정을 시작하지 말고, 현재 수정된 SDK 소스에 대한 미완료 검증부터 진행하세요.**

## 1. 기본 모드 스크롤 안내 검증

무인민원발급기의 실제 구조와 동일한 최소 fixture를 구성하세요.

- scrollArea: main.stage
- 기본 모드 실제 scroll owner: Document
- 하단 80% 실제 scroll owner: main.stage
- bottomControls: .device-footer
- footer: position fixed, bottom 0
- footer 높이: 약 86px
- 처음화면·전화면 버튼: footer 안에 배치

390×844 기본 모드에서 기존 측정:

- footer: y=758~844
- 스크롤 안내: y=787.61~832
- footer와 버튼에 실제 겹침 발생

수정 후 성공 기준:

- 스크롤 안내가 footer 상단에서 약 12px 떨어진 위쪽에 표시
- footer 및 버튼과 교차 면적 0
- 스크롤 중 위치 점프 없음
- 스크롤 끝에서 숨김
- pointer-events:none 유지

하단 80% 모드에서는 기존에 정상 확인된 위치인 y≈701.61~746과 footer 위 12px 간격이 유지되어야 합니다.

호스트 CSS를 수정하거나 새로운 SDK 등록 API를 추가하지 마세요.

## 2. 쉬운 말 안내 추가 확인

기존 수정 결과는 유지하세요.

자동 하단 80%:

- 320×844: 4페이지
- 360×667: 4페이지
- 390×844: 2페이지
- 1080×1920: 2페이지

특히 다음을 추가 확인하세요.

1. 실제 원문 보존
2. 한 단어씩 페이지 분할 없음
3. 제목·본문·버튼 잘림 없음
4. 페이지 이동 중 총 페이지 수 안정성
5. 접기·펼치기 후 원래 안내 상태 복원
6. Smart Guide 종료 후 기존 쉬운 말 페이지 복원
7. 상단 8px 유지

360×667 명시적 70%가 6페이지, 명시적 80%가 4페이지로 나온 이유를 분석하세요.

70%는 상단 공간이 더 넓을 것으로 예상되므로, 차이가 레이아웃·제목 줄바꿈·본문 측정 중 무엇 때문인지 확인하세요.

**원인 진단만 수행하고, 추가 수정이 필요하다면 보고한 뒤 승인을 기다리세요.**

## 3. 스마트 길잡이 회귀

기존 검증된 실제 결제 안내 67자와 같은 원문을 사용하세요.

- 360×667 하단 80%에서 최대 2페이지
- 기본 1페이지 10초
- 기본 2페이지 15초, 약 7.5초에 전환
- 느린 안내 20초
- 설명 잘림 없음
- 스마트 길잡이 종료 후 쉬운 말 상태 복원
- 패널 상단 위치 안정성

스마트 길잡이의 기존 문구·타이머·정책은 변경하지 마세요.

- 자동 하단 80%
