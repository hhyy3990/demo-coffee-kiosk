# 내 방식 QR — 공통 접근성 SDK v0.5.3 개발: QR 프로필 v3 및 하단 조작 모드 자동 적용

현재 데모커피 프로젝트에서 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.2`의 소스를 개발·관리하고 있습니다.

중앙 '내 방식 QR' 서비스의 Development 환경에는 프로필 v3가 구현됐습니다.

v3에서는 기존 `bottomControls: boolean` 대신 다음 `viewportMode` 설정을 사용합니다.

- `null`: 하단 조작 모드 사용하지 않음
- `{ "mode": "bottom", "heightPercent": 60 }`
- `{ "mode": "bottom", "heightPercent": 70 }`
- `{ "mode": "bottom", "heightPercent": 80 }`

현재 SDK에는 개발용 `setViewportMode()` API와 방법 B 레이아웃 기능이 이미 구현되어 있지만, QR 프로필의 `viewportMode`를 읽어 자동 적용하는 연결은 아직 없습니다.

이번 작업에서는 공통 SDK가 프로필 v3를 검증하고 `viewportMode`를 실제 키오스크 화면에 적용하도록 확장한 뒤, **SDK v0.5.3 tarball을 제작하고 독립 소비자에서 검증**해 주세요.

중앙 서버·DB와 무인민원발급기 프로젝트는 이번에 수정하지 않습니다.

## 1. 작업 전 기존 구조 조사

먼저 SDK와 데모커피 호스트의 현재 코드를 확인해 주세요.

- QR 프로필 v1/v2 파싱 및 검증
- SDK 공개 타입과 프로필 설정 인터페이스
- 중앙 QR 조회 응답의 `preferences` 구조
- 프로필 적용 및 교체
- `setViewportMode()` 호출 구조
- QR 도크 `createQrEntryDock()`
- 호스트의 QR 조회·적용 흐름
- `endSession()` 초기화
- 현재 개발용 `?bottom-poc=` 등의 viewport 테스트 경로

특히 현재 접근성 프로필 적용 책임이 SDK와 호스트 중 어디에 있는지 확인해 주세요.

SDK에 이미 존재하는 메서드와 수명주기를 재사용하고, 별도의 독립 상태 관리 시스템을 중복으로 만들지 마세요.

## 2. QR 프로필 v3 지원

현재 v1/v2를 지원하는 SDK 프로필 검증기에 v3를 추가해 주세요.

v3의 핵심 필드는 다음과 같습니다.

```json
{
  "schemaVersion": 3,
  "preferences": {
    "textSize": "extraLarge",
    "buttonSize": "large",
    "contrast": "high",
    "easyLanguage": false,
    "viewportMode": {
      "mode": "bottom",
      "heightPercent": 70
    },
    "smartGuide": true,
    "guideDelaySeconds": 10,
    "voiceGuidance": false
  }
}
```

위 JSON은 예시입니다.

**실제 중앙 서비스의 응답 계약을 확인하고, 기존 `preferences` 위치와 메타데이터 구조에 맞춰 구현해 주세요.**

`settings` 등의 별도 속성을 임의로 만들어 실제 중앙 API와 어긋나게 하지 마세요.

v3 검증 조건:

- `schemaVersion: 3` 지원
- `viewportMode: null` 허용
- `mode: "bottom"` 허용
- `heightPercent: 60 | 70 | 80`만 허용
- 문자열 `"70"` 거부
- 50, 65, 90 등 미지원 비율 거부
- 잘못된 mode 거부
- 필수 설정 누락 또는 잘못된 값에 대한 명확한 검증 실패
- 기존 v3 계약에 없는 `bottomControls`, `simplifiedLayout`을 새 v3 프로필 설정으로 받아들이지 않음

그 외 기존 접근성 설정과 `updatedAt` 등 메타데이터는 유지합니다.

## 3. 기존 v1/v2 처리

기존 QR은 내부 테스트용이므로, v1/v2의 과거 하단 조작 방식까지 그대로 재현할 필요는 없습니다.

다만 이전에 구현한 v1/v2 파싱이 갑자기 오류를 일으키지 않게 해 주세요.

권장 처리:

- v1/v2 프로필은 기존 방식으로 읽기
- 기존 `bottomControls` 값으로 방법 B의 비율을 추측하지 않음
- v1/v2에서 하단 viewport 설정은 비활성으로 정규화
- v3에서는 명시적인 `viewportMode`만 사용
- `simplifiedLayout`은 복원하지 않음

가능하다면 정규화된 내부 프로필 타입에서 하단 viewport 설정을 일관되게 취급해 주세요.

## 4. QR 적용 시 하단 모드 자동 실행

가장 중요한 요구사항입니다.

사용자가 첫 화면에서 QR을 스캔하거나 주소·토큰을 입력하면 기존 QR 조회 흐름으로 중앙 프로필을 받아옵니다.

이후 SDK가 해당 프로필을 검증·적용할 때 다음 동작이 자동 실행돼야 합니다.

| QR 설정 | 키오스크 동작 |
|---|---|
| `viewportMode: null` | 하단 모드 해제, 일반 화면 사용 |
| 60% | 화면 아래쪽 60% 영역 사용 |
| 70% | 화면 아래쪽 70% 영역 사용 |
| 80% | 화면 아래쪽 80% 영역 사용 |

반드시 기존 방법 B인 `setViewportMode()` 또는 동일한 내부 공통 레이아웃 경로를 사용하세요.

**화면 전체를 CSS transform으로 축소하거나 글씨·버튼 크기를 줄이는 방식은 금지합니다.**

QR을 적용한 뒤 사용자가 개발용 버튼을 누르지 않아도 해당 비율이 화면에 반영되어야 합니다.

## 5. 첫 화면 QR 도크와 결합

현재 SDK v0.5.2에는 첫 화면 전용 QR 하단 도크가 있습니다.

이 도크와 v3 하단 조작 설정을 다음과 같이 결합해 주세요.

### 첫 화면

- QR 미적용 시 기존 기본 화면 표시
- QR 도크는 화면 하단에 유지
- v3 QR을 적용하면 선택 비율 자동 적용
- QR 도크는 적용 이후에도 남아 있음
- 하단 조작 비율은 QR 도크 및 등록된 고정 필수 조작부를 제외한 영역 기준
- 콘텐츠는 해당 하단 영역에서 스크롤
- 글씨와 버튼 크기 유지

### 주문 화면

- 주문 시작 시 QR 도크는 사라짐
- 적용된 viewportMode는 유지
- QR 도크가 없어진 만큼 화면 높이를 다시 계산
- 메뉴·옵션·장바구니·결제에서 같은 하단 조작 비율 유지
- 주문 중 새 QR을 불러오는 일반 사용자 경로 없음

### 처음 화면 복귀

- 기존 주문 데이터 초기화
- SDK `endSession()` 호출
- 기존 접근성 설정 및 viewportMode 해제
- 일반 화면 복원
- QR 도크 재표시
- 다음 이용자의 QR을 새로 적용 가능

QR 도크의 표시 상태와 접근성 프로필의 적용 상태는 독립적으로 관리합니다.

## 6. 프로필 재적용·교체

첫 화면에서는 같은 QR을 다시 적용하거나 다른 QR로 변경할 수 있습니다.

다음 전환을 검증해 주세요.

- null → 60%
- 60% → 70%
- 70% → 80%
- 80% → null
- 60% → 80%
- 80% → 60%
- 동일한 70% 반복 적용
- v2 QR 적용 후 v3 QR 적용
- v3 QR 적용 후 v1/v2 QR 적용
- QR 적용 실패 또는 모달 취소

확인 사항:

- 이전 viewportMode가 정확히 해제되거나 교체됨
- 70%를 여러 번 적용해도 높이가 누적해서 줄어들지 않음
- 기존 글씨·버튼 확대가 중복 적용되지 않음
- 스크롤 소유 영역이 불필요하게 중복 생성되지 않음
- QR 도크가 중복 생성되지 않음
- 실패·취소 시 이미 성공적으로 적용된 프로필을 임의로 초기화하지 않음
- 이전 사용자 설정이 새로운 세션에 남지 않음

## 7. QR 조회와 SDK 적용의 책임 분리

서버 조회와 키오스크 화면 변경의 책임을 명확하게 유지해 주세요.

권장 구조:

1. 호스트가 QR 스캔 또는 직접 입력을 받음
2. 호스트가 기존 중앙 조회 API를 호출
3. 응답을 SDK 프로필 검증기에 전달
4. SDK가 v3 프로필을 검증·정규화
5. SDK가 글씨·버튼·고대비·길잡이 등 기존 설정 적용
6. SDK가 viewportMode를 방법 B 레이아웃에 적용
7. 호스트는 성공·실패 UI와 업무 흐름 관리

SDK가 중앙 서버 URL이나 카페 화면 이름을 하드코딩하지 않도록 해 주세요.

호스트가 `setViewportMode()`를 별도로 호출하지 않아도 정상적인 QR 적용 경로를 통해 작동하는 것이 목표입니다.

기존 호스트 아키텍처상 완전히 SDK 내부에서 처리할 수 없는 경우에는 공개 SDK API의 최소 변경으로 해결하고, 필요한 호스트 연결을 문서화해 주세요.

## 8. 기존 개발용 하단 모드 테스트 기능

데모커피의 기존 개발용 viewport 테스트 기능은 유지하되, 실제 QR 적용과 충돌하지 않도록 해 주세요.

- 테스트 기능은 개발 환경에서만 제공
- 일반 사용자 화면에 노출하지 않음
- 개발용 비율 선택과 QR 프로필 비율의 우선순위를 명확히 정의
- QR 적용 상태에서는 QR 프로필의 비율이 우선
- 세션 종료 후 개발용 테스트 상태가 의도치 않게 남지 않음
- 기존 v0.5.2의 방법 B 회귀 테스트 유지

개발용 테스트 파라미터가 중앙 프로필 값을 덮어쓰는 상황은 피해야 합니다.

## 9. 스크롤 안내·스마트 길잡이 회귀

v0.5.2에서 수정한 다음 기능을 유지해 주세요.

- 기본 화면 `no-safe-space` 해결
- QR 도크 및 고정 하단 버튼 위에 스크롤 안내 배치
- 일반 콘텐츠와의 제한적 겹침 허용
- 안내는 pointer-events: none
- 최하단에서 안내 숨김
- 위로 스크롤하면 재표시
- 스마트 길잡이가 나타나면 안내 숨김
- 모달이 열리면 스크롤 안내가 조작을 방해하지 않음

특히 QR 적용과 동시에 화면 높이가 변경될 때 안내가 이전 위치에 남거나, 이전 viewport 크기를 기준으로 표시되지 않도록 확인해 주세요.

스크롤이 갑자기 튀거나 내부·문서 이중 스크롤이 발생해서도 안 됩니다.

소비자는 데모커피 소스 경로가 아닌 설치된 SDK의 공개 API와 CSS만 사용해야 합니다.

- 문서 스크롤형 키오스크
- 내부 스크롤형 키오스크
- 고정 하단 조작부가 있는 키오스크
- 첫 화면 QR 도크가 있는 키오스크
- QR 도크와 고정 조작부가 모두 있는 키오스크

**테스트 코드에서 `setViewportMode()`를 직접 호출해 성공한 것만으로 v3 자동 적용 테스트를 통과 처리하면 안 됩니다.**

반드시 QR 프로필 적용 경로로 검증해 주세요.
