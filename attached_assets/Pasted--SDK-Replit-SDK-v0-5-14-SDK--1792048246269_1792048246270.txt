# 데모커피 공통 SDK — 안내창이 메뉴 담기 버튼을 가리는 문제 수정

현재 프로젝트는 데모커피 Replit입니다.

설치된 공통 SDK 버전은 v0.5.14이며, SDK 원본은 `packages/kiosk-accessibility-sdk/`에 있습니다.

Development 전용 접근성 체험 기능을 추가한 뒤 실제 브라우저에서 다음 오류가 발견됐습니다.

## 1. 실제 재현된 문제

환경:

- 화면 크기: 320×844
- 하단 조작: 60%
- 글씨: 매우 크게
- 버튼: 크게
- 고대비: 켜기
- 쉬운 말: 켜기
- 스마트 길잡이: 켜기
- 길잡이 표시 전 대기: 10초
- 길잡이 표시 후 유지: 15초

오류:

메뉴 담기 버튼 `#item-add`와 SDK 안내창이 겹칩니다.

브라우저 측정값:

- 메뉴 담기 버튼: x=12~293, y=704.5~771.2
- SDK 안내창: x=12~308, y=731.3~847.6
- 메뉴 담기 버튼 중앙을 hit-test하면 `aside.a11y-guide-toast`가 반환됩니다.

안내창이 닫힌 이후에도 쉬운 말 패널이 조작을 가리는 경우가 있습니다.

이는 실제 주문 진행을 막는 문제입니다.

## 2. 원인부터 확인

다음 사항을 먼저 분석하세요.

- 데모커피에서 `#item-add`가 SDK의 주요 동작 또는 회피 영역에 정확히 등록돼 있는지
- 버튼의 실제 DOM 위치가 옵션 선택이나 반응형 레이아웃 변화 후 갱신되는지
- 쉬운 말 패널과 스마트 길잡이가 동일한 배치 검사 로직을 사용하는지
- 안내창의 초기 배치, 재계산 시점, 단계 변경 시점
- 고정 버튼과 스크롤 영역이 중복 계산되거나 누락되는지
- 안내창을 접은 상태에서도 버튼을 가리는지
- SDK의 hit-test 및 충돌 검사 로직이 실제 포인터 차단을 탐지하는지

문제 원인을 먼저 보고한 뒤 수정하세요.

## 3. 수정 원칙

**카페 전용 CSS나 안내창 위치 하드코딩으로 해결하지 마세요.**

가능한 원인별 처리:

A. 버튼이 SDK에 등록되지 않았다면:
- 기존 공개 어댑터의 정상적인 사용으로 실제 주요 동작 영역을 등록하세요.
- 특정 버튼을 위한 SDK 내부 예외는 만들지 마세요.

B. 이미 등록됐는데도 겹친다면:
- 공통 SDK의 범용 충돌 검사 및 배치 로직을 수정하세요.
- 다른 호스트의 버튼과 키패드에도 동일하게 적용될 수 있어야 합니다.

C. 안전한 펼친 배치가 불가능하다면:
- 먼저 접힌 안내창을 시도하세요.
- 접힌 안내창도 버튼을 가리면 안전한 다른 위치를 탐색하세요.
- 업무 조작을 방해하지 않는 배치가 없다면 안내창을 숨겨도 되지만, 그 이유와 조건을 기록하세요.
- 중요한 주문 버튼의 조작 가능성을 최우선으로 보장하세요.

`pointer-events: none` 등을 전체 안내창에 적용해 접기·펼치기 버튼까지 조작할 수 없게 만드는 방식은 피하세요.

## 4. 반드시 확인할 기능

수정 후 다음 상황에서도 버튼이 실제로 클릭되어야 합니다.

- 쉬운 말 안내만 표시
- 스마트 길잡이만 표시
- 쉬운 말 + 스마트 길잡이
- 길잡이 표시 전
- 길잡이 표시 중
- 길잡이 종료 후 쉬운 말로 복귀
- 안내창 접힌 상태
- 안내창 펼친 상태

충돌을 피하기 위해 기존 글씨 크기와 버튼 크기를 임의로 줄이지 마세요.

## 5. 브라우저 회귀 테스트

다음 화면 크기를 검증하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

하단 조작 비율:

- 60%
- 70%
- 80%

각 조합에서 다음 버튼을 확인하세요.

- 메뉴 선택
- 메뉴 담기
- 옵션 선택
- 장바구니
- 결제
- 영수증 선택
- 뒤로 가기
- 체험 종료

단순 DOM 존재 여부가 아니라, 실제 클릭 좌표에서 클릭 가능한지 확인하세요.

## 6. 전체 주문 흐름 검증

개발 전용 접근성 체험 버튼으로 고정 v4 프로필을 적용한 뒤 다음 흐름을 실제 브라우저에서 수행하세요.

1. 접근성 체험하기
2. 메뉴 선택
3. 옵션 선택
4. 메뉴 담기
5. 장바구니 확인
6. 결제
7. 영수증 선택
8. 주문 완료
9. 15초 자동 복귀
10. 모든 접근성 설정 초기화

쉬운 말·스마트 길잡이의 접기·펼치기, 이전·다음, 15초 카운트다운이 계속 작동해야 합니다.

## 7. 다른 키오스크를 고려한 독립 SDK 검증

데모커피에만 맞춰 수정하지 않도록 독립 소비자 fixture에서도 다음을 확인하세요.

- 숫자 키패드가 있는 화면
- 하단 고정 확인 버튼이 있는 화면
- 여러 개의 주요 동작 버튼
- 버튼 위치가 동적으로 바뀌는 화면
- 좁은 화면과 스크롤
- 안내 패널 접기·펼치기

무인민원발급기에서 기존에 성공했던 하단 60/70/80% 배치가 깨지지 않도록 회귀 테스트를 추가하세요.

## 8. SDK 버전 및 패키지

SDK 공통 코드 수정이 필요한 경우, 현재 v0.5.14를 보존하고 **v0.5.15**로 올려 새 tarball을 생성하세요.

예상 경로:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.15.tgz`

SDK 수정 없이 호스트의 기존 공개 API 연결만 바로잡았다면 불필요하게 SDK 버전을 올리지 마세요.

기존 SDK tarball을 덮어쓰지 마세요.
