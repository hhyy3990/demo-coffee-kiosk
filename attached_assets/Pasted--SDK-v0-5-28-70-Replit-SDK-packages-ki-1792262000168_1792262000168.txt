# 데모커피 공통 SDK v0.5.28 — 하단 70% 안내창 개선 및 최종 검증

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 경로:
`packages/kiosk-accessibility-sdk/`

직전 작업에서 다음 두 문제를 수정했지만, 일부 검증이 끝나지 않아 tarball을 갱신하지 않았습니다.

1. 쉬운 말 안내가 짧은 구절·단어 단위로 과도하게 분할되는 문제
2. 기본 모드에서 스크롤 안내가 하단 고정 버튼과 겹치는 문제

현재 수정된 SDK 소스는 유지하세요.

**이번 작업에서는 사용자가 추가로 승인한 하단 70% 모드의 페이지 조작부 개선과 미완료 검증만 진행합니다.**

새 기능, 다른 디자인 변경, 호스트 업무 로직 수정은 금지합니다.

## 1. 하단 70% 모드의 문제

실제 무인민원발급기 안내 원문:

stepId: `certificate.type-selection`

첫 번째 설명:
- 제목: 주민등록표 등본
- 본문: 주민등록표 등본은 한 세대의 구성과 주소 정보를 확인하는 주민등록 서류입니다.

두 번째 설명:
- 제목: 주민등록표 초본
- 본문: 초본 발급은 아직 준비 중입니다. 이 데모에서는 등본만 진행할 수 있습니다.

360×667 화면에서 현재 SDK 소비자 fixture 측정 결과:

- 하단 60%: 2페이지
- 하단 70%: **6페이지**
- 하단 80%: 4페이지

원인은 70% 모드에서 이전·다음 버튼과 페이지 표시가 본문 아래에 별도 줄로 배치되면서 약 44px의 세로 공간을 추가로 차지하는 것입니다.

80% 모드에서는 좁은 안내창 배치가 적용되어 페이지 조작부가 헤더로 이동하고, 그 덕분에 오히려 본문 공간이 더 넓습니다.

**70%에서도 80%처럼 페이지 조작부를 상단에 배치하여 공간을 효율적으로 사용하도록 수정하세요.**

## 2. 허용된 수정 범위

360×667 하단 70%에서 다음을 개선하세요.

- 이전 버튼
- 다음 버튼
- 현재 페이지 / 전체 페이지 표시
- 접기·펼치기 버튼

가능하면 이 조작부를 제목과 함께 상단 영역에 효율적으로 배치하세요.

기존 80% 모드에서 검증한 배치 구조를 우선 재사용하세요.

반드시 유지할 조건:

- 제목·페이지 번호·버튼이 서로 겹치지 않음
- 본문 원문 누락·중복 없음
- 이전·다음·접기 버튼 정상 작동
- 가능하면 기존 44×44px 터치 영역 유지
- 기존 글씨 크기와 버튼 크기 우선 유지
- 필요한 경우에만 안내 패널 내부 여백·글자 간격을 소폭 축소
- 패널 상단 Y=8px 고정
- 하단 70% 업무 영역의 크기 유지
- 글자·본문 잘림 없음
- 페이지 이동 중 패널 위치 점프 없음

**사용자가 승인한 것은 좁은 화면의 조작부 배치 개선입니다.**

쉬운 말 문구를 임의로 축약하거나 바꾸지 마세요.

새로운 버튼이나 별도의 조작 기능을 추가하지 마세요.

## 3. 페이지 수 검증

같은 원문, 같은 설정에서 다음 모드를 비교하세요.

화면: 360×667

설정:
- textSize: extraLarge
- buttonSize: large
- contrast: high
- easyLanguage: true

하단 모드:
- 명시적 60%
- 명시적 70%
- 명시적 80%
- viewportMode:null + 쉬운 말 활성화 → 자동 80%

기존 결과:
- 60%: 2페이지
- 70%: 6페이지
- 80%: 4페이지

목표:
- 70%의 불필요한 별도 페이지 조작부 줄 제거
- 70%에서 6페이지 과분할 개선
- 가능하면 70%가 80%보다 더 많은 페이지를 요구하지 않도록 배치 최적화
- 한 단어·한 글자씩 반복 분할되는 현상 방지
- 원문 전부 보존
- 각 페이지의 실제 본문 표시 높이 검증

특정 페이지 수를 만들기 위해 텍스트를 숨기거나 클리핑하지 마세요.

## 4. 다른 화면 크기 회귀

다음 크기에서도 기존 정상 배치를 유지하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

특히 자동 80%의 기존 결과는 다음과 같습니다.

- 320×844: 4페이지
- 360×667: 4페이지
- 390×844: 2페이지
- 1080×1920: 2페이지

페이지 수가 바뀌더라도 원문 보존과 가독성이 개선된 결과인지 실제 DOM으로 확인하세요.

제목이 긴 경우에도 조작부가 겹치거나 다음 줄로 비정상적으로 밀리지 않아야 합니다.

접기·펼치기 후 페이지 번호가 불필요하게 재계산되거나, 이전·다음 이동 중 전체 페이지 수가 계속 바뀌는 현상도 검증하세요.

## 5. 기본 모드 스크롤 안내 위치 검증

직전 작업에서 SDK의 스크롤 안내가 등록된 `bottomControls`를 고려하도록 수정했습니다.

무인민원발급기 유사 fixture의 390×844 측정 결과:

- 기본 모드: footer 위 12px
- 하단 80%: footer 위 약 13px
- footer와 교차 없음

이번 70% 안내창 수정이 스크롤 안내 배치에 영향을 주지 않는지 확인하세요.

추가로 명시적 하단 70%에서도 안내가 하단 고정 버튼과 겹치지 않아야 합니다.

필수 유지 사항:

- 실제 스크롤 owner 기준 배치
- 하단 조작부 위 약 12px
- 스크롤 중 위치 점프 없음
- 스크롤 끝에서 숨김
- pointer-events:none
- 데모커피 주문 확인 바 위쪽 배치 유지

스크롤 안내 위치 계산을 추가로 변경하지 마세요. 실제 회귀가 발견되면 재현 결과를 보고하고 사용자 승인을 기다리세요.

## 6. Smart Guide 브라우저 검증 완료

이전 브라우저 테스트가 `guideDelaySeconds: 0`이라는 유효하지 않은 설정 때문에 중단됐습니다.

**실제 SDK 타이머를 변경하지 말고 테스트 fixture의 잘못된 설정만 수정하세요.**

허용된 등장 전 지연값은 10·15·20초입니다.

실제 무인민원발급기 결제 안내 원문:

stepId: `certificate.payment-method`

증명서 종류, 발급 부수, 표시 항목과 수수료를 확인해 주세요. 내용이 맞으면 결제 방법을 눌러 가상 결제를 진행하세요.

360×667, 매우 큰 글씨·큰 버튼·고대비·하단 80% 조건에서 검증하세요.

- 최대 2페이지로 표시
- 원문 누락·중복 없음
- 본문 잘림 없음
- 2페이지 일반 안내 총 15초
- 약 7.5초 후 자동 전환
- 1페이지 일반 안내 총 10초
- 느린 안내 총 20초
- 2페이지 느린 안내는 약 10초 후 전환
- 등장 전 지연값 유지
- Smart Guide 종료 후 기존 쉬운 말 페이지와 접힘 상태 복원
- 패널 상단 약 8px 유지
- 무한 재귀 없음

이번에는 테스트 코드가 잘못된 지연값을 사용해 검증을 중단하지 않도록 해 주세요.
