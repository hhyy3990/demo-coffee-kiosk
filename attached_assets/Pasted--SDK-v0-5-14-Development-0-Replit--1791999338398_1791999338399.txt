# 공통 SDK v0.5.14 — Development 전용 접근성 체험하기 버튼

## 0. 작업 대상 및 목적

현재 작업 중인 Replit 프로젝트에 **'접근성 체험하기'** 기능을 추가해 주세요.

이 요청은 **데모커피 키오스크와 무인민원발급기 각각에 동일하게 적용할 공통 요구사항**입니다.

두 프로젝트 모두 `@naebangsik/kiosk-accessibility-sdk@0.5.14`를 사용합니다.

이번 작업의 목표는 중앙 '내 방식 QR' v4를 Publish하지 않은 상태에서도 사용자가 직접 새로운 공통 안내창과 접근성 기능을 체험하도록 하는 것입니다.

**복잡한 설정 선택 화면을 만들지 마세요. 미리 정해진 하나의 테스트 프로필을 버튼 한 번으로 적용하면 됩니다.**

이번 기능은 Development Preview에서만 사용합니다.

## 1. 첫 화면에 접근성 체험하기 버튼 추가

키오스크 첫 화면에서 사용자가 쉽게 발견할 수 있는 위치에 다음 버튼을 추가하세요.

**접근성 체험하기**

버튼 아래에는 작은 설명을 표시해도 됩니다.

"QR 없이 큰 글씨와 쉬운 안내를 체험해 보세요."

요구사항:

- 기존 QR 스캔 버튼 유지
- 기존 업무 시작 버튼 유지
- 첫 화면 디자인을 크게 변경하지 않기
- 모바일에서도 버튼이 잘 보이도록 배치
- 기존 업무 버튼과 겹치지 않기
- Development에서만 표시
- Production에서는 표시되지 않도록 처리

## 2. 고정 QR v4 체험 프로필

사용자가 '접근성 체험하기'를 누르면 다음 프로필을 적용하세요.

```json
{
  "schemaVersion": 4,
  "preferences": {
    "textSize": "extraLarge",
    "buttonSize": "large",
    "contrast": "high",
    "easyLanguage": true,
    "viewportMode": {
      "mode": "bottom",
      "heightPercent": 60
    },
    "smartGuide": true,
    "guideDelaySeconds": 10,
    "voiceGuidance": false,
    "language": "ko",
    "stepByStepGuidance": false,
    "conciseGuidance": false,
    "slowGuidance": true
  }
}
```

실제 SDK 적용 API가 preferences 객체만 받는 등 구조가 다르다면 **설치된 SDK의 공개 타입 정의에 맞춰 변환**하세요.

이 설정은 실제 QR v4에 저장 가능한 접근성 선호를 나타내는 테스트 데이터입니다.

QR 생성, 중앙 API 요청, DB 저장은 하지 마세요.

## 3. 반드시 실제 SDK로 적용

**체험용 별도 CSS로 큰 글씨·버튼·고대비·하단 조작을 흉내 내지 마세요.**

반드시 기존 QR 스캔 성공 시 사용하는 SDK 프로필 적용 경로를 재사용해야 합니다.

현재 호스트에서 사용하는 공개 SDK API를 확인하여 적용하세요.

- 글씨 크기 매우 크게
- 버튼 크게
- 고대비
- 쉬운 말 안내
- 스마트 길잡이
- 하단 조작 60%
- 천천히 안내받기 15초

모두 실제 SDK를 통해 동작해야 합니다.

SDK 내부 코드 직접 수정은 금지합니다.

## 4. 체험 시작 후 업무 진행

체험 설정 적용 후에는 기존 키오스크 업무를 정상적으로 이용할 수 있어야 합니다.

### 데모커피

- 메뉴 선택
- 옵션 선택
- 장바구니
- 결제
- 영수증 선택
- 완료 후 처음 화면 복귀

### 무인민원발급기

- 증명서 선택
- 숫자 키패드 입력
- 발급 옵션 선택
- 발급 부수 선택
- 결제 시뮬레이션
- 발급 완료 후 처음 화면 복귀

체험 때문에 기존 주문·발급 로직을 변경하지 마세요.

호스트별 업무 단계 ID와 안내 문구는 기존 구현을 그대로 활용하세요.

## 5. 쉬운 말·스마트 길잡이 통합 안내창

체험 중 SDK의 v0.5.14 공통 안내창이 실제로 작동해야 합니다.

확인할 동작:

1. 쉬운 말 설명 표시
2. 여러 설명이 있으면 이전·다음 버튼 표시
3. 접기·펼치기 가능
4. 화면 진입 약 10초 후 스마트 길잡이 시작
5. 같은 안내창의 내용이 스마트 길잡이로 전환
6. 숫자 카운트다운 15초부터 감소
7. 15초 뒤 쉬운 말 설명으로 복귀
8. 이전 설명 페이지 및 접힘 상태 보존

특히 사용자가 접어둔 안내창을 스마트 길잡이가 강제로 펼치지 않도록 하세요.

`guideDelaySeconds: 10`은 표시 전 대기시간이고, `slowGuidance: true`는 표시 후 유지시간 15초입니다.

## 6. 하단 조작 60% 확인

이번 체험의 중요한 목적은 하단 조작 모드에서 안내창이 업무 버튼을 가리지 않는지 확인하는 것입니다.

다음 항목을 검증하세요.

- 키패드
- 입력한 숫자·수량 표시
- 메뉴 선택 버튼
- 확인·다음 버튼
- 장바구니·결제 버튼
- 뒤로 가기
- 스크롤
- QR 도크

화면 위쪽의 빈 공간을 SDK 안내창이 사용할 수 있다면 기존 범용 배치 로직에 따라 사용하세요.

호스트에 안내창 전용 CSS를 추가하거나 특정 화면에서 위치를 강제하지 마세요.

SDK 자체의 배치 문제가 발견되면 재현 조건을 보고하고, 데모커피 SDK 원본에서 수정할 수 있도록 남겨 주세요.

## 7. 체험 종료와 초기화

체험 중 사용자가 누를 수 있는 **체험 종료** 버튼을 제공하세요.

체험 종료 시:

1. 기존 업무 진행 상태 정리
2. SDK `endSession()` 호출
3. 글씨·버튼·고대비·하단 조작 초기화
4. 쉬운 말·스마트 길잡이 초기화
5. 기존 타이머 취소
6. 키오스크 처음 화면 복귀

기존 완료 화면의 15초 자동 복귀도 그대로 유지합니다.

체험 모드에서 완료 후 처음 화면으로 자동 복귀할 때도 접근성 설정이 정상 초기화되어야 합니다.

테스트용 버튼이 실제 QR 세션이나 다른 사용자의 상태를 손상시키지 않도록 하세요.

## 8. 체험 모드 표시

개발 전용 체험이 활성화된 동안 사용자에게 다음과 같이 간단히 표시하세요.

**접근성 체험 중**

이 표시가 스마트 길잡이, 쉬운 말 안내, 주요 업무 버튼을 가리지 않도록 하세요.

필요하다면 체험 종료 버튼과 한 줄로 배치할 수 있습니다.

다만 실제 SDK의 QR 도크나 안내창을 가리지 않는 것이 우선입니다.

## 9. Production 노출 방지

이번 기능은 개발 환경에서만 작동해야 합니다.

- Development Preview에서만 버튼 표시
- Production에서는 체험 기능 비활성화
- Production 빌드에서 개발용 버튼·프로필 적용 경로가 활성화되지 않도록 확인
- 개발용 URL 파라미터로 Production 체험 모드를 활성화할 수 없도록 방지
- 기존 QR 스캔 및 운영 업무에 영향 없도록 구현

Publish는 하지 마세요.
