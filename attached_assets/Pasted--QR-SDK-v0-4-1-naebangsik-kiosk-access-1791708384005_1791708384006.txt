# 내 방식 QR — 공통 SDK v0.4.1 안정화: 스크롤 안내 표시 정책 및 모달 스크롤 점프 수정

현재 데모커피 프로젝트에서 `@naebangsik/kiosk-accessibility-sdk@0.4.0`을 개발·관리하고 있습니다.

SDK v0.4.0에는 글씨·버튼 크기를 유지하면서 화면을 아래쪽 60%·70%·80% 영역에 배치하는 방법 B 하단 조작 모드가 구현되어 있습니다.

이를 독립 무인민원발급기에 설치해 검증한 결과, 다음 문제가 발견됐습니다.

**문제 1 — 스크롤 안내가 처음부터 나타나지 않음**

무인민원발급기에서는 스크롤이 필요한 메뉴 화면인데도 맨 위에서 스크롤 안내가 숨겨집니다.

중간까지 스크롤하면 나타났다가 최하단에서는 사라집니다.

조사 결과 SDK 내부의 안내 배치 로직이 `menuItems`, `getActions()`로 등록된 일반 메뉴 버튼까지 겹침 회피 대상으로 판단하는 것이 주요 원인으로 확인됐습니다.

**문제 2 — 발급 불가 안내 모달을 열면 스크롤 위치가 변경됨**

무인민원발급기에서 메뉴를 아래로 스크롤한 뒤 발급 불가 항목을 눌러 안내 모달을 열면, 예를 들어 `.stage.scrollTop`이 724px에서 549px 또는 389px로 변경됩니다.

모달을 닫은 후에도 변경된 스크롤 위치가 유지됩니다.

QR 설정 모달에서는 같은 현상이 재현되지 않았으므로 모달 종류에 따른 차이까지 조사해야 합니다.

이번 작업은 **공통 SDK의 두 문제를 수정하는 안정화 버전 v0.4.1 개발**입니다.

데모커피의 주문 로직, 중앙 QR 서비스, 무인민원발급기 프로젝트는 수정하지 마세요.

## 1. 스크롤 안내의 회피 정책 변경 — 우선 작업

현재 SDK의 스크롤 안내 배치 로직을 확인해 주세요.

특히 다음 정보를 구분해 주세요.

- `menuItems`
- `getActions()`
- `guidanceAvoidAreas`
- 고정 하단 조작부
- 일반 스크롤 콘텐츠
- SDK 스마트 길잡이
- 모달 및 기타 오버레이

### 변경할 핵심 원칙

**일반 스크롤 콘텐츠와 안내 pill이 일부 겹치는 것은 허용합니다.**

다음 요소는 자동으로 절대 회피 대상으로 취급하지 마세요.

- 일반 메뉴 타일
- 상품 카드
- 스크롤되는 선택 버튼
- 스크롤되는 일반 업무 버튼
- `menuItems`에 등록된 항목
- `getActions()`에서 반환된 모든 버튼

`getActions()`로 등록됐다는 사실만으로 해당 버튼이 고정된 필수 조작부라고 판단하면 안 됩니다.

다만 **고정된 필수 조작부는 계속 보호**해야 합니다.

- 처음화면
- 전화면
- 확인
- 결제
- 취소
- 기타 고정된 주요 조작 버튼

이 버튼들이 실제로 화면에 고정돼 있는지와 어댑터에서 어떤 역할로 등록됐는지를 활용해 판단해 주세요.

`guidanceAvoidAreas`에는 호스트가 명시적으로 회피 대상으로 등록한 요소가 있으므로 그 의미를 존중하되, 일반 스크롤 콘텐츠 전체를 금지 영역으로 확대 해석하지 마세요.

### 합격 기준

스크롤할 내용이 남아 있다면 다음처럼 작동해야 합니다.

- 맨 위: 안내 표시
- 중간: 안내 유지
- 최하단: 안내 숨김
- 다시 위로 이동: 안내 재표시

**안내가 일반 메뉴 타일 위에 표시된다는 이유만으로 숨기면 안 됩니다.**

일반 메뉴를 일부 가리더라도 사용자가 스크롤하면 해당 메뉴 전체를 확인할 수 있어야 합니다.

## 2. 안내 pill과 필수 조작부 보호

현재 짧은 안내 문구 두 개를 그대로 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

### 배치 조건

- 작은 pill 오버레이 방식 유지
- 별도의 120px 안내 슬롯 생성 금지
- 안내 때문에 스크롤 영역의 높이 변경 금지
- 안내 표시·숨김 때문에 스크롤 위치 변경 금지
- 일반 콘텐츠와 제한적인 시각적 중첩 허용
- 고정 하단 필수 버튼과 중첩 금지
- 스마트 길잡이와 동시 표시 금지
- 모달이 열린 상태에서는 필요한 경우 숨김
- 큰 글씨·큰 버튼·고대비에서도 안내 잘림 금지
- 좁은 화면에서 자연스러운 줄바꿈 허용
- pointer-events: none 유지

일반 메뉴의 버튼 중앙이 안내 pill과 시각적으로 겹치더라도, 해당 버튼을 스크롤해서 안내가 없는 위치에 완전히 노출할 수 있는지 확인해 주세요.

**만약 안내 때문에 특정 메뉴를 끝까지 확인할 수 없다면 성공이 아닙니다.**

SDK의 기존 스크롤 종료 판정과 3초 안정화 로직을 유지해 주세요.

## 4. 모달 스크롤 점프 문제 재현

무인민원발급기에서 관찰된 다음 현상을 SDK 독립 테스트 환경에서 재현해 주세요.

- 하단 조작 모드 적용
- 긴 메뉴를 아래로 스크롤
- 메뉴 버튼 클릭
- 안내 모달 등장
- 배경 스크롤 위치가 갑자기 위로 이동
- 모달을 닫아도 이동한 위치가 유지됨

모달 종류에 따라 결과가 다를 수 있으므로 다음 두 구조를 각각 테스트합니다.

**A. QR 설정 모달**

- 독립 overlay
- 내부 스크롤
- 닫기 및 제출 버튼
- 배경 스크롤 잠금 또는 이벤트 차단

**B. 일반 안내 모달**

- 메뉴 클릭 시 열림
- 배경 위에 표시되는 안내 대화상자
- 확인·닫기 버튼
- 포커스 및 overlay 등록

실제 무인민원발급기 DOM 구조를 가능한 범위에서 모사하되, SDK가 카페나 민원발급기 전용 CSS 선택자에 의존하지 않도록 독립 fixture를 구성해 주세요.

## 5. 원인 계측

모달을 여닫는 과정에서 다음 값을 기록합니다.

- 실제 스크롤 소유 요소
- scrollTop
- scrollHeight
- clientHeight
- 최대 스크롤 거리
- 클릭 직전 좌표
- 모달 DOM 삽입 직후 좌표
- overlay 등록 직후 좌표
- SDK viewport 배치 갱신 직후 좌표
- 100ms·500ms·1초 뒤 좌표
- 모달 닫은 직후 및 1초 뒤 좌표
- document.activeElement
- 포커스 이벤트
- scroll anchoring 영향
- position: fixed / sticky 변화
- overflow 및 scroll-padding 변화
- SDK 관찰기 호출 횟수
- 안내 pill·스마트 길잡이 갱신 횟수

다음 원인을 구분합니다.

1. 브라우저 포커스 이동
2. 스크롤 앵커링
3. 모달의 DOM 삽입에 따른 레이아웃 변화
4. SDK viewport overlay 재배치
5. SDK의 스크롤 영역 재계산
6. 호스트가 발생시키는 화면 전환 또는 리렌더링

**모달을 연다는 이유만으로 scrollTop을 반복해서 강제로 되돌리는 임시 코드를 추가하지 마세요.**

## 6. 모달 스크롤 점프 수정 원칙

정확한 원인이 밝혀지면 공통 SDK 안에서 최소한으로 수정해 주세요.

목표 동작:

- 모달 열기 전 배경 스크롤 위치 유지
- 모달 표시 중 배경 화면이 임의로 움직이지 않음
- 모달 내부에 스크롤이 있다면 내부만 정상 스크롤
- 모달 닫은 후 이전 배경 위치 유지
- 모달 닫은 뒤 정상 스크롤 재개
- SDK 안내·스마트 길잡이 위치 계산 정상 유지
- 모달 내 버튼과 닫기 버튼 실제 클릭 가능

모달에 포커스가 필요한 경우에는 접근성을 해치지 않도록 적절한 포커스 이동을 유지해야 합니다.

**포커스 자체를 없애거나 키보드 접근성을 포기해서 스크롤 문제를 해결하지 마세요.**

SDK 외부의 호스트 코드가 직접적인 원인으로 밝혀진 경우에는 SDK가 이를 억지로 감추지 말고, 필요한 호스트 수정 사항을 보고해 주세요.

독립 fixture에서 재현되지 않으면 무인민원발급기에서 정확한 원인을 확인하기 위한 추가 계측 지침을 제안하고, 해결됐다고 주장하지 마세요.

## 8. 독립 소비자 테스트

SDK를 데모커피에서 직접 import하는 것 외에도 독립 소비자 프로젝트를 준비해 테스트해 주세요.

테스트 구조:

- 일반 문서 스크롤
- 내부 스크롤
- 하단 고정 버튼
- 스크롤되는 메뉴 버튼
- QR 모달
- 일반 안내 모달
- 긴 키패드
- 스마트 길잡이

각 구조에서 스크롤 안내의 표시와 모달 스크롤 위치를 확인합니다.

특히 **메뉴가 화면을 꽉 채우는 독립 화면에서도 스크롤 안내가 맨 위부터 표시되어야 합니다.**

고정된 필수 버튼은 안내에 가려지면 안 됩니다.

## 9. 데모커피 회귀 검증

일반 화면과 하단 60%·70%·80%에서 다음을 확인해 주세요.

- 첫 화면
- 주문 방식 선택
- 카테고리 좌우 이동
- 메뉴 선택
- 상품 옵션
- 장바구니
- 주문 확인
- 결제
- 완료
- 처음화면 복귀
- 접근성 설정 초기화

QR 모달과 옵션 모달을 열고 닫아도 스크롤이 불필요하게 변하지 않아야 합니다.

하단 조작 모드 미사용 화면에서도 기존 기능이 바뀌면 안 됩니다.
