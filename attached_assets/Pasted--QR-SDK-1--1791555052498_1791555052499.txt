# 내 방식 QR — 범용 접근성 SDK 1차 구현

현재 '데모커피' 프로젝트에서 분석한 아키텍처를 바탕으로, 카페에 종속된 접근성 코드를 다른 키오스크에서도 재사용할 수 있는 공통 SDK로 분리해 주세요.

이번 작업은 AI 모델 연결이나 자동 레이아웃 수정이 아니라, 공통 SDK의 기초 구현입니다.

## 1. 개발 목표

향후 카페, 병원, 독립적인 제3의 웹 키오스크에서 동일한 QR 프로필과 공통 SDK를 사용할 수 있도록 합니다.

기존 중앙 서비스의 프로필 스키마와 API는 유지하고, 카페의 주문 업무 로직은 변경하지 않습니다.

## 2. 공통 SDK 생성

packages/kiosk-accessibility-sdk 아래에 재사용 가능한 TypeScript 모듈을 구현해 주세요.

다음 기능을 우선 분리합니다.

- 기존 QR 프로필 설정값의 타입 및 검증
- 글씨 크기, 버튼 크기, 고대비의 공통 CSS 토큰 적용
- 키오스크 루트 요소에 한정된 접근성 스타일
- 무조작 시간 감지 및 타이머 초기화
- 공통 스마트 길잡이 표시, 닫기, 버튼 강조
- 브라우저 음성 안내 기능
- 읽기 전용 DOM 레이아웃 오류 진단

SDK의 공개 API와 설정 스키마에 버전을 부여해 주세요.

## 3. 키오스크 어댑터 인터페이스

키오스크별 업무 로직을 SDK에 넣지 마세요.

호스트 키오스크는 다음 정보를 제공하도록 합니다.

- 현재 화면 및 진행 단계
- 현재 작업의 최소 상태
- 사용 가능한 행동의 의미 ID와 이름
- 실제 버튼 DOM 요소 또는 요소 참조
- 활성화된 버튼 여부
- 하단 조작 영역 및 스크롤 영역

SDK는 실제 버튼을 대신 클릭하거나 결제·주문 상태를 변경하지 않습니다.

카페의 장바구니, 옵션, 주문 관련 규칙은 cafeAdapter에서 처리하도록 분리합니다.

## 4. 레이아웃 진단 기능

큰 글씨 적용 후 다음 문제를 감지하는 읽기 전용 진단기를 만듭니다.

- 텍스트 잘림
- 가로 영역 넘침
- 버튼이 화면 밖으로 밀리는 현상
- 고정 하단 영역에 버튼이 가려지는 현상
- 비정상적으로 작은 터치 영역

각 문제는 화면 ID, 요소의 의미 ID, 문제 유형과 측정값을 포함한 진단 결과로 기록합니다.

이 단계에서는 AI 수정이나 자동 DOM 재배치를 구현하지 마세요. 오류 진단만 수행합니다.

QR 토큰이나 개인정보는 진단 로그에 포함하지 마세요.

## 5. 데모커피에 적용

현재 카페에서 구현한 접근성 공통 기능을 새 SDK를 사용하도록 이전합니다.

- 기존 QR 불러오기 기능 유지
- 카페 메뉴·옵션·장바구니·결제 코드 유지
- 현재 스마트 길잡이의 올바른 단계 판단 유지
- 기존 디자인 유지
- 접근성 프로필 적용 전후 UI 동작 유지
- 중복된 접근성 코드 제거

카페 고유 기능을 SDK 안으로 복사하지 마세요.

## 6. 필수 테스트

1. 기본 화면 주문 정상 작동
2. QR 프로필 적용 후 큰 글씨·큰 버튼 반영
3. 고대비 정상 적용
4. 스마트 길잡이 10·15·20초 설정 정상 반영
5. 장바구니에 상품이 있을 때 주문 확인 버튼 강조
6. 안내 닫기 및 타이머 초기화
7. SDK 적용 해제 후 기본 화면 복원
8. 모바일 320px, 390px 및 세로형 키오스크 화면 검사
9. 접근성 기능이 카페의 주문 상태를 변경하지 않는지 검사

가능하면 SDK를 카페 내부 파일 상대경로에 의존하지 않는 독립 모듈로 구성하고, 다른 프로젝트에서 설치하거나 가져오는 방법을 README로 문서화해 주세요.

## 7. 개발 제한

- 중앙 내 방식 QR 프로젝트는 수정하지 않습니다.
- OpenAI API는 아직 연결하지 않습니다.
- 카페 디자인과 메뉴 데이터를 변경하지 않습니다.
- 데이터베이스 스키마 변경 금지
- 기존 QR 기능과 서버 중계 유지
- Publish 금지
- 한 번에 대규모 변경이 어렵다면 단계별로 진행하고 각 단계에서 테스트

## 8. 완료 보고

- 공통 SDK가 외부 키오스크에서 사용 가능한 형태인지
- 실제 테스트 결과
- 다른 독립 웹 키오스크에 적용하기 위한 최소 연동 방법
