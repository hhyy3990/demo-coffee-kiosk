# 공통 SDK v0.5.28 — 쉬운 말 과분할 및 하단 스크롤 안내 위치 복구

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본:
`packages/kiosk-accessibility-sdk/`

이번 작업은 무인민원발급기에서 실제 사용자가 확인한 **두 가지 회귀 오류를 수정하는 작업**입니다.

1. 쉬운 말 안내가 단어 단위로 지나치게 쪼개지는 문제
2. 하단 스크롤 안내가 원래 위치보다 아래로 내려가 고정 버튼과 겹치는 문제

두 문제 모두 이전에 정상 작동했던 기능에서 발생한 회귀로 의심됩니다.

**새 기능 추가나 전체 디자인 변경 없이, 원인 확인 후 공통 SDK에서 최소 수정하세요.**

## 1. 실제 사용자 화면 — 쉬운 말 과분할

무인민원발급기의 주민등록표 종류 선택 화면에서 다음 현상이 발생했습니다.

- 화면 상단 쉬운 말 안내 제목: `주민등록표 등본`
- 페이지 표시: `1/21`
- 첫 페이지 본문: `주민등록표`
- 이후 문구가 띄어쓰기 단위로 쪼개져 페이지를 넘겨야 하는 현상
- 이전에 약 85자의 안내가 2~6페이지 정도로 표시되던 화면

한 글자씩 페이지가 넘어가던 과거 오류는 수정했지만, 이번에는 **한 단어씩 페이지가 넘어가는 형태로 비슷한 문제가 다시 나타났습니다.**

기존 자동화에서는 원문 보존과 잘림 없음이 통과됐지만 실제 사용자 화면에서는 사용하기 어려운 상태입니다.

따라서 **원문 보존만으로 성공이라고 판단하지 마세요.**

### 확인할 사항

1. 실제 쉬운 말 안내 데이터의 제목·본문·항목 개수
2. 현재 페이지 분할 알고리즘
3. 페이지별 본문 가용 높이
4. 매우 큰 글씨에서 line-height와 실제 줄 높이
5. 헤더, 이전·다음 버튼 및 페이지 번호가 차지하는 공간
6. 한 페이지에 단어 하나만 들어가는 이유
7. 페이지를 넘길 때 본문 높이와 전체 페이지 수가 재계산되는 현상
8. 최근 Smart Guide 헤더·공간 수정이 Easy Language에도 영향을 줬는지

가장 최근 SDK 수정 전후의 관련 코드를 비교해 회귀 원인을 추적하세요.

### 목표

쉬운 말 안내는 가능한 한 **의미 있는 문장 또는 설명 단위로 표시**되어야 합니다.

단어 하나나 글자 하나가 반복해서 별도 페이지가 되는 현상은 허용하지 않습니다.

다만 공간이 부족할 때 원문을 삭제하거나 잘린 상태로 표시해서는 안 됩니다.

문장 단위 분할이 물리적으로 불가능하면 실제 필요한 높이와 수정 가능한 영역을 측정해 보고하세요.

## 2. 실제 사용자 화면 — 스크롤 안내 위치 변경

무인민원발급기의 주민등록표 종류 선택 화면에서 아래 안내가 표시됩니다.

`↓ 아래에도 내용이 있어요`

사용자가 확인한 최신 화면에서는 이 안내가 화면 맨 아래로 내려가 **하단 고정 '처음으로' 버튼과 겹칩니다.**

이전 사용자 화면에서는 스크롤 안내가 하단 고정 조작부 위의 업무 화면 안쪽에 표시됐고, 크게 문제되지 않았습니다.

이번에는 **기존에 정상 작동하던 위치로 복구**하는 것이 목표입니다.

### 확인할 사항

1. 현재 SDK에서 실제 스크롤 영역을 어떻게 탐지하는지
2. 스크롤 안내의 위치 기준 요소가 무엇인지
3. 하단 고정 버튼·조작부의 경계를 어떻게 계산하는지
4. 무인민원발급기에서 등록한 실제 `.stage`와 하단 조작부 정보를 SDK가 어떻게 사용하는지
5. 일반 모드와 자동 하단 80% 모드의 위치 계산 차이
6. 최근 SDK 변경으로 기준 요소가 바뀌었는지
7. 스크롤 안내가 업무 영역 아래로 내려가는 정확한 재현 조건

**호스트 CSS에 임의의 top/bottom 값을 추가하는 방식으로 해결하지 마세요.**

### 목표

- 스크롤 안내는 실제 스크롤 가능한 업무 영역 안쪽 하단에 표시
- 하단 고정 조작부나 버튼과 겹치지 않음
- 기존 원칙인 하단 약 12px 간격 유지
- 스크롤 중 안내 위치가 튀지 않음
- 스크롤 끝에 도달하면 숨김
- `pointer-events: none` 유지
- 버튼 클릭과 터치 조작을 방해하지 않음
- 일반 모드와 하단 60·70·80% 모드 모두 정상 작동
- 데모커피에서는 기존 주문 확인 바 위쪽 배치 유지

기존에 정상 작동했던 SDK 스크롤 안내 구현을 참고하여 회귀 원인을 수정하세요.

## 3. 공간 부족 시 허용되는 조정

사용자는 필요한 경우 다음 조정을 허용했습니다.

- 안내 패널의 불필요한 여백 축소
- 글자 간격과 줄 간격 조정
- 글씨 크기 소폭 축소
- 안내 패널의 버튼 크기 소폭 축소
- 쉬운 말 안내 문구의 간결화 검토

다만 적용 우선순위는 다음과 같습니다.

1. **잘못된 높이 계산과 위치 계산부터 수정**
2. 헤더·간격·불필요한 여백 최적화
3. 그래도 공간이 부족한 경우에만 가독성을 해치지 않는 범위의 소폭 축소 검토

버튼 크기를 줄이는 경우에도 가능한 한 44×44px 터치 영역을 유지하세요.

**안내 문구는 사용자가 실제 화면에서 읽는 내용이므로 이번 작업에서 임의로 바꾸지 마세요.** 문구 축약이 반드시 필요하다면 원문·수정안·이유를 보고하고 승인을 기다리세요.

다른 기능의 글자 크기나 버튼 크기까지 일괄 변경하지 마세요.

## 4. 실제 화면과 동일한 조건으로 재현

사용자가 올린 두 스크린샷을 기준으로 재현하세요.

단순한 SDK 단위 테스트가 아니라 **무인민원발급기와 유사한 구조의 독립 소비자 fixture**를 사용하세요.

테스트할 화면:

- `certificate.type-selection`
- `certificate.id-input`

기존 무인민원발급기 실제 쉬운 말 원문을 재현 데이터로 사용하세요.

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

설정:

- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 켜기
- 자동 하단 80%
- 명시적 하단 80%
- 일반 모드

테스트 시 SDK가 실제로 계산한 다음 값을 기록하세요.

- 패널 전체 높이
- 헤더 높이
- 본문 가용 높이
- 본문 실제 높이
- line-height
- 총 페이지 수
- 각 페이지에 들어간 원문
- 페이지 전환 전후 전체 페이지 수
- 스크롤 영역 경계
- 스크롤 안내 경계
- 하단 조작부 경계
- 두 요소 사이 실제 거리

독립 fixture가 실제 무인민원발급기의 DOM 구조와 다르면 그 차이를 보고하세요.

**독립 fixture 통과만으로 실제 무인민원발급기 문제가 해결됐다고 단정하지 마세요.**

## 5. 페이지 분할 성공 기준

다음 조건을 모두 확인하세요.

- 한 글자씩 분할되지 않음
- 한 단어씩 연속적으로 분할되지 않음
- 가능한 한 의미 있는 문장·설명 단위로 표시
- 원문 누락·중복 없음
- 제목·본문·버튼 잘림 없음
- 페이지 전환 시 무한 재귀 없음
- 페이지 번호가 비정상적으로 바뀌는 현상 재발 없음
- 상단 패널 Y=8px 유지
- 페이지 전환 시 문서 스크롤 위치 변화 없음
- 스마트 길잡이 실행 후 기존 쉬운 말 페이지 및 접힘 상태 복원

특히 `1/21` 상황을 재현하는 테스트를 추가하세요.

검증 전에 임의로 기대 페이지 수를 정해 놓고 맞추지 말고, 실제 가용 높이를 기반으로 분할하세요.

가능한 페이지 수를 제시할 때에는 각 페이지에 충분한 의미 단위가 들어가는지도 함께 확인하세요.

## 6. 스크롤 안내 성공 기준

일반 모드와 하단 모드 각각에서 확인하세요.

- 업무 스크롤 영역 안쪽에 표시
- 하단 고정 버튼·조작부와 시각적으로 겹치지 않음
- 기존 12px 간격 준수
- 스크롤 중 Y 좌표 안정성
- 실제 스크롤 끝에서는 안내 숨김
- 터치·클릭 방해 없음

스크롤 안내가 스크롤 영역 아래로 내려가거나 고정 버튼과 겹친다면 실패입니다.

데모커피의 주문 확인 바가 등장하는 경우에도 기존처럼 바 위에 표시되어야 합니다.

## 7. 스마트 길잡이 및 기존 기능 보호

최근 어렵게 수정한 스마트 길잡이 동작을 유지하세요.

- 한 페이지 기본 10초
- 두 페이지 총 15초, 각 7.5초
- 느린 안내 20초
- 최대 2페이지
- 360×667 실제 결제 안내 67자 표시 가능
- 44px 헤더 조정 유지
- 스마트 길잡이 종료 후 쉬운 말 상태 복원
- 하단 80% 유지

추가로 다음 기능도 영향을 받지 않아야 합니다.

- 첫 메뉴 쉬운 말 상태 안내
- QR v1~v4 호환성
- QR 도크
- 큰 글씨·큰 버튼·고대비
- 데모커피 주문 과정
- 세션 초기화
- 기존 카메라 QR 입력 흐름

7. 타입 검사 및 빌드
