# 긴급 안정화 — 데모커피 무응답 및 공통 SDK 안내창 문제 조사

현재 프로젝트는 **데모커피 Replit**입니다. 공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`에 있습니다.

현재 SDK는 v0.5.15입니다.

사용자가 실제 모바일 브라우저에서 Development '접근성 체험하기'를 실행한 뒤 심각한 오류를 발견했습니다.

## 1. 최우선: 데모커피 무응답 문제

실제 사용자 증상:

- 카페 메뉴 선택 화면에서 터치가 먹히지 않음
- 위아래 스크롤이 되지 않음
- 브라우저에 '응답 없는 사이트'가 표시됨
- 새로고침해도 같은 현상이 반복됨
- 매우 큰 글씨, 큰 버튼, 고대비, 쉬운 말, 스마트 길잡이, 하단 60%, 느린 안내 15초 체험 프로필 사용

기존 자동 테스트에서 주문 흐름이 통과했다는 이유로 문제를 무시하지 마세요.

다음 원인을 실제로 조사하세요.

- SDK 안내창의 위치 계산이 무한 반복되는지
- ResizeObserver / MutationObserver 콜백의 재귀 호출 여부
- DOM 변경 → 재측정 → DOM 변경의 반복 여부
- scroll / resize 이벤트의 과도한 호출
- hit-test와 배치 재계산이 렌더링을 차단하는지
- SDK 타이머 중복 실행
- 큰 글씨·하단 60% 적용 시 무한 레이아웃 계산
- 브라우저 메인 스레드 장시간 점유
- 안내창이나 투명 오버레이가 터치를 가로채는지
- 터치 스크롤의 passive 이벤트·preventDefault 처리
- React 반복 렌더링 여부
- 개발 서버 HMR 또는 브라우저 환경 문제

원인을 추측해서 임의의 CSS를 추가하지 말고 재현·측정 후 수정하세요.

테스트를 위해 Development에서만 안내창 기능을 일시적으로 비활성화하여 무응답 증상이 사라지는지 비교하는 것은 허용합니다. 그러나 이를 최종 해결책으로 삼거나 기존 기능을 삭제해서는 안 됩니다.

## 2. 공통 안내창의 불규칙한 위치 문제

사용자 테스트에서 쉬운 말, 스마트 길잡이, 스크롤 안내가 화면 상단·중간·하단 사이에서 불규칙하게 이동하고 중요한 업무 내용을 가립니다.

SDK 배치 로직의 다음 문제를 조사하세요.

- 스크롤할 때 불필요한 재배치 반복
- 고정 요소와 스크롤 콘텐츠의 좌표계 혼동
- 패널이 업무 버튼과 콘텐츠를 가리는 경우
- 쉬운 말 안내의 위치가 스크롤할 때 튀는 경우
- 스마트 길잡이 전환 시 기존 쉬운 말 위치가 변하는 경우
- 스크롤 안내와 다른 안내창의 충돌
- 접힌 상태에서도 콘텐츠를 가리는 경우

**사용자가 예상할 수 있는 안정적인 위치를 우선**으로 설계하세요.

매번 빈 공간을 찾아 안내창을 화면 여기저기로 순간 이동시키는 방식은 피하세요.

배치 정책은 키오스크 종류에 의존하지 않는 공통 규칙으로 구현하세요.

## 3. 스크롤하면 쉬운 말 안내가 사라지는 문제

쉬운 말 안내는 스마트 길잡이와 달리 자동 닫힘이 없어야 합니다.

사용자가 직접 접거나 화면 단계가 바뀌지 않았는데 스크롤만으로 설명이 사라지면 안 됩니다.

스크롤로 안전한 위치를 찾지 못하더라도 가능한 한 접힌 안내 헤더를 유지하고 다시 펼칠 수 있도록 하세요.

단, 주요 업무 버튼을 가리는 방식으로 표시하면 안 됩니다.

안내창이 불가피하게 숨겨지는 경우 원인과 조건을 진단으로 기록하세요.

## 4. 빈 설명 상태 처리

실제로 표시할 쉬운 말 설명이 없는 경우:

- 빈 패널 표시 금지
- 내용 없는 펼치기 버튼 표시 금지
- 이전 단계의 설명 재사용 금지
- 접기·펼치기 상태가 꼬이지 않도록 초기화

스마트 길잡이만 있는 단계라면 스마트 길잡이에 필요한 UI만 정상적으로 표시하세요.

## 5. 기존 기능 보존

- QR v1~v4
- 쉬운 말 + 스마트 길잡이 공통 안내창
- 이전·다음 및 접기·펼치기
- 10/15/20초 표시 전 대기
- 기본 10초·느린 안내 15초 표시
- 하단 60/70/80%
- 데모커피 주문·결제·완료
- 15초 자동 복귀
- 개발 전용 접근성 체험하기

새 AI 기능이나 새 QR 스키마는 추가하지 마세요.

## 6. 테스트

재현 조건인 320×844 및 하단 60%를 최우선으로 테스트하세요.

실제 브라우저에서:

- 메뉴 화면 30초 이상 무응답 없이 유지
- 반복 스크롤 및 터치·포인터 조작
- 메뉴 선택, 옵션 선택, 메뉴 담기
- 쉬운 말 펼치기·접기
- 스마트 길잡이 시작·종료
- 안내창 표시 중 터치 스크롤
- 메뉴 화면 재진입
- 체험 종료 및 재시작
- 전체 주문 완료
- 자동 초기화

360×667, 390×844에서도 확인하세요.

단순히 테스트 스크립트가 성공하는 것뿐 아니라, 메인 스레드 과도한 점유, 반복 재배치, 브라우저 장시간 멈춤 여부도 확인하세요.

모바일 터치 이벤트를 가능한 범위에서 실제 재현하고, 헤드리스 브라우저에서 확인할 수 없는 부분은 미검증으로 구분하세요.

## 7. SDK 수정 원칙 및 버전

SDK 원본 수정이 필요하면 v0.5.15는 보존하고 **v0.5.16**으로 올려 새 tarball을 생성하세요.

호스트 전용 CSS 예외, 반복 scrollTo 우회, 특정 화면 ID 하드코딩은 금지합니다.

데모커피 호스트에서는 SDK 공개 API 연동 누락만 보완할 수 있습니다.
