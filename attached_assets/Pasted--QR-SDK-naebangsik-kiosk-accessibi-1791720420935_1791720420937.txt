# 내 방식 QR — 데모커피 첫 화면 이중 스크롤바 및 마지막 콘텐츠 접근 불가 수정

현재 데모커피 프로젝트에는 공통 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.0`이 적용되어 있으며, 첫 화면 하단에 SDK의 `createQrEntryDock()`으로 QR 전용 영역을 표시하고 있습니다.

QR 도크 추가 이후 첫 화면에서 심각한 스크롤 문제가 발견됐습니다.

첨부 스크린샷을 참고해 주세요.

## 1. 확인된 문제

현재 데모커피 첫 화면에는 세로 스크롤바가 두 개 나타납니다.

- 안쪽 스크롤바: 키오스크 콘텐츠를 스크롤
- 바깥쪽 스크롤바: 전체 문서를 별도로 스크롤
- 안쪽 스크롤을 끝까지 내려도 마지막 콘텐츠가 완전히 보이지 않음
- 바깥쪽 스크롤을 추가로 내려야 마지막 콘텐츠에 접근 가능
- 하단에는 SDK가 만든 '내 QR로 화면 설정' 버튼이 고정돼 있음

이 구조는 고령층이나 휠체어 이용자가 사용하기 어렵습니다.

**목표는 첫 화면에 실질적인 세로 스크롤 영역을 하나만 남기고, 그 영역의 스크롤만으로 모든 콘텐츠를 볼 수 있게 만드는 것입니다.**

QR 하단 영역은 계속 고정되어 있어야 합니다.

---

## 2. 원인 분석 — 코드 수정 전 필수

먼저 현재 DOM과 CSS에서 실제 스크롤 소유 요소를 확인해 주세요.

조사 대상:

- html
- body
- #root
- .kiosk
- .shell
- SDK QR 도크 컨테이너
- SDK 하단 viewport shell
- 관련 fixed / sticky 요소
- 기존 첫 화면 콘텐츠 영역

각 요소의 다음 값을 측정해 주세요.

- scrollHeight
- clientHeight
- scrollTop
- overflow-y
- position
- height / min-height / max-height
- getBoundingClientRect()
- 100vh / 100dvh 적용 여부

다음 원인을 구분합니다.

A. SDK QR 도크가 화면 밖에 문서 높이를 추가한 경우

B. SDK가 콘텐츠 높이를 줄이면서 별도 내부 스크롤을 생성한 경우

C. 기존 카페의 문서 스크롤과 SDK 스크롤이 중복된 경우

D. 기존 min-height / padding-bottom / margin-bottom 때문에 바깥쪽 스크롤 범위가 남은 경우

E. QR 도크의 fixed 배치 또는 SDK 루트 스타일 복원이 잘못된 경우

F. 방법 B 하단 조작 모드와 QR 도크가 중복으로 높이를 계산하는 경우

원인을 확인한 뒤 공통 SDK 문제인지 호스트 레이아웃 문제인지 구분해 주세요.

## 3. 첫 화면의 스크롤 구조 정리

첫 화면에서는 다음 구조를 목표로 합니다.

**A. 콘텐츠 표시 영역**

- 화면 상단부터 QR 도크 바로 위까지 사용
- 기존 데모커피 로고·이미지·메뉴·버튼·직원 도움 유지
- 해당 영역 내부에서 세로 스크롤
- 하나의 스크롤 조작으로 마지막 콘텐츠까지 접근 가능

**B. QR 하단 도크**

- 화면 맨 아래에 고정
- 기존 72px 영역과 52px 버튼 크기를 우선 유지
- 콘텐츠 스크롤과 독립적으로 위치 유지
- 스크롤 중 QR 버튼이 위아래로 이동하지 않음
- 콘텐츠의 마지막 항목을 가리지 않음

**C. 바깥쪽 문서**

- 첫 화면에서는 불필요한 별도 세로 스크롤이 발생하지 않음
- 문서 전체와 내부 콘텐츠가 동시에 스크롤되지 않도록 처리
- 모바일 브라우저 주소창 등에 따른 viewport 변화도 고려

특히 CSS에서 스크롤바만 숨기고 실제 스크롤은 두 개 남겨두는 방식은 금지합니다.

실제로 어느 요소가 스크롤을 소유하고, 사용자 입력으로 어느 영역이 움직이는지 검증해 주세요.

## 4. 공통 SDK와 호스트 역할 분리

이번 기능은 다른 키오스크에서도 사용될 QR 도크 기능이므로, 원인이 공통 SDK에 있다면 SDK에서 수정하는 것이 우선입니다.

예를 들어 QR 도크가 콘텐츠 높이를 관리할 때 기존 문서에 별도 스크롤 범위를 만드는 구조라면, 공통 SDK에서 해결해 주세요.

반면 기존 데모커피의 `.shell`이나 `.kiosk`에만 적용된 CSS 때문에 이중 스크롤이 생긴다면 호스트에서 최소한으로 수정해 주세요.

### 반드시 지킬 원칙

- SDK에 데모커피 전용 CSS 클래스 하드코딩 금지
- QR 도크의 공개 API 유지
- 호스트별로 대규모 레이아웃 재작성 금지
- React DOM 자식 요소의 무리한 이동 금지
- 키오스크별 고정 조작부 등록 기능 유지
- 하단 조작 모드와 QR 도크의 높이 중복 계산 방지
- 사용자 스크롤 위치를 반복적으로 강제 변경하지 않기

SDK 소스를 수정해야 한다면 원인과 수정 범위를 별도로 보고하고, 이후 새 패키지 출시가 필요한지 알려 주세요.

이번에는 **SDK 버전을 그대로 0.5.0으로 유지하고 새 tarball은 만들지 마세요.** 우선 문제를 재현하고 해결한 뒤 정식 패키지 반영 여부를 판단하겠습니다.

## 5. 마지막 콘텐츠 접근성 검증

첨부 사진에서 하단에 일부 보이는 '직원 도움' 카드까지 확인해 주세요.

다음 항목이 모두 안쪽 콘텐츠 영역의 스크롤만으로 나타나야 합니다.

- 로고와 환영 이미지
- '오늘도 향긋한 한잔' 제목 및 설명
- 매장 이용 버튼
- 포장하기 버튼
- 직원 도움 카드
- 첫 화면의 기타 안내

### 합격 기준

- 스크롤 시작: 화면 상단 콘텐츠 표시
- 스크롤 중간: 매장·포장 버튼 표시
- 스크롤 최하단: 직원 도움 카드 전체 표시
- 더 이상 별도 바깥 문서 스크롤 불필요
- QR 버튼은 계속 화면 맨 아래에 고정
- 직원 도움 카드도 실제 클릭 가능

안쪽 스크롤만 내려서 마지막 카드의 일부만 보인다면 실패입니다.

## 6. QR 도크와 접근성 기능 검증

다음 기능이 그대로 유지돼야 합니다.

- QR 적용 전 첫 화면 하단 버튼 표시
- 버튼 클릭 시 QR 모달 바로 열림
- QR 카메라·주소·토큰 입력 유지
- QR 적용 후 첫 화면에서도 도크 유지
- 주문 단계 진입 시 QR 도크 제거
- 주문 완료 후 첫 화면 복귀 시 QR 도크 재표시
- 세션 종료 시 기존 접근성 설정 초기화

또한 다음 설정과 함께 검증해 주세요.

- 기본 글씨
- 큰 글씨
- 아주 큰 글씨
- 큰 버튼
- 고대비
- 하단 조작 60%·70%·80%

특히 방법 B와 QR 도크가 동시에 켜졌을 때에도 이중 스크롤이 발생하지 않아야 합니다.

QR 영역을 제외한 남은 높이 기준의 하단 조작 비율 계산은 유지합니다.

## 7. 스크롤 안내와 스마트 길잡이

기존 SDK 안내 문구를 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

검증 사항:

- 실제 콘텐츠 스크롤 영역을 감지
- 스크롤 시작부터 안내 표시
- 최하단에서 안내 숨김
- 다시 위로 움직이면 재표시
- QR 도크와 안내 겹침 없음
- 직원 도움 카드 및 기존 업무 버튼 클릭 가능
- 스마트 길잡이 표시 시 안내 숨김
- 길잡이 종료 후 필요한 경우 안내 복귀

스크롤 안내가 문서와 내부 영역을 각각 독립 스크롤로 잘못 판단하지 않는지도 확인해 주세요.

## 8. 브라우저 검증

- 390×844
- 1080×1920

각각 다음 상태를 검증합니다.

A. 첫 화면 QR 도크만 적용

B. QR 도크 + 하단 60%

C. QR 도크 + 하단 70%

D. QR 도크 + 하단 80%

E. QR 도크 + 아주 큰 글씨 + 큰 버튼 + 고대비

F. 주문 화면으로 이동한 상태

G. 주문 완료 후 첫 화면으로 복귀

각 조건에서 다음을 기록합니다.

- 실제 스크롤 소유 요소
- 활성 세로 스크롤 영역 개수
- 각 scrollHeight / clientHeight
- 내부 및 외부 최대 스크롤 거리
- 마지막 콘텐츠 노출 여부
- QR 도크 위치와 높이
- 글씨·버튼 크기 변화
- 실제 터치·휠 스크롤 성공 여부
- 0.1초·0.5초·1초·3초 후 스크롤 위치 안정성
- 가로 넘침 여부

개발 브라우저에서 스크롤바가 하나만 보이는지만 확인하지 말고, 실제 DOM 스크롤 범위를 측정해 주세요.

## 9. 독립 구조 재현 검증

데모커피 외의 독립 fixture에서도 확인해 주세요.

A. 원래 document가 스크롤을 소유하는 화면

B. 원래 내부 컨테이너가 스크롤을 소유하는 화면

C. 기존 하단 고정 버튼이 있는 화면

세 구조에 QR 하단 도크를 활성화했을 때 불필요한 이중 스크롤이 생기지 않고, 마지막 콘텐츠까지 접근 가능한지 확인합니다.

**모든 호스트에 동일한 스크롤 소유 방식을 강제로 적용하는 것이 아니라, 각 구조에서 안전한 단일 사용자 스크롤 경험을 제공하는 것이 목표입니다.**

### 최종 성공 기준

**첫 화면에 사용자에게 필요한 세로 스크롤이 하나만 존재하고, 그 스크롤을 끝까지 내리면 직원 도움을 포함한 모든 콘텐츠가 보이고 클릭되어야 합니다.**
