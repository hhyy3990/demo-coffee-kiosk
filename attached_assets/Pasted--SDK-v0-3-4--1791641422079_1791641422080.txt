# 데모커피 — 가로 카테고리 스크롤을 좌우 화살표 버튼 방식으로 변경

현재 데모커피에는 공통 접근성 SDK v0.3.4가 적용되어 있습니다.

메뉴 화면의 카테고리는 다음 네 가지입니다.

- 커피·음료
- 케이크
- 디저트
- 간단한 식사

현재 좁은 화면에서는 카테고리 목록을 손가락으로 좌우 스크롤해야 나머지 카테고리를 확인할 수 있습니다.

이를 **좌우 화살표 버튼을 눌러 다음 카테고리를 볼 수 있는 방식**으로 변경해 주세요.

이번 작업은 데모커피 호스트 UI만 수정하며, 공통 SDK는 변경하지 않습니다.

## 1. 좌우 화살표 버튼 구현

카테고리 목록의 왼쪽과 오른쪽에 각각 이전·다음 화살표 버튼을 배치해 주세요.

- 왼쪽 화살표: 이전 카테고리가 보이도록 이동
- 오른쪽 화살표: 다음 카테고리가 보이도록 이동
- 버튼을 누르면 실제 카테고리 목록이 수평 이동
- 현재 보이는 카테고리 다음에 숨겨진 카테고리가 있다면 오른쪽 화살표 활성화
- 왼쪽에 숨겨진 카테고리가 있다면 왼쪽 화살표 활성화
- 더 이상 이동할 항목이 없으면 해당 방향 버튼 비활성화
- 모든 카테고리에 끝까지 접근 가능해야 함

카테고리는 기존처럼 직접 눌러 선택할 수 있어야 합니다.

화살표를 눌렀다는 이유만으로 상품 카테고리가 자동 선택되지는 않도록 해 주세요.

## 2. 기존 가로 스크롤과의 관계

사용자가 화살표 버튼을 이용하는 것을 기본 탐색 방식으로 만들어 주세요.

다만 기존 터치 스와이프나 트랙패드 가로 스크롤을 제거할 필요는 없습니다. 기존 조작이 안정적으로 동작한다면 보조 수단으로 유지해도 됩니다.

중요한 것은 사용자가 가로 스크롤을 몰라도 화살표 버튼만으로 모든 카테고리를 볼 수 있다는 점입니다.

- SDK가 새로운 화살표를 생성하지 않음
- 이번에는 카페 호스트가 버튼 생성과 이동 동작을 담당
- 중복 화살표 생성 금지
- 기존 상품 목록을 숨기거나 삭제하지 않기

## 3. 공통 SDK 연동을 고려한 버튼 의미 표시

향후 SDK v0.3.5에서 기존 키오스크의 '다음 항목으로 이동하는 버튼'을 자동 식별하고 강조하는 기능을 실험할 예정입니다.

따라서 이번에 만드는 화살표 버튼은 역할이 명확해야 합니다.

- 실제 `<button>` 요소 사용
- 접근성 이름 제공: '이전 카테고리 보기', '다음 카테고리 보기'
- `aria-label` 정확하게 설정
- 비활성 상태에서는 `disabled` 또는 적절한 상태 속성 사용
- 가능하면 버튼이 조작하는 카테고리 목록과의 관계를 `aria-controls`로 표시
- 필요한 경우 의미가 분명한 `data-*` 속성을 사용할 수 있으나 특정 SDK 버전의 미확정 API를 가정하지 말 것

SDK가 자동으로 버튼을 클릭하거나 카테고리를 선택하도록 연결하지 마세요.

이번에는 역할과 상태를 명확하게 만드는 것까지만 진행합니다.

## 4. 접근성 및 디자인

기존 데모커피의 디자인 분위기를 유지해 주세요.

- 화살표 버튼은 충분히 크고 누르기 쉬워야 함
- 터치 영역 최소 44×44 CSS px 목표
- 큰 버튼 모드에서도 버튼이 겹치지 않아야 함
- 큰 글씨·아주 큰 글씨 모드에서도 카테고리 이름이 읽혀야 함
- 선택된 카테고리 표시 유지
- 화살표가 상품 카드·결제 버튼을 가리지 않아야 함
- 고대비 모드에서도 화살표와 버튼 경계가 잘 보여야 함
- 좁은 화면에서 가로 넘침이나 글자 잘림이 발생하지 않아야 함

카테고리 이름 자체를 임의로 줄이거나 메뉴 개수를 제한하지 마세요.

## 5. 화면 전환 시 상태

직전 작업에서 해결한 화면 전환 스크롤 초기화 기능은 유지해 주세요.

- 첫 화면 → 메뉴: 상단에서 시작
- 메뉴 → 옵션: 상단에서 시작
- 뒤로 가기: 해당 화면 상단에서 시작
- 처음으로: QR 설정과 주문 상태 초기화

카테고리 목록의 가로 위치는 메뉴 화면에 처음 진입할 때 초기화해도 되지만, 사용자가 카테고리를 선택하고 같은 메뉴 화면에 머무르는 동안에는 불필요하게 맨 왼쪽으로 이동시키지 마세요.

## 6. 브라우저 테스트

320×844, 390×844, 1080×1920에서 다음을 검증해 주세요.

A. 기본 화면

B. 큰 글씨

C. 아주 큰 글씨 + 큰 버튼 + 고대비

D. QR 설정 없이 주문

E. QR 모의 프로필 적용 후 주문

검증 내용:

1. 첫 카테고리에서 왼쪽 화살표 비활성화
2. 다음 항목이 남아 있으면 오른쪽 화살표 활성화
3. 오른쪽 화살표로 네 카테고리 모두 접근 가능
4. 마지막 카테고리에서 오른쪽 화살표 비활성화
5. 왼쪽 화살표로 이전 카테고리 복귀 가능
6. 카테고리 선택 후 실제 상품 목록 변경
7. 큰 글씨·큰 버튼에서도 카테고리 이름과 화살표 정상 표시
8. 버튼의 실제 좌표 클릭 및 hit-test
9. 화면 전환 시 스크롤 위치 초기화 유지
10. 메뉴 → 옵션 → 장바구니 → 가상 결제 → 완료 흐름 정상
11. 주문 도중 처음으로 복귀하면 QR 설정 초기화

실제 카메라·중앙 QR API 테스트와 모의 테스트는 구분해서 보고해 주세요.
