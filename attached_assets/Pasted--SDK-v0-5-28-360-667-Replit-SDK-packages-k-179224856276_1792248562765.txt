# 공통 SDK v0.5.28 — 360×667 스마트 길잡이 공간 부족 최소 수정

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 경로:
`packages/kiosk-accessibility-sdk/`

이번 작업의 목표는 360×667 화면에서 스마트 길잡이가 최대 2페이지 제한 때문에 표시되지 않는 문제를 해결하는 것입니다.

**지난 진단에서 확인된 헤더·간격의 공간만 최소한으로 최적화하세요.**

새 기능, 디자인 리뉴얼, 문구 변경, 페이지 정책 변경은 금지합니다.

## 1. 현재 문제

무인민원발급기 실제 결제 단계에서 다음 오류가 확인됐습니다.

stepId: `certificate.payment-method`

실제 안내 원문:

증명서 종류, 발급 부수, 표시 항목과 수수료를 확인해 주세요. 내용이 맞으면 결제 방법을 눌러 가상 결제를 진행하세요.

검증 조건:
- 화면: 360×667
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 활성화
- 스마트 길잡이 활성화
- 하단 조작 80%
- slowGuidance: false

실제 측정:
- 패널 최대 높이: 99.56px
- 헤더·조작부: 51.19px
- 본문 가용 높이: 44.38px
- 본문 전체 높이: 102.38px
- 두 페이지에 필요한 페이지당 본문 높이: 약 51.2px
- 부족한 높이: 약 6.82px
- 현재 SDK 판정: 4페이지 필요 → 안내 미표시

이전 진단에서는 헤더·간격 최적화로 문제를 해결할 가능성이 있다고 판단했습니다.

다만 헤더를 44px로 줄이는 것만으로는 이론상 약 0.37px의 여유밖에 생기지 않으므로, 실제 브라우저에서 안정적인 표시가 가능한지 반드시 검증해야 합니다.

## 2. 수정 전 실제 구조 확인

먼저 SDK의 현재 스마트 길잡이 패널 구조를 확인하세요.

- 제목 영역
- 카운트다운 표시
- 닫기·접기 버튼
- 헤더 전체 높이
- 헤더와 본문 사이 간격
- 패널 padding
- 본문 가용 높이
- 페이지 분할 계산에서 사용하는 높이

**공간 계산과 실제 DOM 높이가 일치하는지 확인한 후 수정하세요.**

실제 존재하지 않는 여백을 가정해 수정하지 마세요.

## 3. 허용된 최소 수정

다음 범위에서만 변경할 수 있습니다.

1. 스마트 길잡이 표시 중 불필요하게 적용되는 헤더 세로 여백 제거
2. 헤더와 본문 사이의 불필요한 간격 축소
3. 스마트 길잡이의 실제 본문 가용 높이 계산 정확도 개선
4. 페이지 분할 계산과 실제 렌더링의 높이 일치

반드시 유지할 조건:

- 닫기·접기 버튼 최소 44px 터치 영역
- 기존 큰 글씨 크기와 두께
- 제목과 카운트다운의 가독성
- 제목·카운트다운·버튼의 겹침 없음
- 패널 상단 Y=8px 고정
- 하단 80% 업무 영역 크기 유지
- 스마트 길잡이 최대 2페이지
- 글씨 임의 축소 금지
- 본문 일부 삭제 금지
- 내부 스크롤 추가 금지
- 안내 문구 축약 금지

**스마트 길잡이 전용 공간만 수정하고, 일반 쉬운 말 안내 패널의 디자인·레이아웃은 변경하지 마세요.**

공용 스타일 수정이 불가피하다면 변경 전 영향 범위를 확인하고, 쉬운 말 안내의 기존 동작을 유지할 수 있는지 검증하세요.

## 4. 핵심 검증 — 360×667

위의 실제 결제 안내 원문을 사용해 독립 consumer fixture에서 재현하세요.

무인민원발급기 프로젝트 자체는 수정하지 않습니다.

다음을 실제 브라우저 DOM으로 검증하세요.

1. 스마트 길잡이가 정상 표시되는지
2. 안내가 정확히 2페이지 이내로 분할되는지
3. 두 페이지의 원문을 합치면 기존 원문과 정확히 일치하는지
4. 본문 잘림·넘침이 없는지
5. 페이지당 최소 2줄의 설명을 온전히 보여줄 수 있는지
6. 제목·카운트다운·버튼 겹침이 없는지
7. 44px 터치 영역이 유지되는지
8. 패널 상단 Y=8px을 유지하는지
9. 업무 화면 영역이 기존 하단 80% 그대로인지
10. 브라우저 콘솔에 오류가 없는지

특히 `scrollHeight`, `clientHeight`, `getBoundingClientRect()`를 이용해 픽셀 단위로 측정하세요.

**화면에 보이는 것처럼 보인다는 이유만으로 성공 처리하지 마세요.**

본문과 패널에서 잘림이 없는지 실제 치수로 확인해야 합니다.

## 5. 기존 시간 규칙 유지

스마트 길잡이의 시간 정책은 변경하지 마세요.

- 일반 1페이지: 10초
- 일반 2페이지: 총 15초, 각 7.5초
- 느린 안내 1페이지: 20초
- 느린 안내 2페이지: 총 20초, 각 10초

등장 전 대기 시간 `guideDelaySeconds`는 그대로 유지합니다.

스마트 길잡이가 종료되면 기존 쉬운 말 접힘 상태와 페이지를 복원해야 합니다.

## 6. 다른 화면 크기 회귀 검증

다음 화면도 확인하세요.

- 320×844
- 390×844
- 1080×1920

기존 정상 동작을 유지해야 합니다.

특히 320×844에서 결제 안내가 2페이지로 정상 표시됐던 동작이 유지되어야 합니다.

각 화면에서 다음을 확인하세요.

- 안내 내용 보존
- 페이지 수
- 글씨 잘림 없음
- 조작부 겹침 없음
- 패널 상단 위치 안정성
- 업무 화면 위치 유지
- 쉬운 말 접힘·페이지 복원

## 7. 기존 SDK 오류 재발 방지

이전에 수정한 다음 오류를 재발시키지 마세요.

- 쉬운 말 안내 66·137페이지 비정상 분할
- 한 글자씩 분할
- 페이지 계산 중 무한 재귀
- 상단 패널 위치 점프
- 쉬운 말 원문 누락·중복
- QR 도크 위치 변경
- 하단 스크롤 안내 위치 점프
- 스마트 길잡이 종료 후 접힘 상태 복원 실패

기존 QR v1~v4 호환성과 데모커피 주문 흐름도 관련 회귀 테스트로 확인하세요.

## 8. 해결 불가능한 경우

허용된 헤더·간격 수정만으로 실제 360×667에서 2페이지 표시가 불가능하다면 **억지로 맞추지 말고 중단하세요.**

특히 다음 방법은 사용하지 마세요.

- 44px 조작부 축소
- 글씨 크기 축소
- 하단 80%를 70%나 60%로 변경
- 스마트 길잡이 3페이지 이상 허용
- 설명 일부 숨김
- 자동 요약
- 내부 스크롤
- 안내창을 업무 영역 위로 확장
- 무인민원발급기 호스트 CSS 수정

최소 수정으로 해결할 수 없다면 실제 측정값과 제약을 보고하고 사용자 승인을 기다리세요.
