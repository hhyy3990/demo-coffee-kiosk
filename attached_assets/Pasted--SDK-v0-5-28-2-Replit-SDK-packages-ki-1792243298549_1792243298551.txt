# 공통 SDK v0.5.28 — 스마트 길잡이 최대 2페이지 및 표시 시간 개선

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본:
`packages/kiosk-accessibility-sdk/`

현재 버전:
`@naebangsik/kiosk-accessibility-sdk@0.5.28`

이번 작업은 사용자가 승인한 **스마트 길잡이의 문구 잘림 해결, 최대 2페이지 자동 분할, 표시 시간 변경**에 한정합니다.

새로운 기능, 다른 디자인 변경, AI 연결, 쉬운 말 문구 변경은 하지 마세요.

## 1. 기존 오류 및 수정 목표

무인민원발급기 실제 QR 테스트에서 다음 오류가 확인됐습니다.

- 화면: 320×844
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말 활성화
- 하단 조작 80%
- 결제 화면 Smart Guide 본문 약 67자
- 안내 패널 높이 약 134.6px
- 내부 콘텐츠 높이 약 154px
- 안내 문구 아래쪽 약 20px 잘림

호스트는 기존 `setGuideState()` API로 안내를 전달하고 있으며, 호스트 CSS에서 SDK 패널을 덮어쓰지는 않았습니다.

**SDK의 스마트 길잡이 표시 공간 계산을 수정하여 문구가 잘리지 않도록 해야 합니다.**

기존 하단 80% 배치, 글씨 크기, 버튼 크기는 유지하세요.

## 2. 스마트 길잡이의 새로운 표시 규칙

사용자가 승인한 규칙은 다음과 같습니다.

| 조건 | 총 표시 시간 | 페이지 |
|---|---|---|
| 일반 안내, 한 페이지에 들어감 | 10초 | 1페이지 |
| 일반 안내, 두 페이지 필요 | 15초 | 2페이지, 각 7.5초 |
| 느린 안내, 한 페이지에 들어감 | 20초 | 1페이지 |
| 느린 안내, 두 페이지 필요 | 20초 | 2페이지, 각 10초 |

`slowGuidance: true`이면 느린 안내 모드를 적용합니다.

`slowGuidance: false`이면 일반 안내 모드를 적용합니다.

**스마트 길잡이는 최대 2페이지까지만 허용합니다.**

3페이지 이상으로 자동 분할하지 마세요.

쉬운 말 안내에는 이 규칙을 적용하지 않습니다.

## 3. 자동 페이지 분할

SDK가 스마트 길잡이 문구의 실제 표시 높이를 측정합니다.

- 한 페이지에 모두 들어가면 기존처럼 한 페이지 표시
- 한 페이지에 들어가지 않지만 두 페이지에는 들어가면 두 페이지로 분할
- 문장 경계를 우선으로 분할
- 원문 순서 유지
- 문구 누락·중복 금지
- 글씨 크기 임의 축소 금지
- 하단 80% 업무 영역 축소 금지
- 안내창 내부 스크롤 추가 금지
- 이전·다음 버튼 추가 금지

두 페이지인 경우 사용자의 조작 없이 자동으로 전환합니다.

예시:

일반 안내 2페이지:
- 0~7.5초: 첫 번째 페이지
- 7.5~15초: 두 번째 페이지
- 15초: 스마트 길잡이 종료

느린 안내 2페이지:
- 0~10초: 첫 번째 페이지
- 10~20초: 두 번째 페이지
- 20초: 스마트 길잡이 종료

기존 스마트 길잡이 등장 전 대기 시간인 `guideDelaySeconds`(10·15·20초)는 변경하지 마세요.

이번에 변경하는 시간은 **스마트 길잡이가 등장한 후 실제 표시되는 시간**입니다.

## 4. 두 페이지에도 들어가지 않는 문구 처리

스마트 길잡이는 간단하고 이해하기 쉬운 행동 안내여야 하므로 세 페이지 이상이 필요한 설명을 그대로 제공하는 것은 적절하지 않습니다.

이 경우 다음 원칙을 지키세요.

1. SDK가 3페이지 이상 필요한 상황을 감지
2. 해당 화면의 stepId와 필요한 페이지 수를 개발 로그에 기록
3. 실제 호스트에서 문구를 간결하게 수정해야 하는 항목으로 보고
4. 원문을 임의로 삭제하거나 앞부분만 표시하지 않음
5. AI를 호출해 자동 요약하지 않음
6. 세 번째 페이지를 만들지 않음
7. 사용자 승인 없이 해당 문구를 변경하지 않음

**두 페이지로 온전히 표시할 수 없는 사례가 있다면, 새로운 표시 방식을 임의로 추가하지 말고 사용자에게 필요한 수정 사항을 보고하세요.**

해당 조건에서 문구 잘림이 해결되지 않았다면 검증 성공으로 처리하지 마세요.

## 5. 스마트 길잡이 종료 후 쉬운 말 상태 복원

기존 동작을 유지하세요.

1. 사용자가 쉬운 말 안내를 접어 둠
2. 스마트 길잡이 등장
3. 스마트 길잡이가 자동으로 펼쳐짐
4. 한 페이지 또는 두 페이지 안내 표시
5. 설정된 표시 시간 종료
6. 스마트 길잡이 사라짐
7. 이전 쉬운 말 안내로 복귀
8. 쉬운 말 안내는 기존 접힘 상태로 복원

쉬운 말이 원래 펼쳐져 있었다면 기존 페이지 위치와 펼침 상태로 복귀해야 합니다.

실제 업무 단계가 변경되면 이전 스마트 길잡이를 정리하는 기존 정책을 유지하세요.

같은 단계에서 입력·선택·스크롤이 발생해도 타이머가 조기 종료되거나 처음부터 다시 시작되지 않아야 합니다.

## 6. 페이지 전환 중 레이아웃 안정성

두 페이지가 자동으로 전환될 때:

- 상단 패널 Y 좌표 유지
- 하단 모드 상단 약 8px 유지
- 일반 모드 상단 약 12px 유지
- 패널 위치 점프 없음
- 업무 화면 자동 스크롤 없음
- QR 도크 위치 변경 없음
- 하단 스크롤 안내 위치 변경 없음
- 페이지 전환으로 타이머 재시작 없음
- 첫 페이지와 두 번째 페이지 모두 잘림 없음

안내 문구 길이가 달라도 기존 패널의 고정 위치 정책을 유지하세요.

## 7. 기존 오류 재발 방지

우리는 이전 SDK 수정 과정에서 다음 오류들을 해결했습니다.

반드시 회귀 검증을 수행하세요.

### 쉬운 말 안내

- 66·137페이지로 비정상 분할되던 오류 재발 없음
- 한 글자씩 분할 없음
- 원문 누락·중복 없음
- 본문 및 버튼 잘림 없음
- 이전·다음 버튼 정상
- 페이지 번호 변화로 무한 재귀 발생하지 않음

### 자동 하단 조작

- 쉬운 말 켜기 + viewportMode null → 첫 메뉴 포함 하단 80%
- 명시적 60·70·80% 유지
- 중앙 QR 원본 preferences 변경 없음

### 첫 메뉴

- 쉬운 말 활성화 상태 안내 유지
- 업무 진입 후 기존 설명 표시
- 첫 메뉴에 새로운 스마트 길잡이 문구 추가 없음

### 하단 스크롤 안내

- 실제 스크롤 영역 기준 위치 안정성
- 기존 하단 12px 간격 유지
- 데모커피 주문 확인 바가 있으면 그 위 12px
- 스크롤 도중 위아래 위치 점프 없음
- 스크롤 끝에서는 숨김
- pointer-events:none 유지

### 그 밖의 기능

- QR v1~v4 호환
- 큰 글씨·큰 버튼·고대비 유지
- QR 카메라 인식 기능 유지
- 데모커피 주문 전체 흐름 유지
- 세션 종료 및 초기화 유지

## 8. 테스트

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

모드:

- 자동 하단 80%
- 명시적 하단 80%
- 일반 화면
- 필요한 경우 명시적 60·70%

반드시 다음 조건을 테스트하세요.

1. 짧은 안내 + 일반 모드 → 한 페이지, 10초
2. 긴 안내 + 일반 모드 → 두 페이지, 총 15초
3. 짧은 안내 + slowGuidance → 한 페이지, 20초
4. 긴 안내 + slowGuidance → 두 페이지, 총 20초
5. 두 페이지 자동 전환 시 정확한 시간 측정
6. 종료 후 쉬운 말 접힘 상태 복원
7. 종료 후 기존 쉬운 말 페이지 복원
8. 입력·선택·스크롤 중 타이머 유지
9. 안내 패널 상단 위치 안정성
10. 각 페이지 원문 보존 및 잘림 없음
11. 스마트 길잡이 등장 전 기존 지연 시간 유지
12. 실제 무인민원발급기의 결제 안내와 유사한 67자 문구를 이용한 재현

무인민원발급기 실제 안내 원문이 없으면 임의 문구를 정확한 원문이라고 주장하지 마세요.

테스트는 시간 제한에 걸리지 않도록 작은 단위로 나누어 실행하세요.
