# 내 방식 QR — 공통 SDK v0.2.0 개발

현재 데모커피 프로젝트에는 독립 패키지 `@naebangsik/kiosk-accessibility-sdk@0.1.0`이 구현되어 있습니다.

이번 작업은 기존 카페 키오스크에 구현된 카메라 QR 스캔 및 QR 검증 기능을 공통 SDK로 분리하여 v0.2.0을 만드는 것입니다.

목표는 카페뿐만 아니라 앞으로 무인민원발급기, 병원 등 서로 다른 키오스크에서 동일한 QR 스캔 모듈을 재사용하는 것입니다.

## 1. 카메라 QR 스캔 기능 공통화

현재 데모커피의 카메라 스캔 코드와 QR 검증 코드를 조사한 뒤 카페 업무 로직에 종속되지 않는 부분을 SDK로 이동해 주세요.

필수 기능:
- 브라우저 카메라 권한 요청
- ZXing 기반 QR 인식
- 카메라 영상은 브라우저 안에서만 처리
- QR 인식 즉시 카메라 종료
- 중복 인식 방지
- 카메라 권한 거부·카메라 없음 안내
- 공식 QR URL의 HTTPS 주소와 토큰 검증
- 잘못된 QR·중지된 QR 안내
- 카메라 사용 불가 시 직접 입력 방식 제공

카메라 스캔 기능은 선택적 모듈로 구현하고, QR 화면을 열기 전에는 관련 라이브러리를 불러오지 않도록 해 주세요.

## 2. 중앙 QR 프로필 연동

기존 중앙 서비스 주소와 프로필 스키마는 유지해 주세요.

SDK는 프로필 조회를 위한 공통 인터페이스를 제공하되, 각 키오스크의 same-origin 서버 중계를 통해 중앙 API에 접근하도록 구성해 주세요.

- 브라우저에 비밀키 저장 금지
- QR 토큰 로그 출력 금지
- 스캔한 QR 주소를 외부 요청 URL로 직접 사용하지 않기
- 허용된 중앙 서비스 주소만 인정
- QR 토큰 형식 및 응답 스키마 검증
- 실패 시 접근성 설정을 임의 적용하지 않기
- 조회 완료 이전에 새로운 스캔을 중복 처리하지 않기
- 조회 중 취소하거나 화면을 닫을 수 있도록 하기

QR 카메라 인식, 토큰 검증, 프로필 조회 인터페이스는 공통화하되 서버 중계의 실제 구현과 비밀키 관리는 호스트 서버가 담당하도록 해 주세요.

## 3. 기존 SDK 기능 유지

v0.1.0에 구현된 기능을 모두 유지합니다.

- 큰 글씨
- 큰 버튼
- 고대비
- 화면 단순화용 공통 스타일
- 하단 조작 규칙
- 스마트 길잡이
- 음성 안내
- 레이아웃 진단
- SDK 해제 및 기본 상태 복원

SDK는 주문·결제·민원 발급 등의 업무 로직을 실행하지 않습니다.

## 4. 독립 패키지 빌드

패키지 버전을 v0.2.0으로 올려 주세요.

다음 파일을 생성해 주세요.

`naebangsik-kiosk-accessibility-sdk-0.2.0.tgz`

JavaScript 빌드, 타입 선언 파일, CSS, README, QR 스캔 모듈이 포함되어야 합니다.

다른 Replit 프로젝트에서 파일을 업로드하고 npm install로 설치할 수 있어야 합니다.

npm 공개 게시 및 Publish는 하지 마세요.

## 5. 독립 프로젝트 검증

데모커피 내부 테스트만으로 완료 처리하지 마세요.

임시 외부 소비자 프로젝트에서 v0.2.0 패키지를 설치하고 다음 사항을 검증해 주세요.

- SDK 설치 및 import
- 기존 접근성 프로필 적용
- QR 스캐너 모듈 import
- 정상 QR 디코딩
- 잘못된 QR 거부
- 카메라 권한 거부와 대체 입력
- QR 스캔 성공 후 카메라 종료
- 서버 프로필 조회 인터페이스
- SDK 해제 후 기본 화면 복원

모의 카메라·모의 중앙 API 테스트와 실제 카메라·실제 중앙 API 테스트를 구분해서 보고해 주세요.

## 6. 데모커피 회귀 테스트

기존 카페의 스캐너를 SDK 공통 모듈을 사용하는 구조로 이전해 주세요.

다음 기능은 그대로 유지해야 합니다.

- 카메라 스캔 및 QR 직접 입력
- 접근성 프로필 적용
- 메뉴 선택과 옵션
- 장바구니 및 주문 확인
- 스마트 길잡이의 상황별 안내
- 가상 결제와 주문 완료
- 완료 후 기본 설정 초기화

중복된 QR 스캔 코드는 정리하되 디자인과 주문 로직은 변경하지 마세요.
