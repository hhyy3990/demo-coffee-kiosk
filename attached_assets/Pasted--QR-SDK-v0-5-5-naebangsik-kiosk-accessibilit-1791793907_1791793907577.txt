# 내 방식 QR — 무인민원발급기 공통 SDK v0.5.5 설치 및 최종 브라우저 검증

현재 무인민원발급기 프로젝트에는 `@naebangsik/kiosk-accessibility-sdk@0.5.4`가 설치되어 있습니다.

이번에 첨부한 파일은 데모커피 프로젝트에서 개발·검증한 공통 SDK v0.5.5 tarball입니다.

이번 작업의 목적은 **SDK v0.5.5 설치 후 무인민원발급기에서 상단 제목 잘림, 스크롤 되돌아감, 화면 전환 스크롤 잔류 문제가 모두 해결됐는지 확인하는 것**입니다.

새로운 기능을 추가하는 작업이 아닙니다. 기존 호스트 코드 변경을 최소화해 주세요.

## 1. SDK v0.5.5 설치

첨부 tarball을 확인하고 기존 v0.5.4를 교체합니다.

- 패키지명: `@naebangsik/kiosk-accessibility-sdk`
- 버전: `0.5.5`
- 기존 `notifyScreenChange()` API 유지
- QR v3 `viewportMode` 자동 적용 유지
- QR 도크 및 하단 고정 조작부 연동 유지
- 기존 v0.5.4 tarball 보존

패키지 버전뿐 아니라 실제 설치된 JavaScript·CSS가 v0.5.5 내용인지 확인해 주세요.

`node_modules` 또는 SDK 내부 소스는 직접 수정하지 않습니다.

## 2. 호스트 연결 구조 유지

v0.5.4에서 이미 적용한 다음 구조를 유지합니다.

- 업무 화면 전환 시 `notifyScreenChange(screenId)` 호출
- 같은 화면의 상태 변경에서는 스크롤 유지
- QR 모달 열기·닫기에서는 스크롤 유지
- 실제 scrollArea 어댑터 등록
- QR 도크 첫 화면 전용 표시
- 업무 완료 후 `endSession()` 초기화

기존 연결이 정상이라면 다시 작성하지 마세요.

단, 새 SDK의 공개 계약에 맞지 않는 부분이 실제로 확인되면 최소한으로 수정하고 이유를 보고해 주세요.

## 3. 1440×900 상단 제목 잘림 재검증 — 최우선

이전 무인민원발급기에서 다음 문제가 있었습니다.

- 화면 크기: 1440×900
- 큰 글씨·큰 버튼·고대비
- 하단 80% 모드
- `.stage` 시작 y=166px
- 첫 제목 시작 y=144px
- 제목 일부가 스크롤 표시 영역 위로 밀려 잘림
- 첫 제목 중앙 hit-test 실패

v0.5.5의 공통 SDK에는 안전 중앙 정렬 기능이 포함되어 있습니다.

동일한 조건을 재현해 다음을 측정합니다.

- `.stage` 시작·끝 좌표
- 첫 제목 시작·끝 좌표
- 첫 제목 전체 표시 여부
- 제목 중앙 hit-test
- scrollTop=0일 때 첫 콘텐츠 가시성
- 마지막 메뉴까지 스크롤 가능한지

**합격 기준: 첫 제목 전체가 실제 표시 영역 안에 있어야 하고, 상단이 잘리면 안 됩니다.**

SDK가 설정한 하단 viewport의 시작 위치 자체는 0이 아니어도 정상입니다.

## 4. 스크롤 되돌아감 재검증

기존 SDK에서는 스크롤 안내 요소를 제거하는 과정에서 Chromium의 스크롤 위치가 위로 되돌아가는 문제가 있었습니다.

v0.5.5에서는 안내를 즉시 DOM에서 제거하는 대신 시각적·접근성 트리에서 숨기는 방식으로 수정했습니다.

다음 조건을 검사해 주세요.

- 320×844
- 360×667
- 390×844
- 1440×900
- 큰 글씨 및 큰 버튼
- 하단 60·70·80%

검증 절차:

1. 증명서 메뉴를 표시합니다.
2. 실제 휠 또는 Chromium 터치 에뮬레이션으로 아래로 스크롤합니다.
3. 마지막 메뉴까지 도달합니다.
4. 마지막 메뉴 전체가 표시되는지 확인합니다.
5. 실제 hit-test 및 클릭을 실행합니다.
6. 최하단에서 스크롤 위치를 측정합니다.
7. 100ms·500ms·1초·3초 후 위치를 다시 측정합니다.
8. 의도치 않은 스크롤 되돌아감이 없는지 확인합니다.
9. 다시 위로 스크롤했을 때 상단 콘텐츠에 접근 가능한지 확인합니다.

강제로 scrollTop을 최대값으로 설정하는 검사는 별도의 진단으로만 사용합니다.

**사용자 입력으로 끝까지 스크롤하고 마지막 메뉴를 클릭할 수 있어야 합격입니다.**

## 5. 화면 전환 API 회귀

다음 화면 전환을 실제로 진행합니다.

- 첫 화면 → 증명서 선택
- 증명서 선택 → 주민등록번호 입력
- 주민등록번호 입력 → 지문 확인
- 지문 확인 → 발급 옵션
- 발급 옵션 → 신청 내용 확인
- 신청 내용 확인 → 가상 결제
- 가상 결제 → 완료
- 전화면 복귀
- 처음화면 복귀

각 단계 진입 직후 첫 제목이 보이는지 확인합니다.

스크롤을 중간까지 내린 뒤 다음 화면으로 이동하는 경우도 반드시 포함합니다.

측정 항목:

- document.scrollTop
- `.stage.scrollTop`
- 실제 scrollArea.scrollTop
- 첫 콘텐츠 위치
- 첫 콘텐츠 hit-test
- QR 도크 활성화 여부

반대로 같은 화면에서 번호 입력·선택값 변경·모달 열기·닫기를 할 때는 기존 스크롤 위치가 유지되어야 합니다.

## 6. QR v1/v2/v3 및 하단 모드 검증

중앙 Production 서버는 아직 v3로 배포되지 않았으므로, 우선 기존처럼 브라우저 응답 모의를 사용합니다.

검증 항목:

- v1 QR 형식 정상 처리
- v2 QR 형식 정상 처리
- v3 `viewportMode: null` 정상 처리
- v3 하단 60% 적용
- v3 하단 70% 적용
- v3 하단 80% 적용
- QR 프로필 자동 적용
- QR 도크 표시·제거
- QR 도크 높이 재측정
- 세션 종료 후 설정 초기화

v1/v2의 구형 `bottomControls`를 방법 B 하단 viewport로 임의 변환하면 안 됩니다.

호스트에서 SDK를 우회하여 `setViewportMode()`를 중복 호출하지 마세요.

## 7. 하단 고정 조작부 및 접근성 검증

다음 기능을 검사합니다.

- 고정 하단 홈·이전 버튼 유지
- QR 도크와 고정 조작부 겹침 없음
- 스크롤 안내 정상 표시
- 최하단에서 스크롤 안내 숨김
- 위로 이동하면 안내 재표시
- 스마트 길잡이 정상 표시·종료
- 모달 내부 스크롤과 업무 화면 스크롤 구분
- 큰 글씨·큰 버튼·고대비 유지
- 가로 넘침 없음
- 이중 스크롤 없음

스크롤 안내가 화면에서 숨겨져도 DOM에 남아 있는 것은 v0.5.5에서 의도된 동작입니다.

이것을 오류로 판정하지 마세요.

다만 숨겨진 안내가 클릭을 가로채거나 스크린리더에서 읽힌다면 실제 오류입니다.

## 8. 전체 발급 흐름 검증

390×844에서 큰 글씨·큰 버튼·고대비·하단 80% v3 모의 프로필을 적용하고 다음 흐름을 진행합니다.

11. 발급 완료

실제 개인정보나 결제 정보는 사용하지 않습니다.

업무 단계마다 상단 잘림과 스크롤 잔류가 없는지도 확인합니다.
