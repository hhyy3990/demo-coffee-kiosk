# 긴급 재수정 — 공통 SDK v0.5.17 실제 모바일 안내 오류 해결

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`입니다.

현재 SDK 버전은 v0.5.17입니다.

이전 작업에서 안내창 오류를 수정했다고 보고했지만, 사용자가 실제 Development Preview에서 다시 테스트한 결과 **동일한 오류가 계속 발생합니다.**

따라서 이번 작업은 기존 테스트 성공을 근거로 완료 처리하지 말고, 실제 데모커피 접근성 체험 모드에서 아래 증상을 재현하는 것부터 시작하세요.

## 1. 실제 사용자에게 발생하는 오류

### A. 스크롤하면 쉬운 말 안내가 사라짐

쉬운 말 안내가 표시된 상태에서 화면을 스크롤하면 안내창이 없어집니다.

사용자가 접기나 닫기를 누르지 않았고 업무 단계도 변경되지 않았습니다.

원인을 다음과 같이 구분하세요.

- 내부 안내 상태가 삭제되는 것인지
- DOM에서 패널이 제거되는 것인지
- SDK의 안전 배치 로직이 숨기는 것인지
- 패널이 화면 밖으로 이동하는 것인지
- 다른 요소에 가려지는 것인지

단순히 데이터가 메모리에 남아 있다는 이유로 정상이라고 판단하지 마세요.

**사용자가 실제로 안내를 볼 수 있어야 정상입니다.**

### B. 스마트 길잡이도 스크롤하면 사라짐

스마트 길잡이가 표시된 뒤 사용자가 스크롤하면 안내창이 사라집니다.

스마트 길잡이는 설정된 10초 또는 15초 동안 표시되어야 합니다.

스크롤 자체가 타이머를 취소하거나 안내를 종료해서는 안 됩니다.

안전한 위치에 펼친 패널을 표시할 수 없다면 접힌 안내 헤더 등 안전한 대체 방식을 검토하세요.

단, 주요 업무 버튼을 가리도록 강제하지 마세요.

### C. 옵션 선택 화면에서 쉬운 말이 늦게 나타남

사용자가 메뉴를 선택한 뒤 옵션 화면으로 이동하면 쉬운 말 안내가 즉시 표시되지 않습니다.

약 10초 뒤 스마트 길잡이가 나타난 이후에야 쉬운 말 안내가 보입니다.

정상 동작:

1. 옵션 화면 진입
2. 쉬운 말 안내 즉시 표시
3. 10초 동안 조작이 없으면 스마트 길잡이 표시
4. 스마트 길잡이 15초 유지
5. 기존 쉬운 말 안내로 복귀

쉬운 말이 스마트 길잡이의 타이머에 종속되면 안 됩니다.

### D. 주문 확인 화면에서도 쉬운 말이 늦게 나타남

주문 확인 화면 진입 후 쉬운 말 안내가 바로 표시되지 않습니다.

스마트 길잡이가 나타난 다음에야 쉬운 말이 보입니다.

옵션 화면과 동일하게 **화면 진입 즉시 쉬운 말 안내가 표시되도록** 수정하세요.

### E. 스마트 길잡이 페이지 중복 오류

현재 쉬운 말 안내가 2페이지인 화면에서 스마트 길잡이가 시작되면 다음 문제가 발생합니다.

- 스마트 길잡이에 1/2 표시
- 다음 버튼을 누르면 2/2 표시
- 두 페이지의 스마트 길잡이 문구가 동일함

이 오류는 이전 v0.5.17 수정 이후에도 계속 발생합니다.

**스마트 길잡이 모드에는 쉬운 말의 페이지 수와 이전·다음 버튼이 절대 표시되면 안 됩니다.**

스마트 길잡이는 현재 단계의 안내 문구 하나만 표시하세요.

모드별 상태를 분리하세요.

- Easy Language: explanations 배열, currentIndex, 접힘 상태
- Smart Guide: 현재 단계 문구, 표시 시작 시점, 남은 시간

스마트 길잡이가 종료되면 Easy Language의 기존 페이지와 접힘 상태를 복원합니다.

### F. 첫 화면 안내 표시

데모커피 첫 화면에서는 사용자가 요청한 대로 쉬운 말 안내를 표시하지 않습니다.

단, 첫 화면에서 메뉴를 선택해 업무 화면으로 진입하면 해당 단계의 쉬운 말은 즉시 표시되어야 합니다.

첫 화면에서 제거한 안내 상태가 다음 단계에 잘못 영향을 주지 않는지도 확인하세요.

## 2. 구조적인 원인 조사

SDK의 다음 항목을 조사하세요.

- setEasyLanguageState() 호출 시점
- setGuideState() 호출 시점
- notifyScreenChange() 호출 순서
- stepId 변경과 패널 렌더링 순서
- useEffect 및 호스트 상태 변경
- 안내 패널 DOM 생성·갱신·제거
- Easy Language와 Smart Guide의 공통 렌더러
- 이전·다음 버튼 및 페이지 카운터 생성 조건
- 스크롤 이벤트와 배치 재측정
- guide-suppressed 조건
- MutationObserver / ResizeObserver 이벤트
- 스마트 길잡이 대기·표시·종료 타이머

특히 **스마트 길잡이 시작 시에만 쉬운 말 패널이 처음 생성되는 구조인지**, 그리고 **스크롤 시 DOM 상태와 실제 화면 표시 상태가 달라지는지** 확인하세요.

부분적인 CSS 보정으로 증상을 숨기지 말고 원인이 되는 상태 관리 흐름을 수정하세요.

## 3. 실제 데모커피에서 재현 테스트 필수

테스트는 독립 fixture만 사용하지 말고 **현재 데모커피 Development Preview의 실제 접근성 체험하기 흐름**에서 진행하세요.

### 시나리오 A — 옵션 화면

1. 접근성 체험하기 클릭
2. 메뉴 선택
3. 옵션 화면 진입
4. 쉬운 말 안내가 즉시 표시되는지 확인
5. 스마트 길잡이 시작 전에도 쉬운 말이 보이는지 확인
6. 화면 스크롤
7. 쉬운 말이 계속 보이는지 확인
8. 약 10초 후 스마트 길잡이 시작
9. 스마트 길잡이 표시 중 스크롤
10. 안내가 사라지지 않는지 확인
11. 15초 후 쉬운 말로 복귀

### 시나리오 B — 주문 확인 화면

1. 메뉴 담기
2. 주문 확인 화면 진입
3. 쉬운 말 안내 즉시 표시
4. 안내 설명 1/2 → 2/2 이동
5. 스마트 길잡이 시작
6. 스마트 길잡이에 페이지 번호 및 이전·다음 버튼 없음
7. 스마트 길잡이 문구 중복 없음
8. 길잡이 종료 후 이전 쉬운 말 페이지 복원

### 시나리오 C — 스크롤 안정성

- 쉬운 말 표시 중 10회 이상 스크롤
- 스마트 길잡이 표시 중 10회 이상 스크롤
- 스크롤 전후 실제 DOM 존재·visibility·opacity·boundingRect·hit-test 확인
- 안내창이 화면에 실제로 보이는지 확인
- 불가피하게 숨긴 경우 원인 및 안전한 대체 접근 경로 기록

단순히 내부 SDK의 상태가 유지된다는 결과만으로 통과 처리하지 마세요.

## 4. 안내창 배치 정책 재검토

현재 SDK는 안내창과 버튼이 겹치면 숨기는 정책을 사용합니다.

그러나 실제 사용자에게는 스크롤할 때 안내가 사라지는 문제가 발생하고 있습니다.

다음 대안을 비교해 가장 적절한 공통 방식을 선택하세요.

- 안정적인 고정 안내 영역
- 펼친 안내가 불가능하면 접힌 헤더 유지
- 주요 업무 버튼을 피하는 안전한 화면 영역
- 스크롤 중 불필요한 재배치 최소화

기존 하단 조작 60/70/80%, 키패드·결제 버튼 보호 원칙은 유지하세요.

특정 카페 화면에만 맞는 좌표값을 하드코딩하지 마세요.

안내가 업무 버튼을 가리는 것과 안내가 사용자의 의사와 관계없이 사라지는 것 모두 실패입니다.

## 5. 기존 성능 문제 재발 방지

v0.5.16에서 수정한 브라우저 무응답 방지 로직을 유지하세요.

- Observer 무한 루프 없음
- 프레임 단위 재측정
- 장시간 메인 스레드 점유 방지
- 터치·스크롤 조작 정상
- 주문 전체 흐름 정상

이전 수정으로 해결한 문제가 재발하지 않아야 합니다.

## 6. 새 SDK 릴리스

SDK 소스 수정이 필요하면 v0.5.18로 버전을 올리세요.

기존 v0.5.17 및 이전 릴리스는 보존합니다.

새 tarball:

packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.18.tgz

독립 소비자 설치·타입 검사·빌드뿐 아니라 실제 데모커피 브라우저 상호작용을 통과해야 릴리스 성공으로 보고하세요.

실제 사용자 증상이 재현되지 않거나 해결 여부를 확인하지 못했다면 검증 완료로 보고하지 마세요.

기존 테스트만 통과했다고 완료 처리하지 말고, 실제 사용자가 경험한 동작이 해결됐는지 브라우저 화면 기준으로 검증해 주세요.
