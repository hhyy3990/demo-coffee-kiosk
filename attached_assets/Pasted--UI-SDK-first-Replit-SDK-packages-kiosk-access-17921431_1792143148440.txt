# 데모커피 — 접근성 UI 최종 사용성 개선 (SDK-first)

현재 프로젝트는 **데모커피 Replit**이며, 공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`입니다.

현재 공통 SDK 버전은 v0.5.22입니다.

사용자가 실제 휴대전화 화면에서 접근성 체험 모드를 테스트한 결과 전반적인 안내 기능은 개선됐지만, 아래 네 가지 사용성 문제가 남아 있습니다.

이번 작업은 새로운 기능 개발이 아니라 기존 접근성 기능의 사용성 개선입니다.

## 1. 필수 원칙

**SDK-first 원칙을 유지하세요.**

- 안내 패널의 공통 디자인·버튼 크기·스크롤 힌트는 공통 SDK 원본에서 수정
- 쉬운 말의 실제 설명 문구는 데모커피 호스트 안내 데이터에서 수정
- 메뉴 분류 탭의 스크롤 위치는 먼저 원인을 조사하고, SDK 영향이면 SDK에서, 데모커피의 자체 레이아웃 문제이면 호스트에서 수정
- 공통 SDK의 결함을 데모커피 전용 CSS로 우회하지 말 것
- 다른 프로젝트, 중앙 QR, 운영 DB 수정 금지
- Publish 금지

## 2. 첫 화면에서 스크롤 안내가 나오지 않는 문제

사용자가 데모커피 첫 화면에서 아래쪽에 더 볼 내용이 있는데도 스크롤 안내가 표시되지 않는 현상을 발견했습니다.

먼저 실제 화면에서 스크롤 가능 여부를 확인하세요.

- 실제 스크롤 소유자
- scrollHeight
- clientHeight
- scrollTop
- 현재 SDK에 등록된 스크롤 영역
- 스크롤 힌트 표시 조건
- 접근성 체험 시작 직후 SDK 적용 순서

첫 화면에서 실제로 아래에 더 볼 내용이 있다면 **스크롤 안내가 반드시 표시되어야 합니다.**

기존 v0.5.22 정책을 유지합니다.

- 쉬운 말·스마트 길잡이 유무와 관계없이 표시
- 하단 60·70·80% 및 일반 화면에서 동일
- 버튼과 겹친다는 이유로 숨기지 않음
- 스크롤 안내는 클릭을 가로채지 않음
- 스크롤 중 위치가 위아래로 뛰지 않음
- 더 내릴 내용이 없을 때만 숨김

첫 화면에 쉬운 말 안내는 추가하지 마세요. 첫 화면에서 쉬운 말 안내가 없는 것은 사용자의 의도입니다.

## 3. 쉬운 말 안내 문구 전면 개선

현재 데모커피의 쉬운 말 안내가 스마트 길잡이와 비슷하게 행동 순서를 설명하고 있습니다.

두 기능의 역할을 명확히 구분하세요.

### 쉬운 말 안내

**용어, 선택지, 개념의 뜻을 일상적인 말로 설명합니다.**

좋은 예시:

- 메뉴 분류: 비슷한 음식을 모아 놓은 거예요.
- 음료 옵션: 음료를 내 취향에 맞게 고르는 거예요.
- 아이스: 차갑게 만든 음료예요.
- 핫: 따뜻하게 만든 음료예요.
- 사이즈: 음료를 얼마나 많이 담을지 고르는 거예요.
- 장바구니: 고른 메뉴를 주문 전에 모아 두는 곳이에요.
- 주문 확인: 내가 고른 음식과 가격이 맞는지 살펴보는 화면이에요.
- 결제 수단: 돈을 내는 방법이에요.

### 스마트 길잡이

**지금 화면에서 무엇을 해야 하는지 알려줍니다.**

좋은 예시:

- 원하시는 메뉴를 선택해 주세요.
- 따뜻한 음료와 차가운 음료 중 하나를 고르고 다음으로 진행하세요.
- 장바구니에 담긴 메뉴와 가격을 확인해 주세요.
- 결제 방법을 선택해 주세요.

### 작성 기준

- 쉬운 말과 스마트 길잡이에 같은 내용 반복 금지
- 쉬운 말은 '이게 무슨 뜻이지?'라는 질문에 답하도록 작성
- 스마트 길잡이는 '지금 뭘 해야 하지?'에 답하도록 작성
- 어려운 용어를 또 다른 어려운 용어로 설명하지 않기
- 한 설명에 하나의 핵심 개념만 포함
- 문장은 짧고 친절하게
- 사용자에게 필요한 설명만 제공
- 같은 단계에 설명이 여러 개면 기존 이전·다음 기능 활용
- 실제 화면에 없는 선택지나 기능을 설명하지 않기

데모커피의 실제 메뉴 선택, 옵션, 장바구니, 주문 확인, 결제 화면을 모두 점검하세요.

첫 화면에는 쉬운 말을 추가하지 않습니다.

AI API를 연결하지 않고 검증된 고정 문구를 개선합니다.

## 4. 안내 패널 버튼의 세로 크기 축소

사용자가 제공한 사진에서 공통 패널의 다음 조작 버튼이 여전히 세로로 커 보입니다.

- 접기: V
- 펼치기: ^
- 이전
- 다음

현재 버튼의 시각적 높이, 실제 클릭 영역, 패딩, 글씨 크기, line-height를 측정하세요.

### 개선 목표

- 현재보다 시각적인 세로 점유 공간을 조금 더 줄이기
- 패널 전체 높이를 가능하면 추가 축소
- 본문 설명의 글씨 크기와 줄 간격은 유지
- 이전·다음 버튼 글자는 충분히 읽을 수 있도록 유지
- 버튼 사이의 불필요한 여백 축소
- 작은 화면에서도 버튼끼리 겹치지 않음

### 접근성 조건

실제 버튼의 터치 영역은 **44×44 CSS px 이상** 유지합니다.

터치 영역을 줄이는 대신 버튼 안쪽 장식, 테두리, 패딩 또는 주변 여백을 줄이는 방식을 사용하세요.

보이지 않는 클릭 영역을 확보하더라도 인접 버튼과 터치 영역이 겹치지 않도록 하세요.

접기·펼치기 기호에는 명확한 접근성 이름을 유지하세요.

큰 글씨, 큰 버튼, 고대비 모드도 계속 지원해야 합니다.

공통 SDK의 안내 버튼에만 적용하고 업무 버튼 전체를 작게 만들지 마세요.

SDK 수정 전후 패널 높이와 버튼 크기를 보고하세요.

## 5. 메뉴 분류 탭이 스크롤을 따라 내려오는 오류

데모커피의 메뉴 선택 화면에는 다음과 같은 가로 분류 탭이 있습니다.

- 커피·음료
- 케이크
- 디저트 등 기존 카테고리

현재 사용자가 화면을 아래로 스크롤하면 가로 분류 탭 영역이 원래 위치에 남지 않고 화면 아래쪽을 따라 움직입니다.

### 원하는 동작

- 메뉴 분류 탭은 메뉴 목록 상단의 원래 위치에 배치
- 사용자가 메뉴 목록을 스크롤하면 탭도 일반 콘텐츠처럼 자연스럽게 위로 지나감
- 화면 아래쪽을 따라 내려오는 현상 제거
- 가로 탭 넘기기와 카테고리 선택은 정상 유지
- 현재 선택된 카테고리 표시 유지
- 메뉴 카드 클릭 및 장바구니 이동 유지

### 원인 조사

다음을 먼저 구분하세요.

- 데모커피 호스트 자체의 position: sticky/fixed
- 스크롤 소유자와 탭의 부모 요소 관계
- 하단 viewportMode 적용 시 레이아웃 영향
- SDK의 요소 위치 변경 여부
- 스크롤 위치에 따른 탭 transform 또는 positioning 변경 여부

호스트 자체의 sticky/fixed 설정 때문에 발생한다면 해당 화면의 레이아웃만 수정할 수 있습니다.

SDK의 공통 뷰포트 처리 때문에 발생한다면 SDK에서 수정하세요.

다른 키오스크의 하단 조작 기능에 영향을 주는 임시 CSS 우회는 하지 마세요.

## 6. 검증 환경

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

접근성 모드:

- 일반 화면
- 하단 조작 60%
- 하단 조작 70%
- 하단 조작 80%

큰 글씨·큰 버튼·고대비를 함께 활성화한 조합도 확인하세요.

필수 실제 브라우저 검증:

1. 첫 화면 스크롤 안내 표시
2. 스크롤 중 안내 위치 고정
3. 메뉴 분류 탭이 아래로 따라오지 않음
4. 가로 탭 전환 정상
5. 메뉴 카드 선택 정상
6. 옵션 화면 쉬운 말 즉시 표시
7. 쉬운 말 설명과 스마트 길잡이 내용 구분
8. 접기·펼치기 조작
9. 이전·다음 조작
10. 스마트 길잡이 15초 유지
11. 스크롤 중 쉬운 말·길잡이 유지
12. 장바구니·주문 확인
13. 결제 시뮬레이션
14. 주문 완료 후 처음 화면 복귀

## 7. 기존 기능 회귀 방지

다음 기능을 유지하세요.

- QR v1~v4
- 하단 60/70/80% 지원
- 일반 화면 안내 위치 안정성
- 쉬운 말 즉시 표시
- 스마트 길잡이 10/15/20초 대기
- 동일 단계 입력 중 스마트 길잡이 10/15초 유지
- 쉬운 말 페이지·접힘 상태 복원
- 스크롤 힌트 상시 표시 정책
- 접기·펼치기 및 이전·다음
- QR 도크
- 주문 완료 후 자동 복귀
- SDK Observer 무한 루프 방지

## 8. SDK 버전

공통 SDK 소스가 변경된다면 **v0.5.23**으로 버전을 올리세요.

새 tarball:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.23.tgz`

기존 v0.5.22 및 이전 tarball은 보존하세요.

새 SDK 패키지를 독립 소비자 프로젝트에 설치해 검증하세요.

SDK 소스 변경 없이 호스트 안내 데이터와 탭 레이아웃만 수정한 경우라면 불필요하게 SDK 버전을 올리지 마세요.

## 9. 작업 범위 제한

- 데모커피 Replit만 수정
- 공통 문제는 SDK 원본에서 수정
- 데모커피 전용 문제는 해당 화면 호스트 코드에서만 수정
- 무인민원발급기 프로젝트 수정 금지
- 중앙 QR 서비스 수정 금지
- 운영 DB 수정 금지
- QR 스키마 변경 금지
- AI 기능 추가 금지
- Publish 금지

**최종 성공 기준은 데모커피 첫 화면에서 스크롤이 필요할 때 안내가 표시되고, 쉬운 말은 어려운 표현을 쉽게 설명하며, 공통 안내 패널은 더 간결해지고, 메뉴 분류 탭은 스크롤을 따라 내려오지 않는 것입니다.**

기존 기능이 정상 작동하면서 실제 브라우저 화면에서 문제가 해결됐는지 확인해 주세요.
