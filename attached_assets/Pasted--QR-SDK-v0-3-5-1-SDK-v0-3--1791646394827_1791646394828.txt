# 내 방식 QR 공통 SDK v0.3.5.1 — 스크롤 튐 긴급 수정, 범용 스크롤 안내 및 이동 버튼 강조 개선

현재 데모커피와 독립 무인민원발급기에는 공통 SDK v0.3.5가 적용돼 있습니다.

실제 QR을 적용해 사용한 결과, 두 키오스크에서 스크롤을 아래로 내리면 자동으로 중간 위치까지 튀어 올라가 마지막 주문·결제·확인 버튼에 접근하기 어려운 심각한 오류가 확인됐습니다.

또한 스크롤 안내 문구가 카페의 상품 화면에 맞춰져 있어 다른 키오스크에 그대로 재사용하기 어렵고, 메뉴 이동 버튼 강조도 너무 강한 검은색 테두리 방식입니다.

이번에는 이 문제들을 공통 SDK v0.3.5.1에서 수정해 주세요.

**작업 우선순위는 다음과 같습니다.**

1. 스크롤이 튀어 올라가는 오류 해결
2. 스크롤 안내의 표시·숨김과 필수 버튼 접근성 정상화
3. 모든 키오스크에 적용 가능한 안내 문구 통일
4. 기존 메뉴 이동 버튼의 5초간 부드러운 깜빡임 강조
5. 데모커피 및 독립 HTML 구조에서 회귀 검증

중앙 QR 서버와 무인민원발급기 프로젝트는 수정하지 않습니다.

---

## 1. 스크롤이 자동으로 튀어 올라가는 오류 해결

사용자가 QR 프로필을 적용한 뒤 스크롤을 아래로 내리면 화면이 중간 지점까지 자동으로 되돌아오는 현상이 발생합니다.

특히 화면 최하단에 있는 주문·결제 버튼을 확인할 수 없고 스크롤 안내도 사라지지 않습니다.

다음 항목을 조사해 정확한 원인을 확인해 주세요.

- 문서 및 내부 컨테이너의 scrollTop / scrollY
- scrollHeight / clientHeight
- 실제 최대 스크롤 거리
- 스크롤 이벤트 발생 순서
- MutationObserver / ResizeObserver 재실행 횟수
- SDK 글씨 확대 스타일 재적용 시점
- SDK 레이아웃 자동 보정 및 롤백
- 스크롤 안내 UI의 생성·삭제 및 위치 갱신
- 브라우저 scroll anchoring
- 키보드·입력 포커스 복원
- 데모커피의 화면 단계 전환 시 일회성 스크롤 초기화 코드

특히 SDK의 스크롤 안내 갱신 때문에 텍스트 확대나 전체 레이아웃 보정이 반복 실행되는지 확인해 주세요.

사용자가 스크롤하는 동안 SDK가 불필요하게 DOM 크기·스타일을 재설정해서는 안 됩니다.

단순히 스크롤 위치를 강제로 맨 아래로 되돌리는 임시 처리는 금지합니다.

스크롤 안내 위치·표시 상태 변경이 화면의 스크롤 가능한 전체 높이에 불필요하게 영향을 주지 않도록 해 주세요.

### 합격 기준

- 끝까지 스크롤할 수 있음
- 마지막 버튼이 실제 화면에 표시됨
- 사용자가 스크롤을 멈춘 뒤 화면이 다시 위로 튀지 않음
- 최하단에 도달하면 안내가 사라짐
- 안내가 사라져도 스크롤 위치가 갑자기 바뀌지 않음
- 마지막 주문·결제·확인 버튼을 실제로 클릭할 수 있음

## 2. 모든 키오스크에 적용 가능한 세로 안내 문구

기존의 카페 전용 문구인 다음 표현을 제거해 주세요.

- 아래에도 상품이 있습니다.
- 아래에도 증명서 메뉴가 있습니다.
- 아래에 결제 버튼이 있습니다.

앞으로 공통 SDK는 아래 두 가지 문구만 사용합니다.

**기본 문구**

"아래에도 내용이 있습니다. 화면을 위로 밀어보세요."

**버튼이 아래에 있는 것이 확인된 경우**

"아래에도 버튼이 있습니다. 화면을 위로 밀어보세요."

카페·병원·은행·무인민원발급기 등 키오스크 종류에 관계없이 동일하게 사용해야 합니다.

### 안내 선택 기준

- SDK가 실제 스크롤 가능 영역을 감지
- 아래쪽에 더 스크롤할 수 있는 내용이 있으면 기본 문구 표시
- 등록되거나 안전하게 자동 식별된 주요 조작 버튼이 화면 아래에 있다면 버튼 안내 문구 표시
- 버튼이 아래에 있다는 것을 확실히 판단할 수 없으면 기본 문구 사용
- 화면이 마지막 스크롤 위치에 도달하면 안내 숨김
- 다시 위로 이동하면 안내 재표시
- 스크롤할 내용이 없다면 안내 미표시

문구를 키오스크별로 별도로 작성하지 않아도 정상 동작하도록 해 주세요.

기존 호스트 어댑터의 menuMessage처럼 문구를 덮어쓰는 기능이 있으면, 이번 두 공통 문구 정책에 맞게 사용 방식을 정리해 주세요.

안내를 표시하기 위해 상품명·증명서 이름·개인정보를 중앙 서버나 외부 AI에 전송하지 마세요.

## 3. 세로 스크롤 안내 위치 및 필수 버튼 접근성

안내는 기본적으로 화면 하단에 배치합니다.

### 하단 고정 조작부가 없는 키오스크

- 화면 하단에 안내 표시
- 일반 스크롤 콘텐츠와 시각적으로 일부 겹치는 것은 허용
- 클릭과 스크롤 입력은 방해하지 않음
- 최하단에 도달하면 안내 숨김

### 하단 고정 조작부가 있는 키오스크

- 처음화면·전화면·확인 등 하단 고정 버튼 위에 표시
- 고정 버튼을 가리지 않음
- 일반 콘텐츠 일부와 시각적으로 겹칠 수 있지만 모든 항목은 스크롤로 접근 가능해야 함

### 공통 요구사항

- 안내 표시·숨김이 스크롤 위치를 변경하지 않아야 함
- 마지막 필수 버튼의 접근 가능성 보장
- 하단 안내와 스마트 길잡이의 겹침 방지
- 화면 상단 브랜드·시계 헤더를 가리지 않음
- 큰 글씨·고대비에서도 안내가 읽힘
- SDK 안내 자체가 텍스트 자동 확대 대상에 중복 포함되지 않음
- 안내가 실제 클릭을 가로채지 않음
- 끝 위치에서 안내가 숨겨지는지 실제 DOM 좌표로 검증

현재 문제를 단순히 pointer-events:none으로 처리하고 성공으로 보고하지 마세요. 사용자가 버튼을 실제로 보고 누를 수 있어야 합니다.

## 4. 기존 이동 버튼 강조를 부드러운 깜빡임으로 변경

현재 SDK는 오른쪽 카테고리 이동 버튼에 강한 검은색 테두리를 표시합니다.

이를 스마트 길잡이와 유사하게 **약 5초간 부드럽게 깜빡이는 강조 효과**로 변경해 주세요.

강조는 시선을 끌되, 화면 내용이나 버튼 자체를 가리지 않는 방식이어야 합니다.

### 기본 시나리오

1. 카테고리 목록에 처음 진입
2. 오른쪽에 숨겨진 카테고리가 있으면 오른쪽 이동 버튼이 부드럽게 깜빡임
3. 약 5초가 지나면 깜빡임 자동 종료
4. 사용자가 오른쪽 버튼을 누르면 깜빡임 즉시 종료
5. 오른쪽 이동으로 왼쪽 버튼이 새롭게 활성화되면 왼쪽 버튼이 약 5초간 깜빡임
6. 사용자가 왼쪽 버튼을 누르면 깜빡임 즉시 종료

### 양방향 처리

- 처음 위치: 오른쪽 버튼만 강조
- 오른쪽 버튼을 누른 뒤 왼쪽 이동이 가능해지면 왼쪽 버튼 강조
- 중간 위치에서 양쪽 버튼이 활성화되더라도 무조건 두 버튼을 동시에 깜빡이지 않음
- 새롭게 이용 가능해진 방향 또는 아직 안내하지 않은 방향을 우선
- 마지막 위치에서 오른쪽 버튼은 강조하지 않음
- 왼쪽 버튼을 누르면 해당 강조 즉시 종료
- 강조가 끝난 버튼은 이동 가능 상태여도 계속 깜빡이지 않음

### 반복 방지

같은 카테고리 화면에서 사용자가 이미 해당 방향의 버튼을 눌렀다면, 그 방향의 깜빡임이 반복해서 시작되지 않도록 해 주세요.

스크롤 이벤트·ResizeObserver·DOM 재측정 때문에 5초 타이머가 재시작되어서는 안 됩니다.

화면을 완전히 떠났다가 새 사용자 세션으로 다시 들어오면 안내 상태를 초기화할 수 있습니다.

단순히 5초가 지났다는 이유로 강조가 영원히 비활성화되는 것은 아니며, 새로운 세션에서는 다시 안내할 수 있어야 합니다.

### 시각적 효과

- 과도한 검은색 이중 테두리 제거
- 부드러운 배경·윤곽선·그림자 변화 등으로 강조
- 약 5초 후 원래 버튼 스타일 복원
- 클릭 즉시 원래 스타일 복원
- 기존 hover/focus 스타일 유지
- 고대비 화면에서도 버튼 식별 가능
- `prefers-reduced-motion: reduce` 환경에서는 깜빡임 없이 정적인 강조를 짧게 제공
- 빠른 점멸이나 강한 밝기 변화 금지
- 버튼의 실제 클릭 영역·레이블·기능 변경 금지

SDK에서 새 버튼을 생성하거나 자동으로 클릭해서는 안 됩니다.

## 5. 버튼의 범용적 역할 인식

가로 이동 버튼의 강조는 화살표 모양이나 데모커피 전용 클래스만 보고 판단해서는 안 됩니다.

다음 정보들을 종합적으로 활용해 주세요.

- 버튼의 접근성 이름과 의미
- aria-controls로 연결된 목록
- 실제 목록의 이동 가능 방향
- 버튼의 disabled / aria-disabled 상태
- 버튼과 목록의 구조적 관계
- 현재 항목 및 스크롤 위치

예를 들어 다음과 같은 서로 다른 표현도 검토합니다.

- 다음 카테고리 보기
- 다음 메뉴
- 다음 항목
- Next category
- Next items
- 이전 목록
- Previous items

특정 문자열에 정확히 일치할 때만 작동하는 구조는 피해주세요.

단, 단순히 Next라고 표시됐다고 해서 주문·결제의 다음 단계 버튼을 가로 카테고리 이동 버튼으로 잘못 판단하지 마세요.

DOM만으로 역할이 불확실하면 임의로 강조하지 말고 기존 어댑터에서 선택적으로 의미 정보를 받을 수 있도록 해 주세요.

**범용성 검증을 위해 데모커피와 이름·DOM 구조가 다른 독립 fixture에서도 같은 기능이 작동해야 합니다.**

## 6. 스크롤 문제 원인 분리 브라우저 테스트

320×844, 390×844, 1080×1920에서 다음을 검증해 주세요.

- 문서 전체 세로 스크롤
- 내부 컨테이너 세로 스크롤
- 큰 글씨·큰 버튼·고대비 적용 상태
- 스크롤 안내가 나타난 상태에서 끝까지 이동
- 끝에 도달한 후 0.1초·0.5초·1초 대기
- 마지막 버튼 클릭 hit-test
- 화면 전환 후 맨 위 초기화
- 같은 화면에서 사용자가 스크롤하면 위치 유지
- SDK 글씨 확대 재측정 반복 여부
- SDK 안내 표시·숨김 반복 여부
- Observer 이벤트 중복 등록 여부

기존 카페의 화면 전환 스크롤 초기화는 단계가 실제로 바뀌는 경우에만 작동해야 합니다.

테스트 스크립트가 스크롤을 계속 강제로 재설정하면서 실제 문제를 가리지 않도록 해 주세요.

---

## 7. 화살표 깜빡임 동작 테스트

다음 조건을 독립 브라우저 fixture와 데모커피 실제 화면에서 확인해 주세요.

- 오른쪽 버튼 처음 활성화 시 강조 시작
- 오른쪽 버튼 클릭 후 강조 종료
- 왼쪽 버튼 활성화 시 강조 시작
- 왼쪽 버튼 클릭 후 강조 종료
- 클릭하지 않아도 약 5초 후 강조 종료
- 같은 세션에서 이미 안내한 방향은 반복 강조하지 않음
- 중간 위치에서 두 버튼이 동시에 과도하게 깜빡이지 않음
- 카테고리 이동 기능은 기존 호스트가 담당
- QR 설정 변경이나 스크롤 시 타이머가 무한 재시작되지 않음
- 세션 종료 후 스타일·타이머 정리

애니메이션 때문에 버튼이나 카테고리 목록의 크기가 변하지 않도록 해 주세요.

## 8. 기존 기능 유지

다음 기능은 모두 유지합니다.

- QR v1/v2 프로필 적용
- 전체 일반 텍스트 자동 확대
- 큰 글씨·아주 큰 글씨
- 큰 버튼·고대비
- 스마트 길잡이·음성 안내
- 기존 하단 조작 설정
- 세션 종료 초기화
- 화면 크기 변경 후 확대 재계산
- 기존 안전 레이아웃 진단 및 보정
- 데모커피의 카테고리 화살표 이동
- 주문·옵션·장바구니·가상 결제·완료
- 단계 전환 시 스크롤 위치 초기화

가로 스크롤 안내 UI는 다시 추가하지 마세요.

### 최종 합격 기준

1. 사용자가 스크롤을 끝까지 내려도 자동으로 튀어 올라가지 않습니다.
2. 마지막 주문·결제·확인 버튼이 실제로 보이고 클릭됩니다.
3. 스크롤 안내는 '내용' 또는 '버튼' 문구로만 표시되며, 끝까지 내리면 사라집니다.
4. 기존 좌우 메뉴 이동 버튼은 필요할 때 각각 최대 약 5초간 부드럽게 강조되고, 한 번 누르면 즉시 종료됩니다.
5. 동일한 SDK 기능이 데모커피 전용 클래스나 특정 한글 버튼 이름 없이도 독립 HTML 구조에서 동작합니다.

합격 기준을 충족하지 못한 부분은 테스트 통과로 포장하지 말고 미해결 사항으로 보고해 주세요.
