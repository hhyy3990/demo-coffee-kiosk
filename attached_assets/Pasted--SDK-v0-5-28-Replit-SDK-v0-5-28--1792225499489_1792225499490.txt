# 공통 SDK v0.5.28 — 미완료 오류 해결 및 검증 마무리

현재 데모커피 Replit에서 작업 중인 공통 SDK v0.5.28 후보를 이어서 작업하세요.

새로운 버전을 만들지 말고 현재 v0.5.28의 미완료 작업을 해결합니다.

**이번에는 이미 사용자가 승인한 기능과 오류 수정만 진행하세요. 새로운 기능이나 디자인 변경은 금지합니다.**

## 1. 최우선 — 하단 80% 쉬운 말 표시 문제

실제 Production QR 테스트에서 무인민원발급기의 쉬운 말이 한 글자씩 66페이지, 137페이지로 분할됐습니다.

현재 후보의 '한 줄도 들어갈 공간이 없으면 경고' 처리는 충분한 해결책이 아닙니다.

320×844, 360×667, 390×844에서 매우 큰 글씨·큰 버튼·쉬운 말·하단 80% 조합을 실제 브라우저로 검증하세요.

반드시 확인할 사항:

- 한 글자짜리 페이지가 비정상적으로 반복되지 않음
- 설명 원문 전체를 읽을 수 있음
- 본문과 버튼이 잘리지 않음
- 내부 스크롤 없음
- 이전·다음 정상 작동
- 상단 안내 위치 고정
- 하단 80% 업무 영역 유지

현재 높이에서 정상적인 표시가 물리적으로 불가능한 경우, 임의로 글씨를 줄이거나 업무 영역을 축소하거나 새 UI 방식을 추가하지 마세요.

정확히 어느 요소 때문에 공간이 부족한지 실측하고 사용자에게 보고하세요.

## 2. 긴 스마트 길잡이 잘림

카페와 무인민원발급기 모두 하단 80%에서 긴 스마트 길잡이 문구가 잘리는 문제가 있습니다.

기존 스마트 길잡이 단일 안내 구조를 유지하면서 실제 표시 가능한지 확인하세요.

본문 잘림을 발견했다면 해결 가능한 범위를 수정하되, 단일 안내를 임의로 여러 페이지로 바꾸거나 스크롤 기능을 추가하지 마세요.

현재 레이아웃으로 온전히 표시할 수 없다면 실측값과 필요한 선택지를 보고하고 기다리세요.

## 3. 하단 스크롤 안내 및 주문 확인 바

기존 수정에 따라:

- 주문 확인 바 없음 → 스크롤 영역 하단에 표시
- 주문 확인 바 있음 → 주문 확인 바 바로 위에 표시
- 주문 확인 바 사라짐 → 기존 위치 복귀

세 상태를 실제 브라우저에서 검증하세요.

스크롤 중 힌트가 위아래로 튀는 과거 오류가 재발하지 않아야 합니다.

현재 실제 스크롤 소유자가 window인지 하단 뷰포트인지 구분하고 올바른 요소의 좌표를 기준으로 검사하세요.

제품 코드를 테스트에 맞춰 임의로 변경하지 마세요.

## 4. 스마트 길잡이 자동 펼침

다음 동작을 실제 브라우저에서 검증하세요.

쉬운 말 접기 → 스마트 길잡이 시작 → 자동 펼침 → 정상 표시 시간 경과 → 기존 쉬운 말 접힘 상태 복원.

기존 10초 대기, slowGuidance 사용 시 15초 표시 정책을 유지합니다.

## 5. 전체 회귀 검증

다음 화면 크기를 확인하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

특히 확인할 항목:

- 쉬운 말 켬 + viewportMode null → 하단 80%
- 명시적 60·70·80% 설정 유지
- QR v1~v4 호환성
- 안내 패널 위치 안정성
- 스크롤 힌트 위치 안정성
- QR 도크
- 카페 주문 흐름
- 완료 후 초기화
- 카메라 미리보기 수정 상태

기존 QR 도크 테스트가 오래된 화면 구조를 가정하고 있다면 현재 제품 동작에 맞도록 테스트를 정정하세요. 제품의 정상 동작을 구식 테스트에 맞춰 변경하면 안 됩니다.

실기기 카메라 확인이 불가능하면 미검증으로 보고하세요.

## 6. 릴리스 조건

실패한 항목이 남아 있다면 완료 처리하지 말고, 실패 조건과 원인을 알려 주세요.

다른 버전으로 올리지 마세요.

중앙 내 방식 QR과 무인민원발급기 프로젝트는 수정하지 마세요.

Publish도 실행하지 마세요.
