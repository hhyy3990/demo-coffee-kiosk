# 내 방식 QR — 공통 SDK v0.5.9 후보: 스마트 길잡이 표시 보장 및 전체 화면 스크롤 안내 검증

현재 프로젝트는 데모커피 키오스크이며, 공통 접근성 SDK의 원본 소스도 이 프로젝트에서 관리합니다.

현재 SDK 릴리스 버전은 `@naebangsik/kiosk-accessibility-sdk@0.5.8`입니다.

이번 작업의 핵심 원칙은 **SDK 우선, 범용성 유지, 기존 기능 보존**입니다.

카페나 무인민원발급기만을 위한 임시 해결책을 SDK에 하드코딩하지 마세요.

## 1. 이번 작업 목표

다음 세 가지를 진행합니다.

**A. 스마트 길잡이 표시 보장**

작업 영역이 좁거나 하단 60% 모드여서 안전한 팝업 위치를 찾지 못하더라도, 스마트 길잡이가 활성화되어 있고 유효한 안내가 등록되어 있다면 화면에 안내가 나타나도록 개선합니다.

**B. 스마트 길잡이 기존 자동 사라짐 동작 유지**

기존 SDK에서 스마트 길잡이가 일정 시간이 지나면 자동으로 사라지는 기능과 정확한 표시 유지 시간을 먼저 확인합니다.

이미 정상 작동하고 있다면 기존 유지 시간을 그대로 사용하고, 새로운 자동 닫힘 타이머를 중복 구현하지 않습니다.

**C. 스크롤 안내 전체 화면 점검**

'↓ 아래에도 내용이 있어요' 안내가 실제로 스크롤이 필요한 화면에서 정상 표시되는지, 첫 화면뿐 아니라 다른 업무 화면까지 검증합니다.

## 2. 스마트 길잡이 표시 정책

기존 SDK가 대상 버튼 근처에서 팝업을 배치할 수 없는 경우 안내 자체를 표시하지 않는지 확인하세요.

다음 순서로 개선합니다.

1. 기존 팝업 배치 방식을 우선 사용
2. 공간 부족으로 배치에 실패하면 활성 작업 영역 안의 대체 위치 사용
3. 다른 버튼을 잠깐 덮더라도 안내가 보이도록 허용
4. 팝업이 화면 밖으로 잘리거나 완전히 가려지지 않도록 제한
5. 하단 60·70·80% 뷰포트에서도 가능한 위치에 표시
6. 안내 문구와 닫기 조작이 사용자에게 보여야 함

**다른 버튼을 잠시 가린다는 이유만으로 스마트 길잡이 표시를 취소하지 마세요.**

다만 안내가 표시되는 동안에도 비상·취소 등 안전상 중요한 조작을 장시간 막아서는 안 됩니다.

호스트 화면의 CSS를 직접 변경하는 대신, SDK의 공통 팝업 배치 정책을 개선하세요.

## 3. 스마트 길잡이 기존 자동 사라짐 기능 확인 및 보존

현재 SDK의 스마트 길잡이가 안내 표시 후 자동으로 사라지는 기능을 이미 제공하는지, 그리고 표시 유지 시간이 정확히 몇 초인지 소스 코드와 테스트로 확인하세요.

**이미 자동 사라짐이 정상 구현되어 있다면 기존 표시 유지 시간과 동작 방식을 변경하지 마세요.**

특히 다음을 확인합니다.

- 스마트 길잡이 지연 시간 `guideDelaySeconds`(10·15·20초)는 기존대로 유지
- 안내가 나타나기 전의 대기 시간과 나타난 후의 표시 유지 시간을 구분
- 기존 자동 닫힘 타이머가 있다면 그대로 재사용
- 새로운 5초 타이머를 추가하거나 기존 시간을 임의로 5초로 변경하지 않음
- 기존 자동 닫힘 시간이 얼마인지 완료 보고에 명시
- 자동으로 사라질 때 안내 팝업과 버튼 강조 효과가 함께 제거되는지 확인
- 사용자가 직접 닫으면 즉시 제거되는지 확인
- 새로운 화면·업무 단계로 이동하면 이전 안내가 즉시 정리되는지 확인
- 세션 종료 시 팝업과 관련 타이머가 모두 정리되는지 확인
- 같은 단계에서 이미 사라진 안내가 값 변경만으로 반복해서 나타나지 않는지 확인

기존 자동 사라짐 기능이 없거나 실제로 고장 나 있는 것으로 확인될 경우에만 최소한의 공통 SDK 수정을 진행하세요. 이 경우에도 기존 설계와 사용성을 검토해 표시 유지 시간을 결정하고, 임의로 5초를 강제하지 마세요.

## 4. 타이머 및 수명주기 안전성

다음 상황을 검사하세요.

- 스마트 길잡이 표시 전 화면 전환
- 표시 직후 화면 전환
- 자동 닫힘 직전 다른 단계 이동
- 자동 닫힘 후 새로운 단계 진입
- 동일 단계의 옵션·수량 변경
- 안내 문구 업데이트
- 빠른 단계 왕복
- endSession() 호출
- 새 QR 프로필 적용
- 스마트 길잡이 비활성화
- 음성 안내 실행 중 자동 닫힘

어떤 경우에도 이전 안내가 다시 나타나거나, 오래된 자동 닫힘 타이머가 새로운 안내를 닫으면 안 됩니다.

타이머 중복 생성과 메모리 누수를 방지하세요.

## 5. 하단 60% 모드 검증

이전 무인민원발급기에서 360×667 화면에 QR v3 하단 60%를 적용하면 작업 영역 높이가 약 301px이었고, 일부 업무 단계의 스마트 길잡이가 표시되지 않았습니다.

SDK 독립 fixture에서 다음 상황을 재현하세요.

- 화면 360×667
- 하단 60% 작업 영역
- 고정 하단 조작 버튼
- 버튼을 대상으로 하는 스마트 길잡이
- 팝업을 배치할 안전한 빈 공간이 부족한 상태

다음 결과를 확인합니다.

1. 안내가 실제로 화면에 나타남
2. 안내가 작업 영역 밖으로 잘리지 않음
3. 다른 버튼과 일부 겹치더라도 표시됨
4. **기존 SDK에서 확인한 표시 유지 시간이 지나면 자동으로 사라짐**
5. 대상 버튼 강조도 함께 제거됨
6. 타이머 종료 후 기존 버튼을 다시 조작할 수 있음
7. QR 도크·세션 기능은 유지됨

하단 70%, 80%와 기본 모드에서도 같은 규칙을 검사합니다.

## 6. 스크롤 안내 전체 화면 진단

이번에는 스마트 길잡이와 별개로, SDK의 스크롤 안내 기능을 확인합니다.

기존 안내 문구는 다음과 같습니다.

'↓ 아래에도 내용이 있어요'

정상 동작 기준:

- 현재 업무 화면에 아래로 더 볼 내용이 있으면 안내 표시
- 스크롤이 실제로 가능한 영역을 기준으로 판단
- 최하단에 도달하면 안내 숨김
- 새 업무 화면에 진입하면 새 화면의 스크롤 상태 기준으로 다시 판단
- 내용이 적어 스크롤이 필요 없다면 표시하지 않음
- 하단 60·70·80% 모드에서도 정상 판단
- 큰 글씨·큰 버튼 적용으로 스크롤이 새로 필요해지면 표시
- 안내 자체가 업무 버튼이나 QR 도크 뒤에 완전히 가려지지 않음

다음 원인을 조사합니다.

- SDK가 잘못된 스크롤 컨테이너를 인식하는 경우
- 실제 스크롤 가능 범위를 잘못 측정하는 경우
- 화면 전환 후 이전 스크롤 상태가 남는 경우
- 하단 뷰포트 적용 후 측정 시점이 어긋나는 경우
- CSS overflow 및 중첩 스크롤 컨테이너 문제
- 최하단 도달 판정의 오차
- 안내 DOM은 존재하지만 화면상 보이지 않는 경우

## 7. 스크롤 안내 독립 fixture

React에 의존하지 않는 일반 HTML·JavaScript fixture에서 다음을 검증하세요.

- 첫 화면에 긴 메뉴가 있는 경우
- 두 번째 업무 화면에 긴 목록이 있는 경우
- 세 번째 화면에 입력 폼이 긴 경우
- 옵션 모달 내부에 스크롤이 있는 경우
- 스크롤이 필요 없는 짧은 화면
- 중첩 스크롤 영역
- 하단 60·70·80% 모드
- 큰 글씨·매우 큰 글씨
- 큰 버튼
- 화면 전환 직후
- 화면 크기 변경 직후
- 스크롤 도중
- 최하단 도달 후
- 이전 화면으로 복귀
- 세션 종료 후

모달 내부 스크롤을 안내할 때는 현재 활성 모달의 스크롤 영역과 일반 업무 화면의 스크롤 영역을 혼동하지 않도록 주의하세요.

실제로 스크롤 가능한 경우와 안내를 표시해야 하는 경우를 구분해 기록하세요.

## 8. 데모커피 화면별 점검

데모커피에서도 첫 화면만 보지 말고 다음 업무 화면을 점검합니다.

- 초기 화면
- 메뉴 선택
- 메뉴 옵션 선택
- 장바구니·주문 확인
- 결제 방법 선택
- 주문 완료 화면

각 화면에서 스마트 길잡이와 스크롤 안내가 필요한지 판단하고, 필요한 경우 실제 표시 여부를 확인하세요.

스크롤이 필요 없는 화면에서는 안내가 나타나지 않는 것이 정상일 수 있습니다.
