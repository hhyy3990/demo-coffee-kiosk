# 데모커피 최종 수정 — 메뉴 분류 탭 레이어와 결제 화면 쉬운 말 안내

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK는 v0.5.24이며, 스크롤 안내 위치 안정화와 전체 브라우저 검증을 통과한 상태입니다.

사용자가 직접 Development Preview에서 확인한 결과, 기존 스크롤 안내 문제는 해결됐습니다.

이번 작업은 **두 가지 문제만 수정**합니다.

1. 메뉴 선택 화면에서 가로 메뉴 분류 탭이 장바구니·주문 확인 영역 위에 표시되는 문제
2. 결제 수단 선택 화면의 쉬운 말 안내가 실제 선택지와 맞지 않는 문제

이 작업이 완료되면 무인민원발급기에 SDK v0.5.24를 적용할 예정이므로, 기존에 해결한 오류가 절대 재발하지 않도록 해 주세요.

## 1. 메뉴 분류 탭의 레이어 문제

사용자 화면에서 다음 현상이 발견됐습니다.

- 메뉴 분류 탭: 커피·음료, 케이크 등
- 고정 주문 영역: '1개 담았어요', 금액, '주문 확인' 버튼

스크롤하면 메뉴 분류 탭이 고정 주문 영역 위로 지나가면서 주문 영역 일부를 가립니다.

### 원하는 동작

- 메뉴 분류 탭은 기존처럼 일반 콘텐츠와 함께 스크롤
- 다시 position: sticky로 만들지 않음
- 메뉴 분류 탭이 주문 영역보다 앞쪽에 표시되지 않음
- 고정 장바구니·주문 확인 영역이 시각적으로 항상 위쪽 레이어에 표시
- 스크롤할 때 탭이 주문 영역 뒤로 자연스럽게 지나감
- 가로 메뉴 탐색 기능 유지
- 카테고리 선택 정상
- 장바구니와 주문 확인 버튼 정상 클릭

### 원인 조사

다음을 확인하세요.

- 메뉴 분류 탭과 부모 컨테이너의 z-index
- 고정 장바구니 영역의 z-index
- stacking context
- transform 또는 isolation 적용 여부
- 하단 viewportMode가 생성한 stacking context
- SDK의 공통 뷰포트 처리 영향
- sticky 제거 후 남아 있는 레이어 충돌

### 수정 원칙

**호스트 자체의 레이어 구조가 원인이면 데모커피 호스트 CSS에서 수정하세요.**

단, 공통 SDK가 레이어 순서를 잘못 조정해서 발생한 문제라면 SDK 원본에서 수정해야 합니다.

기본적으로는 이미 안정화된 SDK v0.5.24를 유지하고, 호스트에서 필요한 최소한의 레이어 수정만 진행하는 것을 우선 검토하세요.

특정 Y 좌표를 하드코딩하거나 스크롤 이벤트로 강제로 위치를 바꾸는 방식은 금지합니다.

## 2. 결제 화면 쉬운 말 안내 수정

현재 결제 수단 선택 화면의 쉬운 말 안내에 다음 문제가 있습니다.

첫 페이지:
"결제 수단은 돈을 내는 방법이에요."

두 번째 페이지:
영수증 관련 설명

하지만 실제 화면에 영수증 관련 선택지가 없으므로 설명이 부적절합니다.

### 실제 결제 수단

현재 화면의 선택지는 다음 네 가지입니다.

- 카드
- 간편결제
- 모바일 쿠폰
- 상품권

### 원하는 쉬운 말 안내

쉬운 말은 실제 화면에 있는 **선택지의 뜻과 차이**를 쉽게 설명해야 합니다.

다음 문구를 기본안으로 사용하되, 실제 데모커피의 시뮬레이션 기능과 일치하는지 확인하세요.

**페이지 1 — 카드와 간편결제**

제목: 카드와 간편결제

설명:
"카드는 신용카드나 체크카드로 돈을 내는 방법이에요. 간편결제는 휴대전화에 등록한 결제 수단으로 돈을 내는 방법이에요."

**페이지 2 — 모바일 쿠폰과 상품권**

제목: 모바일 쿠폰과 상품권

설명:
"모바일 쿠폰은 휴대전화로 받은 쿠폰을 사용하는 거예요. 상품권은 미리 받은 이용권이나 금액권으로 돈을 내는 방법이에요."

실제 데모 화면에서 지원하는 기능과 다르면 해당 기능에 맞게 정확하게 수정하세요.

### 중요한 작성 원칙

- 실제 화면에 존재하는 결제 선택지만 설명
- 영수증 관련 설명 제거
- 불필요한 결제 절차 추가 금지
- 어려운 용어로 다시 설명하지 않기
- 사용자가 각 선택지의 차이를 이해할 수 있도록 작성
- 쉬운 말과 스마트 길잡이가 같은 설명을 반복하지 않기
- 이전·다음으로 두 페이지를 이동하는 기존 구조 유지

스마트 길잡이는 지금 해야 할 행동을 안내하는 기존 역할을 유지하세요.

예시:
"원하는 결제 방법을 선택해 주세요."

실제 결제·승인 기능은 추가하지 않습니다. 기존 결제 시뮬레이션을 유지하세요.

## 3. 이번 작업에서 변경하지 않을 것

다음 사항은 이미 해결됐으므로 건드리지 마세요.

- 스크롤 안내의 실제 스크롤 영역 하단 기준 배치
- 스크롤 안내가 위아래로 튀지 않는 동작
- 스크롤 안내가 버튼과 겹쳐도 표시되는 정책
- 공통 패널 버튼 44px 높이
- 쉬운 말과 스마트 길잡이 타이머
- 안내창 접기·펼치기
- 쉬운 말 페이지 상태 복원
- 메뉴 분류 탭의 일반 스크롤 방식
- QR 도크 위치
- 하단 조작 60/70/80% 동작
- QR v1~v4 호환
- 주문 완료 후 자동 복귀

SDK 수정이 불필요하다면 v0.5.24를 그대로 유지하세요.

## 4. 필수 브라우저 검증

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

접근성 설정:

- 일반 화면
- 하단 조작 60%
- 하단 조작 70%
- 하단 조작 80%

### 메뉴 화면

실제 브라우저에서 다음을 검증하세요.

1. 메뉴 분류 탭 표시
2. 메뉴 목록을 아래로 스크롤
3. 분류 탭이 장바구니 영역 뒤로 지나가는지 확인
4. 장바구니 텍스트와 버튼이 가려지지 않는지 확인
5. 가로 메뉴 이동 정상
6. 카테고리 변경 정상
7. 주문 확인 버튼 클릭 정상

### 결제 화면

1. 결제 수단 선택 화면 진입
2. 쉬운 말 즉시 표시
3. 카드와 간편결제 설명 확인
4. 다음 버튼으로 이동
5. 모바일 쿠폰과 상품권 설명 확인
6. 영수증 설명이 없는지 확인
7. 스마트 길잡이와 내용 중복 여부 확인
8. 모든 결제 선택지 클릭 가능
9. 결제 시뮬레이션 진행 가능

## 5. 기존 SDK 회귀 테스트

이번에 사용자가 특히 강조한 내용입니다.

**하단 스크롤 안내가 다시 화면 중간으로 이동하거나 튀는 현상이 생기면 작업 실패입니다.**

실제 브라우저에서 다음을 확인하세요.

- 스크롤 안내 위치가 일정함
- 스크롤 시작·중간에서 Y 좌표 변화 1px 이내
- 스크롤 끝에서만 숨김
- 다시 위로 스크롤하면 같은 위치에 표시
- 메뉴 탭의 레이어 변경이 안내창 위치에 영향을 주지 않음
- 쉬운 말·스마트 길잡이 패널도 정상
- 버튼 44px 높이 유지
- 브라우저 무응답 없음

SDK 원본을 수정하지 않았더라도 실제 데모커피의 스크롤 위치 검증은 반드시 수행하세요.

## 6. 전체 주문 흐름

실제 데모커피에서:

메뉴 선택 → 옵션 선택 → 장바구니 → 주문 확인 → 결제 수단 선택 → 결제 시뮬레이션 → 완료 → 처음 화면 복귀

전체 흐름을 다시 검증하세요.

업무 기능을 새로 추가하거나 기존 주문 로직을 변경하지 마세요.

## 7. 버전 및 작업 범위

이번 변경이 호스트 CSS와 안내 데이터 수정만으로 해결되면:

- SDK 버전은 **v0.5.24 유지**
- SDK tarball 재생성 불필요
- 무인민원발급기에는 기존 v0.5.24 tarball 사용

공통 SDK 수정이 불가피하다면:

- 수정 원인을 먼저 명확하게 특정
- 공통 SDK 원본에서 해결
- 독립 소비자 검증 필수
- 기존 v0.5.24 tarball 보존
- 새로운 SDK 버전으로 릴리스

금지 사항:

- 무인민원발급기 수정
- 중앙 QR 프로젝트 수정
- QR 스키마 변경
- AI API 추가
- Production DB 변경
- Publish

**최종 성공 기준**

- 메뉴 분류 탭이 고정 주문 영역 앞에 나타나지 않음
- 탭은 일반 콘텐츠처럼 자연스럽게 스크롤됨
- 결제 화면 쉬운 말은 실제 네 가지 결제 수단을 설명함
- 스크롤 안내가 다시 튀거나 사라지지 않음
- 기존 주문·접근성 기능이 정상 작동함

이 두 가지가 해결되면 추가 기능을 개발하지 말고 완료 결과를 보고하세요.
