# 공통 SDK v0.5.22 — 스크롤 안내 항상 표시 및 일반 화면 위치 점프 수정

현재 프로젝트는 **데모커피 Replit**이며 공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`입니다.

현재 SDK 버전은 v0.5.21입니다.

이번 작업은 v0.5.21에서 남아 있는 두 문제를 완전히 해결하는 것입니다.

**아직 무인민원발급기 프로젝트에는 새 SDK를 설치하지 마세요. SDK-first 원칙을 반드시 지킵니다.**

## 1. 스크롤 안내 표시 정책 변경

기존 SDK는 안전한 공간이 부족하면 스크롤 안내를 숨깁니다.

하지만 사용자가 원하는 정책은 다릅니다.

**실제로 아래에 스크롤할 내용이 남아 있다면 스크롤 안내는 반드시 보여야 합니다.**

적용 조건:

- 일반 화면 및 하단 60/70/80% 모두 동일
- 쉬운 말 안내가 표시돼도 스크롤 안내 유지
- 스마트 길잡이가 표시돼도 스크롤 안내 유지
- 주요 업무 버튼과 공간이 충돌해도 스크롤 안내를 무조건 숨기지 않음
- 스크롤 안내가 화면 위아래로 튀지 않도록 안정적인 위치 유지
- 더 내려갈 내용이 없을 때만 정상적으로 숨김
- 실제 스크롤 영역이 없으면 표시하지 않음
- 모달 등 별도 최상위 화면이 표시되면 그 화면의 스크롤 소유자를 기준으로 판단하며, 뒤쪽 화면의 스크롤 안내를 잘못 표시하지 않음

### 배치 방법

우선 다음 방식으로 해결하세요.

- 스크롤 안내를 작은 크기의 독립 표시 요소로 유지
- 뷰포트 기준으로 위치 고정
- 스크롤 도중 위치 후보를 재선정하지 않음
- 주요 버튼을 최대한 피하되, 피할 수 없다는 이유만으로 스크롤 안내를 없애지 않음
- 불가피하게 버튼 위에 겹칠 때는 스크롤 안내가 버튼 클릭을 막지 않도록 `pointer-events` 등 적절한 방법 검토
- 가독성을 유지하면서 최소한의 면적만 차지하도록 설계
- 쉬운 말·스마트 길잡이 패널과 중첩되면 두 안내를 모두 알아볼 수 있도록 구성

**중요: 버튼 충돌을 이유로 스크롤 안내가 사라지는 기존 정책을 유지하지 마세요.**

## 2. 일반 화면 위치 점프 오류 수정

v0.5.21 검증에서 다음 문제가 남았습니다.

- 일반 화면 320×844: Easy Language 패널이 약 562.9px 재배치
- 일반 화면 390×844: Easy Language 패널이 약 545.7px 재배치

이는 정상적인 스크롤 동작이 아닙니다.

`viewportMode: null`에서도 화면 스크롤만으로 안내창이 위아래로 크게 이동해서는 안 됩니다.

### 조사할 내용

- 일반 화면과 하단 조작 화면에서 서로 다른 좌표계를 사용하는지
- 안내 패널의 배치 후보가 스크롤에 따라 바뀌는지
- 보호 버튼의 실제 가시 영역 판단
- 중첩 스크롤 컨테이너 처리
- fixed·absolute 위치 계산
- ResizeObserver·MutationObserver의 재측정
- 안전한 공간이 있는데도 위치를 변경하는지
- 스크롤만으로 상단·하단 후보가 교체되는지

### 목표

- 일반 화면에서도 안내창의 위치 안정성 확보
- 스크롤 중 큰 위치 점프 방지
- 쉬운 말과 스마트 길잡이 상태 유지
- 주요 업무 조작을 방해하지 않는 배치
- 화면 크기 변경이나 실제 단계 전환 시에만 필요한 재배치 허용

기존 패널의 상태·타이머 로직을 불필요하게 변경하지 마세요.

## 3. 실제 브라우저 검증

다음 화면을 모두 확인하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

각각:

- 일반 화면
- 하단 60%
- 하단 70%
- 하단 80%

다음 상태를 포함합니다.

- 쉬운 말만 활성화
- 스마트 길잡이만 활성화
- 둘 다 활성화
- 매우 큰 글씨
- 큰 버튼
- 고대비
- 긴 목록
- 키패드
- 고정 하단 버튼
- 중첩 스크롤

### 필수 측정

스크롤을 시작·중간·끝까지 진행하면서 다음을 기록하세요.

1. Easy Language 패널 Y 좌표
2. Smart Guide 패널 Y 좌표
3. 스크롤 안내 Y 좌표
4. scrollTop, scrollHeight, clientHeight
5. 스크롤 안내 표시 여부
6. 버튼과 안내 요소의 겹침
7. 실제 버튼 클릭 가능 여부
8. 안내 요소의 가시성
9. 브라우저 성능

특히 **일반 화면 320×844 및 390×844에서 약 500px 이상 점프가 더 이상 발생하지 않는지** 확인하세요.

그리고 **하단 70·80%에서 스크롤할 내용이 남아 있는데도 스크롤 안내가 숨겨지는 사례가 없어야 합니다.**

## 4. 기존 SDK 기능 유지

반드시 유지할 기능:

- QR v1~v4 지원
- 쉬운 말 즉시 표시
- 쉬운 말 이전·다음
- 접기·펼치기
- 스마트 길잡이 단일 안내
- 동일 단계 입력 중 스마트 길잡이 15초 유지
- 길잡이 종료 후 쉬운 말 상태 복원
- 10/15/20초 길잡이 시작 대기
- 스크롤 중 안내 소실 방지
- 완료 후 15초 자동 복귀
- 세션 종료 초기화
- 브라우저 무응답 방지
- QR 도크 정상 작동

## 5. 회귀 테스트

- 독립 소비자 fixture 테스트
- 실제 데모커피 주문 전체 흐름
