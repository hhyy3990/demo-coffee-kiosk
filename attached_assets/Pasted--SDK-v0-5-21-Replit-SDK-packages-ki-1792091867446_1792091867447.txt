# 공통 SDK v0.5.21 — 무인민원발급기에서 재현된 안내창 위치 점프 수정

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`이고, 현재 버전은 v0.5.20입니다.

무인민원발급기에서 SDK v0.5.20을 설치한 후 실제 브라우저 검증 중 공통 배치 오류가 발견됐습니다.

이번 작업은 해당 문제를 공통 SDK에서 재현하고 근본적으로 수정하는 것입니다.

## 1. 실제 오류 재현 정보

무인민원발급기에서 확인된 환경:

- 브라우저 화면: 390×844
- QR v4 모의 프로필
- 매우 큰 글씨, 큰 버튼, 고대비
- 쉬운 말 및 스마트 길잡이 활성화
- 하단 조작 60%
- 스크롤 소유자: `.stage`
- 고정 푸터 및 주요 업무 버튼은 SDK에 등록됨

주민등록 유형 화면에서:

- 스크롤 전 안내 위치: Y=309.56px
- `.stage.scrollTop` 0→240
- 스크롤 후 안내 위치: Y=689.45px
- 위치 변화: 379.89px
- 스크롤 종료 후에도 이동한 위치 유지

주민등록번호, 옵션, 부수 화면에서도 약 380px 이동이 반복됐습니다.

스크롤 끝에서는 안내가 숨겨지기도 했습니다.

호스트의 스크롤 소유자 등록은 실제 DOM과 일치했습니다.

**따라서 무인민원발급기 호스트 CSS를 수정하지 말고 SDK 배치 알고리즘부터 조사하세요.**

## 2. 먼저 어느 안내 요소가 이동했는지 구분

다음 세 요소를 분리해 조사하세요.

1. Easy Language 패널
2. Smart Guide 패널
3. 하단 스크롤 힌트

각 요소의 DOM, boundingRect, visibility, 실제 Y 좌표와 좌표 변화 원인을 기록하세요.

동일한 배치 관리자에 영향을 받더라도 각각의 표시 정책은 구분해야 합니다.

오류가 발생한 정확한 요소를 특정하지 않은 상태에서 모든 안내를 일괄 고정하는 방식으로 수정하지 마세요.

## 3. 실제 무인민원발급기 조건을 독립 fixture에 재현

SDK 독립 소비자 fixture에 아래 조건을 추가하세요.

- 390×844 화면
- 하단 viewport 60%
- 내부 스크롤 소유자 `.stage`와 동등한 구조
- 고정 푸터
- 큰 글씨·큰 버튼·고대비
- 안내 패널
- 240px 이상 실제 스크롤
- 주요 보호 버튼
- 긴 목록과 숫자 키패드 등 다양한 단계

`scrollTop`이 0→240→480→최하단으로 이동할 때 각 안내 요소의 Y 좌표를 기록하세요.

특히 다음을 조사하세요.

- 스크롤 이벤트마다 안전 배치 후보가 교체되는지
- 위치 선정에 스크롤 영역 내부 좌표가 혼용되는지
- DOMRect와 viewport 좌표 변환 오류
- 고정 요소와 스크롤 요소의 충돌 계산
- 쉬운 말 안내와 스크롤 힌트 간 배치 우선순위
- ResizeObserver·MutationObserver가 불필요하게 위치를 재선정하는지
- 안내창이 스크롤 소유자 안에 배치돼 위치가 함께 움직이는지

기존 v0.5.18~v0.5.20에서 수정한 스크롤 중 안내 소실·Observer 반복 오류를 다시 발생시키지 마세요.

## 4. 목표 동작

- 동일 업무 화면에서 단순 스크롤만으로 안내창이 상단에서 하단으로 순간 이동하지 않음
- 스크롤 안내는 스크롤이 필요한 동안 예측 가능한 위치 유지
- 쉬운 말 안내는 계속 접근 가능
- 스마트 길잡이는 표시 중 안정적으로 유지
- 화면의 실제 업무 버튼과 키패드를 가리지 않음
- 스크롤 끝에서 하단 스크롤 힌트는 정상적으로 사라질 수 있음
- 스크롤 끝이라는 이유만으로 쉬운 말 안내를 종료하지 않음

안전 배치를 위해 위치를 바꿔야 하는 예외가 있다면 해당 조건을 명시하고 실제 버튼 접근성을 확인하세요.

중요한 것은 좌표를 무조건 고정하는 것보다 **사용자가 예상할 수 있는 안정적인 위치와 주요 업무 버튼 보호를 동시에 만족하는 것**입니다.

## 5. v0.5.20 기능 유지

다음은 반드시 유지하세요.

- 같은 단계의 입력·선택·수량 변경 중 스마트 길잡이 약 15초 유지
- 실제 업무 단계 전환 시 이전 안내 종료
- 쉬운 말 즉시 표시
- 스마트 길잡이 단일 페이지
- 쉬운 말 설명 페이지·접힘 상태 복원
- 접기·펼치기 44×44px 터치 영역
- 스크롤 안내와 쉬운 말의 안전한 공존
- QR v1~v4 호환
- 하단 60/70/80% 및 일반 화면 지원
- 15초 완료 후 자동 복귀
- 브라우저 무응답 방지

## 6. 필수 브라우저 검증

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

뷰포트:

- 일반 화면
- 하단 60%
- 하단 70%
- 하단 80%

각 조건에서 다음을 확인하세요.

1. 안내 표시 직후 위치
2. 스크롤 시작 시 위치
3. 스크롤 중간 위치
4. 스크롤 끝 위치
5. 스크롤 뒤 다시 위로 올라왔을 때 위치
6. 안내창 표시 상태
7. 스크롤 힌트 표시 상태
8. 주요 업무 버튼의 hit-test 결과
9. 안내창과 키패드 충돌 여부
10. Observer 과다 갱신·브라우저 멈춤 여부

**390×844 하단 60%에서 약 380px 점프가 재현되지 않는지** 반드시 별도로 검증하세요.

단순히 테스트 코드의 상태 변수만 검사하지 말고 실제 렌더링된 DOM 좌표를 측정하세요.
