# 내 방식 QR — SDK 우선 스마트 길잡이 누락 화면 진단 및 범용 개선

현재 프로젝트는 데모커피 키오스크이자 공통 접근성 SDK 개발 프로젝트입니다.

현재 공통 SDK 버전은 `@naebangsik/kiosk-accessibility-sdk@0.5.7`입니다.

이번 작업의 목적은 **카페와 무인민원발급기의 일부 업무 화면에서 스마트 길잡이가 표시되지 않는 원인을 분석하고, 필요한 경우 공통 SDK를 범용적으로 개선하는 것**입니다.

가장 중요한 원칙은 **SDK 우선**입니다. 특정 키오스크의 화면에 타이머나 안내 팝업을 따로 구현하는 방식은 사용하지 마세요.

## 1. 현재 확인된 증상

### 데모커피

다음 화면에서 스마트 길잡이가 나타나지 않는다고 사용자가 확인했습니다.

1. 메뉴 선택 후 온도·크기·컵 종류를 고르는 옵션 화면
2. 장바구니 및 주문 확인 화면
3. 카드·간편결제 등 결제 방법 선택 화면

### 무인민원발급기

별도의 독립 프로젝트에서 다음 화면의 스마트 길잡이가 누락됩니다.

1. 주민등록번호 키패드 입력 화면
2. 증명서 표시 항목 선택 화면
3. 발급 부수 입력 화면
4. 결제 방법 선택 화면

무인민원발급기 프로젝트는 현재 워크스페이스에 없으므로 직접 수정하거나 이미 원인을 확인했다고 주장하지 마세요.

이번에는 데모커피에서 확인 가능한 현상과 SDK의 공통 구조를 먼저 조사합니다.

## 2. 수정하기 전 원인 분석

SDK v0.5.7의 실제 API, 타입 선언, README와 소스 구현을 확인하세요.

특히 다음을 분석합니다.

- 스마트 길잡이가 화면을 인식하는 방식
- `notifyScreenChange(screenId)`와 스마트 길잡이 타이머의 관계
- React의 렌더링 시점과 SDK의 DOM 검사 시점
- 안내를 표시할 화면별 정보 등록 방식
- 화면별 안내 문구가 없을 때 SDK의 처리 방식
- 동일 업무 화면의 모달·옵션 선택도 새로운 안내 단계로 등록할 수 있는지
- 화면 전환 시 기존 타이머 취소 및 새 타이머 시작 여부
- 이전 안내가 표시된 이후 새로운 화면에서도 안내가 가능한지
- 접근성 프로필의 `smartGuide` 설정과 `guideDelaySeconds` 유지 여부

**원인을 확인하기 전 SDK나 호스트를 임의로 수정하지 마세요.**

## 3. 범용 설계 원칙

스마트 길잡이의 동작은 공통 SDK가 담당해야 합니다.

SDK가 담당할 부분:

- 화면별 안내 단계 관리
- 스마트 길잡이 타이머
- 화면 전환 감지 API
- 안내 표시·닫기
- 화면 이탈 시 타이머 및 안내 정리
- 중복 안내 방지
- 사용자 설정에 따른 10·15·20초 지연
- 프로필 해제 및 세션 종료 시 정리

호스트가 담당할 부분:

- 현재 화면 또는 업무 단계의 안정적인 식별자 제공
- 해당 화면에서 사용자에게 필요한 업무 안내 문구 제공
- 필요한 경우 업무 단계 전환을 SDK에 알림

호스트가 별도의 스마트 길잡이 타이머, 안내 팝업, 중복 상태 관리 기능을 구현하지 않도록 해 주세요.

**카페 메뉴 이름이나 무인민원발급기의 특정 업무 명칭을 SDK 핵심 코드에 하드코딩하지 마세요.**

## 4. 화면과 업무 단계의 구분

이번 문제에서 특히 중요한 부분입니다.

예를 들어 카페에서는 메뉴 선택 화면에서 옵션 선택 창이 열릴 수 있고, 장바구니 화면에서 주문 확인 단계가 이어질 수 있습니다.

이 과정이 단순한 React 상태 변경이나 모달 표시로 구현되어 있더라도 사용자의 관점에서는 별도 안내가 필요한 업무 단계입니다.

따라서 SDK가 다음 상황을 지원할 수 있는지 검토하세요.

- 전체 화면 전환
- 동일 화면 안의 옵션 선택 단계
- 모달이지만 별도 안내가 필요한 단계
- 결제 수단 선택 단계
- 이전 단계로 복귀
- 동일 단계의 값만 변경한 경우

안내가 필요한 업무 단계가 바뀌면 새 타이머가 시작되어야 하지만, 옵션 값이나 수량만 바꾼 경우에는 불필요하게 안내가 반복되어서는 안 됩니다.

필요하다면 기존 `notifyScreenChange(screenId)`와 호환되는 범용적인 업무 단계 알림 API를 추가할 수 있습니다.

새 API를 추가하기 전에 기존 API로 충분히 해결되는지 확인하고, 불필요하게 복잡한 설계를 만들지 마세요.

## 5. 데모커피 누락 화면 검증

다음 세 단계를 각각 재현합니다.

### A. 메뉴 옵션

- 온도 선택
- 크기 선택
- 컵 종류 선택

옵션 선택 단계 진입 후 설정된 지연 시간이 지나면 적절한 안내가 나타나는지 확인하세요.

실제 사용자가 선택해야 할 내용을 쉽게 설명하되, 특정 선택을 강요하지 않아야 합니다.

### B. 장바구니·주문 확인

- 담은 메뉴 확인
- 수량 확인
- 결제 이동 전 주문 내용 확인

필요한 시점에 안내가 나타나야 하며, 수량을 한 번 변경할 때마다 타이머가 무조건 초기화되는 상황은 피하세요.

### C. 결제 방법 선택

- 카드 결제
- 간편결제 등 현재 구현된 선택지

현재 화면에 실제로 존재하는 선택지를 기준으로 안내해야 합니다.

없는 결제 수단이나 구현되지 않은 결제 기능을 안내하지 마세요.

## 6. 스마트 길잡이 동작 정책

다음 동작을 유지하거나 구현하세요.

1. QR 접근성 프로필의 `smartGuide`가 활성화된 경우에만 작동
2. `guideDelaySeconds`가 10·15·20초일 때 해당 지연 적용
3. 해당 업무 단계가 실제로 나타난 뒤 타이머 시작
4. 다른 단계로 이동하면 이전 단계 타이머 취소
5. 안내가 열려 있는 동안 화면이 바뀌면 오래된 안내 정리
6. 동일 단계의 일반적인 값 변경은 중복 안내를 유발하지 않음
7. 이전 단계로 돌아왔을 때는 정책에 따라 안내 재시작 가능
8. `endSession()` 후 남은 타이머·안내·음성 재생 정리
9. 기본 스마트 길잡이는 AI 없이 동작
10. 안내 문구가 없는 경우 잘못된 안내를 표시하지 않음

가능하면 안내를 닫는 방법도 기존 SDK 방식을 그대로 유지하세요.

## 7. 독립 SDK fixture 검증

React와 데모커피 업무 코드에 의존하지 않는 일반 HTML·JavaScript 테스트를 구성하세요.

필수 시나리오:

- 화면 A에서 화면 B로 이동
- 동일 화면의 업무 단계 A에서 단계 B로 이동
- 모달 업무 단계 열기·닫기
- 업무 단계 이동 직전에 타이머 취소
- 10·15·20초 지연
- 빠른 화면 전환
- 같은 단계 중복 알림 방지
- 옵션 값 변경 후 불필요한 재시작 방지
- 이전 단계 복귀
- 프로필 비활성화
- endSession() 이후 안내 재등장 금지
- DOM 렌더링 지연
- 호스트에서 안내 문구가 누락된 경우
- 화면 변경과 음성 안내의 충돌 방지

실제 시간을 모두 기다리는 느린 테스트뿐 아니라, 가능한 경우 제어된 타이머 테스트도 활용하세요.

## 8. 데모커피 통합

SDK 공통 기능에 문제가 있으면 SDK를 먼저 수정합니다.

SDK가 이미 필요한 동작을 지원한다면 새 버전을 불필요하게 제작하지 않고, 데모커피의 화면 단계 연결만 수정하세요.

호스트에서 허용되는 변경은 다음으로 제한합니다.

- 화면·업무 단계 ID 전달
- 화면별 안내 문구 등록
- 기존 SDK API 호출
- 업무 단계 전환 이벤트 연결

호스트별 별도 타이머나 스마트 길잡이 컴포넌트를 만들지 마세요.

기존 주문·결제 로직 및 화면 디자인은 유지합니다.

## 9. 회귀 검증

다음 기능의 기존 동작을 보호하세요.

- QR v1/v2/v3
- 큰 글씨·매우 큰 글씨
- 큰 버튼
- 고대비
- 쉬운 말
- 하단 60·70·80%
- QR 도크 자동 동기화
- 선택적 5~10% 글씨 보정
- 개발자 레이아웃 진단
- 스크롤 안내
- 음성 안내
- notifyScreenChange()
- endSession()
- 데모커피 주문·결제 전체 흐름

스마트 길잡이가 결제 버튼을 가리거나 입력을 방해하지 않는지도 확인합니다.

## 10. SDK 새 버전 제작 조건

실제 공통 SDK 수정이 필요하고 독립 fixture와 회귀 검증을 통과했을 때만 v0.5.8 제작을 검토하세요.

예상 경로:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.8.tgz`

기존 v0.5.5·v0.5.6·v0.5.7 tarball은 보존하세요.

반대로 문제가 호스트의 화면 단계 정보 누락에만 있다면 **SDK v0.5.7을 그대로 유지**하고, 원인과 해결 방법을 명확하게 설명하세요.

## 11. 향후 무인민원발급기 연결을 위한 안내

이번 작업을 마친 후, 독립된 무인민원발급기 프로젝트에서 다음 업무 단계를 어떻게 SDK에 등록해야 하는지 설명해 주세요.

- 주민등록번호 키패드
- 증명서 표시 항목 선택
- 발급 부수 입력
- 결제 방법 선택

주민등록번호나 실제 입력값이 화면 ID, 안내 문구, 진단 로그, AI 요청에 포함되지 않도록 설계해야 합니다.

무인민원발급기 코드가 없는 상태에서 해당 프로젝트가 수정됐다고 보고하지 마세요.
