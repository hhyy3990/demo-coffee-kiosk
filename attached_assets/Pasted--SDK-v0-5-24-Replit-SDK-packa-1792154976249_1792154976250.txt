# 공통 SDK 긴급 수정 — 스크롤 안내 위치 재설계 및 v0.5.24 미완료 테스트 해결

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`입니다.

현재 안정 릴리스는 v0.5.23이며, v0.5.24 수정 작업은 일부 진행됐지만 전체 브라우저 회귀 테스트가 실패해 릴리스되지 않았습니다.

이번 작업에서는 기존 변경분을 무조건 폐기하지 말고, 현재 소스 변경 상태부터 확인하세요.

사용자가 실제 Preview에서 확인한 결과, 스크롤 안내가 다시 화면 중간에 나타나 주요 제목과 콘텐츠를 가리고 있습니다.

이번 작업의 핵심은 **스크롤 안내 위치 계산 방식을 단순화하는 것**입니다.

## 1. 사용자가 원하는 정확한 동작

스크롤 안내 문구:

"↓ 아래에도 버튼이 있어요"

원하는 정책:

- 스크롤할 내용이 남아 있으면 반드시 표시
- 일반 화면과 하단 조작 60/70/80% 모두 적용
- 해당 업무 뷰포트의 **하단에 일정한 위치로 고정**
- 스크롤할 때 위쪽·중간·아래쪽으로 이동하지 않음
- 사용자에게 화면 중간에 갑자기 등장하지 않음
- 스크롤이 끝나면 숨김
- 다시 위로 스크롤하면 같은 위치에 재등장
- 버튼이나 주문 확인 영역과 시각적으로 겹쳐도 허용
- 스크롤 안내 자체는 클릭·터치를 가로채지 않음
- 쉬운 말·스마트 길잡이와 동시에 표시 가능

**중요: 주요 버튼을 피하려고 스크롤 안내 위치를 위로 옮기거나 배치 후보를 변경하지 마세요.**

## 2. 기존 배치 후보 탐색 방식 재검토

SDK의 스크롤 힌트 배치 로직을 조사하세요.

특히:

- scroll-guidance.ts
- accessibility-sdk.ts
- styles.css
- DOM overlay root
- 하단 조작 viewport 적용
- QR 도크 위치
- 스크롤 소유자
- position: fixed/absolute
- transform이 적용된 조상 요소
- document layer와 kiosk layer 전환

현재는 QR 도크가 있는 모드에서 힌트를 document layer로 이동시키는 변경이 포함돼 있습니다.

이로 인해 위치 좌표계가 바뀌거나 안내가 업무 화면 중간에 표시되는지 조사하세요.

### 목표 구조

스크롤 힌트에 대해서는 복잡한 안전 위치 후보 탐색을 사용하지 않는 방향을 우선 검토하세요.

- 현재 활성 업무 뷰포트의 하단 경계를 기준으로 단일 기준 위치 결정
- 하단 경계에서 작은 일정 간격만 띄워 표시
- 동일 화면·동일 viewportMode에서는 스크롤 중 Y 좌표 유지
- 버튼 위치·키패드 위치·메뉴 카드 위치를 이유로 재배치하지 않음
- 실제 뷰포트 크기 또는 하단 조작 설정이 바뀌었을 때만 기준 위치 갱신
- DOM의 다른 레이어에 배치하더라도 기준 좌표를 동일하게 유지
- transform·zoom·visualViewport에 의한 좌표 변환은 명시적으로 처리

기존 쉬운 말·스마트 길잡이 패널의 배치 정책을 불필요하게 변경하지 마세요.

이번 작업의 재설계 대상은 **스크롤 힌트 위치**입니다.

## 3. 하단 조작 모드 위치 기준

### 일반 화면

`viewportMode: null`

현재 업무 콘텐츠가 표시되는 실제 뷰포트의 하단을 기준으로 배치하세요.

### 하단 조작 60·70·80%

접근성 프로필이 지정한 하단 업무 뷰포트의 **실제 하단 경계**를 기준으로 배치하세요.

업무 영역이 축소되어 있어도 안내가 임의로 화면 중간으로 이동하면 안 됩니다.

단, 뷰포트 하단은 실제 콘텐츠 영역의 좌표를 기준으로 계산하고, QR 도크나 다른 레이어 때문에 잘못된 경계를 선택하지 마세요.

특정 px Y 좌표를 화면 크기별로 하드코딩하지 마세요.

## 4. 실제 사용자 증상 재현

사용자가 제공한 사진에서는 360px대 폭의 모바일 화면에서 스크롤 안내가 '무엇을 드릴까요?' 제목 주변에 나타났습니다.

반드시 실제 데모커피 Development Preview에서 다음을 확인하세요.

1. 접근성 체험하기 실행
2. 첫 화면에서 스크롤 안내가 나타나는지 확인
3. 안내의 실제 Y 좌표 측정
4. 현재 활성 업무 뷰포트의 하단 Y 좌표 측정
5. 안내 하단과 업무 뷰포트 하단 사이 거리 기록
6. 100px, 200px, 400px 스크롤
7. 안내 Y 좌표가 유지되는지 확인
8. 스크롤 끝에서 사라지는지 확인
9. 다시 위로 돌아오면 같은 위치에 나타나는지 확인
10. 옵션·주문 확인·결제 화면에서도 동일 검증

스크롤 안내가 화면 중간의 콘텐츠 제목 위에 나타나는지 반드시 확인하세요.

**SDK 내부 상태만 정상이라고 실제 배치가 정상인 것으로 보고하지 마세요.**

## 5. 기존 실패한 브라우저 테스트 해결

이전 v0.5.24 작업에서 다음 테스트가 실패했습니다.

- `test:browser:viewport` 320×844
- `test:browser:viewport` 390×844

실패 지점은 QR 모달의 스크롤 힌트 상태입니다.

모달이 열렸다면 배경 업무 화면의 스크롤 힌트가 잘못 표시되지 않아야 합니다.

모달 안에 스크롤할 내용이 있다면 모달의 스크롤 상태에 맞춰 표시합니다.

반대로 모달에 스크롤할 내용이 없다면 힌트를 표시하지 않습니다.

**모달의 실제 스크롤 여부를 기준으로 문제를 수정해야 하며, 테스트 기대값만 변경해 통과시키지 마세요.**

## 6. 공통 안내 버튼 44px 유지

이전 작업에서 이미 수정한 내용을 유지합니다.

- 접기·펼치기 실제 높이 44px
- 이전·다음 실제 높이 44px
- 닫기 버튼 실제 높이 44px
- 최소 44×44px 터치 영역
- 텍스트 잘림 없음
- 쉬운 말 본문 글씨 크기 유지

버튼을 다시 50px 이상으로 키우지 마세요.

## 7. 기존 기능 회귀 방지

다음 기능을 유지하세요.

- 쉬운 말 즉시 표시
- 스마트 길잡이 10/15/20초 대기
- 스마트 길잡이 표시 10/15초 유지
- 같은 단계 입력 시 길잡이 조기 종료 방지
- 스마트 길잡이 단일 안내
- 쉬운 말 페이지·접힘 상태 복원
- 일반 화면 안내창 위치 안정성
- 하단 60/70/80% 지원
- QR v1~v4 호환
- QR 도크 및 모달 정상 조작
- 메뉴 분류 탭 스크롤 문제 해결 상태
- 전체 주문 흐름
- 완료 후 15초 자동 복귀
- Observer 무한 루프 방지
