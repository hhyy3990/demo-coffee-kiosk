# 데모커피 — 중앙 AI API 계약 기반 서버 중계 구현

현재 프로젝트는 데모커피 Replit입니다.

중앙 ‘내 방식 QR’ Replit에서 실제 API 계약을 확인했습니다. 앞서 보류했던 중계 구현을 재개해 주세요.

이번에는 **서버 중계 코드 구현 및 로컬 Mock 검증까지만** 진행합니다. 실제 중앙 AI API 호출과 OpenAI 호출은 하지 마세요.

## 1. 확정된 중앙 API 계약

- HTTP: `POST /api/ai-layout/plan`
- Content-Type: `application/json`
- 최대 요청 본문: 16 KiB
- 인증: 서버 측 `Authorization: Bearer <AI_LAYOUT_SERVICE_TOKEN>`
- 요청 본문: 데모커피 `createMenuScreenModel()`에서 생성한 전체 모델 JSON
- 정상 응답: HTTP 200, 별도 envelope 없는 계획 JSON
- 오류 응답: `{ "error": "일반화된 오류 메시지" }`

데모커피 화면 계약:

- `schemaVersion: 2`
- `hostId: "democoffee"`
- `screenId: "cafe.menu"`
- `structureVersion: "menu.v2"`
- `structureHash: "837f86b3"`
- `viewportClass: "compact" | "regular"`
- `constraintHash`: 접근성 제약에 따라 변동

허용 연산:

- `setGroupColumns`
- `setGroupFlow`
- `setChildBasis`

현재 호스트의 `validateMenuLayoutPlan()`을 유지하고, 중앙 응답도 반드시 이 함수로 다시 검증하세요.

## 2. 서버 중계 구현

기존 `server.mjs`에 개발용 AI 중계 경로를 추가하세요.

권장 경로:

`POST /api/ai-layout/plan`

처리 구조:

데모커피 브라우저 → 데모커피 서버 → 중앙 AI 서버 → 데모커피 서버 → 브라우저

중계 경로는 다음을 만족해야 합니다.

- 허용된 호스트 및 화면만 처리
- 전체 모델의 구조를 검증하고 불필요한 필드 거부
- 요청 크기 제한
- 고정된 중앙 서버 URL만 사용
- 임의 URL 입력을 통한 프록시 요청 금지
- 민감정보·QR 토큰·주문 상태 차단
- 중앙 응답 크기 제한
- 중앙 오류의 안전한 정규화
- 타임아웃
- 불필요한 중복 요청 방지
- 서버 비밀값을 브라우저에 노출하지 않음
- 요청·응답 본문을 로그에 남기지 않음
- 서버 설정이 없으면 안전하게 실패

**모델의 해시만 보고 요청을 무조건 신뢰하지 마세요.** 가능한 범위에서 데모커피의 정적 화면 계약 및 제약과 일치하는지 검증해야 합니다.

## 3. 개발·Production 설정 분리

서버 측 설정값 이름은 다음을 사용하세요.

- `AI_LAYOUT_CENTRAL_URL`: 중앙 개발 서버의 기본 URL
- `AI_LAYOUT_SERVICE_TOKEN`: 중앙 앱의 서버 간 인증 토큰

토큰을 `VITE_` 변수에 넣거나 브라우저 코드에 노출하지 마세요.

Production 주소 `https://naebangsikqr.replit.app`는 이번 작업에서 AI API 대상 주소로 사용하지 마세요.

중앙 Development URL은 임시 주소이므로 하드코딩하지 마세요.

## 4. Replit 인증 충돌 처리

중앙 Development URL은 Replit의 외부 접근 인증이 필요할 수 있습니다.

이 인증과 중앙 앱의 서비스 인증이 모두 Authorization Bearer 형식을 사용하므로 충돌 가능성이 있습니다.

**확인되지 않은 방식으로 두 토큰을 합치거나 인증 우회를 구현하지 마세요.**

이번에는 실제 외부 요청을 비활성화한 상태에서 중계 구조만 구현하세요.

두 인증을 함께 전달할 수 있는 공식적인 방법을 확인하지 못한다면 그 상태를 최종 보고하세요.

## 5. Mock 검증

실제 외부 통신 없이 중앙 서버 응답을 흉내 내는 테스트용 Mock을 주입해 검증하세요.

필수 테스트:

- 정상 계획 반환
- 요청 모델 필드 검증
- 잘못된 화면 ID 거부
- 허용하지 않은 필드 거부
- QR 토큰 및 주문 정보 거부
- 정상 계획 호스트 재검증
- 잘못된 연산 거부
- 중앙 400·401·429·502·503 오류
- 타임아웃 및 연결 실패
- 서버 비밀값 미설정 시 외부 요청 차단
- 중복 요청 방지
- 응답 지연 후 화면 이탈 시 오래된 계획 폐기

일반 사용자용 Mock 버튼이나 공개 Mock API를 만들지 마세요.

기존 데모커피 Mock 레이아웃 테스트는 유지하세요.
