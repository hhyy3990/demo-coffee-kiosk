# 내 방식 QR — 공통 SDK 안내창 디자인 간소화 및 일반 화면 배치 검증

## 0. 작업 대상과 목적

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본은 `packages/kiosk-accessibility-sdk/`에 있습니다.

현재 안정화 기준 버전은 **v0.5.18**입니다.

이번 작업의 목적은 다음 두 가지입니다.

1. 하단 조작을 사용하지 않는 일반 화면에서도 쉬운 말 안내와 스마트 길잡이가 적절한 위치에 표시되는지 검증
2. 공통 안내창의 접기·펼치기·이전·다음 버튼과 정보 아이콘을 간결하게 정리해 화면 점유 면적 축소

최근 실제 사용자 테스트에서 주요 기능은 개선됐지만, 매우 큰 글씨와 큰 버튼을 적용하면 안내창의 조작 요소들이 과도하게 커지는 문제가 확인됐습니다.

**이번 작업은 공통 SDK에서 해결해야 하며, 데모커피 전용 안내창 디자인이나 CSS 우회는 만들지 마세요.**

## 1. 기존 v0.5.18 동작 유지

먼저 기존 SDK의 안내창 렌더링과 스타일 구조를 확인하세요.

유지할 동작:

- 쉬운 말은 단계 진입 직후 표시
- 쉬운 말은 사용자가 접거나 단계가 변경될 때까지 유지
- 스마트 길잡이는 기존 10·15·20초 대기 후 표시
- 스마트 길잡이 표시 유지 기본 10초, slowGuidance 사용 시 15초
- 스마트 길잡이에는 이전·다음 및 페이지 번호 없음
- 길잡이 종료 후 쉬운 말의 이전 페이지·접힘 상태 복원
- 스크롤 시 쉬운 말·스마트 길잡이 소실 방지
- 업무 버튼·키패드 가림 방지
- Observer 재측정 무한 루프 방지
- QR v1~v4 프로필 및 하단 조작 60·70·80% 지원

기존에 여러 번 발생했던 회귀 오류가 다시 나타나면 안 됩니다.

## 2. 공통 안내창 디자인 간소화

### 현재 문제

사용자가 실제 Preview에서 다음 문제를 확인했습니다.

- 접기 버튼의 글씨·테두리·여백이 큼
- 이전·다음 버튼이 지나치게 커서 안내창 높이가 증가
- 큰 정보 아이콘이 별도의 줄을 차지함
- 실제 설명보다 조작 요소가 화면을 많이 차지함

특히 `textSize: extraLarge`, `buttonSize: large`에서 두드러집니다.

### 원하는 구조

가능하면 안내창 상단을 한 줄로 구성하세요.

**[작은 정보 아이콘 + 쉬운 말 안내] [접기]**

스마트 길잡이의 경우:

**[남은 시간 + 스마트 길잡이] [접기]**

정보 아이콘을 설명 위쪽에 별도 줄로 크게 표시하지 마세요.

### 접기·펼치기

- `∨ 접기`, `∧ 펼치기`처럼 아이콘과 글자를 함께 표시
- 버튼 외형과 내부 패딩은 간결하게 조정
- 터치 가능한 실제 영역은 최소 44×44 CSS px 수준 유지
- 글씨 매우 크게 설정에서도 버튼 문구가 잘리지 않도록 처리
- 아이콘만으로 기능을 표현하지 않기
- 접힌 상태와 펼친 상태를 명확히 구분

### 이전·다음

- 이전·다음 버튼의 과도한 패딩과 여백 축소
- 버튼 텍스트의 가독성 유지
- 1/2, 2/2 등의 페이지 표시를 작고 명확하게 배치
- 설명이 하나일 때 이전·다음 및 페이지 번호 숨김
- 스마트 길잡이에서는 항상 이전·다음 및 페이지 번호 숨김
- 버튼의 터치 영역 최소 44×44 CSS px 수준 유지
- 매우 큰 글씨에서 글자 겹침·잘림 방지

### 정보 아이콘

- 현재 크게 표시되는 `i` 아이콘 축소
- 작은 아이콘을 상단 제목과 같은 줄에 배치
- 아이콘 자체에 별도 큰 세로 공간을 할당하지 않기
- 장식적 요소라면 스크린리더가 불필요하게 읽지 않도록 처리
- 안내 제목은 텍스트로 명확하게 제공

### 안내 본문

- 실제 쉬운 말 설명의 글씨 크기를 무리하게 줄이지 말 것
- 문장 줄 간격과 가독성 유지
- 불필요하게 큰 상하 여백만 축소
- 설명이 길면 안전하게 줄바꿈
- 안내창이 커지더라도 주요 업무 조작을 가리지 않도록 SDK 배치 정책 적용
- 페이지를 억지로 줄이기 위해 설명 내용을 생략하지 말 것

**핵심은 설명 자체가 아니라 조작 UI와 장식 요소의 공간을 줄이는 것입니다.**

## 3. 일반 화면 배치 검증

현재 Development '접근성 체험하기'는 하단 조작 60%가 고정 적용되므로, 별도의 자동 브라우저 검증에서 `viewportMode: null`도 테스트하세요.

실제 SDK의 공개 프로필 적용 경로를 사용합니다.

일반 화면에서 다음 조합을 확인하세요.

- 글씨 기본 / 매우 크게
- 버튼 기본 / 크게
- 쉬운 말만 활성화
- 스마트 길잡이만 활성화
- 쉬운 말 + 스마트 길잡이
- 고대비 적용
- 스크롤이 필요한 화면
- 스크롤이 필요 없는 화면

일반 화면에서도 안내창이 주요 업무 버튼을 가리거나 콘텐츠를 과도하게 덮지 않아야 합니다.

### 배치 원칙

- 화면 위쪽·아래쪽을 무작위로 오가는 위치 점프 방지
- 가능한 한 일관된 위치 유지
- 스크롤해도 사용자가 안내 기능을 계속 찾을 수 있어야 함
- 주요 업무 버튼과 안전한 거리 확보
- QR 도크·하단 고정 영역과 충돌 방지
- 안전한 위치가 없다면 접힌 안내 상태 등 최소 표시 우선 검토
- 업무 버튼 위에 안내창을 강제로 표시하지 않음

이번 작업은 일반 화면 검증뿐 아니라 기존 하단 60·70·80%에서의 회귀도 포함합니다.

## 4. 개발용 체험 버튼은 그대로 유지

현재 데모커피의 Development 전용 '접근성 체험하기' 버튼은 유지하세요.

기존 고정 프로필도 변경하지 마세요.

다만 사용자가 일반 화면을 쉽게 비교할 필요가 있으므로, **Development에서만** 다음과 같은 최소 테스트 수단을 추가하는 것은 허용합니다.

- '일반 화면으로 체험' 옵션 또는 내부 테스트용 프리셋
- 기존 하단 60% 체험은 그대로 유지
- 복잡한 전체 설정 선택 화면은 만들지 않음
- Production에는 절대 노출하지 않음

일반 화면 비교가 자동 브라우저 테스트만으로 충분하다면 별도 UI를 추가하지 않아도 됩니다.

어떤 방식으로 검증했는지 완료 보고에서 명확히 설명하세요.

## 5. 실제 브라우저 검증

다음 화면 크기를 사용하세요.

- 320×844
- 360×667
- 390×844
- 1080×1920

각 크기에서 다음 모드를 확인하세요.

- 일반 화면: viewportMode null
- 하단 조작 60%
- 하단 조작 70%
- 하단 조작 80%

### 안내창 확인

- 안내창 전체 높이
- 헤더 높이
- 접기·펼치기 버튼 실제 크기
- 이전·다음 버튼 실제 크기
- 정보 아이콘 크기
- 설명 본문 글씨 크기
- 버튼 간 겹침 여부
- 안내창 내부 텍스트 잘림 여부

가능하면 수정 전후 안내창의 높이와 화면 점유 비율을 비교해 보고하세요.

실제 설명 글씨의 가독성을 희생하면서 높이만 줄이지 마세요.

### 동작 확인

1. 쉬운 말 안내 즉시 표시
2. 이전·다음 이동
3. 접기·펼치기
4. 스마트 길잡이 시작
5. 스마트 길잡이 카운트다운
6. 스마트 길잡이에 페이지 번호 없음
7. 길잡이 종료 후 이전 쉬운 말 페이지 복원
8. 쉬운 말 표시 중 스크롤
9. 스마트 길잡이 표시 중 스크롤
10. 안내창이 사라지거나 위치가 크게 튀지 않음
11. 주요 업무 버튼 실제 클릭
12. 장바구니·결제·주문 완료
13. 완료 후 15초 자동 복귀

단순 스크린샷 검사만 하지 말고 실제 브라우저 포인터와 스크롤로 확인하세요.

## 6. 접근성 기준

- 큰 글씨 설정 반영 유지
- 고대비 모드 지원
- 접기·펼치기 및 이전·다음 키보드 접근 가능
- 적절한 ARIA 레이블
- 버튼에 명확한 텍스트 제공
- 실제 터치 영역 최소 44×44 CSS px 수준 확보
- 320px에서 줄바꿈·가로 넘침 방지
- prefers-reduced-motion 고려
- 카운트다운을 스크린리더가 매초 반복해 읽지 않도록 유지

터치 영역은 충분히 유지하되 시각적 장식과 불필요한 여백을 줄이는 방식으로 개선하세요.

## 7. 성능과 SDK 회귀

v0.5.16~v0.5.18에서 수정한 오류가 다시 나타나지 않아야 합니다.

- Observer 무한 반복 없음
- 지속적인 브라우저 무응답 없음
- 스크롤 시 안내창 사라짐 없음
- 스마트 길잡이 페이지 중복 없음
- 주요 버튼 가림 없음
- 빈 내용의 펼치기 버튼 없음
- 타이머 중복 없음
- 세션 종료 후 안내 초기화
- QR v1~v4 호환

독립 소비자 fixture와 실제 데모커피 주문 흐름을 모두 검증하세요.

## 8. SDK 버전 및 패키지

공통 SDK 코드 변경이 필요하면 **v0.5.19**로 버전을 올리세요.

출력 경로:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.19.tgz`

기존 v0.5.18과 이전 tarball은 보존합니다.

새 패키지를 독립 소비자 프로젝트에 설치하여 타입 검사·빌드·브라우저 검증을 수행하세요.

SDK 소스가 변경되지 않았다면 불필요하게 버전을 올리지 마세요.
