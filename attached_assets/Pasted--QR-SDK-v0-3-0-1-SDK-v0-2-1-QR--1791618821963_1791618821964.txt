# 내 방식 QR SDK v0.3.0 — 범용 화면 확대 및 자동 보정 1차 개발

현재 공통 접근성 SDK v0.2.1은 QR 인식, 프로필 적용, 스마트 길잡이, 음성 안내, 세션 초기화 등을 제공합니다.

독립적으로 제작한 무인민원발급기에서 SDK를 적용해 보니, 접근성 클래스는 정상적으로 붙었지만 기존 키오스크가 고정 픽셀 CSS를 사용하여 큰 글씨와 큰 버튼이 실제로 확대되지 않는 문제가 발견됐습니다.

이번 작업의 목적은 각 키오스크의 CSS를 직접 수정하지 않고도 공통 SDK가 글씨·버튼 크기 확대와 제한적인 자동 레이아웃 보정을 수행할 수 있도록 v0.3.0을 개발하는 것입니다.

## 1. 개발 원칙

- SDK 내부에서 공통 확대·보정 기능 구현
- 카페나 무인민원발급기의 개별 디자인에 의존하지 않기
- 키오스크의 주문·발급 동작은 변경하지 않기
- 기존 모든 메뉴·업무 버튼 유지
- AI 모델 연결은 아직 하지 않기
- 기존 SDK v0.2.1 기능 유지
- 자동 보정 실패 시 안전하게 원래 상태로 복원 가능해야 함

## 2. 기존 고정 CSS에 대한 글씨 확대

SDK 어댑터가 제공하는 주요 텍스트 요소를 대상으로 글씨 크기를 확대해 주세요.

- 원래 계산된 font-size를 기준으로 확대
- 이미 확대된 값에 다시 배율을 적용하지 않도록 방지
- 화면 변경 또는 요소 재생성 시에도 올바르게 적용
- QR 설정의 일반/크게/아주 크게 수준 반영
- 키오스크 CSS의 고정 px 값에도 적용되도록 설계
- 해당 키오스크 루트 영역 밖은 변경하지 않기
- QR 해제나 endSession() 시 원래 스타일 복원

가능하면 `!important`로 화면 전체를 무차별 덮어쓰지 말고, SDK에서 등록한 대상에 한해 안전하게 적용해 주세요.

## 3. 버튼 크기 확대

어댑터가 등록한 주요 조작 버튼에 큰 버튼 설정을 적용해 주세요.

- 버튼 높이·패딩·터치 영역 확대
- 텍스트가 잘리지 않도록 높이도 함께 조정
- 기존 기능과 이벤트 핸들러 유지
- 버튼이 화면 밖으로 밀리는지 검사
- 고정 하단 버튼과 겹치지 않도록 진단
- QR 해제 시 원래 크기 복원

버튼의 크기만 확대하고 눌리는 동작 자체는 변경하지 마세요.

## 4. 자동 레이아웃 진단 및 제한된 보정

기존 읽기 전용 DOM 진단 기능을 확장합니다.

다음 오류를 검사해 주세요.

- 텍스트 잘림
- 버튼과 인접 요소의 겹침
- 가로 넘침
- 화면 밖 버튼
- 하단 고정 조작부에 가려진 콘텐츠
- 작은 터치 영역

감지한 오류 중 안전하게 해결 가능한 경우에만 검증된 보정 전략을 적용합니다.

허용된 전략 예시:
- 버튼 최소 높이 증가
- 줄바꿈 허용
- 컨테이너 최소 너비 해제
- 그리드 열 수 감소
- 추가 세로 공간 확보
- 스크롤 영역 여백 확보

보정 전후 DOM 측정값을 비교해 문제가 해결됐는지 확인하고, 새 문제가 발생하면 해당 보정을 되돌리세요.

발급에 필요한 메뉴나 버튼을 숨기거나 삭제하지 마세요.

## 5. 범용성 유지

무인민원발급기 전용 CSS 선택자, 메뉴 이름, 화면 ID를 SDK에 하드코딩하지 마세요.

SDK는 어댑터가 제공하는 텍스트·액션·레이아웃 영역을 바탕으로 동작해야 합니다.

서로 다른 HTML 구조에서도 같은 확대 규칙을 적용할 수 있도록 테스트해 주세요.

## 6. 테스트

최소한 다음을 확인해 주세요.

1. 고정 px 글씨가 큰 글씨 설정에 따라 실제로 확대되는지
2. 고정 px 버튼이 큰 버튼 설정에 따라 실제로 확대되는지
3. 같은 프로필을 반복 적용해도 크기가 누적되지 않는지
4. 텍스트 잘림을 감지하고 안전하게 보정하는지
5. 버튼 겹침을 감지하고 필요한 경우 되돌리는지
6. SDK 해제 시 원래 스타일이 복원되는지
7. endSession() 이후 접근성 설정이 완전히 초기화되는지
8. 서로 다른 두 가지 독립 HTML 구조에서 동작하는지
9. 기존 스마트 길잡이·QR 스캔 기능 유지
10. 기존 데모커피 주문 기능 유지

자동 보정이 실패하거나 지원되지 않는 화면 유형도 정확히 보고해 주세요.

## 7. 패키징

SDK 버전을 v0.3.0으로 올리고 새 설치형 .tgz 패키지를 생성해 주세요.

기존 v0.1.0, v0.2.0, v0.2.1 파일은 모두 보존합니다.

독립 소비자 프로젝트에 실제 설치해 테스트하고, 타입 검사와 빌드를 수행해 주세요.

npm 공개 게시 및 Publish는 하지 마세요.
