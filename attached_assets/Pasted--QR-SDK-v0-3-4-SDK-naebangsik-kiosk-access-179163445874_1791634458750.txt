# 내 방식 QR 공통 SDK v0.3.4 — 스크롤 안내 개선 및 확대 안정성 강화

현재 데모커피 프로젝트에는 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.3.3`이 구현되어 있습니다.

중앙 '내 방식 QR' Production v2 배포 후 실제 QR을 데모커피와 무인민원발급기에서 사용하며 접근성 문제를 확인했습니다.

이번 작업에서는 두 키오스크에 공통으로 재사용할 수 있는 SDK 기능을 개선하고, 새로운 설치형 SDK v0.3.4를 제작해 주세요.

중요: SDK의 공통 기능은 SDK 내부에 구현하고, 개별 키오스크에는 최소한의 어댑터 연결만 필요하도록 설계합니다.

## 1. 기존 추가 메뉴 안내를 화면 아래로 이동

현재 SDK v0.3.3의 추가 메뉴 안내가 화면 상단에 나타나 무인민원발급기의 브랜드·시계 헤더와 겹칩니다.

안내 UI의 기본 위치를 **화면 아래쪽의 안전 영역**으로 변경해 주세요.

요구사항:

- 화면 아래쪽에 안내 표시
- 기존 메뉴 및 고정 하단 버튼과 겹치지 않음
- 안내가 실제 클릭·터치·스크롤을 방해하지 않음
- 큰 글씨·고대비 적용 시에도 안내를 읽을 수 있음
- 메뉴를 끝까지 내리면 안내가 사라짐
- 다시 위로 스크롤하면 재표시
- QR 적용 전후 모두 동작
- 상단 헤더와 겹치지 않음

기존 `menuItems` 및 `menuMessage` 기능은 유지해 주세요.

필요하면 어댑터가 하단 고정 영역이나 추가 회피 영역을 선택적으로 등록하게 해 주세요.

안전하게 표시할 공간이 없다면 억지로 겹치게 하지 말고 안내를 숨기고 진단 결과를 남겨 주세요.

단순히 `bottom: 0`으로 고정해서 기존 하단 버튼을 가리는 방식은 금지합니다.

## 2. 가로 스크롤 목록 자동 안내

데모커피의 카테고리 목록은 좁은 화면에서 가로 스크롤됩니다.

예를 들어 '커피·음료', '케이크', '디저트', '간단한 식사' 카테고리가 있는데 화면 너비에 따라 오른쪽 메뉴가 보이지 않습니다.

공통 SDK에서 **가로 스크롤 가능 목록의 숨겨진 항목을 감지하는 기능**을 구현해 주세요.

기본 안내:

"오른쪽에도 항목이 있습니다. 왼쪽으로 밀어보세요."

데모커피에서는 다음 문구를 사용합니다.

"오른쪽에도 메뉴 종류가 있습니다. 왼쪽으로 밀어보세요."

요구사항:

- 실제 가로 스크롤 영역과 목록 항목을 어댑터에서 등록
- 오른쪽에 숨겨진 항목이 있고 실제로 스크롤 가능할 때만 안내
- 오른쪽 끝까지 이동하면 안내 숨김
- 다시 왼쪽으로 이동하면 재표시
- RTL 등 방향이 다른 구조를 무조건 같은 방향이라고 가정하지 않기
- 안내 UI는 SDK가 생성
- QR 없이도 기본 동작
- 확대·화면 크기 변경·카테고리 변경 후 재측정
- 카테고리 클릭을 방해하지 않음
- 실제 스크롤이 막혀 있다면 잘못된 안내 대신 진단 결과 표시

다른 키오스크도 사용할 수 있도록 선택적인 어댑터 API로 설계해 주세요.

## 3. 화면 아래 주요 조작 버튼 안내

카페의 '어떻게 결제할까요?' 화면에서는 결제하기 버튼이 처음 화면 아래에 있어 스크롤해야 보일 수 있습니다.

공통 SDK가 **등록된 주요 조작 버튼이 화면 아래에 있고, 스크롤하면 실제로 접근 가능한지** 감지해 안내하도록 해 주세요.

예시 문구:

"아래에 결제하기 버튼이 있습니다. 화면을 위로 밀어보세요."

요구사항:

- 결제·확인·다음 단계 등 주요 조작 버튼을 호스트가 선택적으로 등록
- 모든 일반 버튼을 무차별적으로 안내 대상으로 지정하지 않기
- 이미 버튼이 보이면 안내하지 않음
- 스크롤해서 접근 가능할 때만 안내
- 버튼이 실제로 보이면 안내 숨김
- 화면을 다시 위로 올리면 필요시 재표시
- 하단 고정 버튼과 겹치지 않음
- QR 설정 전후 동작
- 스마트 길잡이와 안내 UI 충돌 방지

무인민원발급기의 확인·다음 버튼에도 재사용할 수 있어야 합니다.

## 4. 여러 스크롤 안내가 동시에 필요한 경우

세로 메뉴 안내, 가로 목록 안내, 주요 버튼 안내가 동시에 나타날 수 있습니다.

안내문이 2~3개씩 겹쳐 사용자를 혼란스럽게 하지 않도록 공통 표시 관리 로직을 구현해 주세요.

- 같은 영역에 여러 안내를 중첩 표시하지 않기
- 현재 사용자가 조작 중인 목록이나 단계의 안내를 우선
- 필요한 경우 한 번에 하나의 핵심 안내만 표시
- 기존 스마트 길잡이와 화면을 가리지 않도록 위치 조정
- 안내가 없어지면 다른 필요한 안내로 전환 가능
- 자동 음성 재생 금지

안내 우선순위와 전환 기준을 README에 명시해 주세요.

## 5. 큰 글씨·큰 버튼 적용 안정성

실제 QR 통합 테스트에서 데모커피의 상품명이 한 글자씩 세로로 표시되는 문제가 있었습니다.

이 문제의 주원인은 카페의 380px 이하 호스트 CSS였고, 해당 호스트 수정은 이미 완료됐습니다.

그러나 SDK의 `overflow-wrap: anywhere` 등 확대 보정 규칙도 복합 콘텐츠 버튼에 영향을 줄 수 있습니다.

다음 사항을 검증하고 공통 SDK를 개선해 주세요.

- 버튼 안에 이미지·상품명·가격·설명이 함께 있는 경우
- 좁은 화면에서 큰 글씨 + 큰 버튼 동시 적용
- 한글·영문 긴 상품명
- flex/grid 내부의 텍스트 폭 계산
- 부모와 자식 요소에 중복 확대가 적용되는지
- 화면 크기 변경 후 확대가 누적되는지
- 복잡한 버튼 내용이 한 글자씩 세로로 떨어지지 않는지

가능하면 읽을 수 있는 줄바꿈과 충분한 콘텐츠 폭을 유지하고, 레이아웃 보정이 악화되면 기존 SDK 원칙대로 롤백해 주세요.

글씨 크기를 무조건 줄이거나 메뉴를 숨겨서 해결하지 마세요.

호스트 DOM 구조상 공통 보정이 불가능하다면 그 한계를 명확히 진단해 주세요.

## 6. 작은 설명·선택 조작부 확대 지원

무인민원발급기에서 큰 글씨 모드를 적용해도 다음 요소가 상대적으로 작게 남아 있습니다.

- '증명서에 표시할 항목' 단계의 설명 문구
- 주소 공개·과거 주소 변동 사항·세대 구성 사유 항목
- 해당 항목의 선택 스위치와 보조 문구
- 수수료 면제 버튼 및 관련 설명

공통 SDK가 어댑터에 등록된 설명 텍스트와 선택 조작부를 확대할 수 있는지 검토하고 개선해 주세요.

- 기존 `getTextTargets()`와 `getActions()` 활용 우선
- 필요시 선택적인 등록 API 확장
- 버튼과 선택 스위치의 클릭 가능 영역 확인
- 스위치의 실제 선택 상태와 의미 보존
- `label` 및 접근성 이름 유지
- 확대 후 주변 설명과 겹치지 않음
- 작게 남는 요소가 있으면 진단 가능하도록 설계

민원발급기 전용 CSS를 SDK에 넣지 마세요.

이번 SDK 프로젝트에서는 실제 민원발급기 코드를 수정할 수 없으므로, 독립 fixture를 통해 공통 동작을 검증하고 민원발급기 어댑터에서 필요한 연결 변경을 명확히 보고해 주세요.

## 9. 데모커피 연결 및 회귀

데모커피 실제 앱에는 새 SDK 기능을 연결해 주세요.

- 기존 상품 메뉴 등록 유지
- 가로 카테고리 레일과 카테고리 항목 등록
- 결제 화면의 주요 버튼 등록
- 별도 카페 전용 안내 UI나 판정 알고리즘 구현 금지
- 상품명·가격·설명 읽기 가능
- 주문 도중 처음으로 복귀 시 QR 설정 초기화
- 전체 주문·옵션·장바구니·가상 결제 회귀 테스트

이전에 해결한 380px 이하 카드 줄바꿈 문제와 `returnToStart()` 연결을 유지해 주세요.
