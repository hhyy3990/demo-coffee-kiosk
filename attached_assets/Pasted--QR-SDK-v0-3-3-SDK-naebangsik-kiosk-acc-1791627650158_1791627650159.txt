# 내 방식 QR 공통 SDK v0.3.3 개발 — 숨겨진 메뉴 자동 감지 및 스크롤 안내

현재 데모커피 프로젝트에서 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.3.2`를 개발·관리하고 있습니다.

이번에는 서로 다른 키오스크에서도 재사용할 수 있는 **'추가 메뉴 자동 안내' 기능**을 SDK v0.3.3으로 구현해 주세요.

이 기능은 사용자가 메뉴를 더 볼 수 있다는 사실을 쉽게 인식하도록 돕기 위한 공통 접근성 기능입니다.

중요: 무인민원발급기 프로젝트에서 기존 터치 스크롤 문제는 CSS 수정으로 해결됐습니다. 이번에는 해당 문제를 SDK에서 다시 해결하려 하지 말고, 실제로 아래에 숨겨진 메뉴가 있을 때 안내하는 기능만 구현합니다.

## 1. 기능 요구사항

SDK가 등록된 메뉴 및 스크롤 영역의 실제 DOM 상태를 분석해, 화면 아래에 추가 메뉴가 있는지 자동으로 판단하도록 구현해 주세요.

아래에 메뉴가 있을 때 안내 문구:

**"아래에도 메뉴가 있습니다. 화면을 위로 밀어보세요."**

아래 메뉴가 없으면 안내를 표시하지 않습니다.

- 첫 화면에서 아래쪽 메뉴가 가려져 있으면 안내 표시
- 스크롤을 내려 마지막 메뉴가 보이면 안내 숨김
- 위로 다시 스크롤해 메뉴가 가려지면 다시 표시
- 화면 크기 변경 시 재판정
- 큰 글씨·큰 버튼 적용 후 재판정
- QR 프로필 변경 및 초기화 후 재판정
- 카테고리·메뉴 전환 후 재판정
- 실제 메뉴가 모두 표시되면 안내하지 않음

단순히 페이지에 스크롤바가 있다는 이유만으로 안내를 표시하지 마세요.

**등록된 메뉴가 실제로 보이는 영역 아래에 남아 있을 때만 안내해야 합니다.**

## 2. QR 적용 전에도 동작

이번 기능은 특정 QR 설정에 종속되지 않는 기본 접근성 기능입니다.

따라서 사용자가 QR을 스캔하기 전의 기본 키오스크에서도 작동해야 합니다.

QR을 스캔하면 커진 메뉴에 맞춰 다시 판단하지만, QR이 없다는 이유로 안내가 비활성화되어서는 안 됩니다.

SDK 초기화 시 공통 기능으로 활성화할 수 있도록 설계해 주세요.

## 3. 서로 다른 스크롤 구조 지원

다음 두 가지 구조를 모두 지원해야 합니다.

A. 메뉴 영역 자체가 스크롤되는 키오스크

B. 메뉴 영역은 스크롤되지 않고 문서 전체가 스크롤되는 키오스크

기존 `getLayoutRegions()`와 `getActions()` 등 SDK 어댑터를 최대한 재사용해 주세요.

필요하면 선택적인 어댑터 등록 항목을 추가해도 됩니다.

단, 기존 SDK 소비자에게 불필요한 필수 구현이나 대규모 수정이 생기지 않도록 설계해 주세요.

- 실제 스크롤 소유 요소 확인
- 등록된 메뉴 항목의 순서와 실제 위치 확인
- 고정 하단 조작부가 메뉴를 가리는지 고려
- 메뉴의 일부만 표시된 경우에도 판단
- 스크롤 도중 안내 상태 갱신
- 스크롤 가능한 범위가 없거나 실제로 추가 메뉴가 없으면 안내하지 않음

스크롤이 불가능한 상태에서 단순히 안내만 표시해 사용자를 혼란스럽게 하지 마세요. 이런 경우에는 기존 SDK 진단에 문제를 보고하도록 해 주세요.

## 4. 공통 안내 UI

안내 UI는 호스트 키오스크마다 직접 작성하는 것이 아니라 **SDK가 생성·관리**해야 합니다.

권장 구성:

- 아래 방향 화살표
- 짧은 한글 안내 문구
- 배경과 글씨가 구별되는 가독성 높은 디자인
- 큰 글씨 모드에서도 잘림 방지
- 고대비 모드에서도 읽기 쉬움
- 기존 버튼 및 메뉴의 클릭 방해 금지
- 키보드·스크린리더 접근성 고려

가능하면 안내를 메뉴 하단이나 스크롤 영역의 안전한 위치에 표시하되, 고정 조작 버튼 위를 가리지 않도록 해 주세요.

안내가 메뉴보다 앞에 떠서 사용자가 메뉴를 선택하지 못하게 되는 상황은 허용하지 않습니다.

안내가 실제로 차지하는 공간 때문에 새로 스크롤 문제가 발생하지 않도록 해 주세요.

## 5. SDK 안내의 표시 조건

SDK가 모든 화면에서 임의로 '메뉴'라는 표현을 사용하면 부정확할 수 있습니다.

따라서 기본 문구는 메뉴 화면용으로 제공하되, 호스트에서 필요하면 문구를 선택적으로 변경할 수 있게 해 주세요.

예시:

- 증명서 목록: "아래에도 증명서 메뉴가 있습니다. 화면을 위로 밀어보세요."
- 카페 메뉴: "아래에도 상품이 있습니다. 화면을 위로 밀어보세요."
- 일반 목록: "아래에도 항목이 있습니다. 화면을 위로 밀어보세요."

문구만 선택적으로 설정할 수 있게 하고, 안내 표시 조건과 UI 로직은 공통 SDK에 두세요.

이 기능은 AI를 사용하지 않는 결정적 DOM 기반 안내 기능입니다.

## 6. 기존 SDK 기능과 충돌 방지

다음 기능은 모두 유지합니다.

- QR v1/v2 프로필 처리
- 큰 글씨·큰 버튼
- 고대비
- 하단 조작
- 쉬운 말 설정
- 스마트 길잡이
- 음성 안내
- QR 카메라 스캔
- 세션 종료 초기화
- 반응형 크기 재계산
- 자동 레이아웃 진단·보정·롤백

특히 스마트 길잡이 안내와 추가 메뉴 안내가 같은 위치에 겹치거나, 음성 안내가 중복 재생되지 않도록 해 주세요.

추가 메뉴 안내는 기본적으로 텍스트로 표시하고, 음성 자동 재생은 하지 마세요.

기존 `simplifiedLayout` 설정을 다시 추가하지 마세요.

## 7. 세션 및 이벤트 관리

다음 상황에서 안내가 정상적으로 갱신되도록 해 주세요.

- QR 적용 전 기본 상태
- QR 적용 후 메뉴 확대
- QR 적용 취소
- 처음화면 복귀
- 전화면 이동
- 주문·발급 단계 변경
- 화면 크기 변경
- 스크롤
- 메뉴 항목 수 변경

`endSession()`이 호출되면 현재 화면에 대한 안내 상태를 정리하고, 호스트가 기본 화면으로 돌아와 새 메뉴를 표시하면 해당 기본 화면을 다시 분석하도록 설계해 주세요.

이 과정에서 이벤트 리스너·ResizeObserver·MutationObserver가 중복 등록되거나 남지 않도록 해 주세요.

## 8. 독립 구조 테스트

반드시 서로 다른 HTML 구조에서 SDK 기능을 검증해 주세요.

Fixture A:
- 자체 스크롤 영역을 가진 메뉴 목록
- 하단 고정 버튼 존재

Fixture B:
- 문서 전체가 스크롤되는 메뉴 목록
- 메뉴 영역 자체에는 스크롤 범위 없음
- 하단 고정 버튼 존재

Fixture C:
- 모든 메뉴가 화면 안에 들어오는 경우
- 안내 표시되지 않아야 함

Fixture D:
- 메뉴가 아래에 있지만 스크롤 자체가 막힌 경우
- 잘못된 안내 표시 대신 진단 결과 확인

Fixture E:
- 큰 글씨·큰 버튼을 켜면서 새로 메뉴가 가려지는 경우

각 fixture에서 다음을 확인해 주세요.

1. 안내 표시 여부
2. 마지막 메뉴 도달 시 숨김
3. 다시 위로 이동하면 재표시
4. 안내가 실제 클릭을 방해하지 않는지 hit-test
5. 하단 고정 조작부와 겹치지 않는지
6. 화면 크기 변경 시 정상 갱신
7. 세션 종료 후 이벤트·DOM 정리

단순한 함수 단위 테스트뿐 아니라 Chromium 브라우저에서 실제 DOM 좌표를 측정해 검증해 주세요.

## 9. 데모커피 실제 적용

데모커피 앱에도 새 SDK 기능을 연결해 주세요.

- 기존 메뉴와 카테고리 유지
- 기존 주문·결제 흐름 유지
- SDK가 메뉴 가림을 감지할 때만 공통 안내 표시
- 필요한 메뉴·스크롤 영역만 어댑터에서 등록
- 카페 전용 추가 메뉴 안내 구현 금지
- 메뉴가 전부 보이면 안내 숨김
- 스마트 길잡이와 충돌하지 않는지 확인

데모커피의 기존 디자인은 유지해 주세요.
