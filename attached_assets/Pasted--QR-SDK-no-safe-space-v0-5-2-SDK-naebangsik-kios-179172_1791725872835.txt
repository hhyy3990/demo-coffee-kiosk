# 내 방식 QR — SDK 스크롤 안내 no-safe-space 문제 수정 및 v0.5.2 릴리스

현재 데모커피 프로젝트에서 공통 접근성 SDK `@naebangsik/kiosk-accessibility-sdk@0.5.1`을 개발·관리하고 있습니다.

동일한 v0.5.1 tarball을 무인민원발급기에 설치한 결과, QR 하단 도크와 기존 고정 조작부, 하단 조작 60·70·80%, 발급 업무 및 세션 초기화까지 정상 작동했습니다.

하지만 실제 무인민원발급기에서 한 가지 공통 SDK 문제가 발견됐습니다.

**기본 화면에서는 스크롤 가능한 메뉴가 있음에도 `no-safe-space` 때문에 `↓ 아래에도 내용이 있어요` 안내가 표시되지 않습니다.**

반면 하단 60·70·80% 모드에서는 같은 안내가 정상 표시되고 스크롤 최하단에서 사라집니다.

이번 작업의 목표는 이 문제를 공통 SDK에서 수정하고, v0.5.2로 패키징하는 것입니다.

## 1. 현상과 재현 조건

무인민원발급기의 현재 구조는 다음과 같습니다.

- 첫 화면에 증명서 메뉴 18개
- 콘텐츠는 `.stage` 내부에서 세로 스크롤
- 첫 화면에 SDK QR 도크 존재
- 기존 하단 고정 조작부 존재
- 390×844 화면 기준 QR 도크 y=667~739, 기존 고정 조작부 y=739.6~844
- 기본 모드에서는 스크롤이 가능하지만 안내 미표시
- SDK 진단값 `no-safe-space`
- 하단 조작 60·70·80%에서는 안내 정상 표시

SDK가 보호 영역 때문에 안내를 배치하지 못한다고 판단하는 것으로 추정됩니다.

이것은 추정 원인이므로 SDK 소스와 재현 fixture에서 정확한 이유를 확인해 주세요.

## 2. SDK 스크롤 안내 배치 로직 분석

기존 스크롤 안내의 다음 기능을 살펴봐 주세요.

- 실제 스크롤 소유자 감지
- 스크롤 가능 여부 계산
- 안내 pill 배치 후보 생성
- 보호 영역과 겹침 판정
- `no-safe-space` 발생 조건
- QR 도크 위치 반영
- `getLayoutRegions().bottomControls` 처리
- 스마트 길잡이 및 모달과의 우선순위
- viewportMode 60·70·80% 적용 시 좌표 계산

특히 기본 화면에서만 `no-safe-space`가 발생하는 이유를 수치로 설명해 주세요.

스크롤 안내가 일반 메뉴 타일 전체를 보호 영역으로 오인하고 있는지, 혹은 QR 도크와 고정 조작부의 높이를 중복 차감하는지도 확인해 주세요.

## 3. 스크롤 안내의 보호 원칙

이번 수정에서는 다음 원칙을 명확히 적용합니다.

### 반드시 보호할 요소

- SDK QR 하단 도크
- 기존 고정 필수 조작부
- 진행 중인 모달의 실제 상호작용 영역
- SDK 스마트 길잡이의 필수 조작 영역
- 호스트가 명시적으로 등록한 중요한 회피 영역

### 일반적으로 겹침을 허용할 요소

- 증명서 메뉴 카드
- 카페 메뉴 카드
- 일반 콘텐츠 영역
- 스크롤되는 설명 텍스트
- 스크롤 영역 안의 일반 버튼과 타일

스크롤 안내는 짧은 안내 UI이므로, 일반 콘텐츠와 시각적으로 일부 겹치는 것을 허용합니다.

하지만 안내가 실제 버튼 조작을 지속적으로 방해하지 않도록, 가능한 경우 빈 영역을 우선 사용하고 안내 자체는 클릭·터치 이벤트를 가로채지 않는 방식도 확인해 주세요.

**일반 메뉴가 많다는 이유만으로 `no-safe-space`가 발생해 안내를 포기해서는 안 됩니다.**

다만 QR 도크나 필수 조작부와 충돌하지 않는 위치가 실제로 전혀 없다면, 억지로 겹쳐 표시하지 말고 그 한계를 명확히 보고해 주세요.

## 4. 독립 무인민원발급기형 fixture 생성

이번에는 데모커피 첫 화면만 시험하면 문제를 재현할 수 없습니다.

공통 SDK 개발 프로젝트 내부에 별도의 독립 HTML fixture를 만들어 주세요.

fixture에는 다음 요소를 포함합니다.

- 세로 스크롤 가능한 콘텐츠 영역
- 여러 개의 일반 메뉴 카드
- 화면 하단 SDK QR 도크
- QR 도크 바로 아래 또는 인접한 기존 고정 조작부
- 하단 고정 버튼 높이 약 104px
- QR 도크 높이 약 72px
- 기본 모드 및 하단 60·70·80% 모드
- QR 도크 활성화·비활성화
- 모달 및 스마트 길잡이 표시 상태

390×844에서는 실제 무인민원발급기의 배치 구조를 최대한 유사하게 재현해 주세요.

단, SDK 내부에 `.stage`, 무인민원발급기 화면 이름, 특정 고정 좌표를 하드코딩하지 마세요.

**fixture는 공통 SDK의 일반적인 DOM·어댑터 계약만 이용해야 합니다.**

## 5. 기본 화면에서 스크롤 안내 표시

다음 동작이 필수입니다.

1. 첫 화면 상단에 스크롤할 콘텐츠가 있음
2. QR 도크와 기존 고정 조작부가 함께 존재
3. 스크롤 안내가 QR 도크 및 조작부를 가리지 않는 위치에 표시됨
4. 아래로 스크롤하면 안내 상태가 갱신됨
5. 최하단에 도달하면 안내가 사라짐
6. 다시 위로 스크롤하면 안내가 나타남

표시 문구는 기존 공통 문구를 유지합니다.

- `↓ 아래에도 내용이 있어요`
- `↓ 아래에도 버튼이 있어요`

새로운 호스트 전용 안내 UI를 추가하지 마세요.

## 6. 안내 위치와 터치 이벤트

안내의 위치를 결정할 때 다음을 확인해 주세요.

- QR 도크와 사각형 충돌 없음
- 기존 고정 필수 버튼과 충돌 없음
- 화면 밖으로 벗어나지 않음
- 확대 상태에서도 글자가 잘리지 않음
- 안내가 일반 메뉴 카드 위에 표시돼도 메뉴 클릭은 정상 가능
- 안내가 스크롤 제스처를 가로채지 않음
- 고대비 모드에서 배경과 구분됨
- 모달이 열리면 안내가 뒤로 숨거나 비활성화됨

안내를 표시하기 위해 키오스크 콘텐츠 전체를 위로 밀거나 스크롤 영역 높이를 추가로 줄이지 마세요.

안내는 가능한 한 기존 스크롤 레이아웃을 변경하지 않는 오버레이로 처리합니다.

## 7. 방법 B 하단 조작 모드와 회귀

기존 방법 B는 화면 자체를 축소하지 않고 아래쪽 일부만 사용합니다.

QR 도크가 있는 첫 화면에서는 QR 도크 및 등록된 고정 조작부를 제외한 나머지 화면 높이에서 60·70·80%를 계산합니다.

이번 수정 이후에도 다음 사항을 보장해야 합니다.

- 기본 모드 안내 정상 표시
- 60% 안내 정상 표시
- 70% 안내 정상 표시
- 80% 안내 정상 표시
- 스크롤 최하단 안내 숨김
- 글씨·버튼 크기 변형 없음
- QR 도크 위치 변경 없음
- 기존 고정 조작부 위치 변경 없음
- 이중 스크롤 재발 없음

## 8. 스마트 길잡이 및 모달 우선순위

기존 SDK 정책을 유지합니다.

- 스마트 길잡이가 표시되면 일반 스크롤 안내 숨김
- 스마트 길잡이가 사라진 뒤 스크롤이 남아 있으면 안내 복귀
- QR 모달이 열려 있으면 스크롤 안내가 모달 조작을 방해하지 않음
- 발급 불가 안내 모달도 동일
- 모달 열기·닫기 전후 사용자의 스크롤 위치 유지

동적으로 삽입되는 모달 때문에 레이아웃 관찰기가 불필요하게 스크롤을 움직이는 경우가 있다면 재현 여부와 원인을 기록해 주세요.

다만 이번 작업의 주목적은 `no-safe-space` 수정이므로, 관련 없는 대규모 모달 구조 개편은 하지 마세요.

## 9. 화면 크기별 브라우저 검증

다음 화면에서 실행합니다.

- 320×844
- 390×844
- 1080×1920
- 360×667

각 화면에서 다음 조합을 검사합니다.

A. QR 도크 + 고정 조작부 + 기본 화면

B. QR 도크 + 고정 조작부 + 하단 60%

C. QR 도크 + 고정 조작부 + 하단 70%

D. QR 도크 + 고정 조작부 + 하단 80%

E. QR 도크 + 고정 조작부 + 아주 큰 글씨·큰 버튼·고대비

F. QR 도크 없는 일반 키오스크 화면

G. 스마트 길잡이 활성 상태

H. 모달 표시 상태

각 조합에서 다음 측정값을 기록합니다.

- 실제 스크롤 소유 요소
- scrollHeight / clientHeight / 최대 스크롤 거리
- 안내 표시 여부
- 표시 실패 시 정확한 이유
- 안내의 실제 화면 좌표
- QR 도크 및 고정 조작부와 충돌 여부
- 마지막 메뉴 접근 및 클릭
- 최하단 안내 숨김
- 위로 복귀 시 안내 재표시
- 가로 넘침
- 스크롤 위치 안정성

360×667에서 이전에 발견된 데모커피 메뉴 버튼 43.5px 문제는 이번에 별도로 수정하지 말고, 새 스크롤 안내가 해당 문제를 악화시키는지만 확인해 주세요.

## 10. 독립 소비자 재설치 검증

수정된 SDK를 패키징한 뒤 반드시 별도 소비자 프로젝트에서 시험합니다.

다음 구조를 포함합니다.

- 문서 전체가 스크롤되는 키오스크
- 내부 스크롤 컨테이너를 가진 키오스크
- 고정 하단 조작부가 있는 키오스크
- QR 도크와 고정 조작부가 함께 있는 키오스크
- QR 도크가 없는 기존 키오스크

독립 소비자는 SDK 소스 경로가 아니라 설치된 tarball을 사용해야 합니다.

수정된 CSS와 JavaScript가 tarball 안에 실제로 포함됐는지도 확인해 주세요.

## 11. SDK v0.5.2 릴리스

문제 수정과 검증을 완료한 후 SDK 버전을 `0.5.2`로 올립니다.

다음 파일을 생성해 주세요.

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.2.tgz`

확인 사항:

- package name: `@naebangsik/kiosk-accessibility-sdk`
- version: `0.5.2`
- 공개 QR 도크 API 유지
- 기존 viewportMode API 유지
- QR 프로필 v1/v2 호환성 유지
- 기존 SDK 아카이브 전부 보존
- README에 수정 내용 및 호스트 어댑터 연결 원칙 기록

중요: 수정이 실제로 검증되지 않거나 기본 화면의 문제를 재현하지 못했다면 성공으로 간주해 릴리스하지 마세요. 이 경우 원인 분석과 미해결 사항을 보고하고 대기합니다.

### 최종 성공 기준

**1. 무인민원발급기와 유사한 기본 화면에서 QR 도크와 고정 하단 조작부가 함께 존재해도 스크롤 안내가 정상 표시됩니다.**

**2. 실제 스크롤 최하단에서는 안내가 사라지고, 위로 돌아오면 재표시됩니다.**
