DemoCoffee → 중앙 QR AI 레이아웃 API 전달 계약
이 문서는 중앙 QR 서버의 현재 소스 기준이다. AI 계획은 검증 후 반환할 뿐, 중앙 서버가 화면에 적용하지 않는다. DemoCoffee는 응답을 자체 validateMenuLayoutPlan()으로 다시 검증해야 한다.

1. 엔드포인트와 인증
Method/path: POST /api/ai-layout/plan
Content-Type: application/json
최대 JSON 본문: 16 KiB (`express.json({ limit: "16kb" })); 초과 시 413
인증: Authorization: Bearer <AI_LAYOUT_SERVICE_TOKEN>
AI_LAYOUT_SERVICE_TOKEN은 Development와 Production 각각 Replit Secrets에 설정되어야 한다. 브라우저/공유 SDK에 두지 않는다.
인증은 요청 모델 검증보다 먼저 실행된다. 서비스 토큰이 없으면 503, 토큰이 설정되어 있고 헤더가 없거나 틀리면 401이다.
인증 성공 뒤 등록된 democoffee / cafe.menu v2 정책과 모델을 검증한다.
요청에 Origin이 없으면 CORS 검사를 건너뛴다. Origin이 포함되면 same-origin 또는 ALLOWED_ORIGINS 등록이 필요하다. 현재 preflight 허용 헤더에는 Authorization이 없으므로 브라우저 직접 호출용 API가 아니다. 토큰은 DemoCoffee 서버에서만 보관한다.
2. DemoCoffee v2 요청 JSON
화면 모델 자체가 요청 본문 최상위 JSON이다. 별도 model/screen envelope는 없다. hostId와 screenId 역시 최상위 필드다. 알 수 없는 필드는 거부된다.

아래는 문서에 있는 390px 표준 프로필의 실제 모델 구조 예시다.

해시 검증:

structureHash는 서버가 문서화된 STRUCTURE 문자열 및 JavaScript charCodeAt 기반 FNV-1a로 재계산한다. 지원 값은 837f86b3다.
constraintHash는 strict schema로 파싱한 제약 객체의 정해진 필드 순서를 유지해 JSON.stringify(constraints)를 만든 뒤 같은 FNV-1a로 재계산한다.
360px 표준 벡터는 compact, 기본 1열, 허용 [1], 제약 해시 207c8de6; 390px 표준은 regular, 기본 2열, 허용 [1,2], 제약 해시 df5bb9a5다.
정책의 호스트·화면·그룹·필수 ID·보호 속성·허용 연산 목록과 일치하지 않으면 요청은 거부된다. QR 토큰, 개인정보, 주문/결제 정보, 사용자 입력, DOM HTML은 모델에 포함하지 않는다.
3. 정상 응답
HTTP 200, 별도 envelope 없이 계획 객체를 그대로 반환한다. 다음은 390px 표준에서 열만 1로 선택하는 유효 예시다.

{
  "schemaVersion": 2,
  "screenId": "cafe.menu",
  "structureHash": "837f86b3",
  "constraintHash": "df5bb9a5",
  "viewportClass": "regular",
  "operations": [
    {
      "type": "setGroupColumns",
      "targetId": "menu.product-list",
      "columns": 1
    }
  ]
}
DemoCoffee는 schemaVersion, 화면 ID, 구조/제약 해시, viewportClass, 그리고 각 operation을 호스트의 validateMenuLayoutPlan()으로 재검증한 뒤에만 적용해야 한다. 응답에는 운영 데이터가 없으며, 기존 메뉴 항목·순서·선택 동작·고정 컨트롤을 보존한다.

허용 operation
setGroupColumns: menu.product-list, 열 1 또는 2이면서 모델의 allowedColumns에 있어야 함
setGroupFlow: menu.product-card, direction: "row", gapPx: 8..20
setChildBasis: menu.product-image, basisPercent: 20..30, minPx: 72..96
열 변경은 단독 가능. 카드 내부 변경은 setGroupFlow와 setChildBasis를 모두 포함해야 한다.
순서는 setGroupColumns → setGroupFlow → setChildBasis; 중복, 추가 필드, 대상·범위 오류는 거부된다.
카드 내부 operation이 있으면 유효 열 수(계획에서 생략한 경우 defaultColumns)는 1이어야 한다.
계획의 화면/해시/뷰포트 값은 입력 모델과 같아야 한다.
서버는 viewportClass와 접근성 제약을 검사한다. 모델에 숫자 화면 너비는 없으므로 호스트의 픽셀 너비 기반 분류를 서버가 독립 재계산할 수는 없다. 중앙 정책은 compact 또는 비표준 글씨/큰 버튼을 단일 열로 보수적으로 제한한다.

4. 오류 응답
응답 본문 형식은 { "error": "<일반화된 메시지>" }다. provider 오류 상세나 요청/응답 본문은 반환 또는 저장하지 않는다.

상태	조건
400	JSON 파싱 오류, 알 수 없는 필드, 잘못된 모델/해시/제약
401	서비스 토큰 설정 후 Bearer 토큰 누락/불일치
403	허용되지 않은 Origin
404	등록되지 않은 호스트/화면
413	16 KiB 초과 본문
429	호스트별 10분 내 10회 제한 초과; Retry-After: 600
500	그 밖의 API 처리 오류
502	AI 공급자 오류/타임아웃/잘못된 계획
503	서비스 토큰 또는 OPENAI_API_KEY 미설정
동일 요청은 프로세스 내 30초 동안 생성 결과를 재사용한다. 제한과 중복 억제는 프로세스별 메모리 방식이며 여러 Autoscale 인스턴스에 걸친 전역 제한은 아니다.

5. 인증·비용 및 처리 조건
OPENAI_API_KEY를 서버에서 사용한다. OPENAI_MODEL 선택 값이 없으면 gpt-4o-mini.
OpenAI Responses 요청은 store: false, 출력 상한 700 토큰, 18초 타임아웃, 자동 재시도 없음.
유효한 인증과 모델 검증을 통과한 뒤에만 계획 생성기에 도달한다.
외부 서버에서 사용할 공개 Mock API나 테스트 전용 서버 모드는 없다. Mock은 Node 테스트에서 주입하는 in-process generator일 뿐이다. 실제 AI 호출 없는 테스트는 server/demo-menu-layout.test.ts 등의 테스트 실행으로만 가능하다.
6. Development 접근 확인
현재 Development URL: https://feb78e58-0e2f-4910-8eb8-288934546a0f-00-3g1hihaz470pp.sisko.replit.dev
안전한 GET /api/health를 이 워크스페이스 셸에서 호출해 HTTP 200, {"status":"ok"}를 확인했다. 이 시험은 같은 워크스페이스 환경에서의 연결 확인일 뿐, 별도 DemoCoffee Replit 서버에서의 접근은 접속 미확인이다.
Replit 공식 문서에 따르면 Development URL(*.replit.dev)은 임시 개발 URL이며 기본적으로 비공개/인증 보호 대상이다. 다른 Replit 앱 같은 자동화 서비스가 private project에 API 요청하려면 Development 범위 External Access Token이 필요하다. 이는 API 트래픽용이지 브라우저 미리보기용이 아니다.
개발 AI 엔드포인트에 인증 없이 {}를 보내면 HTTP 503과 {"error":"화면 구성 계획 API가 아직 설정되지 않았어요."}를 반환했다. 이 확인은 AI 생성기에 도달하지 않았다.
서버 앱 자체는 Authorization: Bearer <AI_LAYOUT_SERVICE_TOKEN>도 요구한다. Replit External Access Token과 앱 서비스 토큰이 모두 Authorization: Bearer를 사용하므로, 다른 프로젝트에서 두 인증을 어떻게 함께 전달할지는 미해결이다. 토큰을 합치거나 인증을 우회하지 말 것.
외부 접속에 필요한 URL·External Access Token 설정은 환경마다 달라지고 URL은 임시다. Development URL은 안정적인 서비스 주소가 아니다.
제공된 Production 주소 https://naebangsikqr.replit.app은 Development URL과 별개다. 중앙 AI API가 Production Publish되지 않았으므로 Production URL을 사용 가능한 API 주소로 취급하면 안 된다.
브라우저 앱에서 직접 호출하지 말고 DemoCoffee 서버에서 중계해야 한다. 현재의 이중 Bearer 인증 연결 방안이 확정되기 전에는 실제 중계 호출을 시작하지 않는다.

Development URLs: https://docs.replit.com/core-concepts/project-editor/app-setup/development-urls
External Access Tokens: https://docs.replit.com/features/deployment-customization/external-access-tokens
7. Mock·호환성 범위
중앙 Mock 테스트는 데모커피 모델을 만들고 중앙의 동일 validator에 전달한다. V1–V3는 승인, V4–V6는 거부된다. 390px 예시에서 V1–V6 요약:

V1: 360px 표준, 카드 내부 operation 쌍 → 승인
V2: 390px 표준, 열 1만 → 승인
V3: 390px 표준, 열 1 + 카드 내부 operation 쌍 → 승인
V4: 360px 표준, 열 2 → 거부
V5: 390px 표준, 열 2 + 카드 내부 operation 쌍 → 거부
V6: 390px 큰 글씨·큰 버튼·고대비·하단 80%, 열 2 → 거부
이는 중앙 서버의 로컬 Mock 검증이며 실제 다른 Replit 프로젝트에서의 네트워크 호출/인증 호환성을 입증하지 않는다.

8. 조사 범위와 미해결 사항
조사 중 소스 코드, Secrets, DB, Production 설정을 변경하거나 Publish하지 않았다.
실제 OpenAI 호출은 하지 않았다.
별도 Replit 프로젝트에서 Development URL에 접근 가능한지는 확인하지 못했다.
Replit External Access Token과 AI_LAYOUT_SERVICE_TOKEN의 Bearer 헤더 충돌을 해결할 인증 전달 방식이 필요하다.
모델에 숫자 뷰포트 너비가 없어 호스트의 700px/900px 상세 경계 조건을 중앙이 독립 재계산할 수 없다. 현재 중앙 검사는 보수적이며, 범위 밖의 일부 호스트 모델을 거부할 수 있다.
호스트가 실제 요청을 보내기 전, 인증 구성과 네트워크 접속을 별도로 승인·검증해야 한다.
