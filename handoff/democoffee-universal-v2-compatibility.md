# DemoCoffee Universal v2 host compatibility

This handoff records the policy and model currently generated by the DemoCoffee Development Fake path. It does not change application behavior and makes no network request.

## Central registry comparison

The registry row provided for this review identifies `democoffee` / `cafe.menu` / `menu.product-list` / `arrangement` / `compact-grid`. Those identifiers match the Development host policy. The registry explicitly says `hostPolicyVerified: false`; therefore central approval is **not verified**.

The local contract is schema version `2`, contract version `universal-layout.v2`, and structure version `menu.v2`. The local v2 validator is the central validator implementation supplied with the project materials, with local module paths adapted. Its contract version matches the copied central v2 contract.

## Actual menu structure and hashes

The live category menu contains five products. Their IDs and names are intentionally omitted. The ordered list is hashed as canonical JSON of `{ "orderedItemIds": [...] }`; the resulting `itemOrderHash` and model `structureHash` are in the JSON file. Array ordering is significant, so a reorder changes the hashes without exposing item details in this handoff.

For the standard text/button and contrast profile with no bottom viewport mode, the structure hash is the same for compact, regular, and wide viewport classes. The constraint hash varies by viewport. The regular viewport constraint hash matches the known synthetic fixture hash. The structure hash does not: the host model uses its actual five-item count and order digest rather than the synthetic fixture structure. No fixture values were substituted.

## Option and accessibility conditions

The local option is `arrangement/compact-grid` on `menu.product-list`. It is emitted only when text scale and button scale are both standard. Large and extra-large text and large buttons remove this option; the host also constrains those profiles to one column. Standard or high contrast and the supported bottom viewport modes do not independently remove the option. The minimum touch target in the policy is 44 px.

The host allows columns `[1]` for compact, `[1, 2]` for regular, and `[1, 2]` for wide. The CSS preset does not set AI-provided CSS or directly choose columns; existing responsive host CSS remains responsible for the grid columns.

## Host-owned CSS preset

When the validated option is selected, React sets the grid's `data-universal-v2-option="compact-grid"` attribute. The fixed host CSS sets a 10 px grid gap, 44 px minimum height for the product-card button, 118 px artwork height, and 12 px metadata padding. At widths up to 700 px, artwork height is 104 px. At widths up to 380 px, the existing one-column horizontal card layout applies, with artwork at `auto` / minimum 138 px. No plan contains arbitrary CSS.

The preset changes layout only. It does not change product data, order, selection, cart behavior, or actions.

## Hash and policy details

Use the `hashRules` section of the JSON as the validation specification: recursively NFC-normalized canonical JSON, sorted object keys, preserved array order, safe integer numbers, UTF-8 SHA-256, lowercase hex. `structureHash` binds host/screen/version and ordered component structure, including the five-item count and item-order digest. `constraintHash` binds the viewport, accessibility state, operations, allowed columns, touch target, protected properties, and effective option groups.

The central row supplied for this task does not state its expected item-count range, accessibility filters, viewport column policy, CSS values, or structure hash. Those policy fields therefore cannot be declared equal based on the registry row alone. Central verification remains pending.
