# SDK v0.5.30 — Consumer 키보드 포커스 테스트 실패 원인 확인

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK:
`packages/kiosk-accessibility-sdk/`

현재 SDK 버전은 **v0.5.30**입니다.

직전 작업에서 스크롤 안내 ON/OFF와 QR v5 지원을 구현했고, SDK 단위 테스트 51/51, 브라우저 레이아웃 테스트, 데모커피 주문 E2E, 타입 검사 및 빌드가 통과했습니다.

다만 다음 명령의 마지막 키보드 포커스 검사만 실패했습니다.

`npm run sdk:verify-consumer`

실패 내용:
- Smart Guide의 Next 버튼에 키보드 포커스가 이동하는지 확인하지 못함
- Collapse 버튼에 키보드 포커스가 이동하는지 확인하지 못함

이번 작업은 **이 실패의 원인을 확인하고, 테스트 자체가 구버전 UI를 참조하는 경우에만 테스트 코드를 수정하는 작업**입니다.

**SDK 기능 코드·CSS·UI·프로필 스키마는 수정하지 마세요.**

## 1. 현재 UI와 테스트 기대값 비교

먼저 다음을 확인하세요.

- SDK v0.5.30에 Smart Guide 접기/펼치기 버튼이 실제로 존재하는지
- Easy Language 접기/펼치기 버튼이 실제로 존재하는지
- Smart Guide의 Next 버튼은 어떤 조건에서 표시되는지
- 이전·다음 버튼의 실제 태그, aria-label, disabled 상태, tabindex
- X 닫기 버튼의 실제 태그, aria-label, tabindex
- consumer 키보드 검증 스크립트의 버튼 탐색 방식

**v0.5.29에서 Easy Language와 Smart Guide의 접기/펼치기는 의도적으로 제거했습니다.**

따라서 존재하지 않는 Collapse 버튼에 대한 포커스 요구는 구버전 테스트일 가능성이 있습니다.

## 2. 실제 키보드 접근성 확인

현재 SDK v0.5.30 tarball을 사용하는 독립 consumer 브라우저에서 다음을 확인하세요.

1. Easy Language가 2페이지 이상일 때 이전·다음 버튼에 Tab으로 접근할 수 있는지
2. Smart Guide가 2페이지일 때 Next 버튼에 Tab으로 접근할 수 있는지
3. Smart Guide X 버튼에 Tab으로 접근할 수 있는지
4. 버튼이 실제 활성 상태일 때 포커스를 받는지
5. aria-label과 접근성 이름이 올바른지
6. 스마트 길잡이가 자동으로 다음 페이지로 넘어가거나 종료되기 전에 검증이 수행되는지
7. 실제 사용자 키보드 입력을 방해하는 focus trap 또는 불필요한 tabindex 설정이 없는지

Next 버튼이 없는 1페이지 상태나 자동 전환 후 비활성화된 상태에서 버튼 포커스를 검사하면 잘못된 결과가 나올 수 있으므로, 정확한 상태를 구분하세요.

버튼이 실제로 존재하고 활성화돼 있는데도 Tab으로 접근할 수 없다면 **실제 SDK 접근성 오류**로 보고하세요.

## 3. 테스트 코드 수정 허용 범위

다음이 확인된 경우에만 테스트 코드를 수정할 수 있습니다.

- 기존 테스트가 제거된 Collapse 버튼을 찾고 있음
- 테스트가 잘못된 aria-label 또는 오래된 선택자를 사용함
- Smart Guide Next 버튼의 표시 조건이나 자동 전환 타이밍을 반영하지 못함
- 테스트의 포커스 검사 시점이 실제 버튼이 존재하는 시점과 다름

수정 원칙:

- Collapse 검사 대신 현재 존재하는 X 버튼의 키보드 접근성 검증
- Easy Language 이전·다음 버튼 검증 유지
- Smart Guide Next 버튼 검증 유지
- 실제 사용자 Tab 이동 검증 유지
- 테스트를 단순 삭제하거나 항상 통과하도록 변경하는 것 금지
- 테스트를 통과시키기 위해 Smart Guide의 실제 타이머 정책 변경 금지

**실제 SDK 코드에 문제가 있다면 테스트 기대값을 낮춰 통과 처리하지 마세요. 원인만 보고하고 사용자 승인을 기다리세요.**

## 4. 최소 재검증

테스트 코드의 오류만 수정했다면 다음을 실행하세요.

1. 해당 키보드 포커스 브라우저 검사
2. `npm run sdk:verify-consumer`

실패했던 검증이 정상 통과하는지 확인하세요.

다른 SDK 단위 테스트 51개, QR v1~v5 테스트, 전체 주문 E2E 등 이미 통과한 검증은 코드가 변경되지 않았다면 불필요하게 다시 실행하지 마세요.
