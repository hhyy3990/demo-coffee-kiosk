# 내 방식 QR — 공통 SDK v0.5.28 접근성 오류 통합 수정 및 데모커피 회귀 검증

현재 프로젝트는 **데모커피 Replit**입니다.

공통 SDK 원본 경로:
`packages/kiosk-accessibility-sdk/`

현재 SDK 버전:
`@naebangsik/kiosk-accessibility-sdk@0.5.27`

이번 작업은 실제 Production QR을 사용해 데모커피와 무인민원발급기를 직접 테스트하면서 발견한 오류를 수정하는 작업입니다.

**사용자가 승인한 아래 항목만 수정하세요. 새로운 기능·디자인·안내 문구·AI 기능·QR 스키마 변경은 금지합니다.**

SDK-first 원칙에 따라 공통 UI와 안내 상태 문제는 SDK 원본에서 해결합니다. 데모커피 고유 기능인 주문 확인 바와 카메라 미리보기는 카페 호스트 코드를 수정할 수 있습니다.

무인민원발급기와 중앙 내 방식 QR 프로젝트는 이번 작업에서 수정하지 마세요.

## 1. 쉬운 말 활성화 시 하단 80% 자동 적용

다음 공통 규칙을 구현하세요.

| easyLanguage | viewportMode | 실제 업무 화면 |
|---|---|---|
| false | null | 일반 화면 |
| true | null | 하단 80% 자동 적용 |
| true | bottom 80% | 하단 80% 유지 |
| true | bottom 70% | 하단 70% 유지 |
| true | bottom 60% | 하단 60% 유지 |
| false | bottom 60/70/80% | 사용자가 선택한 모드 유지 |

핵심 원칙:

1. 중앙 QR에 저장된 원본 preferences를 수정하지 않습니다.
2. SDK가 실제 화면에 적용하는 viewportMode만 계산합니다.
3. 쉬운 말을 끄거나 다른 QR을 적용하면 현재 적용된 설정을 기준으로 다시 계산합니다.
4. 명시적으로 선택한 60%, 70%, 80% 설정은 덮어쓰지 않습니다.
5. 사용자가 쉬운 말 패널을 접어도 하단 80% 배치는 유지합니다.
6. 세션 종료 시 기존 초기화 동작을 유지합니다.
7. 기존 QR v1~v4 호환성을 유지합니다.
8. QR을 통한 적용과 기존 Development 접근성 체험 모두에서 공통 규칙이 일관되게 작동해야 합니다.

사용자가 하단 조작을 별도로 선택하지 않았다면 쉬운 말 활성화 시 자동으로 80%를 적용하는 것이 의도된 동작입니다.

**60%나 70%로 임의 변경하지 마세요.**

## 2. 하단 80%에서 쉬운 말이 한 글자씩 분할되는 오류 수정

무인민원발급기 실제 QR 테스트에서 다음 문제가 확인됐습니다.

- 320px 내외의 모바일 화면
- 매우 큰 글씨
- 큰 버튼
- 쉬운 말 활성화
- 하단 80% 적용
- '주민등록표 등본' 설명이 66페이지로 분할
- 다른 화면의 '주민등록번호' 설명이 137페이지로 분할
- 일부 페이지는 한 글자만 표시
- 기존 v0.5.27에서 본문이 패널 아래로 약 11px 넘치는 현상도 확인됨

이는 정상적인 페이지 분할이 아닙니다.

### 수정 목표

- 하단 80% 배치를 유지
- 상단 안내 영역을 불필요하게 늘리지 않음
- 한 글자씩 나뉘는 비정상적인 분할 방지
- 본문과 이전·다음 버튼 잘림 방지
- 모든 원문 보존
- 안내창 내부 스크롤 없음
- 읽던 문장 위치 유지
- 안내창 상단 위치 안정성 유지

### 반드시 원인을 먼저 측정

실제 브라우저에서 아래 항목을 확인하세요.

- 화면 전체 높이
- 하단 80%가 차지하는 영역
- 안내 패널 최대 높이
- 헤더 높이
- 본문에 남는 높이
- 페이지 버튼 높이
- 패딩·테두리·줄 간격
- 실제 한 줄의 텍스트 높이
- 글씨 크기별 페이지 계산 결과

특히 패널 최대 높이에서 헤더와 버튼을 제외한 뒤 본문 한 줄조차 들어갈 공간이 거의 없어지는지 확인하세요.

### 수정 조건

기존 자동 페이지 분할 방식을 유지하되, 실제 글씨 크기와 패널 가용 높이를 기준으로 정상적인 문장 단위 페이지를 구성하세요.

패널 안에 한 줄도 표시할 수 없는 경우, 한 글자짜리 수십 페이지를 생성하는 방식으로 처리하지 마세요.

필요한 최소 수정은 허용하지만, 상단 20% 영역을 넘겨 업무 콘텐츠를 가리는 방식이나 하단 80%를 임의로 축소하는 방식은 금지합니다.

**현재 상단 20% 영역 안에서 본문과 필수 버튼을 모두 표시할 수 없는 조합이라면, 이를 숨기거나 억지로 통과시키지 말고 정확한 높이 계산과 제약을 보고하세요.**

사용자 승인 없이 새로운 패널 표시 방식으로 변경하지 마세요.

## 3. 긴 스마트 길잡이 문구 잘림 수정

카페와 무인민원발급기 모두 하단 80%에서 긴 스마트 길잡이 문구가 아래로 잘리는 문제가 있습니다.

스마트 길잡이는 기존과 같이 단일 안내로 유지합니다.

수정 조건:

- 안내 문구 전체 표시
- 하단 잘림 없음
- 업무 영역 가림 최소화
- 상단 고정 위치 유지
- 화면 스크롤 시 위치 점프 없음
- 기존 10초 대기 및 15초 표시 정책 유지
- 이전·다음 페이지 버튼 추가 금지
- 텍스트 생략 및 임의 요약 금지
- AI 호출 추가 금지

스마트 길잡이의 길이가 너무 길어 지정된 안내 영역에 들어가지 않는 경우, 사용자 승인 없이 새로운 페이지 전환·내부 스크롤·레이아웃 정책을 추가하지 마세요.

기존 구조 안에서 해결 가능한지 확인하고, 불가능한 조건은 측정 결과를 보고하세요.

## 4. 쉬운 말 접힘 상태에서 스마트 길잡이 자동 펼침

현재 오류:

사용자가 쉬운 말 안내를 접어 두면 스마트 길잡이 표시 시간이 되어도 스마트 길잡이까지 접힌 상태로 표시되어 내용을 볼 수 없습니다.

사용자가 승인한 동작:

1. 사용자가 쉬운 말 패널을 접음
2. 기존 대기 시간이 지나 스마트 길잡이 시작
3. 스마트 길잡이는 자동으로 펼쳐져 설명을 표시
4. 스마트 길잡이 표시 시간이 종료됨
5. 기존 쉬운 말 안내로 복귀
6. 쉬운 말 안내는 이전의 접힘 상태로 돌아감

추가 조건:

- 기존 쉬운 말 페이지 위치 보존
- 스마트 길잡이 타이머 재시작 없음
- 같은 단계에서 입력하거나 스크롤해도 조기 종료되지 않음
- 실제 단계 변경 시 기존 정리 동작 유지
- 쉬운 말이 원래 펼쳐져 있었다면 종료 후 펼쳐진 상태 유지
- 사용자가 명시적으로 변경한 안내 상태를 불필요하게 초기화하지 않음

이 동작은 공통 SDK에서 해결하세요.

## 5. 데모커피 하단 스크롤 안내와 주문 확인 바의 위치 관계 수정

실제 사용자가 확인한 오류:

메뉴를 담으면 화면 하단에 '1개 담았어요' 주문 확인 바가 나타나는데, 기존 하단 스크롤 안내인 '아래에도 버튼이 있어요'가 주문 확인 바를 가립니다.

사용자가 원하는 동작:

### 장바구니가 비었을 때

주문 확인 바가 없으므로 기존처럼 업무 스크롤 영역 하단에 안내를 표시합니다.

### 메뉴를 담았을 때

주문 확인 바가 실제로 표시되면 하단 스크롤 안내를 해당 주문 확인 바 바로 위에 배치합니다.

### 주문 확인 바가 사라질 때

하단 스크롤 안내는 기존 하단 위치로 복귀합니다.

### 반드시 지킬 조건

- 주문 확인 바의 실제 표시 상태와 좌표를 기준으로 판단
- 스크롤 위치에 따라 임의로 안내 Y 좌표를 변경하지 않음
- 스크롤 중 안내가 위아래로 튀는 기존 오류 재발 금지
- 실제 아래쪽 콘텐츠가 남아 있는지 확인하는 기존 표시 정책 유지
- 맨 아래에 도달하면 기존처럼 숨김
- 스크롤 안내는 pointer-events:none 유지
- 버튼 클릭을 방해하지 않음
- 데모커피 외 다른 키오스크의 스크롤 안내 위치 변경 금지

공통 SDK의 기존 스크롤 소유자·힌트 배치 API를 우선 확인하세요.

카페에서 주문 확인 바의 실제 DOM 요소를 SDK에 등록해야 한다면 기존 공개 API를 활용하고, 새 공통 API가 반드시 필요한 경우에만 최소한으로 수정하세요.

주문 확인 바의 디자인과 기능 자체는 변경하지 마세요.

## 6. 데모커피 QR 카메라 미리보기 검은 화면 수정

실제 테스트 결과:

- 데모커피: 카메라 QR 스캔 시 화면이 검게 표시되지만 QR 스캔은 성공
- 무인민원발급기: 같은 기기에서 카메라 영상이 정상 표시됨

QR 스캔 인식은 이미 정상 동작하므로 스캔 로직을 불필요하게 교체하지 마세요.

다음 사항을 확인하세요.

- video 요소 존재 및 크기
- MediaStream이 실제 video.srcObject에 연결됐는지
- video.play() 상태
- autoplay, muted, playsInline
- 비디오 표시 CSS
- opacity, visibility, z-index
- 비디오 위를 덮는 레이어
- 카메라 스트림과 QR 디코더가 같은 입력을 사용하는지

목표:

**현재 정상인 QR 스캔 기능을 유지하면서 카메라 미리보기에 실제 영상이 표시되도록 수정합니다.**

카메라 전환 기능 등 요청하지 않은 새로운 기능은 추가하지 마세요.

## 7. 기존 오류의 재발 방지 — 필수

우리는 공통 SDK v0.5.18~v0.5.27을 거치면서 여러 문제를 수정했습니다.

이번 수정에서 아래 정상 동작을 절대 깨뜨리지 마세요.

### 상단 안내 패널

- 일반 모드 상단 기준 약 12px
- 하단 모드 상단 기준 약 8px
- 이전·다음 버튼 클릭 시 위치 점프 없음
- 접기·펼치기 시 불필요한 위치 점프 없음
- 스마트 길잡이 전환 시 위치 점프 없음

### 하단 스크롤 안내

- 실제 스크롤 영역 하단 기준 위치 유지
- 기존 기본 간격 약 12px 유지
- 스크롤 중 100px 이상 갑자기 튀는 현상 없음
- 아래에 내용이 있으면 표시
- 스크롤 끝에서는 숨김
- 모달에서는 활성 모달의 스크롤 상태 반영
- 다른 버튼과 겹친다는 이유만으로 숨기지 않음
- pointer-events:none 유지

단, 이번에 승인된 데모커피 주문 확인 바와의 배치 관계만 예외로 적용합니다.

### 스마트 길잡이

- 기존 10초 대기 / slowGuidance 설정 시 15초 표시
- 안내 단일 페이지 유지
- 입력·선택·스크롤 중 조기 종료 방지
- 실제 업무 단계 변경 시 정리
- 종료 후 쉬운 말 페이지 위치 복원
- 설명 문구 변경 없음

### QR·접근성 설정

- QR v1~v4 호환성 유지
- 큰 글씨·큰 버튼·고대비 유지
- QR 도크 하단 배치 유지
- 기존 세션 종료·초기화 유지
- 기존 데모커피 주문 단계 유지
- API 구조 및 Production URL 변경 없음

## 8. 실제 브라우저 회귀 검증

화면 크기:

- 320×844
- 360×667
- 390×844
- 1080×1920

모드:

- 일반
- 하단 60%
- 하단 70%
- 하단 80%
- 쉬운 말 켜기 + viewportMode null → 자동 하단 80%

특히 반드시 확인하세요.

1. 하단 80%의 쉬운 말 페이지 수
2. 한 글자씩 나뉘는 문제 재발 여부
3. 본문·버튼 잘림 여부
4. 스마트 길잡이 긴 문구 표시
5. 쉬운 말 접힘 → 스마트 길잡이 자동 펼침 → 접힘 복귀
6. 상단 안내 패널 Y 좌표
7. 하단 스크롤 안내 Y 좌표
8. 장바구니 비어 있음 → 메뉴 담기 → 주문 바 등장 → 주문 바로 위 힌트 표시
9. 장바구니 비우기 → 주문 바 사라짐 → 힌트 복귀
10. 스크롤 도중 힌트 위치 점프 없음
11. QR 카메라 미리보기 실제 영상 표시
12. QR 스캔 정상 유지
13. 데모커피 전체 주문 완료 및 초기화

실제 카메라 하드웨어 검증이 불가능하면 시뮬레이션만으로 성공했다고 보고하지 마세요.

## 9. 릴리스

모든 승인 범위 내 오류가 해결되고 테스트를 통과하면 SDK 버전을 **v0.5.28**로 올리세요.

생성 파일:

`packages/kiosk-accessibility-sdk/releases/naebangsik-kiosk-accessibility-sdk-0.5.28.tgz`

기존 v0.5.27 tarball을 보존하세요.

SDK dist 및 tarball에 수정된 코드가 실제 포함됐는지 확인하세요.

**필수 테스트가 실패하거나 사용자 승인이 필요한 표시 정책 문제가 남으면 v0.5.28을 완료된 버전으로 보고하지 마세요.**
